HTML O Elemento script

O HTML diz o que cada coisa é, o CSS diz como ela fica, e o JavaScript faz a página reagir: um botão que mostra a receita, um cronômetro, um formulário que confere o e-mail antes de enviar. O JavaScript é uma linguagem de programação inteira, com guia próprio; aqui você vai aprender a parte do HTML: o elemento <script>, que liga o programa à página. E vai entender o erro mais comum de quem começa, um script que tenta mexer num elemento que ainda não existe, e os três jeitos de evitá-lo: defer, async e type="module".

Você vai aprender
  • O mínimo de JavaScript para entender os exemplos: console.log, querySelector e textContent.
  • O script dentro da página e o script num arquivo .js (src).
  • Por que um script no head dá Cannot set properties of null, e o que o navegador faz quando encontra um <script>.
  • O que fazem defer, async e type="module", e qual usar.
  • O <noscript> e os erros reais do validador W3C.

As mensagens de erro desta aula são as que o Chrome mostrou no Console, e os arquivos foram validados com o validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/js. No editor do guia, o console aparece embaixo do quadro de Resultado, com o que o programa escreve e os erros, no mesmo formato.

A ideia: a receita e o cozinheiro

Pense numa receita de bolo lida em voz alta, linha por linha, por um cozinheiro muito obediente. Se a linha 2 diz "bata os ovos" e os ovos só aparecem na linha 8 ("pegue os ovos"), ele para e diz: "não tenho ovos". Ele não lê adiante para procurar.

O navegador lê o HTML assim, de cima para baixo. Quando encontra um <script>, ele para de ler a página, roda o programa e só depois continua. Se o programa pede o <h1>, e o <h1> está mais abaixo, ele ainda não existe. Essa é a história inteira desta aula.

1. O mínimo de JavaScript

Três coisas bastam para os exemplos:

const titulo = document.querySelector("h1");
titulo.textContent = "Receitas da Ana (com JavaScript!)";
console.log("O script rodou.");
document.querySelector("h1")
"Página, me dê o primeiro elemento que casa com o seletor h1." O seletor é o mesmo do CSS: "h1", ".promo", "#mensagem" (aula class e id). Se nenhum elemento casar, ele devolve null, que quer dizer "nada".
const titulo =
Guarda o elemento numa variável chamada titulo, para usar na linha de baixo.
titulo.textContent = "…"
Troca o texto de dentro do elemento.
console.log("…")
Escreve uma mensagem no console: o painel Console do F12 (Ferramentas do Desenvolvedor) ou o console do editor do guia. O visitante da página não vê.

O resto (variáveis, funções, eventos) é assunto do futuro Guia JavaScript.

2. O script dentro da página

O jeito mais simples: o programa vai entre <script> e </script>. Aqui ele está no fim do body, depois do h1:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Receitas da Ana</title>
</head>
<body>
  <h1>Receitas da Ana</h1>
  <p>Bolo de cenoura com cobertura de chocolate.</p>
  <script>
    const titulo = document.querySelector("h1");
    titulo.textContent = "Receitas da Ana (com JavaScript!)";
    console.log("O script rodou.");
  </script>
</body>
</html>
<script>
Abre o programa. Tudo até o </script> é JavaScript, e não HTML. Não precisa de type: sem ele, é JavaScript.
const titulo = …
As três linhas da seção 1.
</script>
Fecha o programa. É obrigatório, sempre.

O título do Resultado mudou para "Receitas da Ana (com JavaScript!)", e o console mostrou O script rodou.. Funcionou porque, quando o navegador chegou no <script>, o h1 já tinha sido lido.

3. Um arquivo separado: src

Como no CSS (aula Ligar CSS), o jeito mais usado é pôr o programa num arquivo .js e ligar com o atributo src (source, "fonte", "origem"):

<script src="script.js"></script>
<script
O mesmo elemento.
src="script.js"
O endereço do arquivo, como o src de uma imagem. É src, e não href (o href é do link).
></script>
O </script> continua obrigatório, mesmo sem nada dentro. E nada vai dentro: com src, o navegador ignora o que estiver entre as tags.

As vantagens são as mesmas do .css: um arquivo para o site inteiro, que o navegador guarda e não baixa de novo, e o HTML fica limpo. Agora, o lugar natural para essa linha parece ser o head, junto com o link do CSS. Vamos tentar.

4. O erro: o script que chega cedo demais

A Ana pôs o script no head:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Receitas da Ana</title>
  <script src="script.js"></script>
</head>
<body>
  <h1>Receitas da Ana</h1>
  <p id="mensagem">Carregando...</p>
</body>
</html>

O validador acha tudo certo (vnu --verbose mostrou só o nome do arquivo). Mas o título não mudou, e o Console do Chrome mostrou, em vermelho:

Uncaught TypeError: Cannot set properties of null (setting 'textContent')    script.js:2
Uncaught
"Não capturado": um erro que o programa não tratou. Ele parou ali: a linha 3, o console.log, nunca rodou.
TypeError
"Erro de tipo": o programa tentou fazer algo com um valor que não aceita aquilo.
Cannot set properties of null
"Não é possível definir propriedades de null." O titulo é null, "nada": o querySelector("h1") não achou nenhum h1.
(setting 'textContent')
"(ao definir textContent)": a propriedade que ele tentou mudar.
script.js:2
O arquivo e a linha do erro: a linha 2, titulo.textContent = ….

O h1 existe no arquivo, mas não naquele momento. Veja a ordem em que o navegador trabalhou:

  1. Leu o head até a linha do <script src="script.js">.
  2. Parou de ler a página, baixou o script.js e o rodou.
  3. O script pediu o h1. A página até ali só tinha head, meta e title: nenhum h1. O querySelector devolveu null, e a linha 2 deu erro.
  4. Só então o navegador voltou a ler e montou o body, com o h1. Tarde demais: o script já tinha terminado.

Os outros navegadores mostram o mesmo erro com outras palavras (o Firefox, por exemplo, fala em null também). No editor do guia, o console embaixo do quadro mostra a mensagem do seu navegador, com o arquivo e a linha.

O mesmo acontece com um script dentro da página, no head, e com qualquer script que esteja acima do elemento que ele procura. Há duas saídas: pôr o script no fim do body (como na seção 2) ou pedir ao navegador que espere, com defer.

5. defer: "rode quando a página estiver pronta"

O atributo defer ("adiar") diz ao navegador: "baixe este script, mas só rode depois de ler a página inteira". Uma palavra muda tudo:

<script src="script.js" defer></script>

Com a mesma página e o mesmo script.js, o Chrome mudou o título para "Receitas da Ana (com JavaScript!)" e o console mostrou O script rodou., sem erro nenhum. O defer é um atributo booleano: basta escrever o nome (aula Atributos). E tem uma vantagem a mais: enquanto lê a página, o navegador já vai baixando o arquivo, sem parar a leitura.

Missão: o console mostra um erro, e a mensagem Título: Receitas da Ana não aparece. Sem tirar o script do head, acrescente o atributo que faz o navegador esperar a página inteira.

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Receitas da Ana</title>
  <script src="script.js"></script>
</head>
<body>
  <h1>Receitas da Ana</h1>
  <p>Bolo de cenoura com cobertura de chocolate.</p>
</body>
</html>

console.log("Título: " + titulo.textContent);

<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Receitas da Ana</title>
  <script src="script.js" defer></script>

Antes do conserto, a mensagem era outra: Cannot read properties of null (reading 'textContent'). "Ler" (read) em vez de "definir" (set), porque aqui o script só queria ler o texto. É o mesmo problema: o h1 ainda era null.

6. async: "rode assim que chegar"

O async (de asynchronous, "assíncrono", "sem esperar") também baixa o arquivo sem parar a leitura, mas roda o script assim que ele chega, esteja a página pronta ou não:

<script src="contador-de-visitas.js" async></script>

No teste da Ana, com o arquivo no próprio computador, o script.js com async rodou sem erro. Mas isso foi sorte da velocidade: num site de verdade, o arquivo pode chegar antes de o navegador ler o h1, e o erro volta, às vezes sim, às vezes não. O pior tipo de erro, porque some quando você tenta reproduzi-lo. E com vários scripts async, cada um roda na ordem em que chega, não na ordem em que está escrito.

Use async só para scripts que não mexem na página e não dependem de outros: um contador de visitas, um script de estatísticas.

7. type="module": o JavaScript moderno

O JavaScript moderno divide o programa em vários arquivos, os módulos, que pegam coisas uns dos outros com import ("importar") e export ("exportar"). Para isso, o script precisa de type="module":

export const precoBolo = 25;

import { precoBolo } from "./precos.js";

console.log("Bolo de cenoura: R$ " + precoBolo);
document.querySelector("#mensagem").textContent = "Bolo de cenoura: R$ " + precoBolo;

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Receitas da Ana</title>
  <script type="module" src="loja.js"></script>
</head>
<body>
  <h1>Receitas da Ana</h1>
  <p id="mensagem">Carregando...</p>
</body>
</html>
export const precoBolo = 25;
O precos.js "oferece" o preço para outros arquivos.
import { precoBolo } from "./precos.js";
O loja.js pega o preço. O ./ quer dizer "nesta mesma pasta".
type="module"
Diz ao navegador: "este script é um módulo". Sem isso, o import é proibido.

Pelo servidor local, o Chrome mostrou Bolo de cenoura: R$ 25 no console e no parágrafo. Repare: o script está no head e achou o #mensagem, que está no body. Um módulo já é adiado, como se tivesse defer. (Tanto que o validador proíbe escrever os dois: A “script” element with “type=module” must not have a “defer” attribute.)

Sem o type="module", o mesmo loja.js nem começa:

Uncaught SyntaxError: Cannot use import statement outside a module    loja.js:1

"Erro de sintaxe: não é possível usar import fora de um módulo." Um SyntaxError acontece antes de o programa rodar: nenhuma linha do arquivo foi executada.

Módulos não funcionam com dois cliques

Abrindo o index.html direto do computador (endereço file://), o Chrome bloqueia o módulo e mostra:

Access to script at 'file:///home/ana/js/script.js' from origin 'null' has been blocked by CORS policy: Cross origin requests are only supported for protocol schemes: chrome, chrome-experimental-site-token-provider, chrome-extension, chrome-untrusted, data, http, https, isolated-app.
Failed to load resource: net::ERR_FAILED

(Neste teste, o módulo se chamava script.js.) "O acesso ao script foi bloqueado pela política CORS": por segurança, módulos só são carregados por endereços http ou https. A solução é abrir a página pelo servidor local (aula Servidor Local). O editor do guia funciona como um servidor, então os módulos funcionam nele.

Quando o JavaScript está desligado: <noscript>

Algumas pessoas desligam o JavaScript (por privacidade, ou num navegador de texto). O <noscript> mostra um recado só para elas:

<p>Tempo de forno: 40 minutos.</p>
<noscript>
  <p>Esta página precisa de JavaScript para mostrar o cronômetro da receita.</p>
</noscript>

Com o JavaScript ligado, como no seu navegador agora, o recado não aparece no Resultado. Ponha o noscript no body: no head, ele só aceita link, style e meta, e um <p> lá dentro dá uma cascata de erros (veja abaixo). Melhor ainda é fazer a página funcionar sem JavaScript e usar o script só para melhorar.

Quando dá errado

Uncaught TypeError: Cannot set properties of null (setting 'textContent')

O que significa: o querySelector devolveu null. Ou o elemento ainda não existia (script no head sem defer, ou acima do elemento), ou o seletor está errado ("#mensagen", um . no lugar do #). A variante Cannot read properties of null (reading '…') é o mesmo problema, ao ler.

Como consertar: acrescente defer ao script (ou mova-o para o fim do body). Se já tem defer, confira o seletor letra por letra com o id ou a class do HTML.

A página inteira some: <script src="script.js" />

O que significa: a barra no fim não fecha o script (ela só funciona em elementos vazios, como meta e link, e mesmo neles não faz nada). O navegador ficou esperando um </script>, e tudo o que vinha depois (o resto do head, o body, o h1) foi lido como se fosse o texto do script. No Chrome, a página ficou em branco, sem nenhum h1. O validador:

$ vnu auto-fecha.html
"file:/home/ana/js/auto-fecha.html":6.3-6.28: error: Self-closing syntax (“/>”) used on a non-void HTML element. Ignoring the slash and treating as a start tag.
"file:/home/ana/js/auto-fecha.html":12.8-12.8: error: End of file seen when expecting text or an end tag.
"file:/home/ana/js/auto-fecha.html":6.3-6.28: error: Unclosed element “script”.
"file:/home/ana/js/auto-fecha.html":12.8-12.8: info warning: Found “</head>” in “script” content. Typo for “</script>”?

"Sintaxe de autofechamento (/>) usada num elemento HTML que não é vazio; ignorando a barra e tratando como tag de abertura", "fim do arquivo encontrado quando se esperava texto ou uma tag de fechamento", "elemento script não fechado" e a pista final: "encontrei </head> dentro do script; você quis escrever </script>?"

Como consertar: <script src="script.js"></script>, sempre com a tag de fechamento.

Uncaught SyntaxError: Cannot use import statement outside a module

O que significa: o arquivo usa import, mas o script não tem type="module".

Como consertar: <script type="module" src="…"></script>, e abra pelo servidor local.

… has been blocked by CORS policy … e net::ERR_FAILED

O que significa: um módulo aberto com dois cliques (endereço file://).

Como consertar: python3 -m http.server na pasta e abra http://localhost:8000 (aula Servidor Local).

O código entre as tags não roda: <script src="script.js">console.log("oi");</script>

O que significa: com src, o navegador roda só o arquivo e ignora o que está entre as tags. O validador avisa de um jeito estranho: error: The text content of element “script” was not in the required format: Expected space, tab, newline, or slash but found “c” instead. ("o conteúdo do script não está no formato exigido: esperava espaço, tabulação, quebra de linha ou barra, mas encontrei um c", o c de console.)

Como consertar: use dois script: um com src e vazio, outro sem src com o código.

error: An inline “script” element (…) must not have a “defer” attribute.

O que significa: <script defer>…código…</script>, sem src. "Um script dentro da página não pode ter defer": ele seria ignorado, e o código rodaria na hora. Com async, a mensagem é parecida: An inline classic “script” element (…) must not have an “async” attribute.

Como consertar: passe o código para um arquivo .js e use src + defer, ou mova o script para o fim do body.

error: A “script” element with “type=module” must not have a “defer” attribute.

O que significa: type="module" e defer juntos. O módulo já é adiado.

Como consertar: apague o defer.

error: Attribute “href” not allowed on element “script” at this point.

O que significa: <script href="script.js">. O validador acusa só o href e não sente falta do src, porque um script sem src é permitido (seria um script dentro da página, vazio). O arquivo nunca é carregado.

Como consertar: src="script.js".

error: Bad value “false” for attribute “defer” on element “script”.

O que significa: defer="false". Num atributo booleano, o que vale é estar ou não estar lá: defer="false" ainda adia o script. Os valores aceitos são nenhum (defer), vazio (defer="") ou o próprio nome (defer="defer").

Como consertar: para não adiar, apague o atributo.

info warning: The “type” attribute is unnecessary for JavaScript resources. / The “language” attribute on the “script” element is obsolete.

O que significa: type="text/javascript" e language="javascript", costumes antigos. O primeiro "é desnecessário para JavaScript"; o segundo é "obsoleto". Só avisos leves: o script funciona.

Como consertar: apague os dois. O único type que você vai usar é type="module".

error: Bad start tag in “p” in “noscript” in “head”.

O que significa: um <noscript><p>…</p></noscript> no head. O p é conteúdo visível: o navegador fechou o head ali, e vieram junto Stray end tag “noscript”, Stray end tag “head” e Start tag “body” seen but an element of the same type was already open, os erros da aula O head.

Como consertar: o noscript com texto vai no body.

Resumo

  • O <script> liga JavaScript à página: o código entre as tags ou um arquivo com src. O </script> é sempre obrigatório (/> engole a página).
  • Ao encontrar um script comum, o navegador para de ler, roda o programa e só depois continua. Um script no head não acha o que está no body: Cannot set properties of null.
  • defer: baixa sem parar e roda depois de ler a página, na ordem. É a escolha padrão.
  • async: roda assim que chega, sem ordem garantida; só para scripts independentes.
  • type="module": permite import/export, já é adiado e precisa de http (não funciona com file://).
  • defer e async só valem com src; type="text/javascript" sobra. O noscript com texto vai no body.
