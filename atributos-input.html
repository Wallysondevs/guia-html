HTML placeholder, value, autocomplete…

Um campo de formulário pode vir vazio, já preenchido, com uma dica cinza dentro, travado, apagado, com o cursor piscando nele, ou pronto para o navegador completar com o seu e-mail. Cada uma dessas coisas é um atributo do <input>: value, placeholder, readonly, disabled, autofocus e autocomplete. Eles parecem detalhes, mas mudam o que é enviado, o que a pessoa consegue fazer e quanto ela precisa digitar. Nesta aula você vai conhecer os seis, um por vez, e os enganos mais comuns com cada um.

Você vai aprender
  • value: o valor que o campo já traz quando a página abre.
  • placeholder: a dica que some quando a pessoa digita (e por que ela não substitui o <label>).
  • readonly e disabled: dois jeitos de travar um campo, e a diferença que importa: um é enviado, o outro não.
  • autofocus: o cursor já no campo quando a página abre.
  • autocomplete: como ajudar o navegador a preencher nome, e-mail, CEP e senha.
  • Os erros mais comuns e as mensagens reais do validador W3C.

Você vai precisar de O Elemento input, label e Validação. Os exemplos com o resultado embaixo são desenhados pelo seu navegador. Os comportamentos ("é enviado", "não recebe o foco") foram conferidos no Chromium 155, e as validações com o validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

1. value: o valor inicial

O value ("valor") é o texto que o campo já traz quando a página abre. A pessoa pode apagar e escrever outro:

<label for="cidade">Cidade:</label>
<input type="text" id="cidade" name="cidade" value="São Paulo">
<label for="qtd">Quantidade:</label>
<input type="number" id="qtd" name="qtd" value="1">
  • Se a pessoa não mexer, o value é enviado como está: cidade=São Paulo.
  • Se ela mudar, vai o que ela escreveu. O atributo no HTML não muda: ele continua sendo o valor inicial, e é para ele que o botão reset volta (aula Botões).
  • O value tem de estar no formato do tipo. Num type="date", é sempre ano-mês-dia: value="2026-10-20", mesmo que o navegador mostre a data como 20/10/2026. Num type="number", é um número escrito com ponto: value="2.5".

Nas caixas de marcar e nos rádios, o value tem outro papel: é o que vai no envio quando o item está marcado (aula checkbox e radio). Nos botões, é o valor do botão clicado.

2. placeholder: a dica que some

O placeholder (de place = "lugar" e holder = "que segura": "o que segura o lugar") é um texto clarinho dentro do campo vazio. Ele some assim que a pessoa começa a digitar:

<label for="tel">Telefone:</label>
<input type="tel" id="tel" name="tel" placeholder="ex.: (11) 98765-4321">

Digite um número no resultado: o exemplo desaparece. Apague tudo: ele volta.

No Chromium 155, um campo vazio com placeholder="Seu nome" foi enviado como nome=, sem nada depois do =. Se você precisa de um valor de verdade, use value.

O placeholder não é um rótulo

É muito comum ver formulários só com placeholder, sem <label>: fica mais "limpo". E o validador W3C não reclama: um <input placeholder="Seu nome"> sem rótulo passa sem nenhuma mensagem. Mas:

  • assim que a pessoa digita, a dica some, e ela não lembra mais o que o campo pedia (a cliente está no terceiro campo e esqueceu se o segundo era telefone ou CPF);
  • o texto clarinho é difícil de ler para muita gente;
  • parece já preenchido, e tem gente que pula o campo.

A regra do guia: todo campo tem um <label>, e o placeholder, se houver, só dá um exemplo.

Missão: este formulário usa o placeholder como rótulo. Dê a cada campo um <label> de verdade ("Nome:" e "E-mail:"), ligado pelo id. Tire o placeholder do nome e troque o do e-mail por um exemplo: ex.: ana@example.com.

<form>
  <input type="text" name="nome" placeholder="Nome">
  <input type="email" name="email" placeholder="E-mail">
  <button type="submit">Enviar</button>
</form>

<form>
  <label for="nome">Nome:</label>
  <input type="text" id="nome" name="nome">
  <label for="email">E-mail:</label>
  <input type="email" id="email" name="email" placeholder="ex.: ana@example.com">
  <button type="submit">Enviar</button>
</form>

3. Travar um campo: readonly × disabled

Os dois são atributos booleanos, e os dois impedem a pessoa de mudar o campo. A diferença está no que acontece com o campo no resto do formulário:

<form>
  <p>
    <label for="pedido">Número do pedido:</label>
    <input type="text" id="pedido" name="pedido" value="P-0042" readonly>
  </p>
  <p>
    <label for="cupom">Cupom de desconto:</label>
    <input type="text" id="cupom" name="cupom" value="BOLO10" disabled>
  </p>
</form>

Teste os dois no resultado. No número do pedido, você consegue clicar, selecionar o texto e copiar, mas não consegue mudar. No cupom, nada: ele aparece apagado, o clique não faz nada e o Tab passa direto por ele.

Tudo isso foi conferido no Chromium 155. Num formulário com os dois campos acima, os dados enviados foram só pedido=P-0042: o cupom desligado ficou de fora. O foco foi para o número do pedido e não foi para o cupom. E um campo readonly required vazio não impediu o envio: o navegador não valida um campo que a pessoa não pode mudar.

Quando usar readonly
Um valor que a pessoa precisa ver e que tem de ir junto, mas que ela não deve mudar: o número do pedido, o total calculado.
Quando usar disabled
Algo que não vale agora: o cupom de uma promoção que acabou, os campos de entrega quando a cliente escolheu retirar na loja. Normalmente, um script liga o campo de novo quando ele passa a valer (o grupo inteiro pode ser desligado com <fieldset disabled>, aula fieldset e legend).
readonly não é segurança

O readonly impede a mudança na tela. No F12, qualquer um apaga o atributo e troca P-0042 por outro número. Quem recebe o pedido nunca deve confiar num valor só porque ele estava travado (aula Validação, seção 8).

4. autofocus: o cursor já no lugar

O atributo booleano autofocus ("foco automático") põe o cursor no campo assim que a página abre, como na página de um buscador, em que você já pode sair digitando:

<form action="busca.html">
  <label for="q">Buscar receita:</label>
  <input type="search" id="q" name="q" autofocus>
  <button type="submit">Buscar</button>
</form>

Esse exemplo não tem quadro de resultado de propósito: o autofocus age quando a página abre, e esta página já abriu faz tempo. Na missão abaixo você vai vê-lo funcionar.

  • Só um por página. O validador recusa dois (veja em Quando dá errado), e faria sentido: o cursor só pode estar num lugar.
  • Use pouco. Quem usa leitor de tela é levado direto para o campo e perde tudo o que vinha antes dele (o título, a explicação). No celular, o teclado abre sozinho e cobre a página. O autofocus combina com páginas cuja única tarefa é aquele campo: uma busca, um login.

Missão: ponha o autofocus no campo de busca. Depois clique no botão ↗ do quadro, que abre o resultado numa aba nova: lá, o cursor aparece piscando no campo, pronto para digitar. (O ↻ desenha a página de novo dentro do quadro, mas ali o cursor não vai para o campo: o navegador não deixa uma página dentro de um quadro tirar o foco do botão que você acabou de clicar.)

<h1>Receitas da Ana</h1>
<form>
  <label for="q">Buscar receita:</label>
  <input type="search" id="q" name="q">
  <button type="submit">Buscar</button>
</form>

<h1>Receitas da Ana</h1>
<form>
  <label for="q">Buscar receita:</label>
  <input type="search" id="q" name="q" autofocus>
  <button type="submit">Buscar</button>
</form>

5. autocomplete: ajudar o navegador a preencher

Os navegadores guardam o seu nome, e-mail, endereço e senhas, e oferecem esses dados quando você chega num formulário. Para acertar qual dado vai em qual campo, eles tentam adivinhar pelo name, pelo rótulo… e às vezes erram. O atributo autocomplete ("completar automaticamente") diz com todas as letras o que cada campo pede:

<form>
  <p><label for="nome">Nome completo:</label>
     <input type="text" id="nome" name="nome" autocomplete="name"></p>
  <p><label for="email">E-mail:</label>
     <input type="email" id="email" name="email" autocomplete="email"></p>
  <p><label for="tel">Telefone:</label>
     <input type="tel" id="tel" name="tel" autocomplete="tel"></p>
  <p><label for="cep">CEP:</label>
     <input type="text" id="cep" name="cep" autocomplete="postal-code"></p>
</form>

Clique no campo do nome: se o seu navegador tiver um nome guardado, ele oferece. Repare que o name do campo pode ser qualquer um (nome, em português); quem diz ao navegador o que o campo é, é o autocomplete, com palavras de uma lista fixa, em inglês.

O autocomplete é também uma questão de acessibilidade: para quem tem dificuldade de digitar ou de lembrar dados, um formulário que se preenche sozinho faz muita diferença. As diretrizes de acessibilidade (WCAG) pedem que os campos com dados da própria pessoa digam o que são (aula Formulários Acessíveis).

O autocomplete="off" nem sempre é obedecido

Ele pede ao navegador para não oferecer dados guardados, e serve para campos em que sugestões atrapalham (o código de um cupom, por exemplo). Mas os navegadores podem ignorá-lo em campos de login e senha, para que as pessoas continuem podendo usar o gerenciador de senhas. Não use off para "proteger" nada.

Quando dá errado

Os arquivos desta seção são páginas completas com o mesmo começo de 7 linhas (<!DOCTYPE html> até <body>, como em Estrutura de uma Página). O código mostrado começa na linha 8.

Um placeholder numa caixa de marcar 
<input type="text" name="nome" placeholder="Seu nome">
<label><input type="checkbox" name="v" placeholder="sim"> Vela</label>

$ vnu dica.html
"file:/home/ana/site/dica.html":9.8-9.57: error: Attribute “placeholder” is only allowed when the input type is “email”, “number”, “password”, “search”, “tel”, “text”, or “url”.

O que significa: "o atributo placeholder só é permitido quando o tipo é email, number, password, search, tel, text ou url". Uma caixa de marcar não tem onde escrever, então não tem onde mostrar a dica.

E repare na linha 8: um campo com placeholder e sem <label>. O validador não disse nada. O problema dela é de uso, e não de escrita (seção 2).

Como consertar: tire o placeholder da caixa; o texto dela vai no <label>. E dê um <label> ao campo do nome.

readonly num select ou numa caixa de marcar 
<label for="s">Sabor:</label>
<select id="s" name="s" readonly><option>a</option></select>
<label><input type="checkbox" name="v" readonly> Vela</label>
<label for="t">Texto:</label>
<textarea id="t" name="t" readonly></textarea>

$ vnu travado.html
"file:/home/ana/site/travado.html":9.1-9.33: error: Attribute “readonly” not allowed on element “select” at this point.
"file:/home/ana/site/travado.html":10.8-10.48: error: Attribute “readonly” is only allowed when the input type is “date”, “datetime-local”, “email”, “month”, “number”, “password”, “search”, “tel”, “text”, “time”, “url”, or “week”.

O que significa: o readonly não é permitido no select, e no input só vale para os tipos em que se digita. No <textarea> (linha 12) ele é permitido, e o validador não reclamou.

O que o navegador faz: ignora o atributo. A lista e a caixa continuam mudando normalmente: o "travado" não trava nada.

Como consertar: se o valor não pode mudar, mostre-o como texto comum. Se ele precisa ir no envio, use um campo de texto readonly com o valor. E, se é algo que não vale agora, use disabled, que funciona em todos.

Dois autofocus 
<label for="b">Busca:</label>

$ vnu foco.html
"file:/home/ana/site/foco.html":11.1-11.45: error: There must not be two elements with the same "nearest ancestor autofocus scoping root element" that both have the “autofocus” attribute specified.

O que significa: "não pode haver dois elementos com autofocus no mesmo 'escopo de foco automático'". O nome é complicado; na prática, o escopo é a página (ou um <dialog>, que tem o seu próprio, aula dialog). A linha 11 é o segundo autofocus.

O que o navegador faz: o foco vai para o primeiro, e o segundo é ignorado.

Como consertar: escolha um. Na dúvida, nenhum.

Um valor de autocomplete inventado 
<label for="n">Nome:</label>
<input type="text" id="n" name="n" autocomplete="nome">
<label for="e">E-mail:</label>
<input type="email" id="e" name="e" autocomplete="email">

$ vnu completar.html
"file:/home/ana/site/completar.html":9.1-9.55: error: Bad value “nome” for attribute “autocomplete” on element “input”: The string “nome” is not a valid autofill field name.

O que significa: "valor ruim, nome, para o autocomplete: não é um nome de campo de preenchimento automático válido". Os valores são palavras fixas, em inglês, como as da tabela da seção 5. O email da linha 11 está certo.

Como consertar: autocomplete="name". Na dúvida, confira na tabela; o validador pega todo valor inventado.

Um value fora do formato do tipo 
<label for="q">Quantidade:</label>
<input type="number" id="q" name="q" value="dois">
<label for="d">Data:</label>
<input type="date" id="d" name="d" value="20/10/2026">

$ vnu formato.html
"file:/home/ana/site/formato.html":9.1-9.50: error: Bad value “dois” for attribute “value” on element “input”: Expected a minus sign or a digit but saw “d” instead.
"file:/home/ana/site/formato.html":11.1-11.54: error: Bad value “20/10/2026” for attribute “value” on element “input”: The literal did not satisfy the date format.

O que significa: o primeiro erro diz "esperava um sinal de menos ou um algarismo, mas encontrou d"; o segundo, "o texto não está no formato de data". O formato de data do HTML é sempre 2026-10-20, qualquer que seja a língua do navegador.

O que o navegador faz: joga o valor fora. No Chromium 155, os dois campos abriram vazios e foram enviados vazios (q=&d=).

Como consertar: value="2" e value="2026-10-20".

readonly="false" 
<label for="n">Nome:</label>
<input type="text" id="n" name="n" disabled="disabled" readonly="false">

$ vnu booleano.html
"file:/home/ana/site/booleano.html":9.1-9.72: error: Bad value “false” for attribute “readonly” on element “input”.

O que significa: como em todo atributo booleano, o false não vale: o campo continua readonly. Já o disabled="disabled" é aceito: repetir o nome do atributo é uma das três formas válidas (as outras são disabled e disabled="").

Como consertar: para um campo que pode ser mudado, apague o readonly.

Resumo

  • value: valor inicial, enviado se a pessoa não mudar; precisa estar no formato do tipo (data = 2026-10-20), senão o navegador o joga fora.
  • placeholder: exemplo clarinho que some ao digitar; não é enviado e não substitui o <label> (o validador não avisa).
  • readonly: não muda, mas recebe foco e é enviado. disabled: não muda, não recebe foco e não é enviado. Nenhum dos dois é validado, e nenhum é segurança.
  • autofocus: cursor no campo ao abrir a página; um por página, e com moderação.
  • autocomplete: diz ao navegador que dado preencher, com palavras fixas (name, email, tel, postal-code, current-password…). Ajuda todo mundo, e mais ainda quem tem dificuldade de digitar.
  • Atributo booleano com ="false" continua ligado: para desligar, apague o atributo.
