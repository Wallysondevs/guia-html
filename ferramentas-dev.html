HTML Ferramentas do Desenvolvedor

Todo navegador de computador tem uma caixa de ferramentas escondida, feita para quem constrói sites: as ferramentas do desenvolvedor (em inglês, developer tools, ou só DevTools). Ela abre com uma tecla, o F12, e mostra a página "por dentro": a árvore de elementos que o navegador montou, os erros, os arquivos que chegaram. Nesta aula você aprende a abri-la e, principalmente, a diferença entre duas formas de olhar o HTML de uma página: Ver código-fonte e Inspecionar. Elas parecem iguais, mas não são, e a diferença ensina muito sobre HTML.

Você vai aprender
  • Abrir as ferramentas do desenvolvedor no Chrome, no Edge, no Firefox e no Safari.
  • Ver código-fonte (Ctrl + U): o arquivo exatamente como chegou.
  • Inspecionar: o DOM, a árvore que o navegador montou, com os consertos dele.
  • Comparar os dois com um HTML que o navegador consertou (o tbody que ninguém escreveu, o parágrafo fechado antes da hora).
  • Mexer na página ao vivo, e por que nada disso fica salvo.
  • O console, a aba de rede e o modo de celular.
As telas variam

As ferramentas do desenvolvedor mudam a cada versão do navegador, e cada navegador dá nomes um pouco diferentes para as mesmas coisas, que ainda mudam com o idioma. Por isso esta aula descreve o que você vai encontrar e onde, mas não promete o texto exato de cada menu. Os atalhos de teclado são os de sempre. Os arquivos e as árvores mostrados aqui são reais: as árvores foram montadas por um navegador de verdade (Chromium) a partir de cada arquivo.

A ideia: a planta e a casa construída

Pense na planta de uma casa, desenhada pelo arquiteto, e na casa pronta. Quase sempre são iguais. Mas, se a planta tinha um erro (uma porta que dava na parede), o pedreiro deu um jeito na obra, e a casa ficou um pouco diferente do papel. Para saber como a casa realmente ficou, você não olha a planta: entra na casa.

1. Abrir as ferramentas do desenvolvedor

Há três caminhos, e todos levam ao mesmo painel, que aparece grudado num lado da janela (embaixo ou à direita):

CaminhoWindows e LinuxmacOS
Tecla de funçãoF12(em geral não funciona; use o atalho abaixo)
AtalhoCtrl + Shift + ICmd + Option + I
Botão direitoClique com o botão direito em qualquer parte da página e escolha Inspecionar (o nome exato muda um pouco de navegador para navegador). Esse caminho já abre a árvore no elemento em que você clicou.
  • Chrome e Edge têm ferramentas quase idênticas, porque os dois são feitos sobre o mesmo motor (o Chromium).
  • Firefox tem as suas próprias, com outros nomes e outra arrumação, mas as mesmas ideias.
  • Safari, no macOS, vem com elas escondidas: nos ajustes do Safari, na parte avançada, ligue a opção dos recursos para desenvolvedores. Depois disso, o Cmd + Option + I funciona.
  • Em notebooks, o F12 às vezes controla o volume ou o brilho; aí é preciso segurar a tecla Fn junto.
  • No celular, os navegadores não têm esse painel. As ferramentas são coisa de computador.

O painel tem várias abas (também chamadas de painéis) no alto. Nesta aula você vai usar três: a de elementos (no Chrome e no Edge ela se chama Elements, ou Elementos em português; no Firefox, Inspetor), o Console e a de rede (Network, ou Rede). As outras, de desempenho, memória e armazenamento, ficam para quando você estiver mais adiante.

2. Ver código-fonte: o arquivo como chegou

Antes do F12, a ferramenta mais simples: Ver código-fonte. Ela mostra, numa aba nova, o texto que o navegador recebeu, letra por letra, sem nenhum conserto. Para abrir:

  • Ctrl + U no Chrome, no Edge e no Firefox (no macOS: Cmd + Option + U no Chrome, no Edge e no Safari; Cmd + U no Firefox);
  • ou o botão direito na página e a opção de ver o código-fonte;
  • ou escreva view-source: antes do endereço, na barra: view-source:https://exemplo.com/ (no Chrome, no Edge e no Firefox).

Para um arquivo do seu computador, o código-fonte é o próprio arquivo, igualzinho ao que o cat mostra no terminal. Veja a tabela de preços da lojinha da Ana:

$ cat precos.html
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Preços</title>
</head>
<body>
<table>
<tr><td>Bolo</td><td>R$ 30</td></tr>
</table>
</body>
</html>

Abrindo o precos.html no navegador e apertando Ctrl + U, você vê exatamente essas doze linhas, com as cores do navegador e os números de linha na margem. Numa página da internet, o código-fonte é o que o servidor mandou, como o curl mostrava em Como o Navegador Lê HTML.

3. Inspecionar: a árvore que o navegador montou

Agora abra o F12 na mesma página. A aba de elementos mostra o HTML de novo, mas com diferenças:

  • Ele aparece como árvore: cada elemento que tem filhos tem um triângulo do lado, que abre e fecha.
  • Passando o mouse sobre um elemento da árvore, ele acende na página, com uma cor por cima, e uma etiqueta mostra o nome e o tamanho. O caminho inverso também funciona: com a ferramenta de seleção (um ícone de seta, no canto do painel), clique em algo na página e a árvore pula para ele.
  • Ao lado ou embaixo da árvore, outro quadro mostra o CSS que vale para o elemento selecionado, inclusive a folha de estilo padrão do navegador (o "estilo do agente do usuário", em inglês user agent stylesheet).
  • E, o mais importante: a árvore não é o seu arquivo. É o DOM, já com os consertos do navegador.

Para o precos.html, esta é a árvore que o navegador montou (mostrada aqui como texto, do jeito que ela aparece aberta no F12):

<html lang="pt-BR"><head>
<meta charset="utf-8">
<title>Preços</title>
</head>
<body>
<table>
<tbody><tr><td>Bolo</td><td>R$ 30</td></tr>
</tbody></table>
</body></html>

Apareceu um <tbody> que a Ana não escreveu! Toda tabela tem um "corpo" (tbody, de table body), e as linhas (tr) moram dentro dele. Se o arquivo não tem o tbody, o navegador cria um. Isso não é erro: o validador aceita a tabela sem tbody, porque a regra do HTML deixa essa tag ser omitida.

$ vnu --verbose precos.html
precos.html                          « nenhum erro: o tbody pode ficar implícito

A tabela em si aparece igual nos dois casos (as tabelas têm a sua própria seção: Cabeçalhos (th, thead, tbody, tfoot)). Você pode ver esse tbody agora mesmo, no seu navegador, sem abrir o F12: a caixa abaixo tem um script.js que pede ao navegador o HTML da tabela como ele está no DOM e escreve no console, embaixo do resultado.

<table>
<tr><td>Bolo</td><td>R$ 30</td></tr>
</table>
<script src="script.js"></script>

// mostra o HTML da tabela como o navegador montou (o DOM)
console.log(document.querySelector("table").outerHTML);

O index.html não tem tbody, e o console mostra um. É o seu navegador, agora, fazendo o conserto. (O outerHTML é o jeito do JavaScript de pedir o HTML de um elemento a partir da árvore; o JavaScript tem guia próprio.)

4. Código-fonte × Inspecionar com um HTML consertado

O tbody é um conserto inofensivo. Agora um que muda a página. A Ana escreveu a lista de compras dentro de um parágrafo:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Compras</title>
</head>
<body>
<p>Lista de compras:
<ul>
<li>Farinha</li>
<li>Ovos</li>
</ul>
</p>
</body>
</html>

O Ver código-fonte mostra exatamente esse texto: o <ul> dentro do <p>, como ela escreveu. Já o Inspecionar mostra outra coisa:

<body>
<p>Lista de compras:
</p><ul>
<li>Farinha</li>
<li>Ovos</li>
</ul>
<p></p>
</body>

No F12, você veria três irmãos dentro do body: um p com o texto, o ul e um segundo p, vazio. Passando o mouse no p vazio, ele acende na página como uma faixa fina, sem conteúdo. Nenhum dos dois p contém a lista. Como explicado em Como o Navegador Lê HTML, um parágrafo não pode ter uma lista dentro: o navegador fechou o p quando chegou o <ul> e transformou o </p> que sobrou num parágrafo vazio.

Quando a página não está como você esperava, compare os dois. Se o Inspecionar mostra um elemento num lugar diferente do código-fonte, o navegador consertou alguma coisa ali, e o validador vai dizer o quê:

$ vnu compras.html
"file:/home/ana/site/compras.html":13.1-13.4: error: No “p” element in scope but a “p” end tag seen.

Experimente: as missões do guia olham o DOM, como o Inspecionar. Esta confere quantas linhas existem dentro do tbody, e repare que o código não tem tbody nenhum. Acrescente uma segunda linha à tabela, com Pudim e R$ 25, copiando o padrão da primeira: <tr><td>Pudim</td><td>R$ 25</td></tr>. A missão vai achar as duas linhas dentro do tbody que o navegador criou.

<table>
<tr><td>Bolo</td><td>R$ 30</td></tr>
</table>

<table>
<tr><td>Bolo</td><td>R$ 30</td></tr>
<tr><td>Pudim</td><td>R$ 25</td></tr>
</table>

5. Mexer na página ao vivo

Na aba de elementos, você pode mudar a página: dê dois cliques num texto da árvore para editá-lo, num atributo para trocar o valor, ou selecione um elemento e aperte Delete para apagá-lo. Clicando com o botão direito num elemento da árvore, há também a opção de editar o HTML dele inteiro. A página muda na hora.

É ótimo para testar uma ideia ("como ficaria com outro título?") sem mexer no arquivo. Mas atenção:

Nada do que você muda no F12 é salvo

As mudanças acontecem só na árvore que está na memória do navegador, naquela aba. O arquivo no disco continua igual, e basta recarregar a página (F5) para tudo voltar. Gostou do resultado? Faça a mesma mudança no editor e salve. (E, pelo mesmo motivo, mudar uma página de outro site no F12 não muda nada para ninguém além de você: é só a cópia do seu navegador. Uma "captura de tela" de um site editado no F12 não prova nada.)

6. O console

O Console é a aba onde o navegador escreve avisos e erros: um arquivo que não foi encontrado, um erro de JavaScript, um problema de segurança. Quando "alguma coisa não funciona", olhe ali primeiro. Erros aparecem destacados (normalmente em vermelho), avisos em amarelo.

No console você também pode digitar JavaScript e ver a resposta na hora. Experimente, em qualquer página, digitar document.title e apertar Enter: o console responde com o título da página, o mesmo texto do <title> que aparece na aba. Na primeira vez que você tenta colar alguma coisa no console, o navegador pode mostrar um aviso de segurança e pedir uma confirmação: é uma proteção contra golpes em que alguém pede para você colar um código ali. Nunca cole no console um código que um desconhecido mandou.

7. Outras ferramentas úteis para HTML

A aba de rede

A aba de rede (Network) lista cada arquivo que a página pediu: o HTML, as imagens, o CSS, o JavaScript. Para cada um, ela mostra o código de status (200, 404…), o tipo (o Content-type) e o tamanho, as mesmas informações que o curl -i mostrava em Como o Navegador Lê HTML. Ela só registra o que acontece com o painel aberto, então abra o F12 e recarregue a página. Uma imagem que não aparece quase sempre está ali, numa linha com 404, com o endereço errado à vista (aula Caminhos Relativos e Absolutos).

O modo de celular

No Chrome, no Edge e no Firefox, o atalho Ctrl + Shift + M (Cmd + Shift + M no macOS), com as ferramentas abertas, liga o modo de design responsivo: a página passa a ser desenhada numa "tela" do tamanho de um celular, que você pode trocar por outros tamanhos. É o jeito rápido de ver se a página funciona numa tela pequena (aula Celular (meta viewport)).

Acessibilidade

Os navegadores também mostram a árvore de acessibilidade, a versão do DOM que os leitores de tela usam, com o nome e o papel de cada elemento (no Chrome, num quadro ao lado da árvore de elementos; no Firefox, numa aba própria). Ela vai ser útil no Nível 3, em Acessibilidade.

Quando dá errado

O F12 não abre nada

O que significa: no notebook, o F12 pode estar fazendo outra coisa (volume, brilho); no Safari, os recursos para desenvolvedores estão desligados; num computador de escola ou de empresa, o administrador pode ter bloqueado as ferramentas.

Como consertar: tente Fn + F12, ou Ctrl + Shift + I, ou o botão direito e Inspecionar. No Safari, ligue a opção nos ajustes avançados. Se for bloqueio, só o administrador libera.

Eu consertei no F12, recarreguei e o erro voltou

O que significa: as mudanças no F12 ficam só na memória do navegador. O arquivo não foi alterado.

Como consertar: faça a mesma mudança no editor, salve e recarregue.

O Inspecionar mostra tags que eu não escrevi

O que significa: o navegador completou o DOM. html, head, body e tbody aparecem sempre, mesmo que o arquivo não tenha. Isso é normal e não é erro.

Como consertar: nada a consertar. Se quiser que o código-fonte e a árvore fiquem iguais, escreva essas tags no arquivo.

O Inspecionar mostra um elemento em outro lugar, ou um elemento vazio a mais

O que significa: o navegador consertou um erro: um elemento num lugar proibido (a lista dentro do parágrafo), uma tag não fechada, um fechamento sem abertura.

Como consertar: passe a página no validador. A mensagem dele aponta a linha do problema, e a árvore do F12 mostra o efeito.

O código-fonte não tem o texto que aparece na tela

O que significa: o conteúdo foi colocado na página pelo JavaScript, depois que ela carregou. Muitos sites grandes funcionam assim: o código-fonte é quase vazio, e o JavaScript monta o resto. O Inspecionar mostra o DOM atual, com tudo o que o JavaScript acrescentou; o código-fonte, não.

Como consertar: para estudar o HTML de uma página assim, use o Inspecionar. Nas páginas deste guia (só HTML), os dois mostram o mesmo conteúdo, a não ser pelos consertos do navegador.

Missão final: o parágrafo que não fecha

Missão: este é o código da lista de compras da Ana, com o erro desta aula. No DOM, ele vira um p, um ul e um p vazio. Conserte de verdade: feche o primeiro parágrafo logo depois de Lista de compras:, deixe a lista fora dele e apague o </p> que sobrou. No fim, acrescente um parágrafo novo depois da lista: <p>Comprar até sábado.</p>. A missão confere a árvore: dois p, nenhum vazio, e a lista logo depois do primeiro.

<p>Lista de compras:
<ul>
  <li>Farinha</li>
  <li>Ovos</li>
</ul>
</p>

<p>Lista de compras:</p>
<ul>
  <li>Farinha</li>
  <li>Ovos</li>
</ul>
<p>Comprar até sábado.</p>

Repare que o código inicial já tinha "dois p" no DOM, só que um deles vazio. Por isso a missão também confere que nenhum está vazio (p:empty). Se tiver um navegador de computador por perto, abra o F12 neste resultado e compare a árvore antes e depois do seu conserto.

Resumo

  • As ferramentas do desenvolvedor abrem com F12, Ctrl + Shift + I (Cmd + Option + I no macOS) ou com o botão direito → Inspecionar. No Safari, é preciso ligá-las nos ajustes.
  • Ver código-fonte (Ctrl + U, view-source:) mostra o arquivo como chegou. Inspecionar mostra o DOM: a árvore montada pelo navegador, com os consertos dele.
  • Elementos que você não escreveu (html, head, body, tbody) aparecem no Inspecionar: é normal. Um elemento fora do lugar ou um p vazio é sinal de erro consertado; o validador diz qual.
  • Mudar a página no F12 é ótimo para testar, mas nada é salvo: recarregou, voltou.
  • O Console mostra avisos e erros e aceita JavaScript (nunca cole código de desconhecidos). A aba de rede mostra cada arquivo pedido, com o status. O modo responsivo (Ctrl + Shift + M) imita um celular.
  • O F12 não aponta erros de HTML: para isso, o validador.
