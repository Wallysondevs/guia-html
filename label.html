HTML label

Todo campo de formulário precisa de um texto que diga o que escrever nele: "Nome", "E-mail", "Quero receber novidades". Esse texto é o rótulo, e em HTML ele tem um elemento próprio, o <label>. Parece um detalhe, porque um texto qualquer do lado do campo fica igualzinho na tela. Mas o <label> liga o texto ao campo, e essa ligação muda a vida de quem usa leitor de tela, de quem tem dificuldade de acertar uma caixinha pequena com o dedo e de quem preenche formulários pelo teclado.

Você vai aprender
  • A diferença entre um texto solto do lado do campo e um <label> ligado a ele.
  • Os dois jeitos de ligar: com for + id e envolvendo o campo.
  • O que a ligação faz: clicar no rótulo foca o campo (ou marca a caixinha), e o leitor de tela lê o rótulo.
  • Qual forma usar em cada caso, e por que o placeholder não substitui o rótulo.
  • Os erros reais do validador W3C: for que não acha o campo, id duplicado, dois campos num rótulo, rótulo dentro de rótulo.

Os exemplos foram validados com o validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook). Para onde cada rótulo errado aponta foi conferido no Chromium. Os quadros "Resultado" são desenhados pelo seu próprio navegador: clique nos rótulos para testar.

A ideia: a etiqueta colada no pote

Na cozinha da Ana, os potes de tempero são todos iguais. Ela pode fazer de dois jeitos:

  • colar um papelzinho na prateleira, mais ou menos embaixo de cada pote: se alguém mudar um pote de lugar, ninguém sabe mais qual é qual;
  • colar a etiqueta no próprio pote: o pote pode ir para qualquer lugar, e a etiqueta vai junto.

Um texto comum do lado do campo é o papel na prateleira: para os olhos, parece ligado; para o navegador e o leitor de tela, não tem ligação nenhuma. O <label> é a etiqueta colada no pote.

1. Texto solto × <label>

Os dois campos abaixo parecem iguais. Clique na palavra "Nome" de cada um:

<p>Nome: <input name="nome1"></p>
<p><label for="nome2">Nome:</label> <input id="nome2" name="nome2"></p>

No primeiro, nada acontece. No segundo, o cursor pula para dentro do campo. E isso é só a parte visível. A diferença completa:

Texto solto<label> ligado
Clicar no textonadafoca o campo (ou marca a caixinha)
Leitor de tela, ao entrar no camposó "editar texto" (a pessoa não sabe o que digitar)"Nome, editar texto"
Controle por voz ("clicar em Nome")não acha o campoacha
Preenchimento automático do navegadoradivinha piorusa o rótulo como pista

O texto do leitor de tela varia de um programa para outro (e de um idioma para outro), mas a regra é a mesma em todos: o que está no <label> vira o nome do campo. Esse "nome para a acessibilidade" é o assunto de Formulários Acessíveis.

2. Primeiro jeito: for + id

<p>
  <label for="email">E-mail:</label>
  <input type="email" id="email" name="email">
</p>
<label>
"Rótulo", "etiqueta". Um elemento em linha que contém o texto do rótulo.
for="email"
"Para": o id do campo a que este rótulo pertence. É a cola da etiqueta.
id="email"
O id do campo, que tem de ser exatamente igual ao for: mesmas letras, mesmas maiúsculas, sem espaço.
name="email"
Não participa da ligação. O name é para o envio (aula O Elemento input). O for procura o id.

Com for + id, o rótulo e o campo podem ficar em qualquer lugar da página, até em células diferentes de uma tabela. A ligação é pelo nome, e não pela posição.

Missão: os textos "Nome:", "E-mail:" e "Celular:" estão soltos. Transforme cada um num <label> com o for certo (olhe o id de cada campo). Depois clique em cada rótulo no resultado: o cursor tem de ir para o campo dele.

<form action="contato.html">
  <p>Nome: <input id="nome" name="nome"></p>
  <p>E-mail: <input type="email" id="email" name="email"></p>
  <p>Celular: <input type="tel" id="tel" name="tel"></p>
  <button>Enviar</button>
</form>

<form action="contato.html">
  <p><label for="nome">Nome:</label> <input id="nome" name="nome"></p>
  <p><label for="email">E-mail:</label> <input type="email" id="email" name="email"></p>
  <p><label for="tel">Celular:</label> <input type="tel" id="tel" name="tel"></p>
  <button>Enviar</button>
</form>

3. Segundo jeito: envolvendo o campo

Em vez de apontar com for, você pode colocar o campo dentro do <label>. Aí não precisa de for nem de id: o rótulo vale para o campo que está dentro dele.

<p><label>Cidade: <input name="cidade"></label></p>
<p><label><input type="checkbox" name="novidades"> Quero receber novidades</label></p>
<p><label><input type="checkbox" name="termos"> Li e aceito os termos</label></p>
<label>Cidade: <input …></label>
O texto e o campo, juntos, dentro do rótulo. O texto pode vir antes ou depois do campo.
As caixinhas
Clique no texto "Quero receber novidades": a caixinha marca e desmarca. Uma caixinha tem uns 13 pixels; com o rótulo, a área de clique passa a ser a frase inteira. No celular, isso faz toda a diferença.

Missão: nas três opções de cobertura, só dá para clicar no quadradinho. Envolva cada caixinha e o seu texto com um <label>, para a frase inteira virar área de clique. Teste clicando nos nomes.

<p>Coberturas:</p>
<p><input type="checkbox" name="cobertura" value="chocolate"> Chocolate</p>
<p><input type="checkbox" name="cobertura" value="coco"> Coco ralado</p>
<p><input type="checkbox" name="cobertura" value="morango"> Morango</p>

<p>Coberturas:</p>
<p><label><input type="checkbox" name="cobertura" value="chocolate"> Chocolate</label></p>
<p><label><input type="checkbox" name="cobertura" value="coco"> Coco ralado</label></p>
<p><label><input type="checkbox" name="cobertura" value="morango"> Morango</label></p>

Um grupo de opções como esse ainda ganha um título com <fieldset> e <legend> (aula fieldset e legend); as caixinhas têm aula própria em checkbox e radio.

Que campos aceitam um <label>?

Além do <input> (menos o type="hidden", que não aparece), o <label> serve para <textarea>, <select>, <button>, <meter>, <output> e <progress>. Um campo pode até ter dois rótulos (os dois focam o campo), mas um rótulo pertence a um campo só.

O placeholder não é rótulo

O texto cinza de exemplo dentro do campo (placeholder, aula placeholder, value, autocomplete…) some quando a pessoa começa a digitar. No meio do formulário, ela esquece o que aquele campo pedia. Além disso, o cinza claro costuma ser difícil de ler. Use o placeholder para um exemplo ("ana@exemplo.com.br"), e o <label> para dizer o que é o campo.

E quando não há espaço para um texto visível?

Numa caixa de busca com um botão de lupa, por exemplo, o desenho não tem um texto "Buscar". Aí o nome pode vir do atributo aria-label="Buscar receitas" no próprio campo, que o leitor de tela lê e ninguém vê. É uma exceção; o rótulo visível ajuda todo mundo. Veja ARIA.

Quando dá errado

Erros de rótulo quase nunca aparecem na tela: o texto continua do lado do campo, igualzinho. Só clicando no rótulo (ou usando um leitor de tela) dá para perceber, e o validador acusa a maioria. As páginas abaixo têm o esqueleto de sempre nas linhas 1 a 7, e o trecho mostrado começa na linha 8.

O for não acha o id 
<label for="email">E-mail:</label>
<input type="email" id="e-mail" name="email">

$ vnu nome.html
"file:/home/ana/rotulos/nome.html":8.1-8.19: error: The value of the “for” attribute of the “label” element must be the ID of a non-hidden form control.

O validador diz: "O valor do for do label tem de ser o id de um campo de formulário que não seja escondido (hidden)".

O que o navegador faz: nada. Clique em "E-mail:" no resultado: o cursor não vai para o campo, e o leitor de tela não lê o rótulo. O for="email" procura um id="email", e o campo tem id="e-mail" (o name="email" não conta). A mesma mensagem aparece para for="Nome" com id="nome": maiúsculas importam.

Como consertar: copie o id do campo e cole no for.

Dois campos com o mesmo id 
<p><label for="nome">Seu nome:</label> <input id="nome" name="nome"></p>
<p><label for="nome">Nome do bolo:</label> <input id="nome" name="bolo"></p>

$ vnu duplo.html
"file:/home/ana/rotulos/duplo.html":9.44-9.72: error: Duplicate ID “nome”.
"file:/home/ana/rotulos/duplo.html":8.40-8.68: info warning: The first occurrence of ID “nome” was here.

O validador diz: "id repetido: nome", e mostra onde ele apareceu primeiro.

O que o navegador faz: o for sempre acha o primeiro elemento com aquele id. Clique em "Nome do bolo:" no resultado: o cursor vai para o campo de cima. O segundo campo fica sem rótulo. Acontece muito quando se copia e cola um bloco do formulário.

Como consertar: cada campo com um id único (id="bolo") e o for do rótulo acompanhando.

Dois campos dentro do mesmo <label> 
<label>Nome e sobrenome:
<input name="nome">
<input name="sobrenome">
</label>

$ vnu dois.html
"file:/home/ana/rotulos/dois.html":10.1-10.24: error: The “label” element may contain at most one “button”, “input”, “meter”, “output”, “progress”, “select”, or “textarea” descendant.
"file:/home/ana/rotulos/dois.html":8.1-8.7: info warning: “label” element with multiple labelable descendants.

O validador diz: "O label pode conter no máximo um" desses campos. A linha 10 é o segundo <input>.

O que o navegador faz: liga o rótulo só ao primeiro campo. O do sobrenome fica sem nome para o leitor de tela.

Como consertar: um rótulo por campo: "Nome:" e "Sobrenome:".

O for aponta para um campo, e o <label> envolve outro 
$ sed -n 8,11p outro.html
<label for="nome">Nome:
<input id="apelido" name="apelido">
</label>
<input id="nome" name="nome">
$ vnu outro.html
"file:/home/ana/rotulos/outro.html":9.1-9.35: error: Any “input” descendant of a “label” element with a “for” attribute must have an ID value that matches that “for” attribute.

O validador diz: "Todo input dentro de um label com for tem de ter o id igual a esse for".

O que o navegador faz: o for vence. Clicar em "Nome:" leva o cursor para o campo de fora, e o campo de dentro (o apelido) fica sem rótulo.

Como consertar: escolha um jeito só, ou faça o for apontar para o campo de dentro.

Rótulo dentro de rótulo 
$ sed -n 8p dentro.html
<label>Nome: <label>Apelido</label> <input name="nome"></label>
$ vnu dentro.html
"file:/home/ana/rotulos/dentro.html":8.14-8.20: error: The element “label” must not appear as a descendant of the “label” element.

Como consertar: um <label> nunca vai dentro de outro. Separe-os.

Um rótulo vazio passa no validador 
$ sed -n 8,9p vazio.html
<label for="nome"></label>
<input id="nome" name="nome">
$ vnu vazio.html

O que acontece: nenhum erro, mas o campo continua sem nome: o rótulo não tem texto. Acontece quando o texto ficou fora do <label> por engano (<label for="nome"></label>Nome:). O validador confere a ligação, mas não o texto.

Como consertar: o texto vai entre <label> e </label>.

Resumo

  • O <label> liga um texto a um campo: clicar no texto foca o campo (ou marca a caixinha), e o leitor de tela lê o texto como o nome do campo. Um texto solto do lado não faz nada disso.
  • Dois jeitos: <label for="x"> + id="x" no campo (o for procura o id, não o name), ou o campo dentro do <label>.
  • Envolver é ótimo para caixinhas; for + id serve quando rótulo e campo estão longe. Os dois juntos são válidos se apontarem para o mesmo campo.
  • O placeholder não substitui o rótulo. Sem texto visível, use aria-label como exceção.
  • Erros que o validador pega: for que não acha o id, Duplicate ID (o rótulo vai para o primeiro), dois campos num rótulo, rótulo dentro de rótulo. Um rótulo vazio passa calado.
