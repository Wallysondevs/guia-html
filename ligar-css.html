HTML Ligar CSS: link e style

O HTML diz o que cada coisa é: isto é um título, isto é um parágrafo, isto é uma lista. Quem diz como cada coisa fica (a cor, a fonte, o tamanho, o espaçamento) é outra linguagem, o CSS (Cascading Style Sheets, "folhas de estilo em cascata"). Este é um guia de HTML, então você não vai aprender CSS aqui. Mas vai aprender a parte que é do HTML: como ligar o CSS à página, com o elemento <link> (um arquivo separado) e com o elemento <style> (o CSS dentro da página).

Você vai aprender
  • O mínimo de CSS para entender os exemplos: seletor, propriedade e valor.
  • Como ligar um arquivo .css com <link rel="stylesheet" href="…">.
  • Como um arquivo de estilo serve para todas as páginas do site.
  • Como escrever CSS dentro da página com <style>.
  • Qual dos dois vence quando eles mandam coisas diferentes, e qual usar.
  • Os erros reais: caminho errado, <style> dentro do .css, ponto e vírgula esquecido.

Os arquivos desta aula foram validados com o validador W3C (vnu, que também confere CSS) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/css. As cores que o navegador aplicou foram conferidas no Chrome.

Quando decide trocar o laranja por verde, ela muda uma linha do manual, e todo mundo segue.

1. O mínimo de CSS

Uma regra de CSS tem esta forma:

h1 {
  color: darkorange;
}
h1
O seletor: em quem a regra vale. Aqui, em todo <h1> da página.
{
Abre a lista de ajustes.
color
A propriedade: o que mudar. color = a cor do texto.
: darkorange
Os dois-pontos e o valor: darkorange ("laranja-escuro") é um dos nomes de cor que o CSS conhece.
;
O ponto e vírgula termina o ajuste. Esquecê-lo é um dos erros mais comuns (veja em Quando dá errado).
}
Fecha a regra.

Isso basta para esta aula. Seletores, cores, fontes e espaçamento são assunto do futuro Guia CSS.

2. Um arquivo separado: <link rel="stylesheet">

A forma mais usada: o CSS fica num arquivo próprio, com a extensão .css, e a página o liga com um <link> no head:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Receitas da Ana</title>
  <link rel="stylesheet" href="estilo.css">
</head>
<body>
  <h1>Receitas da Ana</h1>
  <p>Bolo de cenoura.</p>
</body>
</html>
<link
O elemento que liga a página a outro arquivo. É vazio: não existe </link>. Você já o viu no Ícone da Aba.
rel="stylesheet"
A relação: "este arquivo é a minha folha de estilo" (stylesheet = "folha de estilo").
href="estilo.css"
O endereço do arquivo. Aqui, um caminho relativo: o estilo.css está na mesma pasta do index.html (aula Caminhos).
>
Fim. O type="text/css" que aparece em sites antigos não é mais necessário: stylesheet já quer dizer CSS.
$ ls
estilo.css
index.html
$ vnu --verbose index.html
index.html
$ vnu --css --verbose estilo.css
estilo.css

O vnu confere também o arquivo de CSS, com a opção --css ("trate o arquivo como CSS"). Sem ela, ele acha que todo arquivo é HTML e reclama que falta o <!DOCTYPE html> no estilo.css.

No editor abaixo, cada arquivo é uma aba. O index.html liga o estilo.css exatamente como no seu computador:

}

Um estilo para o site inteiro

A grande vantagem do arquivo separado: várias páginas ligam o mesmo estilo.css. A Ana muda uma linha, e o site inteiro muda. E o navegador baixa o estilo.css uma vez só e o guarda (o cache): as outras páginas abrem mais rápido.

Missão: as duas páginas ligam o mesmo estilo.css (clique no link "Sobre a Ana" para trocar de página). Sem mexer nos arquivos .html, deixe os títulos das duas verdes (green) e acrescente uma regra que deixe os parágrafos cinza (p { color: gray; }).

<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Receitas da Ana</title>
  <link rel="stylesheet" href="estilo.css">
</head>
<body>
  <h1>Receitas da Ana</h1>
  <p>Bolo de cenoura, pão de queijo e brigadeiro.</p>
  <p><a href="sobre.html">Sobre a Ana</a></p>
</body>
</html>

3. CSS dentro da página: <style>

O CSS também pode ficar dentro do HTML, num elemento <style> no head. As regras são escritas exatamente como no arquivo .css:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Receitas da Ana</title>
  <style>
    h1 {
      color: chocolate;
    }
    p {
      color: gray;
    }
  </style>
</head>
<body>
  <h1>Receitas da Ana</h1>
  <p>Bolo de cenoura.</p>
</body>
</html>
<style>
Abre o bloco de CSS. Tudo até o </style> é lido como CSS, e não como HTML.
h1 { color: chocolate; }
Uma regra comum de CSS (chocolate também é um nome de cor).
</style>
Fecha o bloco. Diferente do link, o style tem tag de fechamento obrigatória.

Funciona sem nenhum arquivo extra, e o validador também confere o CSS de dentro do <style>. A desvantagem: o estilo vale só para esta página. Se o site tem dez páginas, são dez cópias para manter iguais.

4. Quando os dois mandam: quem vence?

Uma página pode ter link e style ao mesmo tempo (e vários de cada). Se duas regras mandam coisas diferentes para o mesmo elemento, vence a que o navegador lê por último. É a "cascata" do nome CSS: as regras vão caindo umas sobre as outras, e a de baixo fica por cima.

O rgb(…) é como o navegador informa uma cor: quanto de vermelho, verde e azul, de 0 a 255. Não é o arquivo que vence, é a posição. (A regra completa tem mais detalhes, como a "força" de cada seletor, e é assunto do futuro Guia CSS.)

<style>…</style>No head da páginaSó esta páginaUma página única (um teste, um exemplo) ou umas poucas regras que só esta página tem.

CSS só para a impressão: media

O link aceita o atributo media ("mídia"), que diz quando o estilo vale. Com media="print", o arquivo só vale quando a página é impressa (ou salva em PDF):

<link rel="stylesheet" href="estilo.css">
<link rel="stylesheet" href="impressao.css" media="print">

Na tela, o Chrome não aplicou o impressao.css (o título ficou com a cor padrão quando ele era o único estilo). É útil para esconder menus e botões no papel da receita impressa.

Quando dá errado

A página aparece sem estilo nenhum (texto preto, fonte padrão)

O que significa: o navegador não achou o arquivo de CSS. Aqui, a Ana escreveu href="css/estilo.css", mas o arquivo está na mesma pasta da página. O Console do F12 mostra, ao abrir o arquivo direto do computador:

Failed to load resource: net::ERR_FILE_NOT_FOUND

("Falha ao carregar o recurso: arquivo não encontrado.") Pelo servidor local, a mensagem é a do 404: Failed to load resource: the server responded with a status of 404 (File not found). O validador não acusa nada: ele não confere se o arquivo existe.

Como consertar: confira o caminho com ls, a partir da pasta do HTML (aula Caminhos). Cuidado com maiúsculas: Estilo.css e estilo.css são arquivos diferentes no servidor.

A primeira regra do .css não funciona, as outras sim

O que significa: a Ana copiou o CSS de dentro de um <style> para o arquivo .css, junto com as tags:

<style>
h1 {
  color: darkorange;
}
p {
  color: gray;
}
</style>

Num arquivo .css não existe HTML. O navegador leu <style> h1 como um seletor estranho, que não casa com nada, e jogou a regra do h1 fora: no Chrome, o título ficou preto (rgb(0, 0, 0)) e o parágrafo, cinza (rgb(128, 128, 128)). O validador, com --css:

$ vnu --css estilo-com-tag.css
"file:/home/ana/css/estilo-com-tag.css":1.1-1.7: error: CSS: Parse Error. Style sheets should not include HTML syntax.
"file:/home/ana/css/estilo-com-tag.css":10.1-10.8: error: Stray end tag “style”.

"Erro de leitura. Folhas de estilo não devem conter sintaxe de HTML."

Como consertar: apague o <style> e o </style> do arquivo .css. As tags só existem dentro do HTML.

Uma regra inteira some: o ponto e vírgula esquecido 
h1 {
  color: darkorange
  font-size: 3em;
}

O que significa: sem o ; depois de darkorange, o navegador leu color: darkorange font-size: 3em como um ajuste só, com um valor sem sentido, e jogou fora os dois: no Chrome, o título ficou preto e do tamanho normal. O validador diz exatamente o que falta:

$ vnu --css sem-pv.css
"file:/home/ana/css/sem-pv.css":3.3-3.11: error: CSS: “color”: Missing a semicolon before the property name “font-size”.

"Falta um ponto e vírgula antes da propriedade font-size." Num <style>, o erro aparece validando a própria página HTML; um color darkorange sem os dois-pontos, por exemplo, deu error: CSS: “color”: Parse Error.

Como consertar: termine cada ajuste com ;, inclusive o último (não é obrigatório nele, mas evita o erro quando você acrescentar outro embaixo).

error: Attribute “src” not allowed on element “link” at this point.

O que significa: <link rel="stylesheet" src="estilo.css">. O src é das imagens e dos scripts; o link usa href. O validador ainda mostra A “link” element must have an “href” or “imagesrcset” attribute, or both. E <style src="estilo.css"> também não existe: Attribute “src” not allowed on element “style” at this point. O style não carrega arquivos.

Como consertar: para um arquivo, <link rel="stylesheet" href="estilo.css">.

error: Element “link” is missing one or more of the following attributes: “itemprop”, “property”, “rel”.

O que significa: <link href="estilo.css"> sem rel. Sem a relação, o navegador não sabe que aquilo é CSS, e não aplica.

Como consertar: rel="stylesheet".

error: Style rule “h1” not allowed outside an “@scope” rule in a “style” element in “body”.

O que significa: o <style> está no body. O navegador até aplica o estilo, mas o validador reclama: "regra de estilo para h1 não permitida fora de uma regra @scope num style dentro do body". O @scope é um recurso recente do CSS para estilos que valem só num pedaço da página; para o uso comum, o lugar do style é o head. (Já um <link rel="stylesheet"> no body passou no validador sem erro, mas a página pode aparecer sem estilo por um instante enquanto o arquivo chega.)

Como consertar: mova o <style> (e os link) para o head.

info warning: The “type” attribute for the “style” element is not needed and should be omitted.

O que significa: <style type="text/css">, um costume antigo. "O atributo type não é necessário e deve ser omitido." É só um aviso leve. (No <link rel="stylesheet" type="text/css">, o validador não disse nada, mas o type também sobra.)

Como consertar: apague o type="text/css".

error: Stray end tag “link”.

O que significa: um </link>. O link é vazio, sem tag de fechamento.

Como consertar: apague o </link>.

Resumo

  • O HTML diz o que cada coisa é; o CSS diz como ela fica. Uma regra de CSS: seletor { propriedade: valor; }.
  • <link rel="stylesheet" href="estilo.css"> no head liga um arquivo de CSS. É a forma padrão: um arquivo serve para o site inteiro.
  • <style>…</style> no head põe o CSS dentro da página: vale só para ela.
  • Quando duas regras brigam, vence a que vem por último.
  • Caminho errado: página sem estilo e ERR_FILE_NOT_FOUND ou 404 no Console (o validador não vê). Tags HTML dentro do .css e ponto e vírgula esquecido derrubam regras inteiras: valide o CSS com vnu --css.
