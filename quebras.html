HTML Quebras

Na aula de Parágrafos você viu que o navegador ignora as quebras de linha do código. Mas às vezes a linha nova faz parte do texto: num poema, cada verso tem a sua linha; num endereço, a rua vem numa linha e a cidade em outra. Para isso existe o <br>. E quando a página muda de assunto, como no fim de uma receita e no começo de outra, existe o <hr>, que desenha uma linha horizontal. Os dois são elementos vazios: não têm conteúdo nem tag de fechamento.

Você vai aprender
  • O <br>: pular uma linha dentro do mesmo texto, e quando usá-lo (poemas, endereços) ou não (espaçamento, listas).
  • O <hr>: marcar uma mudança de assunto, e não só desenhar uma linha.
  • O que é um elemento vazio, e por que </br> e <hr></hr> estão errados.
  • A barra de <br/> e <br />: de onde ela vem e o que o validador diz dela.
  • O <wbr>, um "pode quebrar aqui" para palavras compridas.
  • O que o navegador faz com um <hr> dentro de um parágrafo, e os atributos antigos do hr.

Os exemplos são desenhados pelo seu navegador, no quadro "Resultado". As mensagens do validador saíram do vnu (o validador do W3C) na máquina fictícia da Ana, na pasta ~/site.

A ideia: o "Enter" e a linha pontilhada

Pense num caderno. Quando você copia um poema, aperta o "Enter" no fim de cada verso: o poema continua sendo um texto só, mas cada verso começa numa linha nova. Esse "Enter" é o <br> (de break, "quebra"; em inglês, line break é "quebra de linha").

Quando você termina um assunto e começa outro no mesmo caderno, talvez faça um traço de um lado a outro da página, para mostrar que dali em diante é outra coisa. Esse traço é o <hr> (de horizontal rule, "linha horizontal"; o HTML de hoje o chama de thematic break, "quebra de assunto").

ElementoNo cadernoQuer dizer
<br>O "Enter" no fim de um verso"Continue na linha de baixo, no mesmo texto"
<hr>O traço entre dois assuntos"Aqui termina um assunto e começa outro"

1. O <br>: pular uma linha

Esta quadrinha popular foi digitada com um verso por linha. Sem <br>, o navegador junta tudo, como você viu em Parágrafos:

<p>Batatinha quando nasce
espalha a rama pelo chão.
Menininha quando dorme
põe a mão no coração.</p>

Agora com um <br> no fim de cada verso (menos no último):

<p>Batatinha quando nasce<br>
espalha a rama pelo chão.<br>
Menininha quando dorme<br>
põe a mão no coração.</p>
<br>
"Quebre a linha aqui." O texto que vem depois começa na linha de baixo, sem o espaço maior que fica entre dois parágrafos.
(sem </br>)
O <br> não tem tag de fechamento, porque não tem nada dentro: ele é a quebra. Elementos assim se chamam elementos vazios (void elements).
a quebra de linha do código
Continua sendo ignorada. Ela está ali só para o código ficar fácil de ler; quem quebra a linha na tela é o <br>. Você poderia escrever os quatro versos numa linha só do código, com os <br> no meio, e o resultado seria o mesmo.
<p>…</p>
O poema inteiro continua sendo um parágrafo. O <br> fica dentro do <p>, no meio do texto.

Experimente: o poema abaixo saiu numa linha só. Coloque um <br> no fim de cada verso, menos no último, para cada verso ficar na sua linha. Tudo dentro do mesmo parágrafo.

<p>Fui ao mercado comprar café,
a formiguinha subiu no meu pé.
Eu sacudi, sacudi, sacudi,
mas a formiguinha não parava de subir.</p>

<p>Fui ao mercado comprar café,<br>
a formiguinha subiu no meu pé.<br>
Eu sacudi, sacudi, sacudi,<br>
mas a formiguinha não parava de subir.</p>

Quando usar o <br>

Use o <br> quando a quebra de linha faz parte do texto, ou seja, quando o texto ficaria errado sem ela:

  • versos de poemas e letras de música;
  • as linhas de um endereço (o endereço de contato tem elemento próprio, o <address>, na aula Endereço, e lá dentro o <br> também é usado);
  • a assinatura no fim de uma mensagem ("Um abraço,<br>Ana").
<p>Lojinha da Ana<br>
Rua das Flores, 123<br>
Centro – São Paulo</p>

Quando não usar

O <br> não é ferramenta de espaçamento nem de organização. Os usos errados mais comuns:

O erroPor que é ruimO certo
<br><br> para separar dois parágrafosVira um parágrafo só, com um buraco no meio. Quem usa leitor de tela não fica sabendo que ali começa outro assunto.Dois <p>
Vários <br> seguidos para "dar espaço"O tamanho do espaço muda com a letra, e o código fica cheio de tags sem significado.Margem com CSS (quer aprender mais? futuro Guia CSS)
Uma "lista" de itens separados por <br>Para o navegador e para o leitor de tela, é um texto corrido, sem itens.Uma lista de verdade (aula Listas com Marcadores)

O validador não reclama desses usos: três <br> seguidos entre dois parágrafos passam sem nenhuma mensagem. É uma questão de bom senso, que o validador não consegue julgar. Veja como a "lista" feita com <br> parece certa na tela, mas para o navegador é só um parágrafo:

<p>Ingredientes:<br>
3 cenouras<br>
3 ovos<br>
1 xícara de óleo</p>

2. O <hr>: mudança de assunto

A página de sobremesas da Ana tem duas receitas. Entre uma e outra, um <hr>:

<h1>Sobremesas</h1>
<h2>Pudim de leite</h2>
<p>Leite condensado, leite, ovos e calda de açúcar.</p>
<hr>
<h2>Mousse de maracujá</h2>
<p>Suco de maracujá, leite condensado e creme de leite.</p>
<hr>
Uma quebra de assunto. O navegador a desenha como uma linha horizontal, de um lado a outro, com um espaço em cima e embaixo.
(sem </hr>)
Também é um elemento vazio: nada de fechamento.
fora do <p>
O <hr> é um bloco e fica entre os parágrafos, nunca dentro de um (veja em Quando dá errado).

O nome antigo era "linha horizontal", e muita gente ainda o usa só para enfeitar. Mas, no HTML de hoje, o <hr> tem um significado: "aqui muda o assunto". Os leitores de tela costumam anunciá-lo como um separador. Use-o:

  • entre duas receitas, duas notícias curtas ou duas partes independentes da mesma página;
  • numa história, para marcar uma mudança de cena ("Três anos depois…");
  • antes do rodapé de uma mensagem, separando o texto principal das observações.
Título já separa

Se o novo assunto começa com um título (<h2>), o título já mostra a mudança, e o <hr> é opcional. Ele brilha onde não há título: entre cenas de um conto, entre dois avisos curtos. Uma linha só de enfeite (uma borda colorida embaixo do cabeçalho, por exemplo) é trabalho do CSS.

Este guia usa <hr> entre as partes de cada aula: repare nas linhas desta página.

3. Elementos vazios e a barra de <br/>

O <br> e o <hr> fazem parte de um grupo pequeno de elementos que nunca têm conteúdo. Você já conhece ou vai conhecer outros: <img> (imagem), <meta>, <link>, <input> (campo de formulário) e o <wbr> da seção 4. Para todos eles, a regra é a mesma: só a tag de abertura.

Em muitos sites e tutoriais você vai ver <br/> ou <br />, com uma barra no fim. Essa barra vem do XHTML, uma versão antiga e mais rígida do HTML (aula Versões do HTML), que exigia "fechar" todo elemento vazio. No HTML de hoje, a barra é permitida, mas não faz nada:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<p>Rua das Flores, 123<br/>
Centro</p>
</body>
</html>

$ vnu barra.html
"file:/home/ana/site/barra.html":8.23-8.27: info: Trailing slash on void elements has no effect and interacts badly with unquoted attribute values.
$ echo $?
0                        « não é erro
info:
Uma informação, o nível mais leve de mensagem. O código de saída continua 0: o HTML é válido.
Trailing slash on void elements has no effect
"A barra no fim de elementos vazios não tem efeito." O navegador monta exatamente o mesmo <br>, com ou sem barra.
and interacts badly with unquoted attribute values
"e se dá mal com valores de atributo sem aspas." Um exemplo: em <img src=foto.jpg/>, sem aspas, a barra vira parte do endereço (foto.jpg/), e a imagem não aparece. Com aspas (src="foto.jpg"), como o guia sempre escreve, o problema não existe.

Este guia escreve <br> e <hr>, sem barra. Se você trabalhar num projeto que usa a barra, tudo bem: mantenha o estilo do projeto.

4. <wbr>: "pode quebrar aqui"

O navegador quebra as linhas nos espaços entre as palavras. Uma palavra enorme, sem espaço nenhum, não tem onde quebrar e pode vazar para fora da caixa onde está, principalmente na tela estreita de um celular. O <wbr> (de word break opportunity, "oportunidade de quebra de palavra") marca os pontos onde a palavra pode ser quebrada, se faltar espaço. Se couber, nada muda.

No exemplo, o atributo style só serve para desenhar uma caixa estreita, de borda cinza, onde a palavra não cabe (CSS tem aula própria: O Atributo style). A primeira palavra vaza da caixa; a segunda, com <wbr>, quebra nos pontos marcados:

<p style="width: 10em; border: 1px solid gray;">pneumoultramicroscopicossilicovulcanoconiótico</p>
<p style="width: 10em; border: 1px solid gray;">pneumo<wbr>ultra<wbr>microscopico<wbr>ssilico<wbr>vulcano<wbr>coniótico</p>

A diferença para o <br>: o <br> sempre quebra a linha; o <wbr> só quebra se precisar, e sem colocar hífen. É raro precisar dele; serve para palavras muito compridas e endereços de sites longos escritos no meio do texto.

Quando dá errado

O navegador conserta tudo sem mostrar erro. Em cada caso, veja o que ele fez de verdade e o que o validador diz.

</br>: fechar o que não fecha 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<p>Rua das Flores, 123</br>
Centro</p>
</body>
</html>

O que o navegador faz: uma curiosidade do HTML. Um </br> solto é tratado como se fosse um <br>: a linha quebra do mesmo jeito. Por isso esse erro passa despercebido.

$ vnu fechabr.html
"file:/home/ana/site/fechabr.html":8.23-8.27: error: End tag “br”.

"Tag de fechamento br." Curta e direta: br não tem fechamento. As colunas 23 a 27 da linha 8 são o </br>.

E o par <br></br>, de quem acha que todo elemento precisa fechar? Como o </br> vira um <br>, o navegador monta duas quebras de linha, e uma linha em branco aparece no texto. O validador dá o mesmo error: End tag “br”.

Como consertar: escreva só <br>.

<hr></hr> 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<p>Fim da receita do bolo.</p>
<hr></hr>
<p>Agora, a torta.</p>
</body>
</html>

O que o navegador faz: ignora o </hr>. Na tela, uma linha só, como se ele não existisse.

$ vnu hrfecha.html
"file:/home/ana/site/hrfecha.html":9.5-9.9: error: Stray end tag “hr”.

"Tag de fechamento hr perdida." Stray quer dizer "perdida", "sem dono": é uma tag de fechamento que não fecha nada.

Como consertar: só <hr>.

<hr> dentro de um parágrafo 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<p>Fim da receita do bolo.
<hr>
Agora, a torta.</p>
</body>
</html>

O que o navegador faz: o <hr> é um bloco e não cabe dentro de um parágrafo. Então o navegador fecha o parágrafo antes da linha. O texto "Agora, a torta." fica solto, fora de qualquer parágrafo, e o </p> do fim vira um parágrafo vazio. A página que o navegador montou ficou assim:

<p>Fim da receita do bolo.
</p><hr>
Agora, a torta.<p></p>

$ vnu hrp.html
"file:/home/ana/site/hrp.html":10.16-10.19: error: No “p” element in scope but a “p” end tag seen.

"Nenhum elemento p aberto, mas foi vista uma tag de fechamento p" (a mesma mensagem da aula Parágrafos). O validador aponta o </p> da linha 10, que sobrou; a causa é o <hr> da linha 9.

Como consertar: o <hr> fica entre dois parágrafos: <p>Fim da receita do bolo.</p>, <hr>, <p>Agora, a torta.</p>.

Missão: o <hr> está dentro do parágrafo, e o navegador deixou "Agora, a torta." solto e criou um parágrafo vazio. Conserte para ficarem dois parágrafos com o <hr> entre eles.

<p>Fim da receita do bolo.
<hr>
Agora, a torta.</p>

<p>Fim da receita do bolo.</p>
<hr>
<p>Agora, a torta.</p>
Os atributos antigos do <hr>

Páginas antigas controlavam a linha com atributos: espessura, largura, cor, alinhamento.

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<hr size="3" width="50%" noshade color="red" align="center">
</body>
</html>

O que o navegador faz: ainda obedece (por isso a linha sai vermelha e pela metade), para não quebrar sites antigos.

$ vnu hrattr.html
"file:/home/ana/site/hrattr.html":8.1-8.60: info warning: The “size” attribute on the “hr” element is obsolete. Use CSS instead.
"file:/home/ana/site/hrattr.html":8.1-8.60: info warning: The “width” attribute on the “hr” element is obsolete. Use CSS instead.
"file:/home/ana/site/hrattr.html":8.1-8.60: info warning: The “noshade” attribute on the “hr” element is obsolete. Use CSS instead.
"file:/home/ana/site/hrattr.html":8.1-8.60: info warning: The “color” attribute on the “hr” element is obsolete. Use CSS instead.
"file:/home/ana/site/hrattr.html":8.1-8.60: info warning: The “align” attribute on the “hr” element is obsolete. Use CSS instead.

Uma mensagem por atributo: "o atributo … no elemento hr é obsoleto. Use CSS no lugar." São avisos informativos (código de saída 0), mas o conselho vale: a aparência fica no CSS. O mesmo vale para o antigo <br clear="all">, que dá info warning: The “clear” attribute on the “br” element is obsolete. Use CSS instead.

Como consertar: escreva só <hr> e mude a aparência com CSS (quer aprender mais? futuro Guia CSS).

Missão: monte o cartão de visita da lojinha. No primeiro parágrafo, o endereço tem três linhas: coloque um <br> no fim de cada uma, menos na última. Depois, coloque um <hr> entre o endereço e o horário, que é outro assunto. No fim, devem ser dois parágrafos com o <hr> entre eles.

Resumo

  • <br> quebra a linha dentro do mesmo texto: versos, linhas de endereço, assinatura. Não use para separar parágrafos, dar espaço ou fazer listas.
  • <hr> marca uma mudança de assunto e aparece como uma linha horizontal. É um bloco: fica entre parágrafos, nunca dentro de um.
  • Os dois são elementos vazios: sem conteúdo e sem fechamento. </br> dá End tag “br”. (e o navegador o transforma num <br>); </hr> dá Stray end tag “hr”.
  • A barra de <br/> vem do XHTML, não faz nada e só gera um info do validador. O guia escreve <br>.
  • <wbr> marca onde uma palavra comprida pode quebrar, se faltar espaço.
  • Espessura, cor e largura do <hr> e espaços entre blocos são aparência: CSS.
