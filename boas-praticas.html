HTML Boas Práticas

Duas páginas podem aparecer iguaizinhas na tela e ser muito diferentes por dentro. Uma funciona com teclado, é lida direito por um leitor de tela, aparece bem no buscador e é fácil de mudar daqui a um ano. A outra só funciona no mouse da pessoa que a fez. Esta aula junta as boas práticas que apareceram ao longo do guia numa lista de conferência, com o porquê de cada item, e separa o que o validador pega do que só você pode conferir.

Você vai aprender
  • O esqueleto que toda página deve ter, e o que o validador diz quando falta uma parte.
  • Por que usar o elemento certo (semântica) e manter os títulos em ordem.
  • Os cuidados de acessibilidade que mais fazem diferença: alt, label e <button>.
  • Como deixar o código legível e separar o conteúdo (HTML) da aparência (CSS) e do comportamento (JS).
  • O que o validador não pega, e como conferir o resto.

Os arquivos desta aula foram conferidos no validador W3C (vnu 26.10.12, o mesmo do validator.w3.org) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/boas, e o comportamento no Chromium 155. Os quadros "Resultado" são desenhados pelo seu navegador.

A ideia: a receita bem escrita

Duas pessoas escrevem a mesma receita de bolo. A primeira anota tudo num guardanapo, sem ordem, com "aquela farinha" e "o tempo de sempre". A segunda escreve o título, a lista de ingredientes com as quantidades e o modo de preparo em passos numerados. As duas sabem fazer o bolo. Mas só a segunda receita serve para outra pessoa: a vizinha, a filha, a própria autora daqui a cinco anos.

Boas práticas de HTML são isso: escrever para quem vem depois. E quem vem depois são muitos: o navegador, o leitor de tela, o buscador, o celular, o validador, e você mesmo, quando for mudar o site.

3. O elemento certo para cada coisa

Use o elemento que diz o que o conteúdo é, e não o que deixa a tela do jeito que você quer (aula HTML Semântico). A aparência é trabalho do CSS.

Títulos em ordem

Os títulos (<h1> a <h6>) formam o sumário da página: quem usa leitor de tela navega pulando de título em título. Por isso: um <h1> com o assunto da página, e depois <h2>, <h3>… sem pular degraus (aula Títulos). Escolha o nível pelo lugar no sumário, nunca pelo tamanho da letra. O validador 26.10.12 já confere isso:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Pulo</title>
</head>
<body>
<h1>Receitas</h1>
<h3>Ingredientes</h3>
<section><p>sem título</p></section>
<img src="bolo.jpg" alt="">
<img src="bolo.jpg" alt="bolo.jpg">
<img src="bolo.jpg" alt="Bolo de cenoura com cobertura de chocolate" width="800" height="600">
</body>
</html>

4. Acessibilidade: o que o validador não vê

Na tela, as versões abaixo parecem quase iguais. Por dentro, não:

<div onclick="location.href='#bolo'">Bolo de cenoura (div)</div>
<p><a href="#bolo">Bolo de cenoura (link)</a></p>

<p>Nome: <input type="text" name="nome"></p>
<p><label>Nome: <input type="text" name="nome2"></label></p>

Faça o teste no Resultado: aperte Tab algumas vezes. O foco pula a <div> e para no link. Clique na palavra "Nome:" das duas linhas: só a segunda leva o cursor para o campo. No Chromium 155, a <div onclick> não aceitou o foco (tabIndex = -1), o link e um <button> aceitaram, o primeiro campo ficou sem nenhum rótulo (labels.length = 0) e o clique no <label> levou o foco ao segundo.

5. Código que outra pessoa consegue ler

O navegador não se importa com espaços, maiúsculas e aspas; as pessoas sim. Estes dois trechos dão o mesmo resultado:

<UL><LI><A HREF=bolo.html>Bolo</A><LI><A href='pudim.html'>Pudim</a></UL>
<ul>
  <li><a href="bolo.html">Bolo</a></li>
  <li><a href="pudim.html">Pudim</a></li>
</ul>

Mas só o segundo é fácil de ler, de achar um erro e de mudar. As regras de costume:

  • Tudo em minúsculas: tags e atributos (<ul>, href).
  • Atributos sempre entre aspas duplas: href="bolo.html". Sem aspas funciona até o dia em que o valor tiver um espaço (aula Atributos).
  • Feche o que você abre, mesmo quando o HTML deixaria omitir (</li>, </p>): fica claro onde cada coisa termina.
  • Indente (recue com espaços) o que está dentro de outro elemento, sempre com a mesma quantidade (2 espaços é o mais comum). Os editores fazem isso sozinhos (aula Editores).
  • Comente o que não é óbvio, e só isso (aula Comentários). E lembre: comentários são públicos (aula Segurança).
  • Nomes de arquivos, class e id que descrevem o conteúdo: class="ingredientes", e não class="caixa2" nem class="vermelho" (aula class e id).

6. Cada um no seu arquivo: HTML, CSS e JS

O HTML diz o que é o conteúdo; o CSS, como ele aparece; o JavaScript, o que ele faz. Misturar os três no mesmo lugar funciona, mas cobra caro depois:

MisturadoSeparadoGanho
<p style="color: red">Promoção!</p><p class="promocao"> + .promocao { color: red; } no css/estilo.cssMudar a cor de todas as promoções do site num lugar só (aula O Atributo style)
<button onclick="comprar()"><button id="comprar"> + addEventListener no js/script.jsFunciona com uma CSP que bloqueia script dentro da página (aula Segurança)
<style> copiado em cada páginaum <link rel="stylesheet"> para o mesmo arquivoO navegador baixa o CSS uma vez e reaproveita nas outras páginas (aula Ligar CSS)
<script> no começo do <head>, sem nada<script src="js/script.js" defer> no <head>, ou o <script> no fim do <body>A página aparece antes de o script terminar de baixar (aula Desempenho)

7. Imagens que não atrapalham

  • width e height em toda <img>: o navegador reserva o espaço antes de a imagem chegar, e o texto não "pula" quando ela carrega (aula Largura e Altura).
  • O tamanho certo: não mande uma foto de 4000 pixels para mostrar em 400. Para telas diferentes, srcset (aula Imagens Responsivas).
  • O formato certo: foto em JPG, WebP ou AVIF; logotipo e ícone em SVG (aula Formatos).
  • loading="lazy" nas imagens que ficam lá embaixo da página (aula Carregamento Preguiçoso).

8. O que conferir antes de dar a página por pronta

O validador é o primeiro passo, não o último. A lista completa:

  1. Validador sem erros: vnu no laboratório ou validator.w3.org/nu (aula Validar o HTML). Leia também os warning e os info.
  2. Só o teclado: largue o mouse e use Tab, Shift+Tab e Enter. Dá para chegar em todo link, botão e campo? Dá para ver onde está o foco? (aula Teclado e Foco)
  3. Sem imagens: os alt fazem sentido lidos em voz alta?
  4. O sumário: lendo só os títulos, dá para entender a página?
  5. No celular: o F12 tem um modo que simula telas pequenas (aula Ferramentas do Desenvolvedor); melhor ainda, abra no seu celular.
  6. Num servidor local, sem nenhum 404 no registro (aula Servidor Local).
  7. Em mais de um navegador: pelo menos dois diferentes, como Chrome e Firefox, ou Safari no iPhone.
  8. Os links: clique em todos. Nenhum leva a um 404?

Quando dá errado

"O validador não deu nenhum erro, então está tudo certo"

O que significa: está tudo certo com a escrita do HTML. O validador não sabe se o alt descreve a imagem, se o link diz aonde vai, se a <div onclick> funciona com o teclado ou se a página cabe no celular. Na página antiga da Ana, quatro dos problemas passaram sem uma palavra.

Como consertar: depois do validador, passe pela lista da seção 8.

The heading “h3” (with computed level 3) follows the heading “h1” (with computed level 1), skipping 1 heading level.

O que significa: "o título h3 vem logo depois de um h1, pulando um nível". Quase sempre, o h3 foi escolhido pelo tamanho da letra.

Como consertar: escolha o nível pelo lugar no sumário (h2) e ajuste o tamanho com CSS.

The “center” element is obsolete. Use CSS instead.

O que significa: "o elemento center é obsoleto; use CSS". O mesmo para <font>, <marquee>, <big> e outros do HTML antigo. Os navegadores ainda mostram, mas eles não fazem mais parte do HTML.

Como consertar: o elemento que diz o que o conteúdo é (<h1>, <p>) e o CSS para a aparência.

info warning: This document has heading elements but none of them has a computed heading level of 1.

O que significa: "o documento tem títulos, mas nenhum de nível 1". A página não tem um <h1> dizendo qual é o assunto dela.

Como consertar: um <h1> por página, com o assunto principal, antes dos <h2>.

Resumo

  • Toda página: <!DOCTYPE html>, lang="pt-BR", charset, viewport, <title> e description. O validador cobra só parte disso.
  • O elemento certo para cada coisa: títulos em ordem (um <h1>, sem pular nível), regiões com <header>, <nav>, <main>, <footer>, nada de elementos obsoletos.
  • Acessibilidade: alt que descreve, <label> em todo campo, <a> para ir e <button> para agir, links com texto que diz aonde vão. O validador não pega quase nada disso: teste com o teclado.
  • Código legível: minúsculas, aspas duplas, tags fechadas, indentação, nomes que descrevem.
  • HTML para o conteúdo, CSS em .css, JS em .js. Imagens com width, height e o tamanho certo.
  • Antes de publicar: validador, teclado, celular, servidor local e dois navegadores.
