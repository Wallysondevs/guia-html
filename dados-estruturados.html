HTML Dados Estruturados (JSON-LD)

Uma pessoa que lê a página da Ana entende na hora: é uma receita de bolo, leva 1 hora, rende 12 fatias, precisa de 3 cenouras. Um programa não entende tão fácil: para ele, é tudo texto. Os dados estruturados são uma ficha escondida na página que diz isso de um jeito que o programa entende. Com ela, um buscador pode mostrar a receita da Ana com foto, tempo de preparo e rendimento direto na lista de resultados. Nesta aula você vai escrever a ficha de uma receita em JSON-LD, conferir no terminal e nos validadores.

Você vai aprender
  • O que são dados estruturados e o vocabulário schema.org.
  • O bloco <script type="application/ld+json">, que o navegador guarda sem mostrar nem rodar.
  • As regras do JSON: chaves, aspas duplas, vírgulas, listas.
  • A ficha completa de uma receita (Recipe), com ingredientes, modo de preparo e tempos como PT40M.
  • Como conferir o JSON com python3 -m json.tool no terminal.
  • O validador do schema.org e o teste de resultados do Google.
  • Por que o validador W3C não pega erro nenhum dentro do JSON.

Os arquivos desta aula foram conferidos na máquina fictícia da Ana, na pasta ~/site, com o validador W3C (vnu, versão 26.10.12) e o Python 3.14. O endereço https://ana.exemplo.com/ é fictício.

A ideia: a ficha da biblioteca

Na aula HTML e SEO, o buscador era um bibliotecário que lê cada livro e escreve uma ficha. Ler e adivinhar dá trabalho, e ele pode errar: "50 minutos" é o tempo de preparo ou de forno? "12" são fatias ou ovos?

Os dados estruturados são a ficha já preenchida pelo autor, com campos de nome fixo: "tipo: receita", "rendimento: 12 fatias", "tempo de forno: 40 minutos". Os nomes dos campos vêm de um dicionário comum, o schema.org, criado em 2011 pelo Google, pela Microsoft, pelo Yahoo e pelo Yandex e usado por todos os buscadores grandes. Ele tem tipos para quase tudo: Recipe (receita), Product (produto), Event (evento), Person (pessoa), Organization, Article…

Existem três formas de escrever essa ficha no HTML. A mais usada, e a recomendada pelo Google, é o JSON-LD (JavaScript Object Notation for Linked Data, "notação de objetos do JavaScript para dados ligados"): a ficha inteira num bloco só, separado do texto da página.

1. O bloco <script type="application/ld+json">

A ficha vai dentro de um <script>, com um type especial. Esta é a menor ficha que faz sentido:

<h1>Bolo de cenoura</h1>
<p>O bolo que a minha avó fazia todo domingo.</p>
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Recipe",
  "name": "Bolo de cenoura"
}
</script>

No Resultado, só o título e o parágrafo. O bloco não aparece, e o navegador também não o roda: com um type que não é de JavaScript, o <script> vira um bloco de dados, guardado na página para quem quiser ler. Quem lê são os robôs dos buscadores.

type="application/ld+json"
"Isto é JSON-LD." Escreva exatamente assim. Pode ficar no <head> ou no <body>.
{ … }
As chaves abrem e fecham um objeto: uma ficha com campos.
"@context": "https://schema.org"
"Os nomes desta ficha vêm do dicionário schema.org." O @ marca as palavras do próprio JSON-LD.
"@type": "Recipe"
O tipo da ficha: uma receita. O nome do tipo começa com maiúscula, como no schema.org.
"name": "Bolo de cenoura"
Um campo: o nome da receita. Os nomes dos campos são em inglês e começam com minúscula.

2. As regras do JSON

O JSON é exigente: um erro de uma vírgula estraga a ficha inteira, e o robô a joga fora. As regras são poucas:

RegraCertoErrado
Nomes e textos entre aspas duplas"name": "Bolo"'name': 'Bolo', name: "Bolo"
Dois-pontos entre o nome e o valor"name": "Bolo""name" = "Bolo"
Vírgula entre os campos"a": 1, "b": 2"a": 1 "b": 2
Nada de vírgula depois do último{"a": 1, "b": 2}{"a": 1, "b": 2,}
Números sem aspas"porcoes": 12(com aspas vira texto)
Listas entre colchetes["3 ovos", "3 cenouras"]("3 ovos", "3 cenouras")
Sem comentários—// tempo do forno

Um valor pode ser outro objeto: o autor da receita é uma pessoa, com @type e name próprios: "author": {"@type": "Person", "name": "Ana"}. E uma lista pode ter objetos dentro, como os passos do modo de preparo (seção 3).

Neste editor, o script.js lê o bloco de dados com o JavaScript (JSON.parse, "analisar o JSON") e diz no console se o JSON está certo. A mensagem de erro é do seu navegador e muda de um navegador para outro.

Missão: o console mostra um erro. Esta ficha tem dois problemas: um nome com aspas simples e uma vírgula sobrando. Conserte os dois até o console dizer JSON válido.

3. A ficha completa de uma receita

Esta é a página do bolo da Ana com a ficha completa. Repare que tudo o que está na ficha também está no texto da página: a ficha descreve a página, não acrescenta nada escondido.

<!DOCTYPE html>
<html lang="pt-BR">

<script type="application/ld+json">
{

  "prepTime": "PT20M",
  "cookTime": "PT40M",
  "totalTime": "PT1H",

  "recipeIngredient": [
    "3 cenouras médias",
    "3 ovos",

    },

Os tempos: PT40M

Os tempos usam o formato de duração da norma ISO 8601, o mesmo do atributo datetime do <time>. Parece código secreto, mas é só uma regra:

P
De period, "período". Toda duração começa com P.
T
De time, "tempo": daqui em diante vêm horas, minutos e segundos.
1H, 40M, 30S
O número seguido da unidade: H horas, M minutos, S segundos.

Então PT40M = 40 minutos, PT1H = 1 hora, PT1H30M = 1 hora e meia. Um erro comum é esquecer o T: P40M quer dizer 40 meses.

4. Conferir o JSON no terminal: python3 -m json.tool

O Python, que já vem no Ubuntu, tem uma ferramenta que lê um arquivo JSON e o mostra arrumado, ou diz onde está o erro: python3 -m json.tool (o -m roda um módulo do Python como programa). Ela lê JSON puro, então primeiro a Ana copia a ficha para um arquivo à parte. Com o sed, dá para tirar a ficha de dentro do HTML sem copiar à mão:

$ sed -n '/ld+json/,/<\/script>/p' bolo.html | sed '1d;$d' > receita.json
$ head -4 receita.json
{
  "@context": "https://schema.org",
  "@type": "Recipe",
  "name": "Bolo de cenoura fofinho",
sed -n '/ld+json/,/<\/script>/p' bolo.html
Mostra as linhas da que tem ld+json até a que tem </script> (aula de sed no Guia Bash).
sed '1d;$d'
Apaga a primeira e a última dessas linhas: as tags <script> e </script>. Sobra o JSON puro.
> receita.json
Grava o resultado no arquivo receita.json.

Agora a conferência:

$ python3 -m json.tool receita.json | head -9
{
    "@context": "https://schema.org",
    "@type": "Recipe",
    "name": "Bolo de cenoura fofinho",
    "image": "https://ana.exemplo.com/fotos/bolo-de-cenoura.jpg",
    "author": {
        "@type": "Person",
        "name": "Ana"
    },
$ python3 -m json.tool receita.json > /dev/null     « só o código de saída
$ echo $?
0

Quando o JSON está certo, a ferramenta o mostra de volta, arrumado, e termina com código de saída 0. Repare num detalhe: por padrão ela troca as letras acentuadas por códigos como \u00ed (o í). Isso também é JSON válido, mas é difícil de ler. A opção --no-ensure-ascii ("não force o ASCII") mantém os acentos:

$ python3 -m json.tool receita.json | grep farinha
        "2 x\u00edcaras de farinha de trigo",
            "text": "Misture o a\u00e7\u00facar, a farinha e o fermento."
$ python3 -m json.tool --no-ensure-ascii receita.json | grep farinha
        "2 xícaras de farinha de trigo",
            "text": "Misture o açúcar, a farinha e o fermento."

5. Os validadores de dados estruturados

O json.tool confere se o JSON está bem escrito, mas não sabe nada de receitas. Um "recipeIngrediente" (com um "e" a mais) passa nele sem problema. Para conferir os nomes e os tipos, existem dois validadores gratuitos na internet:

ValidadorEndereçoO que confere
Schema Markup Validator (do próprio schema.org)validator.schema.orgSe os tipos e os campos existem no schema.org e se o JSON-LD está bem formado. Mostra a ficha como uma árvore, com cada campo e valor.
Teste de pesquisa aprimorada do Google (Rich Results Test)search.google.com/test/rich-resultsSe a página pode ganhar um resultado aprimorado no Google, e quais campos obrigatórios ou recomendados faltam.

Os dois aceitam o endereço de uma página publicada ou o código colado direto. Cole o HTML inteiro do bolo.html: o validador do schema.org encontra uma ficha do tipo Recipe e lista os campos; o do Google diz se a receita pode aparecer com o visual especial e avisa o que está faltando ou o que é só recomendado. Os textos exatos dos avisos mudam com o tempo; leia com calma e conserte um por vez.

Nada garantido, e nada de inventar
  • Os dados estruturados permitem um resultado aprimorado, mas o buscador decide se mostra.
  • A ficha tem de descrever o que está na página. Avaliações (aggregateRating, as estrelinhas) só podem ser marcadas se a página tiver avaliações de verdade, de visitantes de verdade. Inventar estrelas vai contra as regras dos buscadores, e o Google pode punir o site.

Outras formas: microdados

O JSON-LD não é o único jeito. Os microdados (microdata) são atributos do próprio HTML, colados no texto que aparece:

<div itemscope itemtype="https://schema.org/Recipe">
  <h1 itemprop="name">Bolo de cenoura</h1>
  <p>Rende <span itemprop="recipeYield">12 fatias</span>.</p>
  <ul>
    <li itemprop="recipeIngredient">3 cenouras</li>
    <li itemprop="recipeIngredient">3 ovos</li>
  </ul>
</div>
itemscope
"Aqui começa uma ficha." Tudo o que está dentro pertence a ela.
itemtype="https://schema.org/Recipe"
O tipo da ficha, com o endereço completo do schema.org.
itemprop="name"
"O texto deste elemento é o campo name."
JSON-LDMicrodados
Onde ficaUm bloco separadoAtributos espalhados no texto
Mexer no visual mexe na ficha?NãoSim: é fácil quebrar a ficha mudando o HTML
Repete o texto da página?Sim (fica duas vezes no arquivo)Não
Recomendado pelo GoogleSimAceito

Qual usar: o JSON-LD. É mais fácil de escrever, de conferir com o json.tool e de manter. Existe ainda uma terceira forma, o RDFa (atributos vocab, typeof, property), parente do Open Graph da aula Open Graph; ela é pouco usada para receitas.

Quando dá errado

O validador W3C não lê o JSON

Esta página tem uma vírgula sobrando dentro da ficha. O navegador mostra a página normalmente, o robô do buscador joga a ficha fora, e o validador W3C…

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Bolo de cenoura | Receitas da Ana</title>
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Recipe",
  "name": "Bolo de cenoura",
}
</script>
</head>
<body>
<h1>Bolo de cenoura</h1>
</body>
</html>

$ vnu --verbose virgula.html
virgula.html             « nenhuma mensagem
Nenhuma mensagem: o vnu não confere o conteúdo da ficha

Para o validador W3C, o conteúdo de um bloco de dados é texto qualquer. Ele não confere o JSON nem os nomes do schema.org. Como achar: python3 -m json.tool para o JSON e o validador do schema.org para os nomes. São três conferências diferentes, uma para cada camada: o HTML, o JSON e o schema.org.

A “script” element with a “type” attribute whose value is neither a JavaScript MIME type, “module”, “importmap”, nor “speculationrules” (i.e., a data block) must not have a “src” attribute.

A Ana guardou a ficha num arquivo receita.json e tentou ligá-lo com src, como um script comum:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Bolo de cenoura | Receitas da Ana</title>
<script type="application/ld+json" src="receita.json"></script>
</head>
<body>
<h1>Bolo de cenoura</h1>
</body>
</html>

$ vnu src.html
"file:/home/ana/site/src.html":6.1-6.54: error: A “script” element with a “type” attribute whose value is neither a JavaScript MIME type, “module”, “importmap”, nor “speculationrules” (i.e., a data block) must not have a “src” attribute.

O que o validador diz: "um script cujo type não é JavaScript, module, importmap nem speculationrules (ou seja, um bloco de dados) não pode ter src". O que o navegador faz: não baixa o arquivo, e o robô não acha a ficha. Como consertar: o JSON-LD vai sempre dentro do <script>.

Outros enganos que nenhum validador de HTML vê
  • "@type": "recipe", com minúscula: o tipo é Recipe. O validador do schema.org acusa.
  • "cookTime": "40 minutos" ou "P40M": o primeiro não é ISO 8601; o segundo é 40 meses.
  • "image": "fotos/bolo.jpg": use o endereço completo, como no Open Graph.
  • type="application/json+ld" (invertido): o navegador aceita como bloco de dados, o vnu também, mas nenhum robô procura esse tipo. É application/ld+json.

Resumo

  • Dados estruturados são uma ficha para programas, com nomes do dicionário schema.org. A forma recomendada é o JSON-LD.
  • A ficha vai num <script type="application/ld+json">, que o navegador não mostra nem roda. Ela não pode vir de um arquivo com src.
  • JSON: aspas duplas, dois-pontos, vírgula entre os campos e nunca depois do último, listas entre colchetes, sem comentários.
  • Uma receita: "@type": "Recipe" com name, image, author, tempos (PT20M), recipeYield, recipeIngredient e recipeInstructions.
  • Três conferências: o vnu para o HTML, o python3 -m json.tool para o JSON e o validador do schema.org ou o teste do Google para os nomes e os campos.
