HTML Ícone da Aba (favicon)

Olhe para as abas abertas no seu navegador agora: cada uma tem um iconezinho do lado do título. Esse ícone se chama favicon (de favorite icon, "ícone dos favoritos", porque no começo ele aparecia só nos favoritos). É ele que faz você achar a aba certa entre vinte. Nesta aula a Ana vai dar um ícone ao site de receitas: você vai ver o que o navegador faz quando não há ícone, como ligar um com <link rel="icon">, quais formatos usar e os erros mais comuns.

Você vai aprender
  • Onde o favicon aparece e por que vale a pena ter um.
  • Que o navegador procura um /favicon.ico sozinho, e o que isso deixa no registro do servidor.
  • A linha <link rel="icon" href="…"> e os atributos type e sizes.
  • Os formatos (SVG, PNG, ICO) e o apple-touch-icon da tela inicial do celular.
  • Os erros reais do validador W3C e os erros que só o servidor mostra.

Os arquivos desta aula foram validados com o validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/fav. Os pedidos de arquivos foram registrados pelo servidor local do Python (aula Servidor Local) com o Chrome abrindo as páginas.

A ideia: o logotipo na fachada

Numa rua cheia de lojas, você reconhece a sua padaria pelo logotipo na fachada, antes mesmo de ler o nome. O favicon é o logotipo do site, em miniatura: um quadradinho de 16 ou 32 pixels, que precisa ser reconhecível mesmo pequeno.

Ele aparece:

  • na aba do navegador, ao lado do title;
  • nos favoritos e no histórico;
  • em alguns resultados de busca, ao lado do nome do site;
  • na tela inicial do celular, quando alguém "adiciona o site à tela de início" (com o apple-touch-icon, seção 4).

Como o title, o favicon fica no head e não aparece dentro da página. No quadro de Resultado do editor, que não tem aba, você também não vai vê-lo: os efeitos desta aula aparecem quando você abre o arquivo no navegador.

1. Sem ícone: o navegador procura sozinho

A página da Ana ainda não fala de ícone nenhum:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Receitas da Ana</title>
</head>
<body>
  <h1>Receitas da Ana</h1>
  <p>Bolo de cenoura com cobertura de chocolate.</p>
</body>
</html>

Ela abriu o site pelo servidor local e olhou o registro que ele escreve no terminal: uma linha para cada arquivo que o navegador pediu.

$ python3 -m http.server 8000
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
127.0.0.1 - - [17/Oct/2026 15:53:03] "GET /index.html HTTP/1.1" 200 -
127.0.0.1 - - [17/Oct/2026 15:53:03] code 404, message File not found
127.0.0.1 - - [17/Oct/2026 15:53:03] "GET /favicon.ico HTTP/1.1" 404 -
127.0.0.1
Quem pediu: o próprio computador da Ana (o navegador dela).
[17/Oct/2026 15:53:03]
Quando.
"GET /index.html HTTP/1.1" 200
"Me dê o /index.html." O 200 é o código de "deu certo": o servidor entregou a página.
"GET /favicon.ico HTTP/1.1" 404
"Me dê o /favicon.ico." A Ana nunca escreveu isso! Foi o navegador que pediu por conta própria. O 404 é o famoso "não encontrado" (File not found, "arquivo não encontrado"), dito também na linha de cima.

É um costume antigo: quando a página não diz qual é o ícone, o navegador tenta o arquivo favicon.ico na raiz do site (a pasta principal, a do /). Não achou? A aba fica com um ícone genérico do navegador. O Console do F12 mostrou o mesmo 404, com estas palavras:

Failed to load resource: the server responded with a status of 404 (File not found)

"Falha ao carregar o recurso: o servidor respondeu com o código 404 (arquivo não encontrado)." Não é grave, a página funciona, mas é um pedido desperdiçado em cada visita, e uma aba sem identidade.

Abrindo o arquivo direto, sem servidor

Quando você abre o index.html com dois cliques (o endereço começa com file://), não há servidor nem registro, e a aba pode mostrar só o ícone genérico. Para testar o favicon de verdade, use o servidor local.

2. Ligar um ícone: <link rel="icon">

A Ana desenhou um ícone simples, um círculo laranja com um "A", no formato SVG (um desenho escrito em texto, que fica nítido em qualquer tamanho; aula SVG no HTML). O arquivo é este:

<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 32 32">
  <circle cx="16" cy="16" r="15" fill="#e8743b"/>
  <text x="16" y="22" font-size="16" text-anchor="middle" fill="white" font-family="sans-serif">A</text>
</svg>

Para você ver o desenho, aqui ele está colado dentro de uma página, em dois tamanhos: o da aba (16 pixels) e um maior (64 pixels):

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>O ícone da Ana</title>
</head>
<body>
  <p>Tamanho da aba:
    <svg width="16" height="16" viewBox="0 0 32 32" role="img" aria-label="Ícone das Receitas da Ana">
      <circle cx="16" cy="16" r="15" fill="#e8743b"/>
      <text x="16" y="22" font-size="16" text-anchor="middle" fill="white" font-family="sans-serif">A</text>
    </svg>
  </p>
  <p>Ampliado:
    <svg width="64" height="64" viewBox="0 0 32 32" role="img" aria-label="Ícone das Receitas da Ana, ampliado">
      <circle cx="16" cy="16" r="15" fill="#e8743b"/>
      <text x="16" y="22" font-size="16" text-anchor="middle" fill="white" font-family="sans-serif">A</text>
    </svg>
  </p>
</body>
</html>

Repare como 16 pixels é pouco: um desenho com muitos detalhes vira uma mancha. Ícones bons são simples: uma letra, uma forma, duas cores.

Agora, a linha que liga o ícone à página, no head:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Receitas da Ana</title>
  <link rel="icon" href="favicon.svg" type="image/svg+xml">
</head>
<body>
  <h1>Receitas da Ana</h1>
  <p>Bolo de cenoura com cobertura de chocolate.</p>
</body>
</html>
<link
O elemento que liga a página a outro arquivo. Como o meta, é vazio: não tem </link>. O mesmo elemento liga o CSS (aula Ligar CSS).
rel="icon"
rel = "relationship", a relação entre a página e o arquivo: "este arquivo é o meu ícone".
href="favicon.svg"
href = "hypertext reference", o endereço do arquivo, como no link <a>. Aqui, um caminho relativo: o favicon.svg está na mesma pasta da página (aula Caminhos).
type="image/svg+xml"
O tipo do arquivo, no formato que a internet usa (o "tipo MIME"). É opcional, mas ajuda o navegador a pular, sem baixar, um formato que ele não entende.

O registro do servidor mudou:

$ python3 -m http.server 8000
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
127.0.0.1 - - [17/Oct/2026 15:53:06] "GET /icone.html HTTP/1.1" 200 -
127.0.0.1 - - [17/Oct/2026 15:53:06] "GET /favicon.svg HTTP/1.1" 200 -

Agora o navegador pediu o favicon.svg, que a página indicou, e recebeu (200). E não pediu mais o /favicon.ico: quando a página diz qual é o ícone, o navegador não precisa adivinhar. (O arquivo se chamava icone.html neste teste; o conteúdo é o mesmo do index.html acima.)

$ vnu --verbose certo.html
certo.html

3. Os formatos

FormatotypeVantagensCuidados
SVG (.svg)image/svg+xmlUm arquivo só, nítido em qualquer tamanho, pequeno, editável num editor de texto.Nem todo navegador aceita SVG como favicon, principalmente os mais antigos: tenha também um PNG.
PNG (.png)image/pngFunciona em todo navegador atual. Fácil de exportar de qualquer programa de desenho.Tem um tamanho fixo: diga qual com sizes.
ICO (.ico)image/x-iconO formato original, do Windows. Guarda vários tamanhos num arquivo só. É o que o navegador procura sozinho em /favicon.ico.Precisa de um programa ou site conversor para ser criado.

Os formatos de imagem têm aula própria: Formatos (JPG, PNG, WebP, SVG, AVIF).

O atributo sizes

Para PNG e ICO, o sizes diz o tamanho, em pixels, no formato LARGURAxALTURA (com um x minúsculo no meio):

<link rel="icon" href="favicon-32.png" sizes="32x32" type="image/png">

Com vários ícones, o navegador escolhe o tamanho que precisa sem baixar todos. Para SVG, que não tem tamanho fixo, existe sizes="any" ("qualquer um"), opcional.

4. O ícone da tela inicial: apple-touch-icon

Quando alguém adiciona um site à tela inicial do iPhone, o sistema procura um ícone maior, com rel="apple-touch-icon". A Apple recomenda um PNG de 180 × 180 pixels, sem transparência (o sistema arredonda os cantos sozinho). Outros celulares também aproveitam esse ícone.

<link rel="apple-touch-icon" href="apple-touch-icon.png">

Qual usar: o conjunto recomendado

Para um site pessoal, três linhas cobrem quase tudo:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Receitas da Ana</title>
  <link rel="icon" href="favicon-32.png" sizes="32x32" type="image/png">
  <link rel="icon" href="favicon.svg" type="image/svg+xml">
  <link rel="apple-touch-icon" href="apple-touch-icon.png">
</head>
<body>
  <h1>Receitas da Ana</h1>
</body>
</html>

"Troquei o ícone e a aba continua com o antigo"

Os navegadores guardam o favicon por um bom tempo, para não baixá-lo a cada visita (isso se chama cache). Depois de trocar o ícone, recarregue a página forçando (Ctrl+F5), abra a página numa janela anônima ou mude o nome do arquivo (favicon-v2.svg) e a linha do link.

Quando dá errado

O ícone não aparece, e o servidor mostra "GET /imagens/favicon.svg HTTP/1.1" 404

O que significa: o caminho do href está errado. Aqui, a Ana escreveu href="imagens/favicon.svg", mas o arquivo está na mesma pasta da página. O registro do servidor mostra exatamente o que o navegador tentou buscar:

$ python3 -m http.server 8000
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
127.0.0.1 - - [17/Oct/2026 15:53:21] "GET /errado.html HTTP/1.1" 200 -
127.0.0.1 - - [17/Oct/2026 15:53:21] code 404, message File not found
127.0.0.1 - - [17/Oct/2026 15:53:21] "GET /imagens/favicon.svg HTTP/1.1" 404 -

Repare: com um link errado, o navegador não tentou o /favicon.ico como plano B. O Console do F12 mostra Failed to load resource: the server responded with a status of 404 (File not found). O validador não percebe nada: ele não confere se o arquivo existe.

Como consertar: compare o endereço do registro com a pasta (ls) e corrija o href (aula Caminhos).

O validador não diz nada, mas o ícone não aparece: rel="favicon"

O que significa: favicon não é um valor de rel que o navegador conheça; o certo é icon. O validador aceitou a linha sem erro (como o name="autor" da aula title e meta), e o Chrome ignorou o link e voltou a pedir o /favicon.ico: no registro, o mesmo "GET /favicon.ico HTTP/1.1" 404 da página sem ícone.

Como consertar: rel="icon". (O antigo rel="shortcut icon" ainda funciona e passa no validador, mas o shortcut não faz nada.)

error: Bad value “imagens\favicon.svg” for attribute “href” on element “link”: Backslash ("\") used as path segment delimiter.

O que significa: "valor ruim no href: barra invertida usada para separar as partes do caminho". No Windows, as pastas são separadas por \, mas na web o separador é sempre a barra normal /.

Como consertar: href="imagens/favicon.svg".

error: A “link” element must have an “href” or “imagesrcset” attribute, or both.

O que significa: um <link rel="icon"> sem href: a página diz que tem um ícone, mas não diz onde ele está. ("Um elemento link precisa ter um atributo href ou imagesrcset, ou os dois.")

Como consertar: acrescente o href com o endereço do arquivo.

error: Element “link” is missing one or more of the following attributes: “itemprop”, “property”, “rel”.

O que significa: um <link href="favicon.svg"> sem rel: a página aponta para um arquivo, mas não diz o que ele é (ícone? estilo?).

Como consertar: rel="icon".

error: Bad value “32” for attribute “sizes” on element “link”. / Bad value “svg” for attribute “type” on element “link”: Subtype missing.

O que significa: o sizes precisa de largura e altura (32x32, não 32). E o type tem duas partes separadas por barra, o tipo e o subtipo (image/svg+xml, não só svg): Subtype missing = "falta o subtipo".

Como consertar: sizes="32x32"; type="image/svg+xml", type="image/png" ou type="image/x-icon".

error: Stray end tag “link”.

O que significa: um </link>. O link é um elemento vazio, como o meta: não tem tag de fechamento.

Como consertar: apague o </link>.

Bad value “data:image/svg+xml,<svg …” for attribute “href” on element “link”: Illegal character after “ta:”. “<” is not allowed.

O que significa: você copiou da internet um truque que põe o desenho SVG dentro do href (um endereço data:, que carrega o próprio arquivo). Os navegadores costumam aceitar, mas um endereço não pode ter < nem espaços sem codificação, e o validador acusa.

Como consertar: o mais simples é gravar o desenho num arquivo favicon.svg e apontar para ele.

Resumo

  • O favicon é o ícone da aba, dos favoritos e da tela inicial. Fica no head, com <link rel="icon" href="…">; o link é vazio (sem </link>).
  • Sem link, o navegador pede /favicon.ico sozinho: o servidor registra "GET /favicon.ico HTTP/1.1" 404 se ele não existir.
  • SVG fica nítido em qualquer tamanho; PNG funciona em todo lugar (com sizes="32x32"); ICO é o formato antigo. O apple-touch-icon (PNG 180 × 180) serve para a tela inicial.
  • O validador acusa href faltando, rel faltando, sizes e type mal escritos e a barra invertida, mas não percebe rel="favicon" nem um arquivo que não existe. Para esses, olhe o registro do servidor e o Console.
