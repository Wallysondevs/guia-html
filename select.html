HTML select e option

No formulário de encomendas da Ana, a cliente precisa dizer o sabor do bolo. Se for um campo de texto livre, vão chegar "chocolate", "Chocolate", "choc." e "aquele marrom". Quando as respostas possíveis já são conhecidas, o melhor é mostrar a lista e deixar a pessoa escolher. Em HTML, essa lista é o <select>, e cada item dela é um <option>. Nesta aula você vai montar listas de escolha, decidir o que é mostrado e o que é enviado, agrupar opções e conhecer as mensagens que o validador dá quando algo sai do lugar.

Você vai aprender
  • Como criar uma lista de escolha com <select> e <option>, ligada a um <label>.
  • A diferença entre o texto que a pessoa vê e o valor (value) que é enviado.
  • Como deixar uma opção já escolhida (selected) e como fazer a opção vazia "Escolha…".
  • Como agrupar opções com <optgroup> e desligar opções com disabled.
  • Como deixar escolher várias opções (multiple) e mostrar a lista aberta (size).
  • Os erros mais comuns e as mensagens reais do validador W3C.

Você vai precisar de Formulários e label. Os exemplos com o resultado embaixo são desenhados pelo seu navegador, na hora: abra a lista e escolha. As validações foram feitas com o validador W3C (vnu, o mesmo do validator.w3.org) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: o cardápio da padaria

Na padaria, você não inventa o nome do pão: olha o cardápio na parede e aponta. "Quero esse aqui." O atendente sabe exatamente do que você está falando, porque só existem aqueles itens.

O <select> é o cardápio do formulário. Ele aparece fechado, ocupando uma linha só (por isso também é chamado de lista suspensa, ou dropdown, "cair para baixo"). Quando a pessoa clica, a lista abre e mostra as opções. Ela escolhe uma, e a lista fecha mostrando a escolha.

No cardápioNo HTML
O cardápio inteiro<select> (de select, "selecionar", "escolher")
Cada item do cardápio<option> ("opção")
A placa "Escolha seu bolo:"<label> (o rótulo do campo)
As seções "Bolos", "Tortas"<optgroup> ("grupo de opções")

1. A primeira lista

Um <select> tem dentro dele um <option> para cada escolha possível. O texto entre <option> e </option> é o que aparece na lista:

<label for="sabor">Sabor do bolo:</label>
<select id="sabor" name="sabor">
  <option>Cenoura</option>
  <option>Chocolate</option>
  <option>Laranja</option>
</select>

Clique na lista do resultado: ela abre, mostra os três sabores e fecha quando você escolhe um. Repare que, sem você fazer nada, ela já mostra Cenoura: num <select> comum, a primeira opção já vem escolhida.

<label for="sabor">
O rótulo do campo. O for ("para") aponta para o id do select. Assim, clicar no texto "Sabor do bolo:" põe o foco na lista, e o leitor de tela anuncia "Sabor do bolo" quando a pessoa chega nela. Todo campo precisa de um rótulo (aula label).
<select id="sabor" name="sabor">
Começa a lista. O id é a identificação usada pelo label. O name ("nome") é o nome com que a resposta vai ser enviada. São coisas diferentes, que muitas vezes têm o mesmo texto.
<option>Cenoura</option>
Uma opção. Dentro dela vai só texto: nada de <strong>, imagens ou parágrafos.
</select>
Fecha a lista. O </option> até pode ser omitido (o navegador fecha uma opção quando a próxima começa), mas o guia sempre escreve: fica mais fácil de ler.
Um select sozinho, fora de um <form>?

Para aprender, os exemplos desta aula mostram só o campo. Num site de verdade, ele fica dentro de um <form>, com um botão de enviar, como você viu em Formulários. O envio em si é a aula Enviar (action, method, GET e POST).

2. O texto que aparece e o value que é enviado

Quando o formulário é enviado, o navegador manda um par nome=valor: o name do select e o valor da opção escolhida. Sem nenhum atributo, o valor é o próprio texto da opção:

<select id="sabor" name="sabor">
  <option>Cenoura</option>
  <option>Chocolate</option>
</select>

Escolhendo Chocolate, o navegador envia sabor=Chocolate.

Só que o texto é feito para pessoas: tem acento, maiúscula, pode mudar amanhã ("Chocolate" vira "Chocolate belga"). Quem recebe a encomenda (um programa no servidor, uma planilha) prefere um código fixo. Para isso existe o atributo value ("valor"):

<label for="sabor">Sabor do bolo:</label>
<select id="sabor" name="sabor">
  <option value="cenoura">Cenoura com cobertura</option>
  <option value="chocolate">Chocolate belga</option>
  <option value="laranja">Laranja com calda</option>
</select>

Na tela não mudou nada de importante: a cliente continua vendo os nomes bonitos. Mas agora, escolhendo "Chocolate belga", o que é enviado é sabor=chocolate.

<option>Chocolate</option>Chocolatesabor=Chocolate
<option value="chocolate">Chocolate belga</option>Chocolate belgasabor=chocolate
<option value="">Escolha</option>Escolhasabor= (valor vazio)

Experimente: escolha um sabor e clique em Enviar. O editor do guia não tem servidor, então ele mostra uma página "Formulário enviado" com o que seria enviado: a tabela name → value. Escolha "Chocolate belga" e confira que vai chocolate. Depois apague o value="laranja", escolha Laranja e envie de novo.

<form action="enviar.php">
  <label for="sabor">Sabor do bolo:</label>
  <select id="sabor" name="sabor">
    <option value="cenoura">Cenoura com cobertura</option>
    <option value="chocolate">Chocolate belga</option>
    <option value="laranja">Laranja com calda</option>
  </select>
  <button type="submit">Enviar</button>
</form>

Se o select não tem name, nada dele é enviado, nem o nome nem o valor. Esse é um esquecimento comum, e o validador não avisa (o select sem name é válido, porque um script pode usá-lo sem enviar nada). Você vai ver o envio de verdade, com cada par aparecendo no endereço, em Enviar.

Espaços no texto

Quando o valor vem do texto, o navegador junta os espaços repetidos e tira os das pontas. Testamos <option> Cenoura com mel </option> no Chromium 155: o valor enviado foi Cenoura com mel. Com value, nada disso importa: vai exatamente o que está entre as aspas.

3. Uma opção já escolhida: selected

Se quase todo mundo pede chocolate, a Ana pode deixar chocolate já escolhido. O atributo selected ("selecionado") na opção faz isso. Ele é um atributo booleano: não leva valor, basta estar lá (aula Atributos).

<label for="sabor">Sabor do bolo:</label>
<select id="sabor" name="sabor">
  <option value="cenoura">Cenoura</option>
  <option value="chocolate" selected>Chocolate</option>
  <option value="laranja">Laranja</option>
</select>

A lista já começa em Chocolate, mesmo sendo a segunda opção. A pessoa continua podendo trocar. O selected só decide o ponto de partida.

A opção vazia: "Escolha um sabor"

Deixar uma opção já escolhida tem um risco: a cliente com pressa nem olha a lista e envia o padrão, sem querer. Quando você precisa de uma escolha de verdade, comece a lista com uma opção que não é resposta, com o value vazio, e marque o select como obrigatório com required ("obrigatório"):

<label for="tamanho">Tamanho:</label>
<select id="tamanho" name="tamanho" required>
  <option value="">Escolha um tamanho</option>
  <option value="p">Pequeno (10 fatias)</option>
  <option value="m">Médio (20 fatias)</option>
  <option value="g">Grande (30 fatias)</option>
</select>
required
O campo é obrigatório. Se o formulário for enviado com o valor vazio, o navegador não envia: ele para, põe o foco na lista e mostra um balãozinho pedindo para escolher um item. O texto desse balão é do navegador (muda de um navegador para outro e com o idioma dele). A aula Validação mostra tudo sobre isso.
<option value="">Escolha um tamanho</option>
A opção "de mentira", chamada de rótulo de espera (placeholder). Ela é a primeira, então vem escolhida, e o valor dela é vazio. Com o required, valor vazio conta como "não respondeu".

O validador conhece essa combinação e cobra a regra: num select com required (e sem multiple nem size maior que 1), a primeira opção tem de ser a de espera, com value="". Você vai ver a mensagem em Quando dá errado.

Missão: a Ana começou a fazer bolo de limão. Acrescente uma quarta opção, com o texto Limão e o valor limao (sem acento, que é mais seguro para códigos). Depois deixe Chocolate já escolhido quando a página abre.

  <option value="cenoura">Cenoura</option>
  <option value="chocolate">Chocolate</option>
  <option value="laranja">Laranja</option>
</select>

4. Grupos de opções: <optgroup>

A lista da Ana cresceu: tem bolos, tortas e doces. Com 12 opções soltas, a cliente se perde. O <optgroup> ("grupo de opções") separa a lista em seções, como os títulos do cardápio:

<label for="produto">Produto:</label>
<select id="produto" name="produto">
  <optgroup label="Bolos">
    <option value="bolo-cenoura">Cenoura</option>
    <option value="bolo-chocolate">Chocolate</option>
  </optgroup>
  <optgroup label="Tortas">
    <option value="torta-limao">Limão</option>
    <option value="torta-morango">Morango</option>
  </optgroup>
</select>

Abra a lista: os nomes Bolos e Tortas aparecem como títulos (em geral em negrito), e as opções ficam embaixo de cada um, um pouco para dentro. Tente clicar num título: não dá. O grupo não é uma opção, só um título.

<optgroup label="Bolos">
Começa um grupo. O label é o título do grupo e é obrigatório. (É outro label: aqui é um atributo, e não o elemento <label> do rótulo do campo.)
</optgroup>
Fecha o grupo. Um grupo não pode ter outro grupo dentro: são só dois níveis, título e opções.
value="bolo-cenoura"
O grupo não é enviado. Por isso, se "Limão" existe como bolo e como torta, o value precisa dizer qual é qual.

Missão: separe a lista em dois grupos: Bolos (Cenoura e Chocolate) e Tortas (Limão e Morango). Use <optgroup label="…"> em volta de cada par de opções.

<label for="produto">Produto:</label>
<select id="produto" name="produto">
  <option value="bolo-cenoura">Cenoura</option>
  <option value="bolo-chocolate">Chocolate</option>
  <option value="torta-limao">Limão</option>
  <option value="torta-morango">Morango</option>
</select>

<label for="produto">Produto:</label>
<select id="produto" name="produto">
  <optgroup label="Bolos">
    <option value="bolo-cenoura">Cenoura</option>
    <option value="bolo-chocolate">Chocolate</option>
  </optgroup>
  <optgroup label="Tortas">
    <option value="torta-limao">Limão</option>
    <option value="torta-morango">Morango</option>
  </optgroup>
</select>

5. Opções desligadas: disabled

Acabou o morango? Em vez de apagar a opção (e a cliente achar que a Ana nunca faz torta de morango), ela pode desligar a opção com disabled ("desabilitado"), outro atributo booleano. A opção continua aparecendo, mas apagadinha, e não dá para escolher:

<label for="torta">Torta:</label>
<select id="torta" name="torta">
  <option value="limao">Limão</option>
  <option value="morango" disabled>Morango (esgotado)</option>
  <option value="maracuja">Maracujá</option>
</select>

O disabled também funciona num <optgroup> (desliga o grupo inteiro) e no próprio <select> (desliga a lista toda). Um select desligado não é enviado, como se não existisse no formulário. Testamos no Chromium 155: num formulário com um select desligado, ele simplesmente não apareceu entre os dados enviados. O disabled dos outros campos é assunto de placeholder, value, autocomplete….

E se a primeira opção estiver desligada?

A lista começa na primeira opção que pode ser escolhida. Com <option disabled>X</option><option>Y</option>, ela começou em Y no Chromium 155. Para um rótulo de espera, use o value="" da seção 3, e não o disabled.

6. Várias escolhas (multiple) e a lista aberta (size)

Até aqui, a pessoa escolhe uma opção. Com o atributo booleano multiple ("múltiplo"), ela pode escolher várias. O select deixa de ser suspenso e vira uma caixa de lista, já aberta, com várias linhas à vista:

<label for="adicionais">Adicionais:</label>
<select id="adicionais" name="adicionais" multiple>
  <option value="granulado">Granulado</option>
  <option value="morango">Morangos</option>
  <option value="vela">Vela de aniversário</option>
  <option value="cartao">Cartão</option>
</select>

Clique numa opção: ela fica marcada. Para marcar mais de uma, segure Ctrl (no Mac, Cmd) enquanto clica. Para marcar uma sequência, clique na primeira e, segurando Shift, na última. No celular, a lista costuma abrir um quadro com caixinhas de marcar.

No envio, cada opção marcada vira um par, todos com o mesmo nome. Testamos com duas opções marcadas no Chromium 155: o formulário enviou adicionais=granulado&adicionais=vela. (O & separa os pares; a aula Enviar mostra isso no servidor.)

O atributo size ("tamanho") diz quantas linhas ficam à vista. Ele funciona com ou sem multiple:

<label for="dia">Dia da entrega:</label>
<select id="dia" name="dia" size="3">
  <option>Segunda</option>
  <option>Terça</option>
  <option>Quarta</option>
  <option>Quinta</option>
  <option>Sexta</option>
</select>

Agora a lista aparece aberta, com três linhas e uma barra de rolagem para o resto. Repare numa diferença importante: com size maior que 1, nenhuma opção vem escolhida. No Chromium 155, o valor desse select ao abrir a página era vazio. Se a pessoa não clicar em nada, o campo não é enviado.

multiple é difícil de usar

Muita gente não sabe do Ctrl+clique e, ao clicar na segunda opção, desmarca a primeira sem perceber. Para poucas opções (até umas 8), caixinhas de marcar são muito mais claras: veja checkbox e radio.

Formas diferentes: qual usar?

O <select> não é a única forma de oferecer escolhas. Cada uma tem a sua hora:

SituaçãoUsePor quê
Uma escolha entre 2 a 5 opçõesradioTodas as opções ficam à vista; a pessoa compara sem abrir nada.
Uma escolha entre muitas opções (estado, mês, sabor)<select>Ocupa uma linha só; a lista aparece quando a pessoa precisa.
Várias escolhas entre poucas opçõescheckboxMais fácil que o Ctrl+clique do multiple.
Várias escolhas entre muitas opções<select multiple>Uma caixa com rolagem no lugar de dezenas de caixinhas. Avise sobre o Ctrl.
Sugestões, mas a pessoa pode escrever outra coisadatalistO select só aceita o que está na lista; o datalist aceita qualquer texto.

Quando dá errado

Todos os arquivos desta seção são páginas completas com o mesmo começo de 7 linhas (<!DOCTYPE html>, <html lang="pt-BR">, o <head> com charset e title, e <body>; veja Estrutura de uma Página). O código mostrado começa na linha 8, e é por isso que as linhas das mensagens começam em 8.

Duas opções com selected 
<label for="sabor">Sabor:</label>
<select id="sabor" name="sabor">
  <option selected>Cenoura</option>
  <option selected>Chocolate</option>
</select>

$ vnu dois.html
"file:/home/ana/site/dois.html":11.3-11.19: error: The “select” element cannot have more than one selected “option” descendant unless the “multiple” attribute is specified.

O que significa: "o elemento select não pode ter mais de um option selecionado, a não ser que o atributo multiple esteja presente". Numa lista de uma escolha só, só uma opção pode vir marcada. O 11.3-11.19 é a linha 11, da coluna 3 à 19: a tag <option selected> da segunda opção.

O que o navegador faz: não reclama e fica com a última. No Chromium 155, a lista abriu em Chocolate e enviou sabor=Chocolate.

Como consertar: deixe o selected numa opção só. Se a ideia era escolher várias, acrescente multiple ao select.

required sem a opção vazia no começo 
<label for="tamanho">Tamanho:</label>
<select id="tamanho" name="tamanho" required>
  <option value="p">Pequeno</option>
  <option value="g">Grande</option>
</select>

$ vnu obrigatorio.html
"file:/home/ana/site/obrigatorio.html":10.3-10.20: error: The first “option” element in a “select” element with a “required” attribute, and without a “multiple” attribute, and without a “size” attribute whose value is greater than “1”, must have either an empty “value” attribute, or must have no text content. Consider either adding a placeholder option label, or adding a “size” attribute with a value equal to the number of “option” elements.

O que significa: "o primeiro option de um select com required (sem multiple e sem size maior que 1) precisa ter o value vazio ou não ter texto. Considere acrescentar uma opção de espera, ou um size igual ao número de opções."

O motivo: aqui a primeira opção, Pequeno, já vem escolhida e tem valor. O campo nunca fica vazio, então o required não serve para nada. Quem não mexer na lista encomenda um bolo pequeno sem saber.

Como consertar: comece com <option value="">Escolha um tamanho</option>, como na seção 3.

<optgroup> sem label 
<label for="doce">Doce:</label>
<select id="doce" name="doce">
  <optgroup>
    <option>Brigadeiro</option>
    <option>Beijinho</option>
  </optgroup>

$ vnu grupo.html
"file:/home/ana/site/grupo.html":13.3-13.13: error: An “optgroup” element with no child “legend” element must have a “label” attribute.

O que significa: "um optgroup sem um legend dentro precisa ter o atributo label". O validador aponta o </optgroup> (linha 13), o lugar onde ele terminou de ler o grupo e viu que faltava o título. O legend da mensagem é uma novidade recente do HTML, o select personalizável, em que o título do grupo pode ser um elemento; ele depende de CSS e ainda não funciona em todos os navegadores. Por enquanto, use o label.

O que o navegador faz: mostra um grupo com o título vazio, um espaço em branco estranho no meio da lista.

Como consertar: <optgroup label="Doces">.

Uma opção vazia 
<label for="cor">Cor da vela:</label>
<select id="cor" name="cor">
  <option></option>
  <option>Azul</option>
  <option>Rosa</option>
</select>

$ vnu vazia.html
"file:/home/ana/site/vazia.html":10.11-10.19: error: Element “option” without attribute “label” must not be empty.

O que significa: "um option sem o atributo label não pode ser vazio". Uma linha em branco na lista não diz nada a ninguém, e o leitor de tela anuncia uma opção sem nome. (O atributo label de um option é um texto alternativo para mostrar na lista; quase ninguém usa.)

Como consertar: escreva um texto: <option value="">Sem vela</option> ou <option value="">Escolha uma cor</option>. Repare que a regra do required aceita a opção vazia, mas esta regra não: a saída é sempre dar um texto e deixar só o value vazio.

Outra coisa dentro do select 
<label for="doce">Doce:</label>
<select id="doce" name="doce">
  <p>Escolha um doce</p>
  <option>Brigadeiro</option>

$ vnu dentro.html
"file:/home/ana/site/dentro.html":10.3-10.5: error: Element “p” not allowed as child of element “select” in this context. (Suppressing further errors from this subtree.)

O que significa: "o elemento p não é permitido como filho de select neste contexto (os próximos erros dentro dele não serão mostrados)". Dentro de um select comum vão só <option>, <optgroup> e <hr> (uma linha separadora).

O que o navegador faz: depende da idade dele. Os navegadores antigos jogavam fora a tag <p>. O Chromium 155 que usamos guardou o <p> dentro do select (dá para ver no F12, aula Ferramentas do Desenvolvedor), por causa do select personalizável. Em nenhum caso o texto vira uma opção que se possa escolher.

Como consertar: o texto de instrução vai no <label> ("Doce:") ou numa opção de espera (<option value="">Escolha um doce</option>).

O for do label não bate com o id 
<label for="sabores">Sabor:</label>
<select id="sabor" name="sabor">
  <option>Cenoura</option>
  <option>Chocolate</option>
</select>

$ vnu rotulo.html
"file:/home/ana/site/rotulo.html":8.1-8.21: error: The value of the “for” attribute of the “label” element must be the ID of a non-hidden form control.

O que significa: "o valor do for do label precisa ser o id de um campo de formulário visível". Não existe nenhum id="sabores": o rótulo aponta para o nada.

O que o navegador faz: mostra tudo normalmente. Mas clicar em "Sabor:" não faz nada, e o leitor de tela anuncia a lista sem nome. É um erro que só aparece para quem depende do rótulo.

Como consertar: copie o id exato do select para o for.

A escolha não chega: select sem name

Um <select id="sabor"> sem name é HTML válido: o vnu não dá nenhum erro. Mas, no envio, ele fica de fora. A encomenda chega sem o sabor, e ninguém percebe até o dia da festa.

Como consertar: todo campo que precisa ser enviado leva um name: <select id="sabor" name="sabor">.

Repare que a opção de espera fica fora dos grupos: ela não é um bairro de nenhuma zona. E confira o resultado: abra a lista e veja os dois títulos.

Resumo

  • <select> é a lista de escolha; cada <option> é uma opção. Ligue a lista a um <label for="…"> pelo id.
  • O envio é name=valor. O valor é o value da opção escolhida ou, sem ele, o texto dela. Sem name, nada é enviado (e o validador não avisa).
  • selected escolhe o ponto de partida; sem ele, vale a primeira opção. Só uma opção pode ter selected numa lista de uma escolha.
  • Para obrigar uma escolha: required no select e uma primeira opção de espera com value="" e um texto.
  • <optgroup label="…"> agrupa opções com um título, que não é enviado. disabled desliga uma opção, um grupo ou a lista inteira.
  • multiple permite várias escolhas (com Ctrl+clique) e envia um par para cada uma; size mostra a lista aberta. Para poucas opções, prefira radio e checkbox.
