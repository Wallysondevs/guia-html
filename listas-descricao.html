HTML Listas de Descrição

Algumas listas não são de itens soltos, e sim de pares: uma palavra e a explicação dela, um nome e o valor dele. "Untar: passar manteiga na forma." "Rendimento: 12 fatias." Para isso o HTML tem uma terceira lista, a lista de descrição, feita com três tags: <dl>, <dt> e <dd>. Nesta aula a Ana monta o glossário do site de receitas e a ficha técnica do bolo.

Você vai aprender
  • O que são dl, dt e dd e como montar um glossário.
  • Como o navegador desenha a lista (e o que ele não desenha).
  • Como fazer fichas do tipo "nome: valor".
  • Como pôr várias descrições para um termo e vários termos para uma descrição.
  • Como agrupar cada par com div.
  • Quando usar dl, ul ou uma tabela.
  • Os erros reais do validador: dd sem dt, dt sem dd, título dentro do dt e div pela metade.

Os quadros Resultado são desenhados pelo seu navegador. As mensagens do validador saíram do vnu 26.10.12 na máquina fictícia da Ana, na pasta ~/site.

A ideia: o dicionário

Abra um dicionário em qualquer página: cada entrada tem a palavra, em destaque, e logo abaixo a explicação. Uma lista de descrição é igual: uma sequência de pares "termo → descrição".

TagVem do inglêsNo dicionário
<dl>description list, "lista de descrição"o dicionário inteiro
<dt>description term, "termo descrito"a palavra
<dd>description details, "detalhes da descrição"a explicação

Em livros antigos você vai encontrar "definition list" ("lista de definições"). É a mesma tag: o nome mudou porque ela serve para muito mais do que definições.

1. O primeiro glossário

<h2>Glossário da cozinha</h2>
<dl>
  <dt>Banho-maria</dt>
  <dd>Cozinhar dentro de uma panela que fica sobre outra com água quente.</dd>
  <dt>Untar</dt>
  <dd>Passar manteiga ou óleo na forma para a massa não grudar.</dd>
</dl>
<dl> … </dl>
A lista inteira. Junta todos os pares.
<dt>Banho-maria</dt>
O termo: a palavra (ou nome) que vai ser explicada.
<dd>Cozinhar dentro…</dd>
A descrição do termo que veio logo antes. Quem liga um ao outro é a ordem: cada dd descreve o dt de cima.

Repare no que o navegador desenhou:

  • O termo fica encostado na margem, e a descrição fica com um recuo à esquerda.
  • Não há bolinhas nem números.
  • O termo não fica em negrito. Muita gente imagina que fica; o destaque, se você quiser, vem do CSS (quer aprender mais? futuro Guia CSS).

O esquema que você está lendo agora, com o código em destaque e a explicação embaixo, é uma lista de descrição: o guia usa dl em todas as aulas, com um pouco de CSS por cima.

Numa página completa, o glossário passa no validador sem nenhuma mensagem:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Glossário</title>
</head>
<body>
<h1>Glossário da cozinha</h1>
<dl>
  <dt>Banho-maria</dt>
  <dd>Cozinhar dentro de uma panela que fica sobre outra com água quente.</dd>
  <dt>Untar</dt>
  <dd>Passar manteiga ou óleo na forma para a massa não grudar.</dd>
</dl>
</body>
</html>

$ vnu --verbose glossario.html
glossario.html              « só o nome: nenhum erro

2. Fichas "nome: valor"

A lista de descrição não serve só para palavras difíceis. Qualquer conjunto de pares nome → valor cabe nela: a ficha técnica de uma receita, os dados de um produto, as informações de contato.

<h2>Bolo de cenoura</h2>
<dl>
  <dt>Rendimento</dt>
  <dd>12 fatias</dd>
  <dt>Tempo de preparo</dt>
  <dd>20 minutos</dd>
  <dt>Tempo de forno</dt>
  <dd>40 minutos</dd>
</dl>

Para quem lê com os olhos, tanto faz escrever "Rendimento: 12 fatias" num parágrafo. Para o navegador e para o leitor de tela, a dl diz algo a mais: "12 fatias" é o valor de "Rendimento". Alguns leitores de tela anunciam a lista e quantos termos ela tem.

Experimente: acrescente um quarto par no fim da ficha: o termo Dificuldade com a descrição fácil.

<h2>Bolo de cenoura</h2>
<dl>
  <dt>Rendimento</dt>
  <dd>12 fatias</dd>
  <dt>Tempo de preparo</dt>
  <dd>20 minutos</dd>
  <dt>Tempo de forno</dt>
  <dd>40 minutos</dd>
</dl>

<h2>Bolo de cenoura</h2>
<dl>
  <dt>Rendimento</dt>
  <dd>12 fatias</dd>
  <dt>Tempo de preparo</dt>
  <dd>20 minutos</dd>
  <dt>Tempo de forno</dt>
  <dd>40 minutos</dd>
  <dt>Dificuldade</dt>
  <dd>fácil</dd>
</dl>

3. Vários dd, vários dt

Os pares não precisam ser de um para um. Um termo pode ter várias descrições, e uma descrição pode servir para vários termos:

<dl>
  <dt>Cobertura</dt>
  <dd>Chocolate meio amargo</dd>
  <dd>Granulado</dd>

  <dt>Fubá</dt>
  <dt>Farinha de milho</dt>
  <dd>Pó amarelo feito de milho moído. Nome diferente em cada região.</dd>
</dl>
um dt, dois dd
"Cobertura" tem dois valores: chocolate e granulado. Cada dd que vem depois do mesmo dt é mais uma descrição dele.
dois dt, um dd
"Fubá" e "Farinha de milho" são dois nomes para a mesma coisa, e dividem a mesma descrição. Os termos ficam um embaixo do outro, e a descrição vem depois de todos.
a linha em branco
Só para você ler o código. O navegador ignora; quem separa os grupos é a ordem: um grupo novo começa quando um dt aparece depois de um dd.

4. Agrupar cada par com div

Às vezes é preciso tratar cada par como um bloco, por exemplo para desenhar cada um num cartão com CSS. O HTML deixa embrulhar cada grupo inteiro (seus dt e seus dd) num div (aula div e span):

<dl>
  <div>
    <dt>Rendimento</dt>
    <dd>12 fatias</dd>
  </div>
  <div>
    <dt>Tempo de forno</dt>
    <dd>40 minutos</dd>
  </div>
</dl>

Sem CSS, o resultado fica igual ao da lista sem div. As regras desse embrulho são rígidas:

  • O div só pode ser filho direto do dl, e cada um contém um grupo completo: pelo menos um dt e, depois, pelo menos um dd.
  • É tudo ou nada: se um grupo está num div, todos os grupos daquele dl precisam estar.

Quebrar essas regras dá erro, como você vai ver em Quando dá errado.

5. dl, ul ou tabela?

O conteúdo é…UseExemplo
uma sequência de itens simplesul ou olingredientes, passos
pares: um nome e o valor (ou a explicação)dlglossário, ficha técnica, dados de contato
vários itens com as mesmas várias informaçõestabelatrês bolos, cada um com preço, peso e sabor (aula Tabelas)
Dois usos que o HTML não quer
  • Diálogos. A especificação diz que a dl não serve para conversas ("Ana: oi!", "Bia: olá!"): uma fala não é a descrição de quem fala. Use parágrafos.
  • Só para ganhar recuo. Um dd sozinho dá um recuo bonito, mas o recuo é coisa do CSS (margin-left). A tag tem de dizer o que o conteúdo é.

Quando dá errado

Os arquivos completos têm as mesmas 7 primeiras linhas do glossario.html; o código mostrado começa na linha 8. Em todos os casos, o navegador desenha alguma coisa sem reclamar. Só o validador conta o problema.

error: Element “dl” is missing a required child element.

A Ana escreveu a descrição e esqueceu o termo:

<dl>
  <dd>Rende 12 fatias.</dd>
</dl>

$ vnu dd-sozinho.html
"file:/home/ana/site/dd-sozinho.html":9.3-9.6: error: Element “dl” is missing a required child element.

O que significa: "falta um elemento filho obrigatório no dl". O validador aponta o <dd> (linha 9): antes de qualquer dd, tem de haver um dt.

O que o navegador faz: desenha o texto com recuo, como se estivesse tudo certo.

Como consertar: ponha o termo antes: <dt>Rendimento</dt>. Se você só queria o recuo, o problema é outro: troque a dl por um parágrafo e faça o recuo com CSS.

error: Element “dl” is missing a required instance of child element “dd”.

O contrário: o último termo ficou sem descrição.

<dl>
  <dt>Rendimento</dt>
  <dd>12 fatias</dd>
  <dt>Tempo de forno</dt>
</dl>

$ vnu dt-sozinho.html
"file:/home/ana/site/dt-sozinho.html":12.1-12.5: error: Element “dl” is missing a required instance of child element “dd”.

O que significa: "falta no dl um filho dd obrigatório". A posição (linha 12) é o </dl>: foi ali que o validador percebeu que a lista acabou com um termo sem descrição.

Como consertar: escreva o dd do último termo, ou apague o termo.

error: Element “dt” not allowed as child of element “body” in this context.

A Ana esqueceu o <dl>:

<dt>Rendimento</dt>
<dd>12 fatias</dd>

$ vnu sem-dl.html
"file:/home/ana/site/sem-dl.html":8.1-8.4: error: Element “dt” not allowed as child of element “body” in this context. (Suppressing further errors from this subtree.)
"file:/home/ana/site/sem-dl.html":9.1-9.4: error: Element “dd” not allowed as child of element “body” in this context. (Suppressing further errors from this subtree.)

O que significa: dt e dd só podem morar dentro de um dl (ou de um div dentro dele), como o li só mora numa lista.

O que o navegador faz: o resultado fica igual ao de uma lista certa, porque o recuo vem do próprio dd. Esse é o tipo de erro que só o validador pega: olhando a página, ninguém percebe.

Como consertar: embrulhe os pares em <dl>…</dl>.

error: The element “h2” must not appear as a descendant of the “dt” element.

A Ana quis o termo em letras grandes e pôs um título dentro do dt:

<dl>
  <dt><h2>Untar</h2></dt>
  <dd>Passar manteiga na forma.</dd>
</dl>

$ vnu titulo-dt.html
"file:/home/ana/site/titulo-dt.html":9.7-9.10: error: The element “h2” must not appear as a descendant of the “dt” element.
"file:/home/ana/site/titulo-dt.html":9.7-9.10: info warning: This document has heading elements but none of them has a computed heading level of 1.

O que significa: "o elemento h2 não pode aparecer como descendente do elemento dt". Descendente é qualquer elemento lá dentro, filho, neto ou bisneto. Um dt não pode ter títulos (h1 a h6), nem header, footer, section ou article. O info warning da segunda linha é outro assunto: este arquivo de teste tem títulos, mas nenhum h1 (aula Títulos).

Como consertar: tire o h2. Para destacar o termo, use <dt><strong>Untar</strong></dt> ou CSS. Se cada termo merece mesmo um título, talvez o conteúdo não seja uma lista, e sim seções com h2 e parágrafos.

error: Element “dt” not allowed as child of element “dl” in this context.

A Ana embrulhou só o primeiro par num div:

<dl>
  <div>
    <dt>Rendimento</dt>
    <dd>12 fatias</dd>
  </div>
  <dt>Tempo de forno</dt>
  <dd>40 minutos</dd>
</dl>

$ vnu div-misturado.html
"file:/home/ana/site/div-misturado.html":13.3-13.6: error: Element “dt” not allowed as child of element “dl” in this context. (Suppressing further errors from this subtree.)
"file:/home/ana/site/div-misturado.html":14.3-14.6: error: Element “dd” not allowed as child of element “dl” in this context. (Suppressing further errors from this subtree.)

O que significa: parece estranho, "dt não é permitido como filho de dl", mas a palavra importante é in this context, "neste contexto". Depois que o primeiro grupo veio num div, o dl passou a aceitar só div: é a regra do tudo ou nada.

Como consertar: embrulhe o segundo grupo num div também, ou tire o div do primeiro.

Missão final: a ficha do caderno

Missão: a Ana escreveu a ficha do caderno num parágrafo com <br>. Transforme em uma lista de descrição com 3 pares: o que vem antes dos dois-pontos é o termo, o que vem depois é a descrição. O primeiro termo é Preço. Não deixe nenhum <br>.

<h2>Caderno universitário</h2>
<p>Preço: R$ 25,00<br>
Folhas: 96<br>
Capa: dura</p>

<h2>Caderno universitário</h2>
<dl>
  <dt>Preço</dt>
  <dd>R$ 25,00</dd>
  <dt>Folhas</dt>
  <dd>96</dd>
  <dt>Capa</dt>
  <dd>dura</dd>
</dl>

Os dois-pontos sumiram: na dl, quem diz que "R$ 25,00" é o valor de "Preço" é a estrutura, e não a pontuação. Se a Ana quiser os dois-pontos de volta na tela, o CSS consegue desenhá-los sem mexer no HTML.

Resumo

  • dl (description list) é uma lista de pares: dt (o termo) e dd (a descrição).
  • Cada dd descreve o dt que veio antes. Pode haver vários dd para um termo e vários dt para uma descrição.
  • O navegador põe recuo no dd; não há marcador, número nem negrito.
  • Serve para glossários e fichas "nome: valor". Para itens simples, ul/ol; para várias colunas, tabela. Nunca para diálogos ou só para recuar texto.
  • Cada grupo pode ir num div, mas é tudo ou nada.
  • Erros do validador: missing a required child element (dd sem dt), missing a required instance of child element “dd”, “dt” not allowed as child of element “body” e “h2” must not appear as a descendant of the “dt” element.
