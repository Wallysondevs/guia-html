HTML Atributos data-*

O HTML tem uma lista fechada de atributos: você não pode inventar um preco="35", porque o validador recusa. Mas às vezes o seu site precisa guardar uma informação num elemento: o preço de um produto, a categoria de uma receita, quantas fatias tem um bolo. Para isso existem os atributos data-*: qualquer nome que comece com data- é válido. Nesta aula você vai criar os seus, lê-los com o JavaScript (o dataset) vendo tudo no console, e usá-los no CSS.

Você vai aprender
  • Para que servem os data-* e por que não inventar atributos sem o data-.
  • As regras do nome: data-preco, data-preco-kg.
  • Como ler os valores no JavaScript com dataset, e o hífen que vira maiúscula (precoKg).
  • Por que "35" + 1 dá 351: o valor é sempre texto.
  • Como mudar e apagar um data-* pelo JavaScript.
  • Como o CSS escolhe elementos pelo valor de um data-*.
  • Quando não usar data-*.

As mensagens do validador desta aula saíram do validador W3C (vnu, o mesmo do validator.w3.org) na máquina da Ana (usuária ana, computador notebook), na pasta ~/site. O que aparece no console foi conferido num navegador de verdade, e você pode repetir tudo nos editores da página.

A ideia: a etiqueta do estoque

Na lojinha da Ana, cada pote de doce tem um rótulo bonito, para o cliente: "Brigadeiro de colher". Embaixo do pote, tem uma etiquetinha que só a Ana olha: o preço, o código do fornecedor, quantos ainda tem no estoque. O cliente nem vê, mas é ela que faz o caixa funcionar.

Os data-* são essa etiqueta de baixo do pote: dados que não aparecem na página, guardados no próprio elemento, para o seu JavaScript e o seu CSS usarem.

1. Escrever um data-*

<ul>
  <li data-preco="35" data-categoria="bolo">Bolo de cenoura</li>
  <li data-preco="2" data-categoria="doce">Brigadeiro</li>
  <li data-preco="40" data-categoria="bolo" data-preco-kg="80">Bolo de morango</li>
</ul>

O resultado é uma lista comum: os preços não aparecem. Eles estão guardados nos elementos, esperando quem os use.

data-
O começo obrigatório. É ele que diz ao navegador e ao validador: "este atributo é um dado do autor da página". Data = "dados".
preco
O nome que você escolhe. Escreva em minúsculas, sem espaço; para juntar palavras, use hífen.
="35"
O valor: sempre um texto, entre aspas. Pode ser um número, uma palavra, uma frase.
data-categoria="bolo"
Um elemento pode ter quantos data-* quiser.
data-preco-kg="80"
Nome com hífen: preco-kg. Guarde este, ele vai mudar de cara no JavaScript.

As regras do nome

NomeVálido?Por quê
data-precosimo jeito recomendado
data-preco-kgsimpalavras ligadas por hífen
preconãofalta o data-: atributo inventado
data-nãofalta o nome depois do hífen
data-Precopassa no validador, mas eviteo navegador transforma em data-preco (veja em Quando dá errado)

Veja o que o validador diz dos dois casos inválidos:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Lojinha da Ana</title>
</head>
<body>
<ul>
  <li data-preco="35">Bolo de cenoura</li>
  <li data-="2">Brigadeiro</li>
  <li preco="5">Café</li>
</ul>
</body>
</html>

$ vnu index.html
"file:/home/ana/site/index.html":10.3-10.16: error: Attribute “data-” not allowed on element “li” at this point.
"file:/home/ana/site/index.html":11.3-11.16: error: Attribute “preco” not allowed on element “li” at this point.

O 10.3-10.16 quer dizer "linha 10, da coluna 3 à 16": a tag <li data-="2"> inteira (as colunas 1 e 2 são os espaços do começo).

"O atributo preco não é permitido no elemento li neste ponto." O navegador até guarda o preco="5", mas a página fica inválida, e um atributo inventado hoje pode virar um atributo de verdade, com outro significado, numa versão futura do HTML. O data- é o espaço reservado para você: o HTML promete nunca criar um atributo oficial com esse começo.

2. Ler no JavaScript: o dataset

Cada elemento tem uma propriedade dataset ("conjunto de dados"): uma caixa com todos os data-* dele, sem o data- na frente. Rode e veja o console, embaixo do resultado:

<ul>
  <li id="bolo" data-preco="35" data-categoria="bolo" data-preco-kg="80">Bolo de cenoura</li>
</ul>
<script src="script.js"></script>

const bolo = document.getElementById("bolo");

console.log(bolo.dataset.preco);
console.log(bolo.dataset.categoria);
console.log(bolo.dataset.precoKg);
console.log(bolo.dataset);

No console aparecem quatro linhas:

35
bolo
80
DOMStringMap {preco: '35', categoria: 'bolo', precoKg: '80'}
bolo.dataset.preco
O valor de data-preco: o texto 35.
bolo.dataset.categoria
O valor de data-categoria.
bolo.dataset.precoKg
O valor de data-preco-kg. No JavaScript, um hífen no meio de um nome seria lido como "menos". Por isso o navegador tira o hífen e põe a letra seguinte em maiúscula: preco-kg vira precoKg. Esse estilo de escrever se chama camelCase ("caixa de camelo"), por causa das "corcovas" das maiúsculas.
bolo.dataset
A caixa inteira de uma vez: cada nome (já em camelCase) e o seu valor. Repare que até o 35 está entre aspas: é texto. DOMStringMap é o nome técnico da caixa, um "mapa de textos".
No F12 do navegador

Nas Ferramentas do Desenvolvedor, o console mostra o mesmo DOMStringMap, e você pode abri-lo com um clique para ver cada valor. Outro truque do F12: na aba dos elementos, clique no <li>; depois, no console, $0.dataset mostra os dados do elemento que você clicou ($0 é "o elemento selecionado"). Já em lugares que transformam tudo em texto puro, a caixa aparece só como [object DOMStringMap]; aí, use JSON.stringify(bolo.dataset), que dá {"preco":"35","categoria":"bolo","precoKg":"80"}.

Outro jeito: getAttribute

O getAttribute ("pegar atributo") lê qualquer atributo pelo nome completo, como está no HTML:

console.log(bolo.getAttribute("data-preco-kg"));   // 80

Os dois funcionam. O dataset é mais curto; o getAttribute evita a troca para camelCase.

O valor é sempre texto

Isto pega todo mundo uma vez. Rode:

<p id="bolo" data-preco="35">Bolo de cenoura</p>
<script src="script.js"></script>

const bolo = document.getElementById("bolo");

console.log(bolo.dataset.preco + 1);
console.log(Number(bolo.dataset.preco) + 1);

A primeira linha do console mostra 351, e não 36. Com textos, o + do JavaScript cola um no outro: "35" com 1 dá "351". Para fazer conta, transforme o texto em número com Number(…): a segunda linha mostra 36.

Missão: o bolo tem 12 fatias. Guarde isso no elemento com um atributo data-fatias e conserte a última linha do script.js (ela está lendo o preço) para que o console mostre Fatias: 12, lendo o valor pelo dataset.

<p id="bolo" data-preco="35">Bolo de cenoura</p>
<script src="script.js"></script>

const bolo = document.getElementById("bolo");

console.log("Preço: " + bolo.dataset.preco);
console.log("Fatias: " + bolo.dataset.preco);

<p id="bolo" data-preco="35" data-fatias="12">Bolo de cenoura</p>
<script src="script.js"></script>

const bolo = document.getElementById("bolo");

console.log("Preço: " + bolo.dataset.preco);
console.log("Fatias: " + bolo.dataset.fatias);

Do jeito que começa, o console mostra Fatias: 35: o texto está certo, mas o valor é o do data-preco. Se você escrever bolo.dataset.fatias antes de criar o atributo, o console mostra Fatias: undefined ("indefinido"): o JavaScript não achou nenhum data-fatias.

3. Mudar e apagar pelo JavaScript

O dataset também escreve. Guardar um valor novo cria (ou troca) o atributo no elemento; o delete apaga:

<p id="bolo" data-preco="35" data-categoria="bolo">Bolo de cenoura</p>
<script src="script.js"></script>

const bolo = document.getElementById("bolo");

bolo.dataset.estoque = "0";
bolo.dataset.precoPromo = "30";
console.log(bolo.outerHTML);

delete bolo.dataset.categoria;
console.log(bolo.outerHTML);

O outerHTML ("HTML de fora") mostra a tag do elemento como ela está agora. O console mostra:

<p id="bolo" data-preco="35" data-categoria="bolo" data-estoque="0" data-preco-promo="30">Bolo de cenoura</p>
<p id="bolo" data-preco="35" data-estoque="0" data-preco-promo="30">Bolo de cenoura</p>
  • dataset.estoque = "0" criou o atributo data-estoque="0".
  • dataset.precoPromo virou data-preco-promo: o caminho de volta do camelCase. A maiúscula vira hífen + minúscula.
  • delete bolo.dataset.categoria apagou o data-categoria.

Essas mudanças acontecem na página aberta, não no seu arquivo. No F12, na aba dos elementos, você vê os atributos novos no elemento; o index.html no disco continua igual.

4. Usar no CSS

O CSS escolhe elementos pelo valor de um atributo com colchetes: [data-estoque="0"] quer dizer "todo elemento cujo data-estoque vale 0". Assim, a Ana risca o que acabou sem escrever nenhum JavaScript:

Missão: o brigadeiro acabou. Mude o data-estoque dele para 0 e veja a regra do estilo.css riscar o item sozinha. O bolo continua com 5.

<link rel="stylesheet" href="estilo.css">
<ul>
  <li id="bolo" data-estoque="5">Bolo de cenoura</li>
  <li id="brigadeiro" data-estoque="12">Brigadeiro</li>
</ul>

[data-estoque="0"] {
  text-decoration: line-through;
  color: gray;
}

<link rel="stylesheet" href="estilo.css">
<ul>
  <li id="bolo" data-estoque="5">Bolo de cenoura</li>
  <li id="brigadeiro" data-estoque="0">Brigadeiro</li>
</ul>
[data-estoque="0"]
O seletor: quais elementos a regra pega. Aqui, os que têm data-estoque igual a 0.
text-decoration: line-through
"Decoração do texto: uma linha atravessada": o risco.
color: gray
Cor do texto: cinza.

O CSS tem guia próprio (o futuro Guia CSS). O que importa aqui: o data-* é uma etiqueta que o CSS também sabe ler. Juntando as duas coisas, o JavaScript só precisa trocar o valor (dataset.estoque = "0") e o CSS cuida da aparência. Mas lembre: um risco visual não chega ao leitor de tela; escreva também "esgotado" no texto quando a informação for importante.

5. Quando usar e quando não usar

Use data-* para…Não use data-* para…
dados que o seu script ou CSS usa: preço, categoria, código, estado ("aberto", "esgotado")informação que o visitante precisa ler: ela tem de estar no texto da página
ligar um botão ao que ele controla, quando não existe atributo oficial para issosubstituir um atributo que já existe: data-link no lugar de href, data-descricao no lugar de alt, data-escondido no lugar de hidden
poucos dados, curtosguardar dados grandes ou secretos: qualquer um vê o código da página (Ctrl + U)

Leitores de tela, buscadores e tradutores ignoram os data-*: eles são só para o seu código. Para um valor que as máquinas de fora devem entender (como o preço de um produto para o Google), existem os Dados Estruturados e o elemento <data value="…"> (aula time e data).

Quando dá errado

Attribute “preco” not allowed on element “li” at this point.

O que significa: um atributo inventado, sem o data-. O navegador guarda o atributo, mas o dataset não o enxerga (dataset.preco dá undefined, "indefinido").

Como consertar: data-preco="5".

Attribute “data-” not allowed on element “li” at this point.

O que significa: o data- sozinho, sem nome depois. Como consertar: dê um nome: data-preco.

dataset.Fatias dá undefined (o nome tinha maiúscula)

O que o navegador faz: no HTML, os nomes de atributos não diferenciam maiúsculas de minúsculas, e o navegador guarda tudo em minúsculas. O data-Fatias="12" vira data-fatias="12", e o validador não reclama. Aí, no JavaScript, dataset.Fatias não existe (dá undefined), e o certo é dataset.fatias.

<p id="bolo" data-Fatias="12">Bolo de cenoura</p>
<script src="script.js"></script>

const bolo = document.getElementById("bolo");
console.log(bolo.dataset.Fatias);
console.log(bolo.dataset.fatias);

O console mostra undefined e depois 12. Como consertar: escreva o nome do atributo todo em minúsculas, com hífen entre as palavras. A maiúscula aparece só no JavaScript, e só no lugar do hífen.

No console: ReferenceError: kg is not defined

O que significa: você escreveu bolo.dataset.preco-kg, com hífen, no JavaScript. Ele leu "bolo.dataset.preco menos kg", e não existe nada chamado kg. (ReferenceError: kg is not defined = "erro de referência: kg não está definido".)

Como consertar: bolo.dataset.precoKg, ou bolo.getAttribute("data-preco-kg").

A conta deu 351 em vez de 36

O que significa: o valor de um data-* é sempre texto, e + com texto cola em vez de somar. O validador não tem como ver isso: o HTML está certo.

Como consertar: Number(bolo.dataset.preco) + 1.

Resumo

  • data-* guarda dados seus num elemento: qualquer nome que comece com data-. Inventar um atributo sem o data- é erro no validador.
  • Escreva os nomes em minúsculas, com hífen: data-preco-kg. O navegador põe tudo em minúsculas de qualquer jeito.
  • No JavaScript, el.dataset.preco lê e escreve; o hífen + letra vira maiúscula (precoKg); delete apaga. getAttribute("data-…") lê pelo nome completo.
  • O valor é sempre texto: use Number(…) para fazer conta.
  • No CSS, [data-estoque="0"] escolhe os elementos com esse valor.
  • Leitores de tela e buscadores ignoram os data-*: o que o visitante precisa saber vai no texto.
