HTML Primeiro Arquivo

Até aqui, você mexeu em HTML só nas caixas do guia. Agora é hora de criar uma página no seu computador: uma pasta para o site, um arquivo chamado index.html, algumas linhas de HTML e dois cliques para ver tudo no navegador. É assim que todo site começa, do blog da Ana ao maior portal do mundo. Nesta aula você também aprende as regras para dar nome aos arquivos e o ciclo que vai repetir milhares de vezes: editar, salvar, recarregar.

Você vai aprender
  • Criar a pasta do site, pelo gerenciador de arquivos ou pelo terminal.
  • Por que a primeira página se chama index.html.
  • As regras para nomes de arquivo: minúsculas, sem espaços, sem acentos, e o porquê de cada uma.
  • Escrever e salvar o arquivo no VS Code ou no nano.
  • Mostrar as extensões dos arquivos no Windows e no macOS (e fugir do index.html.txt).
  • Abrir a página no navegador de quatro jeitos e entender o endereço file://.
  • Conferir a página no validador.

Os comandos desta aula rodaram na máquina fictícia da Ana (usuária ana, computador notebook, Linux em português), e as saídas foram copiadas da tela. As telas do Windows, do macOS e do navegador não puderam ser reproduzidas na máquina do guia: elas são descritas, sem prometer o texto exato de cada menu, que muda com a versão e o idioma.

A ideia: a gaveta e a capa

Pense no site como uma gaveta de arquivo. A pasta é a gaveta: tudo o que é do site (páginas, imagens, estilos) fica dentro dela, e nada de fora entra. O index.html é a capa: a primeira folha, a que todo mundo vê quando abre a gaveta. As outras páginas (sobre.html, contato.html) são as folhas de dentro, e a capa tem links para elas.

1. Criar a pasta do site

Escolha um lugar fácil de achar e crie uma pasta chamada site:

  • Windows: no Explorador de Arquivos, entre em Documentos, clique com o botão direito num espaço vazio e escolha a opção de criar uma nova pasta.
  • macOS: no Finder, entre na sua pasta pessoal ou em Documentos e crie uma nova pasta (atalho Cmd + Shift + N).
  • Linux: no gerenciador de arquivos, do mesmo jeito; ou pelo terminal, como a Ana:
$ mkdir site                « cria a pasta "site" dentro da pasta pessoal
$ cd site                   « entra nela
$ ls                        « lista o que tem dentro: nada, por enquanto

Nenhum dos três comandos escreveu nada: o mkdir (make directory, "criar pasta") e o cd (change directory, "mudar de pasta") ficam quietos quando dão certo, e o ls (list) não tinha o que listar. Repare que o prompt mudou para ~/site: a Ana está dentro da pasta nova. (Esses comandos são do terminal, não do HTML; o Guia Bash explica cada um.)

2. O nome: index.html

A primeira página de um site se chama index.html ("índice"), e não é só costume. Quando alguém visita um endereço sem nome de arquivo, como https://exemplo.com/, o servidor procura um arquivo chamado index.html na pasta e entrega esse. Veja com o servidor simples do Python, que você conheceu em Como o Navegador Lê HTML:

$ curl -s http://localhost:8000/        « o endereço termina em "/", sem nome de arquivo
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<p>Olá! Este é o meu primeiro site.</p>
</body>
</html>

A Ana não pediu nenhum arquivo, e o servidor entregou o index.html. No GitHub Pages, onde você vai publicar o site no Nível 3 (Publicar no GitHub Pages), acontece o mesmo. Por isso a capa do site sempre se chama assim.

As regras para nomes de arquivo

Nomes de arquivo de sites viram parte do endereço da página. Por isso, o guia segue três regras:

RegraBomEvitePor quê
Só letras minúsculasindex.htmlIndex.html, INDEX.HTMLNos servidores (quase todos rodam Linux), maiúscula e minúscula são letras diferentes: um link para index.html não acha Index.html.
Sem espaçosbolo-de-cenoura.htmlbolo de cenoura.htmlEspaços não podem aparecer num endereço: viram %20.
Sem acentos nem cedilhapagina-inicial.htmlpágina-inicial.htmlAcentos também viram códigos no endereço (á = %C3%A1) e confundem algumas ferramentas.

Para separar palavras, use o hífen (-). E a extensão é sempre .html. Veja o endereço que um nome "proibido" ganha, calculado pelo Python do mesmo jeito que um navegador faria:

$ python3 -c 'import pathlib; print(pathlib.Path("/home/ana/site/Página Inicial.html").as_uri())'
file:///home/ana/site/P%C3%A1gina%20Inicial.html

O á virou %C3%A1 e o espaço virou %20. Funciona, mas ninguém consegue ditar esse endereço por telefone, e qualquer link escrito "do jeito normal" pode não achar a página. E as maiúsculas: com o arquivo index.html na pasta, o servidor não acha Index.html:

$ curl -s -I http://localhost:8000/Index.html | head -1     « só a primeira linha da resposta
HTTP/1.0 404 File not found
No Windows e no macOS "funciona", no servidor não

O Windows e o macOS, por padrão, não diferenciam maiúsculas de minúsculas nos nomes de arquivo. Um link para Sobre.html abre o sobre.html no seu computador e dá 404 depois de publicado. Seguindo a regra das minúsculas, esse problema nunca acontece.

3. Escrever e salvar

Abra o editor (veja Editores) e crie um arquivo novo. Digite esta página, linha por linha:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<p>Olá! Este é o meu primeiro site.</p>
</body>
</html>

O quadro Resultado mostra como ela vai ficar. Você ainda não precisa entender as linhas da moldura (elas são o assunto da próxima aula, Estrutura de uma Página); só copie com cuidado, porque cada sinal conta.

No VS Code

  1. Abra a pasta site no VS Code (a opção de abrir pasta, no menu Arquivo).
  2. Na barra lateral, use o botão de arquivo novo e digite o nome index.html. O editor já sabe que é HTML pela extensão e liga as cores.
  3. Digite a página. (Se quiser, comece com ! e o Emmet, e ajuste o lang e o title.)
  4. Salve com Ctrl + S (Cmd + S no macOS). A bolinha da aba some.

No nano, pelo terminal

$ nano index.html          « abre o nano com um arquivo novo chamado index.html
  1. O terminal vira um editor: no alto, GNU nano 8.7.1 e o nome do arquivo; embaixo, [ Novo arquivo ] e a lista de atalhos, como ^O Gravar e ^X Sair (o ^ é a tecla Ctrl).
  2. Digite as onze linhas.
  3. Ctrl + O grava. O nano pergunta o nome (Escrever para o arquivo: index.html); confirme com Enter.
  4. Ctrl + X sai e volta ao terminal.

Conferir o arquivo

De qualquer editor, o resultado no disco é o mesmo. Pelo terminal:

$ ls -l                                 « lista com detalhes
total 4
-rw-rw-r-- 1 ana ana 195 out 17 16:03 index.html
$ file index.html
index.html: HTML document, Unicode text, UTF-8 text
195
O tamanho do arquivo, em bytes. São 193 caracteres, mas as duas letras acentuadas (o á de "Olá" e o é) ocupam dois bytes cada em UTF-8.
out 17 16:03
A data e a hora em que o arquivo foi salvo pela última vez. Útil para ver se o "salvar" funcionou.

O nome, com a extensão certa.

O file olhou o conteúdo e reconheceu uma página HTML.

Salvo em UTF-8, a codificação certa (veja Editores).

4. Mostrar as extensões dos arquivos

O Windows e o macOS, por padrão, escondem a extensão de vários tipos de arquivo. Você vê só "index" no lugar de "index.html", e pode não perceber quando o arquivo se chama, na verdade, index.html.txt. Para quem faz sites, vale mostrar as extensões sempre:

  • Windows 11: no Explorador de Arquivos, abra o menu Exibir e ligue a opção de mostrar as extensões de nomes de arquivos (fica no submenu de mostrar itens).
  • Windows 10: no Explorador de Arquivos, guia Exibir, marque a caixa das extensões de nomes de arquivos.
  • macOS: no Finder, abra os ajustes (ou preferências) do Finder, vá à parte avançada e ligue a opção de mostrar todas as extensões de nome de arquivo.
  • Linux: os gerenciadores de arquivos mostram a extensão sempre.

Com as extensões à vista, um arquivo errado se denuncia sozinho:

$ ls
index.html.txt                       « o nome verdadeiro termina em .txt
$ file index.html.txt
index.html.txt: HTML document, Unicode text, UTF-8 text

O conteúdo é HTML (o file percebeu), mas o nome termina em .txt, e o navegador vai mostrar o código como texto. Esse é o tropeço mais comum de quem usa o Bloco de Notas: ele acrescenta .txt se o tipo do arquivo na janela de salvar estiver como documento de texto. Escolha o tipo "todos os arquivos" e digite o nome completo, index.html.

5. Abrir no navegador

Com o arquivo salvo, há quatro jeitos de abri-lo:

JeitoComoQuando usar
Dois cliquesNo gerenciador de arquivos, dê dois cliques no index.html. Ele abre no seu navegador padrão.O mais simples, para o dia a dia
Abrir com…Clique com o botão direito no arquivo e escolha a opção de abrir com outro programa; escolha o navegador.Para testar em outro navegador, que não é o padrão
ArrastarArraste o arquivo para dentro de uma janela do navegador.Quando o navegador já está aberto
Pelo navegadorNo navegador, aperte Ctrl + O (Cmd + O no macOS) e escolha o arquivo.Quando não acha a pasta no gerenciador

Pelo terminal também dá: xdg-open index.html no Linux, open index.html no macOS e start index.html no Prompt de Comando do Windows. Os três abrem o arquivo no navegador padrão e não escrevem nada no terminal.

O endereço file://

Olhe a barra de endereço do navegador. Em vez de https://, ela mostra o caminho do arquivo no seu disco, começando com file://:

SistemaEndereço da página da Ana
Linuxfile:///home/ana/site/index.html
macOSfile:///Users/ana/site/index.html
Windowsfile:///C:/Users/ana/Documents/site/index.html

Esse endereço só funciona no seu computador: ele aponta para o seu disco. Mandar esse link para uma amiga não adianta nada. Para outras pessoas verem o site, ele precisa estar num servidor, com um endereço https:// (aula Publicar no GitHub Pages). E alguns poucos recursos do navegador, por segurança, não funcionam em páginas file://; quando chegar a hora, o guia avisa e usa um servidor local (aula Servidor Local). Para tudo do Nível 1, o file:// basta.

No seu computador, faça o mesmo no seu index.html, salve e recarregue o navegador.

Repare no título da aba: ele não aparece no quadro Resultado, que mostra só o corpo da página. No seu navegador, ele aparece na aba, lá em cima. É uma boa forma de conferir se você está olhando o arquivo certo.

6. O ciclo: editar, salvar, recarregar

A partir de agora, todo trabalho num site segue o mesmo ciclo:

  1. Editar o arquivo no editor.
  2. Salvar (Ctrl + S). Sem isso, o navegador continua vendo a versão antiga.
  3. Recarregar o navegador (F5, ou Ctrl + R; Cmd + R no macOS).
  4. Olhar o resultado e voltar ao passo 1.

Deixe o editor e o navegador lado a lado na tela, cada um ocupando metade. Assim, o ciclo fica tão rápido quanto nas caixas Experimente. (A extensão Live Server, de Editores, faz o passo 3 sozinha.)

7. Conferir no validador

A página apareceu certa? Ótimo, mas lembre: o navegador conserta erros em silêncio. Passe a página pelo validador. Na máquina da Ana, ele está instalado como vnu:

$ vnu --verbose index.html
index.html                           « só o nome: nenhum erro, nenhum aviso

Você não precisa instalar nada para fazer o mesmo: o validador oficial está na internet, em validator.w3.org/nu. Lá, escolha a opção de enviar um arquivo (file upload) e mande o seu index.html, ou cole o código na opção de digitar o texto (text input). As mensagens são as mesmas do vnu, porque é o mesmo programa. A aula Validar o HTML ensina a ler o resultado com calma.

Quando dá errado

O navegador mostra o código, com as tags

O que significa: o arquivo se chama index.html.txt (ou index.txt) e o navegador o abriu como texto simples.

Como consertar: ligue a exibição das extensões (seção 4), renomeie para index.html e abra de novo. Se o sistema perguntar se você quer mesmo mudar a extensão, confirme.

A página abriu em branco 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana
</head>
<body>
<h1>Receitas da Ana</h1>
<p>Olá! Este é o meu primeiro site.</p>
</body>
</html>

O que significa: o resultado ficou vazio porque faltou o </title> na linha 5. Dentro do title, o navegador não procura tags: ele trata tudo como o texto do título até achar o fechamento, que nunca chega. A página inteira virou o título da aba. O validador:

$ vnu index.html
"file:/home/ana/site/index.html":11.8-11.8: error: End of file seen when expecting text or an end tag.
"file:/home/ana/site/index.html":5.1-5.7: error: Unclosed element “title”.

"Fim do arquivo quando eu esperava texto ou uma tag de fechamento" e "elemento title não fechado", apontando a linha 5. Outras causas de página em branco: o arquivo está vazio (não foi salvo) ou todo o conteúdo ficou dentro do <head>.

Como consertar: <title>Receitas da Ana</title>, na mesma linha.

"Arquivo não encontrado" (ou 404)

O que significa: o endereço aponta para um arquivo que não existe com aquele nome exato. Do disco, o navegador mostra uma mensagem de arquivo não encontrado; de um servidor, o erro 404. Causas: um link com maiúscula para um arquivo em minúsculas, um acento ou espaço no nome, ou o arquivo foi movido para outra pasta.

Como consertar: compare, letra por letra, o endereço na barra do navegador com o nome do arquivo na pasta. Siga as regras de nome: minúsculas, hífen no lugar do espaço, sem acentos.

Dois cliques abrem o editor, e não o navegador

O que significa: o sistema associou os arquivos .html ao editor de código (alguns editores fazem isso na instalação).

Como consertar: use o "abrir com…" do botão direito e escolha o navegador; quase sempre há uma opção para usar esse programa sempre. Ou abra pelo navegador, com Ctrl + O.

Mudei o arquivo e a página continua igual

O que significa: o arquivo não foi salvo, ou você está editando um arquivo e vendo outro (por exemplo, uma cópia em Downloads).

Como consertar: salve, recarregue e confira o caminho na barra de endereço. No terminal, o ls -l mostra a hora do último salvamento.

Resumo

  • Todo site mora numa pasta. A primeira página se chama index.html: é ela que o servidor entrega quando o endereço termina em /.
  • Nomes de arquivo: minúsculas (servidores diferenciam Index.html de index.html), hífen no lugar de espaço (%20), sem acentos (%C3%A1) e extensão .html.
  • Mostre as extensões no Windows e no macOS, para não cair no index.html.txt.
  • Abra a página com dois cliques, arrastando, pelo "abrir com…" ou com Ctrl + O no navegador. O endereço começa com file:// e só funciona no seu computador.
  • O ciclo de trabalho é editar, salvar, recarregar. O título da aba ajuda a conferir que você está vendo o arquivo certo.
  • Valide sempre: vnu index.html ou validator.w3.org/nu.
