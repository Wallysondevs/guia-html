HTML Tipos de input

O <input> é um só elemento, mas o atributo type o transforma em 22 campos diferentes: caixa de texto, calendário, seletor de cor, caixa de marcar, botão… Esta página de consulta mostra todos eles, o que cada um envia para o servidor e que atributos funcionam em cada um. Para aprender com calma, veja as aulas O Elemento input e Tipos de input.

Como usar esta página
  • Todos os exemplos são desenhados pelo seu navegador, no quadro "Resultado". Num celular, num Firefox ou num Chrome, o calendário e o seletor de cor têm outra cara: é normal. O que o HTML garante é o tipo do valor, não o desenho.
  • As mensagens do validador saíram do vnu na máquina da Ana, na pasta ~/ref.
  • Os atributos que valem para todos os campos (name, value, disabled, autofocus, form…) estão em Atributos.

Anatomia

<label for="email">Seu e-mail</label>
<input type="email" id="email" name="email" placeholder="ana@exemplo.com" required>
type="email"
O tipo do campo. Sem type, o campo é text. Um tipo que não existe (type="numero") também vira text, sem aviso do navegador.
id="email"
Liga o campo ao <label for="email">. Clique no rótulo do resultado: o cursor vai para o campo (aula label).
name="email"
O nome com que o valor é enviado (email=ana%40exemplo.com). Sem name, o campo não é enviado.
placeholder, required
Atributos que dependem do tipo: veja a tabela Atributos × tipos.

Os campos de texto

<p><label>Nome: <input type="text" name="nome"></label></p>
<p><label>Buscar receita: <input type="search" name="q"></label></p>
<p><label>E-mail: <input type="email" name="email"></label></p>
<p><label>Site: <input type="url" name="site"></label></p>
<p><label>Telefone: <input type="tel" name="tel"></label></p>
<p><label>Senha: <input type="password" name="senha"></label></p>

No computador, os seis parecem iguais. As diferenças aparecem quando você digita (a senha vira pontos), quando envia (o email e o url são conferidos) e no celular, que mostra um teclado diferente para cada um (veja Teclado do celular).

<p><label>Data e hora: <input type="datetime-local" name="quando" value="2026-10-17T19:30"></label></p>
<p><label>Mês: <input type="month" name="mes" value="2026-10"></label></p>
<p><label>Semana: <input type="week" name="semana" value="2026-W42"></label></p>
<p><label>Cor da cobertura: <input type="color" name="cor" value="#7b3f00"></label></p>
A data aparece de um jeito e é enviada de outro

No código, o value é sempre 2026-10-17 (ano-mês-dia). Na tela, o navegador mostra a data na ordem do idioma dele: num navegador em português, normalmente 17/10/2026. Ao enviar, volta a ser 2026-10-17. Por isso, nunca escreva value="17/10/2026": o validador acusa erro, e o campo fica vazio.

Nem todo navegador tem um seletor pronto para month e week; onde não há, aparece uma caixa de texto comum. Se o resultado acima mostrou uma caixa simples nesses dois, é o seu navegador.

Botões

<form action="/pedido">
  <p><label>Recado: <input type="text" name="recado" value="Parabéns!"></label></p>
  <input type="submit" value="Enviar pedido">
  <input type="reset" value="Limpar">
  <input type="button" value="Não faz nada">
</form>

Mude o recado e clique em "Limpar": ele volta a ser "Parabéns!", o valor inicial. O que acontece quando o formulário é enviado está na aula Enviar.

O que é enviado

Com method="get" (o padrão), os campos vão no endereço, depois do ?, no formato name=valor, separados por &. Se os campos dos exemplos acima estivessem todos num só formulário com action="/pedido", a Ana veria algo assim na barra de endereço depois de enviar:

/pedido?nome=Ana+Souza&email=ana%40exemplo.com&fatias=8&data=2026-10-17&cor=%237b3f00&cobertura=sim&tamanho=m&origem=site
  • Espaço vira +, @ vira %40 e # vira %23 (veja Enviar).
  • Checkbox desmarcada: o nome nem aparece. Com disabled: também não. Com readonly: aparece.
  • Campo sem name: não aparece. É o erro mais comum de quem monta o primeiro formulário.

Atributos × tipos

Cada atributo só vale em alguns tipos. Num tipo errado, o navegador ignora o atributo, e o validador dá erro. Esta tabela segue as listas que o próprio vnu imprime nas mensagens (veja abaixo). ✓ = funciona; · = não vale.

Outros, específicos:

  • autocomplete: todos os tipos de texto, números, datas, color e hidden (no hidden, sem os valores on e off); não vale em checkbox, radio, file nem nos botões.
  • src, alt, width, height: só image.
  • formaction, formmethod, formnovalidate…: só submit e image.
  • capture (abrir a câmera do celular): só file.
  • value: todos, menos file (por segurança, a página não pode escolher um arquivo do seu computador).

O teclado do celular

No celular, o tipo escolhe o teclado. O atributo global inputmode muda o teclado sem mudar o tipo nem a conferência.

CampoTeclado que o celular costuma mostrar
type="email"Letras com @ e . à mão.
type="url"Letras com / e .com.
type="tel"O teclado do telefone: números, * e #.
type="number"Números (com sinal e vírgula, em alguns aparelhos).
type="search"Letras, com a tecla Enter virando "Buscar".
type="text" inputmode="numeric"Só algarismos. Bom para CEP, CPF e códigos, que não são números de fazer conta (um number tiraria o zero do começo).

Quando dá errado: o validador não confere a lógica

A Ana escreveu <input type="number" name="fatias" min="10" max="1">, com o mínimo maior que o máximo. O vnu não deu nenhum erro nessa linha: ele confere se cada valor tem o formato certo, não se a regra faz sentido. No navegador, nenhum número passa na conferência ao enviar. Releia sempre os seus min e max.

Experimente

Experimente: troque o type do campo (por date, color, range, password, checkbox, numero…) e veja o seu navegador desenhar outro campo. Um tipo que não existe vira caixa de texto.

<label for="campo">Meu campo:</label>
<input type="text" id="campo" name="campo">

Missão: o cadastro da lojinha da Ana usa type="text" em tudo. Deixe só o nome como texto e troque o tipo dos outros três campos: e-mail, telefone e data de nascimento (com calendário).

<form action="/cadastro">
  <p><label for="nome">Nome</label> <input type="text" id="nome" name="nome"></p>
  <p><label for="email">E-mail</label> <input type="text" id="email" name="email"></p>
  <p><label for="tel">Telefone</label> <input type="text" id="tel" name="tel"></p>
  <p><label for="nasc">Nascimento</label> <input type="text" id="nasc" name="nasc"></p>
  <p><button type="submit">Cadastrar</button></p>
</form>

Resumo

  • Sem type (ou com um tipo inventado), o campo é text.
  • Texto: text, search, email, url, tel, password. Números e datas: number, range, date, time, datetime-local, month, week, color. Escolha: checkbox, radio, file, hidden. Botões: submit, reset, button, image.
  • Datas são sempre enviadas como 2026-10-17, números com ponto, cores como #rrggbb, não importa como apareçam na tela.
  • Cada atributo vale em alguns tipos; a mensagem do validador lista quais.
  • Sem name, nada é enviado. Checkbox desmarcada e campo disabled também não.
  • CEP, CPF e telefone não são números de conta: type="text" com inputmode="numeric", ou type="tel".
