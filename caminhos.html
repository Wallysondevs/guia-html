HTML Caminhos Relativos e Absolutos

Na aula Links, os arquivos da Ana estavam todos na mesma pasta, e bastava o nome: href="sobre.html". Mas o site cresceu: agora há uma pasta só de receitas, e dentro dela uma de doces. Como uma página dentro de receitas/doces/ aponta para a página inicial, duas pastas acima? E por que um link que funciona no computador da Ana dá "404" depois de publicado? Nesta aula você vai aprender a escrever o caminho de um arquivo para outro, do jeito que funciona em qualquer lugar.

Você vai aprender
  • As partes de um endereço absoluto: https://, o domínio e o caminho.
  • Endereços relativos: o mesmo arquivo dito "a partir de onde eu estou".
  • Descer para uma pasta (receitas/bolo.html) e subir com ../ (../index.html).
  • O caminho que começa com / (a raiz) e por que ele quebra no seu computador e no GitHub Pages.
  • Link para uma pasta (receitas/) e o papel do index.html.
  • Por que Bolo.html e bolo.html são arquivos diferentes no servidor.
  • Como ver a estrutura do site com tree e testar os caminhos com ls e curl.

Os comandos desta aula rodaram na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site. O domínio ana.example é inventado (o final .example é reservado para exemplos), como se o site já estivesse publicado.

A ideia: o endereço completo e "a casa do lado"

Há dois jeitos de dizer onde fica uma casa:

  • O endereço completo: "Rua das Flores, 123, Belo Horizonte, MG". Funciona para qualquer pessoa, em qualquer lugar do mundo.
  • A partir de onde você está: "a casa do lado", "subindo a rua, duas casas". É mais curto, mas só funciona se você souber de onde a pessoa está partindo.

Na web é igual. O endereço completo é o caminho absoluto; o "a partir daqui" é o caminho relativo. E o "aqui" é sempre a pasta da página onde o link está.

Os galhos da árvore. Cada nível de recuo é uma pasta "para dentro". O └── marca o último item de uma pasta.

Há dois arquivos chamados index.html, um na raiz e outro em receitas/. Não tem problema: estão em pastas diferentes, como duas pessoas chamadas Maria em casas diferentes. O caminho é que diz qual é qual.

2. O endereço absoluto

Um endereço absoluto tem tudo: o protocolo, o nome do site e o caminho até o arquivo. Ele leva ao mesmo lugar não importa em que página o link esteja.

https://ana.example/receitas/doces/brigadeiro.html
https://
O protocolo (ou esquema): como conversar com o servidor. https é a conversa segura, criptografada. O :// separa o protocolo do resto.
ana.example
O domínio: o nome do site, o "prédio".
/receitas/doces/
As pastas, separadas por /, da raiz do site para dentro.
brigadeiro.html
O arquivo.

Use endereço absoluto para outros sites. Para as páginas do seu próprio site, ele funciona, mas tem um defeito: se o site mudar de domínio, ou se você quiser testá-lo no seu computador, todos os links continuam apontando para o endereço antigo.

3. Relativo: descer para uma pasta

Na página index.html, da raiz, a Ana quer links para a receita do bolo e para o brigadeiro. O caminho parte da pasta onde está o index.html e entra nas pastas, separadas por /:

<h1>Receitas da Ana</h1>
<ul>
  <li><a href="sobre.html">Quem é a Ana</a></li>
  <li><a href="receitas/bolo.html">Bolo de cenoura</a></li>
  <li><a href="receitas/doces/brigadeiro.html">Brigadeiro</a></li>
</ul>
sobre.html
"O arquivo sobre.html, aqui na minha pasta."
receitas/bolo.html
"Entre na pasta receitas; lá dentro, o bolo.html."
receitas/doces/brigadeiro.html
"Entre em receitas, depois em doces, e pegue o brigadeiro.html." Cada / é "entrar em mais uma pasta".

(O <ul> e o <li> fazem uma lista com marcadores, aula Listas com Marcadores.) Repare que o caminho relativo não tem https:// nem domínio: o navegador junta o caminho com o endereço da página atual. Na página https://ana.example/index.html, o receitas/bolo.html vira https://ana.example/receitas/bolo.html.

4. Relativo: subir com ../

Agora o caminho de volta. A página receitas/bolo.html quer um link para o index.html da raiz. Se ela escrever só index.html, o navegador procura na pasta dela, a receitas/, e acha o outro index.html, o das receitas. Para sair da pasta e subir um nível, existe o ../:

<h1>Bolo de cenoura</h1>
<p><a href="../index.html">Início</a></p>
<p><a href="index.html">Todas as receitas</a></p>
<p><a href="doces/brigadeiro.html">Brigadeiro</a></p>
<img src="../imagens/bolo.jpg" alt="Bolo de cenoura com cobertura de chocolate">
../
Os dois pontos querem dizer "a pasta de cima" (a pasta-mãe). ../index.html = "suba uma pasta e pegue o index.html de lá": o da raiz.
index.html
Sem ../, é o index.html da pasta atual, receitas/: a lista de todas as receitas.
doces/brigadeiro.html
De dentro de receitas/, a pasta doces está logo ali: basta descer uma.
../imagens/bolo.jpg
Imagens usam os mesmos caminhos no src: suba para a raiz e entre em imagens.

E do brigadeiro, dois níveis abaixo da raiz? Um ../ para cada pasta que se sobe:

<p><a href="../../index.html">Início</a></p>
<p><a href="../index.html">Todas as receitas</a></p>
<p><a href="../bolo.html">Bolo de cenoura</a></p>

O terminal entende o ../ do mesmo jeito. Da pasta do brigadeiro, o ls confirma que os três caminhos existem:

$ cd receitas/doces
$ pwd
/home/ana/site/receitas/doces
$ ls ../bolo.html ../../index.html ../../imagens/bolo.jpg
../bolo.html
../../imagens/bolo.jpg
../../index.html

Se o ls encontra o arquivo a partir da pasta da página, o link também encontra. É um bom jeito de conferir um caminho antes de escrevê-lo.

No editor, cada aba com / no nome (receitas/bolo.html) é um arquivo dentro de uma pasta, como no site de verdade. A página 404 do editor lista os arquivos que existem, com os caminhos certos a partir da página onde você está.

5. O / do começo: a raiz do site

Existe um terceiro jeito: começar o caminho com /. Ele quer dizer "a partir da raiz do domínio", não importa a página:

<p><a href="/index.html">Início</a></p>

Em https://ana.example/receitas/doces/brigadeiro.html, o /index.html vira https://ana.example/index.html. Parece prático, porque é igual em todas as páginas. Mas a raiz do domínio nem sempre é a raiz do seu site:

Onde a página está/index.html viraFunciona?
Site no próprio domínio: https://ana.example/…https://ana.example/index.htmlSim
GitHub Pages de um projeto: https://usuario.github.io/receitas-da-ana/…https://usuario.github.io/index.htmlNão: a raiz do domínio não é a pasta do projeto
Arquivo aberto do disco: file:///home/ana/site/…file:///index.htmlNão: é a raiz do disco inteiro
Servidor local: http://localhost:8000/…http://localhost:8000/index.htmlSim, se o servidor rodar na pasta do site

No GitHub Pages, o site de um projeto fica numa subpasta do domínio (aula Publicar no GitHub Pages). Lá, o ../index.html do brigadeiro continua certo (https://usuario.github.io/receitas-da-ana/index.html), e o /index.html cai fora do site. No editor do guia, que também guarda cada caixa numa subpasta, um link que começa com / não abre e o console do quadro avisa que ele "leva para fora dos arquivos desta caixa".

A regra do guia

Para as páginas e imagens do seu site, use sempre caminhos relativos (sobre.html, receitas/bolo.html, ../index.html). Eles funcionam no seu computador, no servidor local, no GitHub Pages e num domínio próprio, sem mudar nada. Endereço absoluto (https://…), só para outros sites.

6. Link para uma pasta e o index.html

Um caminho pode terminar numa pasta, com / no fim: href="receitas/". O servidor, então, entrega o arquivo index.html daquela pasta. É por isso que a página inicial de quase todo site se chama index.html ("índice"): ela é a página da pasta.

Com o servidor local do Python (aula Servidor Local) rodando em ~/site, o curl busca o endereço como um navegador faria:

$ python3 -m http.server > /dev/null 2>&1 &
[1] 3
$ sleep 1                                 « dá tempo para o servidor ligar
$ curl -s http://localhost:8000/receitas/ | grep h1
<h1>receitas/index.html</h1>           « a pasta entregou o index.html dela
$ curl -s http://localhost:8000/imagens/ | grep -i title
<title>Directory listing for /imagens/</title>
$ kill %1

A pasta imagens/ não tem index.html, e o servidor do Python mostrou a lista dos arquivos dela (directory listing). Outros servidores, como o GitHub Pages, respondem 404. E abrindo direto do disco, sem servidor, o navegador mostra a lista de arquivos da pasta em vez da página. Por isso, no seu site, prefira href="receitas/index.html", que funciona em todo lugar, ou garanta que toda pasta linkada tenha um index.html.

7. Maiúsculas, acentos e espaços

No Windows e no macOS, Bolo.html e bolo.html são o mesmo arquivo. No Linux, e nos servidores que publicam a maioria dos sites (inclusive o GitHub Pages), são dois nomes diferentes:

$ ls receitas/Bolo.html
ls: não foi possível acessar 'receitas/Bolo.html': Arquivo ou diretório inexistente
$ python3 -m http.server > /dev/null 2>&1 &
[1] 4
$ sleep 1
$ curl -sI http://localhost:8000/receitas/bolo.html | head -1
HTTP/1.0 200 OK
$ curl -sI http://localhost:8000/receitas/Bolo.html | head -1
HTTP/1.0 404 File not found
$ kill %1
curl -sI
O -I pede só o cabeçalho da resposta, sem a página; o -s esconde a barra de progresso.
HTTP/1.0 200 OK
O código 200 quer dizer "achei, aqui está".
404 File not found
O famoso 404: "arquivo não encontrado". Uma letra maiúscula bastou.

Esse é o link que "funciona no meu computador e quebra no site". O validador não ajuda: ele não sabe que arquivos existem. A solução é um costume: nomes de arquivos e pastas em minúsculas, sem acentos e sem espaços, com hífen entre as palavras (pao-de-queijo.html). Acentos até funcionam, mas viram códigos no endereço (p%C3%A3o.html); espaços dão erro no validador (aula Links). Mais sobre nomes em Organizar os Arquivos de um Site.

Quando dá errado

O link de dentro da pasta leva para o lugar errado

O que acontece: em receitas/bolo.html, o link href="index.html" abre a lista de receitas, e não a página inicial. Se a pasta não tiver index.html, dá 404. O mesmo com href="sobre.html": o navegador procura receitas/sobre.html.

O que o validador diz: nada; o caminho é válido, só aponta para outro lugar.

Como consertar: parta sempre da pasta da página onde o link está: ../index.html, ../sobre.html. Na dúvida, entre na pasta pelo terminal e teste com ls.

Funciona no computador, quebra no servidor

O que acontece: o arquivo se chama bolo.html e o link diz Bolo.html (ou o contrário). No Windows ou no macOS, abre; publicado, dá 404 File not found.

Como consertar: o href idêntico ao nome do arquivo, letra por letra. Melhor ainda: só minúsculas nos nomes.

Um caminho do seu disco: Illegal character after “c:”

A Ana arrastou o arquivo para o editor de código e ele colou o caminho do Windows no href. Numa página com <a href="C:\Users\Ana\site\sobre.html"> na linha 8:

$ vnu disco.html
"file:/home/ana/testes/disco.html":8.4-8.42: error: Bad value “C:\Users\Ana\site\sobre.html” for attribute “href” on element “a”: Illegal character after “c:”. “\” is not allowed.

O que significa: para o validador, C: parece o começo de um endereço (como https:), e a barra invertida não é permitida depois dele. Já um href="file:///home/ana/site/sobre.html" passa no validador, porque é um endereço bem escrito. Mas os dois têm o mesmo defeito: só existem no computador da Ana. Para qualquer outra pessoa, o link não leva a nada.

Como consertar: caminho relativo: sobre.html.

O / no começo: funciona no servidor local, quebra no disco e no GitHub Pages

O que acontece: com href="/sobre.html", o site funciona com python3 -m http.server rodando na pasta do site. Aberto com dois cliques (file://), o link procura sobre.html na raiz do disco. Publicado como projeto no GitHub Pages, procura na raiz do domínio, fora da pasta do projeto. No editor do guia, o console avisa que o link sai da caixa.

Como consertar: tire a barra do começo e escreva o caminho a partir da página: sobre.html ou ../sobre.html.

../ demais

O que acontece: num site publicado, subir além da raiz não dá erro: o navegador para na raiz do domínio. Em https://ana.example/index.html, o ../../index.html vira https://ana.example/index.html, e o erro passa despercebido. Mas no disco (file://), cada ../ sobe mesmo uma pasta, para fora do site, e o link quebra. E no GitHub Pages de projeto, o ../ a mais sai da pasta do projeto.

Como consertar: conte as pastas: um ../ para cada nível acima, nem mais nem menos.

Resumo

  • Absoluto (https://ana.example/receitas/bolo.html): protocolo + domínio + caminho. Leva ao mesmo lugar de qualquer página. Use para outros sites.
  • Relativo: parte da pasta da página onde o link está. bolo.html = mesma pasta; receitas/bolo.html = desce; ../index.html = sobe uma; ../../ = sobe duas. Use para o seu site.
  • O / no começo parte da raiz do domínio: quebra no disco e no GitHub Pages de projeto. Evite.
  • Um caminho terminado em / é uma pasta: o servidor entrega o index.html dela (ou uma lista de arquivos, ou 404).
  • No servidor, Bolo.html ≠ bolo.html (404 File not found). Nomes em minúsculas, sem acentos nem espaços, com hífen.
  • O validador só pega caminhos mal escritos (\, espaço, C:\); um caminho que aponta para o lugar errado, só testando. tree, ls e curl -sI ajudam.
