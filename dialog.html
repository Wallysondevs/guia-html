HTML dialog

"Tem certeza de que quer apagar esta receita?" Essa janelinha que aparece por cima da página, esperando você responder, se chama caixa de diálogo. Durante anos, cada site montava a sua com muito JavaScript e CSS, e muitas eram impossíveis de usar pelo teclado. Hoje o HTML tem um elemento pronto para isso, o <dialog>, e o navegador cuida das partes difíceis: o foco, a tecla Esc, o fundo escurecido.

Você vai aprender
  • O que é o <dialog> e como mostrá-lo com o atributo open.
  • Como fechar a janela sem JavaScript, com <form method="dialog">.
  • A diferença entre uma janela comum e uma janela modal, e como abrir uma modal com showModal(), num script de três linhas.
  • Como saber qual botão a pessoa clicou (returnValue).
  • Os botões commandfor, que abrem e fecham a janela sem nenhum JavaScript nos navegadores atuais.
  • Os erros reais: do validador W3C e do console do navegador.

Os exemplos foram validados com o validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook). As mensagens do console foram conferidas no Chromium. Os quadros "Resultado" e os editores são desenhados pelo seu próprio navegador.

A ideia: o quadro de avisos e o balcão de atendimento

Numa loja, existem dois jeitos de falar com o cliente:

  • O quadro de avisos na parede: ele está ali, você lê se quiser e continua andando pela loja. É a janela comum (não modal).
  • O balcão de atendimento: quando chega a sua vez, você para tudo e só conversa com o atendente até resolver. É a janela modal: enquanto ela está aberta, o resto da página fica bloqueado.

O <dialog> ("diálogo", uma conversa) faz os dois. Quem decide é o jeito de abrir.

1. A primeira janela: open

Um <dialog> começa escondido. O atributo open ("aberto") faz ele aparecer:

<h1>Receitas da Ana</h1>
<p>Bem-vindo ao site!</p>
<dialog open>
  <p>Novidade: receitas de bolo toda sexta-feira.</p>
</dialog>
<p>Esta linha vem depois do dialog no código.</p>
<dialog>
A caixa de diálogo. Dentro vai qualquer conteúdo: textos, títulos, imagens, botões, formulários.
open
Atributo booleano (como o do <details>): escrito na tag, a janela aparece; sem ele, fica escondida. open="false" também mostra a janela.

Repare no resultado: o navegador desenha a janela com uma borda, centralizada na horizontal, e ela fica por cima do texto que vem depois (a última linha do exemplo some atrás dela). É uma janela comum: o resto da página continua funcionando. A borda, o espaçamento e a posição exata mudam um pouco de um navegador para outro, e tudo pode ser trocado com CSS (assunto do futuro Guia CSS).

2. Um botão para fechar: form method="dialog"

Uma janela que não fecha incomoda. O jeito mais simples de fechar não usa JavaScript: um formulário com method="dialog" dentro da janela.

<dialog open>
  <p>Novidade: receitas de bolo toda sexta-feira.</p>
  <form method="dialog">
    <button>Fechar</button>
  </form>
</dialog>
<form method="dialog">
Um formulário (aula Formulários). O method ("método") diz o que fazer quando ele é enviado. Normalmente o formulário manda os dados para um servidor; com o valor dialog, ele não manda nada para lugar nenhum: só fecha a janela em que está.
<button>Fechar</button>
Um botão dentro de um formulário envia o formulário ao ser clicado (aula Botões). Enviar, aqui, é fechar.

Clique em "Fechar" no resultado: a janela some. O navegador tirou o atributo open da tag. (Para ver de novo, clique no botão ↻ da barra do Resultado, que desenha o exemplo outra vez.)

Missão: o aviso de entrega não tem como ser fechado. Acrescente, dentro do <dialog>, um formulário com method="dialog" e um botão "Entendi". Depois clique no botão para testar.

<h1>Lojinha da Ana</h1>
<dialog open>
  <p>Esta semana não haverá entregas na quarta-feira.</p>
</dialog>

<h1>Lojinha da Ana</h1>
<dialog open>
  <p>Esta semana não haverá entregas na quarta-feira.</p>
  <form method="dialog">
    <button>Entendi</button>
  </form>
</dialog>

3. A janela modal: showModal()

O open só serve para a janela já começar aberta, e ela é sempre comum, nunca modal. Para abrir a janela quando a pessoa clica num botão, e como modal, é preciso uma linha de JavaScript: o comando showModal() ("mostrar como modal"). O JavaScript tem aula própria (O Elemento script); aqui ele tem só três linhas.

<h1>Bolo de cenoura</h1>
<button id="apagar">Apagar receita</button>

<dialog id="confirma">
  <p>Apagar a receita do bolo de cenoura?</p>
  <form method="dialog">
    <button value="nao">Cancelar</button>
    <button value="sim">Apagar</button>
  </form>
</dialog>

<script>
  const botao = document.querySelector("#apagar");
  const janela = document.querySelector("#confirma");
  botao.addEventListener("click", () => janela.showModal());
</script>
<button id="apagar">
O botão que abre a janela. O id é o "nome único" que o script usa para achá-lo (aula class e id).
<dialog id="confirma">
A janela, sem open: começa escondida.
<script>
O lugar do JavaScript. Ele fica no fim, depois do botão e da janela, porque o navegador lê a página de cima para baixo: o script só acha o que já foi lido.
document.querySelector("#apagar")
"Procure na página o elemento com id="apagar"". É o mesmo # do CSS. O resultado é guardado no nome botao; a linha de baixo faz o mesmo com a janela.
botao.addEventListener("click", …)
"Quando alguém clicar no botão, faça isto". Event listener = "ouvinte de evento".
() => janela.showModal()
"Isto" é: abrir a janela como modal.

Experimente: clique em "Apagar receita" e repare no que o navegador faz sozinho (a lista vem logo abaixo). Tente clicar no botão de trás com a janela aberta, use o Tab e aperte Esc.

<dialog id="confirma">

  <form method="dialog">

<script>

  const janela = document.querySelector("#confirma");
  botao.addEventListener("click", () => janela.showModal());
</script>

O que o navegador faz sozinho, sem nenhuma linha a mais:

  • Fundo escurecido: a página atrás fica coberta por uma camada (o backdrop, "pano de fundo"). Em quase todos os navegadores ela é um cinza leve; dá para mudar com CSS.
  • Página bloqueada: o botão "Apagar receita" e todo o resto não respondem a cliques, e o Tab só passeia pelos botões da janela.
  • Foco: o foco do teclado vai para dentro da janela, no primeiro botão ("Cancelar"). Quando a janela fecha, ele volta para o botão que a abriu.
  • Tecla Esc: fecha a janela, como "Cancelar".
  • Leitor de tela: anuncia que um diálogo abriu e lê o conteúdo dele.

Qual botão foi clicado? returnValue

Cada botão da janela tem um value. Quando um deles fecha a janela, o valor dele fica guardado em janela.returnValue ("valor de retorno"). Com mais três linhas, o script pode reagir. Experimente: abra a janela e clique em "Apagar"; depois abra de novo e clique em "Cancelar"; depois abra e aperte Esc. Veja o que o console mostra em cada caso. Por fim, troque o showModal() por show() e compare: sem fundo escuro, sem Esc, e o botão de trás continua clicável.

<h1>Bolo de cenoura</h1>
<button id="apagar">Apagar receita</button>

<dialog id="confirma">
  <p>Apagar a receita do bolo de cenoura?</p>
  <form method="dialog">
    <button value="nao">Cancelar</button>
    <button value="sim">Apagar</button>
  </form>
</dialog>

<script>
  const botao = document.querySelector("#apagar");
  const janela = document.querySelector("#confirma");
  botao.addEventListener("click", () => janela.showModal());
  janela.addEventListener("close", () => {
    console.log("Resposta: " + janela.returnValue);
  });
</script>
janela.addEventListener("close", …)
"Quando a janela fechar, faça isto". O evento close acontece de qualquer jeito que ela feche: botão, Esc ou script.
console.log("Resposta: " + janela.returnValue)
Escreve no console o value do botão clicado: Resposta: sim ou Resposta: nao.
E o Esc?
Nenhum botão foi clicado, então o returnValue continua com o valor da vez anterior (ou vazio, na primeira vez). Por isso, num caso de verdade, trate qualquer resposta diferente de "sim" como "não".
Dê um título e um foco inicial à janela

Uma janela com um título (<h2>) é mais fácil de entender, principalmente para quem usa leitor de tela. E o atributo autofocus num botão escolhe onde o foco começa: numa confirmação de "apagar", coloque-o no Cancelar, para um Enter distraído não apagar nada.

<dialog id="confirma">
  <h2>Apagar receita?</h2>
  <p>Esta ação não pode ser desfeita.</p>
  <form method="dialog">
    <button value="nao" autofocus>Cancelar</button>
    <button value="sim">Apagar</button>
  </form>
</dialog>

4. Sem JavaScript: commandfor e command

Os navegadores atuais (o Chrome desde 2025; o Firefox e o Safari desde o fim de 2025) entendem dois atributos novos de botão que abrem e fecham a janela sem nenhum script:

<button commandfor="confirma" command="show-modal">Apagar receita</button>

<dialog id="confirma">
  <p>Apagar a receita do bolo de cenoura?</p>
  <button commandfor="confirma" command="close">Cancelar</button>
</dialog>
commandfor="confirma"
"Comando para": o id do elemento que o botão controla.
command="show-modal"
O que fazer com ele: show-modal abre como modal; close fecha. (Existe também request-close, que pede para fechar.)

Se o botão do resultado acima não abrir nada, o seu navegador é anterior a esses atributos; atualize-o. É por isso que muitos sites ainda usam o showModal(), que funciona em todos os navegadores atuais. O validador W3C já conhece os dois atributos.

Quando usar um <dialog>

SituaçãoO que usar
Confirmar uma ação ("Apagar?", "Sair sem salvar?")<dialog> modal (showModal())
Um formulário curto que precisa de atenção total (login rápido, endereço de entrega)<dialog> modal
Um aviso que não impede de usar a página<dialog> comum (open ou show())
Um conteúdo extra que abre e fecha no meio da página, empurrando o resto<details>
Um menu ou uma dica que some ao clicar forapopover (Nível 3)
Não abuse da janela modal

A modal interrompe a pessoa. Abrir uma ao entrar no site ("Assine a newsletter!") irrita e atrapalha quem usa leitor de tela. Use quando a resposta é realmente necessária para continuar.

Quando dá errado

Os erros de <dialog> aparecem em dois lugares: no validador (erros de HTML) e no console do navegador (erros do script). No editor do guia, o console fica embaixo do resultado; no navegador, ele está nas Ferramentas do Desenvolvedor (F12). As mensagens abaixo são as do Chrome; outros navegadores dizem o mesmo com outras palavras.

TypeError: Cannot read properties of null (reading 'showModal')

O que significa: "Não dá para ler propriedades de null (lendo showModal)". O null é o "nada": o querySelector não achou o elemento, e o script tentou abrir o nada. Clicar no botão não faz nada, e o erro aparece no console a cada clique. Três causas comuns:

  • o nome no script está diferente do id: "#confrima" em vez de "#confirma", ou sem o #;
  • o <script> está no <head> ou antes do <dialog>: quando ele roda, a janela ainda não foi lida;
  • o id está repetido ou escrito com maiúsculas diferentes (Confirma).

Como consertar: copie o id do HTML para o script, com o # na frente, e deixe o <script> no fim do <body>.

InvalidStateError: … The dialog is already open as a non-modal dialog, and therefore cannot be opened as a modal dialog.

A mensagem completa no Chrome é: Failed to execute 'showModal' on 'HTMLDialogElement': The dialog is already open as a non-modal dialog, and therefore cannot be opened as a modal dialog.

O que significa: "A janela já está aberta como comum e por isso não pode ser aberta como modal". Acontece quando o <dialog> tem open no HTML (ou já foi aberto com show()) e depois o script chama showModal().

Como consertar: numa janela que vai abrir com showModal(), não escreva open. Chamar showModal() numa janela que já está aberta como modal não dá erro: não acontece nada.

"Usei open e a janela não é modal"

O que acontece: com <dialog open>, a janela aparece, mas o fundo não escurece, a página atrás continua clicável e o Esc não fecha. Não é erro: é a janela comum.

Como consertar: tire o open e abra com showModal() (ou com um botão command="show-modal").

Valor errado em command ou commandfor

Os dois arquivos abaixo têm o esqueleto de sempre (<!DOCTYPE html>, <head> e <body> nas linhas 1 a 7), e o botão está na linha 8. No primeiro, a Ana traduziu o comando: command="abrir". No segundo, o commandfor="janela" aponta para um id que não existe (o da janela é confirma):

$ vnu cmd.html
"file:/home/ana/dialogo/cmd.html":8.1-8.46: error: Bad value “abrir” for attribute “command” on element “button”.
$ vnu cmd2.html
"file:/home/ana/dialogo/cmd2.html":8.1-8.49: error: The value of the “commandfor” attribute of the “button” element must be the ID of an element in the same tree as the “button” with the “commandfor” attribute.

O que significa: o primeiro: "valor ruim abrir para o atributo command": os comandos são palavras fixas, em inglês. O segundo: "o valor de commandfor tem de ser o id de um elemento da mesma página". No navegador, nos dois casos, o botão simplesmente não faz nada.

Como consertar: use show-modal ou close, e copie o id exato da janela.

Um <dialog> dentro de um parágrafo 
$ sed -n 8p dentro.html
<p>Aviso: <dialog open>Oi</dialog></p>
$ vnu dentro.html
"file:/home/ana/dialogo/dentro.html":8.35-8.38: error: No “p” element in scope but a “p” end tag seen.

O que significa: como o <details>, o <dialog> é um bloco e não pode ficar dentro de <p>. O navegador fecha o parágrafo antes da janela, e o </p> do fim fica sem par.

Como consertar: o <dialog> fica fora dos parágrafos; os parágrafos vão dentro dele.

Resumo

  • <dialog> é uma caixa de diálogo que fica por cima da página. Começa escondida; open a mostra como janela comum.
  • <form method="dialog"> com um <button> fecha a janela sem JavaScript. O value do botão clicado fica em returnValue.
  • showModal() abre como modal: fundo escurecido, resto da página bloqueado, foco dentro da janela, Esc fecha. O script fica no fim do <body>.
  • Nos navegadores recentes, <button commandfor="id" command="show-modal"> faz o mesmo sem script.
  • Erros comuns: Cannot read properties of null (reading 'showModal') (script não achou a janela) e InvalidStateError (a janela já estava aberta com open). O <dialog> não vai dentro de <p>.
