HTML Servidor Local

Até aqui, para ver uma página, você dava dois cliques no arquivo e o navegador a abria. Funciona, mas não é assim que o seu site vai chegar aos visitantes: na internet, quem entrega cada página é um servidor. Algumas coisas funcionam de um jeito com o arquivo aberto direto e de outro com o servidor, e a surpresa costuma aparecer no dia de publicar. Nesta aula a Ana liga um servidor de verdade no próprio computador, com um comando só, e vê lado a lado o que muda.

Você vai aprender
  • A diferença entre abrir o arquivo (file://) e abrir pelo servidor (http://).
  • Três coisas que quebram no file://: o caminho que começa com /, o fetch e os módulos de JavaScript.
  • A ligar e desligar o servidor do Python: python3 -m http.server, com porta, --bind e -d.
  • A ler o registro de cada pedido e a conferir uma resposta com curl -I.
  • O erro Address already in use e a extensão Live Server do VS Code.

Os comandos desta aula rodaram na máquina fictícia da Ana (usuária ana, computador notebook, Ubuntu), com o Python 3.14.4, na pasta do site de receitas arrumada na aula Organizar os Arquivos. As páginas foram abertas no Chromium 155.

A ideia: a receita no caderno e a receita no restaurante

A Ana pode ler uma receita direto no caderno dela: abre, folheia, pronto. Num restaurante, o cliente não pega o caderno: ele pede ao garçom, que vai até a cozinha e entrega o prato. Com o garçom no meio, valem as regras do restaurante: o pedido tem de ter o nome certo do prato, a cozinha diz "acabou" quando não tem, e ninguém mexe nas gavetas da casa.

Com dois cliques (file://)

Aberta direto do disco, em file:///home/ana/sites/srv/index.html, a página escreveu:

protocolo: file: origin: file:// seguro: true
fetch falhou: TypeError: Failed to fetch
cor do h1: rgb(0, 0, 0)
modulo rodou: false

E o console do F12 mostrou duas mensagens (aula Ferramentas do Desenvolvedor):

Access to script at 'file:///home/ana/sites/srv/js/modulo.js' from origin 'null' has been blocked by CORS policy: Cross origin requests are only supported for protocol schemes: chrome, chrome-experimental-site-token-provider, chrome-extension, chrome-untrusted, data, http, https, isolated-app.
Access to fetch at 'file:///home/ana/sites/srv/receitas.json' from origin 'null' has been blocked by CORS policy: Cross origin requests are only supported for protocol schemes: chrome, chrome-experimental-site-token-provider, chrome-extension, chrome-untrusted, data, http, https, isolated-app.

Três problemas:

  1. O título ficou preto (rgb(0, 0, 0)). No file://, a "raiz" é a raiz do disco: o navegador procurou file:///css/estilo.css, uma pasta css no começo do disco, que não existe.
  2. O módulo não rodou. A mensagem diz: "o acesso ao script modulo.js a partir da origem null foi bloqueado pela política de CORS: pedidos entre origens só são aceitos para os protocolos chrome, data, http, https…". Em português simples: arquivo aberto do disco não tem "endereço de site" (a origem é null, "nenhuma"), e o Chromium não deixa uma página assim carregar módulos.
  3. O fetch falhou, pelo mesmo motivo. Para o JavaScript, o erro é só TypeError: Failed to fetch ("falha ao buscar"); a explicação está no console.

CORS é a sigla de Cross-Origin Resource Sharing, "compartilhamento de recursos entre origens": as regras que decidem que arquivos uma página pode carregar com JavaScript. Elas existem para proteger você: sem elas, uma página qualquer que você baixasse e abrisse poderia ler outros arquivos do seu disco. Outros navegadores têm regras parecidas para o file://, cada um com seus detalhes.

Pelo servidor (http://)

A mesma pasta, o mesmo arquivo, agora em http://localhost:8000/:

protocolo: http: origin: http://localhost:8000 seguro: true
fetch ok: 2 receitas
cor do h1: rgb(178, 34, 34)
modulo rodou: true

Tudo funcionou: o /css/estilo.css virou http://localhost:8000/css/estilo.css (a raiz do site), o módulo rodou (o console mostrou módulo carregado) e o fetch trouxe as 2 receitas. O seguro: true dos dois lados quer dizer que o navegador trata localhost como um lugar confiável, mesmo sem https: alguns recursos do navegador só funcionam em páginas "seguras", e o localhost conta.

2. Ligar o servidor do Python

O Python, que já vem instalado no Ubuntu e no macOS, traz um servidor simples. Abra o terminal, entre na pasta do site e rode:

$ python3 -m http.server
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
python3
O Python 3. (No Windows, o comando costuma ser python ou py, depois de instalar o Python pelo site python.org ou pela Microsoft Store.)
-m http.server
"Rode o módulo http.server", que vem com o Python.
Serving HTTP on 0.0.0.0 port 8000
"Servindo HTTP em 0.0.0.0, porta 8000". O 0.0.0.0 quer dizer "atendo em todas as redes deste computador". O servidor entrega os arquivos da pasta onde você rodou o comando.
O terminal "travou"
De propósito: o servidor fica ligado, esperando pedidos, até você desligá-lo. Abra outra aba do terminal se precisar dele.

Agora abra o navegador e digite na barra de endereços: http://localhost:8000/. Aparece o index.html da pasta. Não digite o 0.0.0.0 da mensagem: ele descreve onde o servidor atende, e não é um endereço garantido para o navegador; o localhost funciona em todo lugar.

Desligar: Ctrl+C

$ python3 -m http.server
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
^C
Keyboard interrupt received, exiting.

O ^C é o Ctrl+C que a Ana apertou. "Interrupção pelo teclado recebida, saindo." O servidor parou e o terminal voltou a aceitar comandos. Recarregue a página no navegador: agora ele não consegue se conectar, porque não há ninguém atendendo na porta 8000.

As opções mais úteis

$ python3 -m http.server --bind 127.0.0.1 8080
Serving HTTP on 127.0.0.1 port 8080 (http://127.0.0.1:8080/) ...
^C
Keyboard interrupt received, exiting.
OpçãoExemploO que faz
um número no fimpython3 -m http.server 8080Usa outra porta (o padrão é 8000). O endereço vira http://localhost:8080/.
--bind (ou -b)--bind 127.0.0.1Atende só este computador. 127.0.0.1 é o número do localhost.
--directory (ou -d)-d ~/sites/receitasServe outra pasta, sem precisar entrar nela com cd.
--helppython3 -m http.server --helpLista todas as opções (em inglês).
Só para testar, e de preferência com --bind 127.0.0.1

Sem o --bind, o servidor atende em todas as redes (o 0.0.0.0): qualquer aparelho no mesmo Wi-Fi pode abrir os arquivos da pasta, digitando o endereço do seu computador na rede (algo como http://192.168.0.15:8000/). Isso é útil para testar o site no celular, mas num Wi-Fi público é uma porta aberta. E o http.server é feito para testes: a própria documentação do Python avisa que ele não deve ser usado para publicar um site de verdade. Para publicar, veja a aula Publicar.

3. O registro: cada pedido, uma linha

Enquanto está ligado, o servidor escreve no terminal, embaixo da linha "Serving HTTP…", uma linha para cada pedido que recebe. Quando o Chromium abriu a página de teste da seção 1, apareceram estas:

127.0.0.1 - - [17/Oct/2026 16:02:18] "GET / HTTP/1.1" 200 -
127.0.0.1 - - [17/Oct/2026 16:02:18] "GET /css/estilo.css HTTP/1.1" 200 -
127.0.0.1 - - [17/Oct/2026 16:02:18] "GET /js/modulo.js HTTP/1.1" 200 -
127.0.0.1 - - [17/Oct/2026 16:02:18] "GET /receitas.json HTTP/1.1" 200 -
127.0.0.1 - - [17/Oct/2026 16:02:18] code 404, message File not found
127.0.0.1 - - [17/Oct/2026 16:02:18] "GET /favicon.ico HTTP/1.1" 404 -
127.0.0.1
Quem pediu: este mesmo computador (o localhost).
- -
Dois campos de identificação que este servidor não usa.
[17/Oct/2026 16:02:18]
Data e hora do pedido.
"GET /css/estilo.css HTTP/1.1"
O pedido: o método GET ("pegar"), o caminho pedido e a versão do HTTP.
200 / 404
O código de resposta: 200 = "achei, aqui está"; 404 = "não encontrado".

Repare na ordem: primeiro o navegador pediu a página (/); lendo o HTML, achou o CSS, o módulo e o fetch, e pediu cada um. Uma página é uma conversa de vários pedidos, e o registro mostra todos.

E o /favicon.ico? Ninguém pediu no HTML: o navegador procura sozinho o ícone da aba na raiz do site. Como a pasta não tem esse arquivo, deu 404. É inofensivo, e a aula Ícone da Aba mostra como acabar com ele.

O registro é o seu detetive

Uma imagem que não aparece, um CSS que não pega: olhe o registro. Se o caminho pedido tem um 404, compare-o com o nome do arquivo na pasta. Quase sempre é uma maiúscula, um ../ faltando ou uma extensão diferente (aula Organizar os Arquivos).

4. Conferir a resposta com o curl

O curl faz um pedido ao servidor pelo terminal, sem navegador. Com -I, ele mostra só o cabeçalho da resposta, as informações que o servidor manda antes do arquivo. Para usar o mesmo terminal, a Ana ligou o servidor em segundo plano: o & no fim devolve o terminal na hora, e o > ~/servidor.log 2>&1 manda o registro para um arquivo, em vez de misturá-lo com as respostas:

$ python3 -m http.server 8000 > ~/servidor.log 2>&1 &
[1] 4
$ curl -I http://localhost:8000/
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.14.4
Date: Sat, 17 Oct 2026 19:04:59 GMT
Content-type: text/html
Content-Length: 494
Last-Modified: Sat, 17 Oct 2026 18:56:22 GMT
[1] 4
O Bash avisa que o servidor virou o "trabalho 1" em segundo plano (o 4 é o número do processo).
HTTP/1.0 200 OK
A resposta: "200, tudo certo".
Server
Quem respondeu: o servidor simples do Python.
Date
A hora da resposta, em GMT (o horário de Greenwich, 3 horas à frente do horário de Brasília: 19:04 GMT = 16:04 no registro).
Content-type: text/html
O tipo do arquivo: "texto HTML". É assim que o navegador sabe que deve desenhar uma página, e não mostrar o código. O servidor decide o tipo pela extensão (.html, .css, .jpg).
Content-Length: 494
O tamanho do arquivo, em bytes.
Last-Modified
Quando o arquivo foi alterado pela última vez.

Uma pasta sem index.html também responde 200, mas com outro tipo: é a lista de arquivos que o próprio servidor monta (aula Organizar os Arquivos). E o registro guardou os dois pedidos; HEAD é o método "só o cabeçalho", que o curl -I usa:

$ curl -I http://localhost:8000/receitas/
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.14.4
Date: Sat, 17 Oct 2026 19:05:00 GMT
Content-type: text/html; charset=utf-8
Content-Length: 384

$ cat ~/servidor.log
127.0.0.1 - - [17/Oct/2026 16:04:59] "HEAD / HTTP/1.1" 200 -
127.0.0.1 - - [17/Oct/2026 16:05:00] "HEAD /receitas/ HTTP/1.1" 200 -

Para desligar um servidor em segundo plano, use kill %1 (o %1 é o "trabalho número 1", o [1] que apareceu quando ele foi ligado). Fechar o terminal também desliga.

5. "Address already in use"

Só um programa pode atender numa porta. Com o servidor da seção 4 ainda ligado, a Ana tentou ligar outro na mesma porta 8000. O Python mostrou uma mensagem longa, com o caminho do erro por dentro do Python; a parte que importa é a última linha:

$ python3 -m http.server 2>&1 | tail -1
OSError: [Errno 98] Address already in use

"Endereço já em uso": a porta 8000 já tem dono. Ou você esqueceu um servidor ligado em outra aba do terminal (desligue-o com Ctrl+C lá), ou outro programa usa essa porta. A saída mais rápida é escolher outra: python3 -m http.server 8001.

$ kill %1
$ python3 -m http.server --bind 127.0.0.1 8080
Serving HTTP on 127.0.0.1 port 8080 (http://127.0.0.1:8080/) ...
^C
Keyboard interrupt received, exiting.
[1]+  Terminado                  python3 -m http.server 8000 > ~/servidor.log 2>&1

A última linha é o Bash avisando que o servidor da porta 8000, desligado pelo kill %1, terminou.

7. Live Server, no VS Code

Se você usa o VS Code (aula Editores), uma extensão faz o papel do servidor sem terminal: a Live Server (de Ritwick Dey). Ela também recarrega a página sozinha cada vez que você salva o arquivo.

  1. No VS Code, abra a aba de extensões (o ícone de quadradinhos na barra da esquerda, ou Ctrl+Shift+X), procure "Live Server" e instale a do autor Ritwick Dey.
  2. Abra a pasta do site no VS Code (menu Arquivo, abrir pasta), e não só um arquivo: a pasta aberta vira a raiz do servidor.
  3. Clique no botão Go Live que aparece na barra de baixo da janela, à direita, ou clique com o botão direito num arquivo .html e escolha Open with Live Server.
  4. O navegador abre num endereço como http://127.0.0.1:5500/index.html: a porta padrão da extensão é a 5500.
  5. Edite e salve: a página no navegador se atualiza sozinha. Para desligar, clique no mesmo botão da barra de baixo, que passa a mostrar a porta.

Por baixo, é a mesma ideia do python3 -m http.server: um servidor no seu computador entregando os arquivos de uma pasta por http://. A Microsoft tem uma extensão parecida, a Live Preview, que mostra a página dentro do próprio VS Code. Os textos dos botões podem mudar de uma versão para outra (e aparecer em português, se o VS Code estiver em português); o que importa é o endereço com http:// na barra do navegador.

Quando dá errado

Access to fetch at 'file:///…' from origin 'null' has been blocked by CORS policy

O que significa: a página foi aberta com dois cliques (file://) e o JavaScript tentou buscar um arquivo. O Chromium bloqueia. Com type="module", a mensagem começa com Access to script at.

Como consertar: abra a página por um servidor: python3 -m http.server na pasta e http://localhost:8000/ no navegador.

OSError: [Errno 98] Address already in use

O que significa: já existe um programa atendendo naquela porta, quase sempre um servidor esquecido em outra janela do terminal.

Como consertar: desligue o outro (Ctrl+C na janela dele) ou use outra porta: python3 -m http.server 8001.

"O navegador não consegue se conectar a localhost"

O que significa: não há servidor ligado naquela porta. Ou ele foi desligado (você apertou Ctrl+C ou fechou o terminal), ou o endereço tem outra porta (:8000 × :8080 × :5500). Cada navegador mostra essa falha com o seu próprio texto.

Como consertar: confira no terminal se a linha Serving HTTP on … port 8000 está lá e se a porta do endereço é a mesma.

O site abre, mas mostra a lista de arquivos (Directory listing for /)

O que significa: o servidor foi ligado na pasta errada (uma acima, por exemplo) ou a pasta não tem index.html.

Como consertar: desligue, entre na pasta onde está o index.html (cd ~/sites/receitas) e ligue de novo, ou use -d ~/sites/receitas.

O CSS some só no servidor (ou só no file://)

O que significa: um caminho que depende de onde está a raiz. /css/estilo.css funciona no servidor e quebra no file://; um caminho com a pasta do seu computador (C:\…) funciona no file:// e quebra no servidor.

Como consertar: use caminhos relativos (css/estilo.css, ../css/estilo.css) e confira o registro do servidor: o 404 mostra o caminho que o navegador pediu.

Resumo

  • Dois cliques abrem a página em file://, direto do disco. Na internet, quem entrega é um servidor, por http://.
  • No file://, caminhos com / no começo vão para a raiz do disco, e o Chromium bloqueia fetch e módulos (blocked by CORS policy, origin 'null').
  • python3 -m http.server serve a pasta atual em http://localhost:8000/. Porta no fim, --bind 127.0.0.1 para atender só você, -d para outra pasta, Ctrl+C para desligar.
  • O registro mostra cada pedido com o código: 200 achou, 404 não achou. O curl -I mostra o cabeçalho da resposta.
  • Address already in use: a porta já tem um servidor; desligue-o ou use outra porta.
  • No VS Code, a extensão Live Server faz o mesmo com um botão (porta 5500) e recarrega a página ao salvar.
