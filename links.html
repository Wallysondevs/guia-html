HTML Links

O que transforma um monte de páginas soltas num site, e um monte de sites na web, são os links: um clique e você está em outro lugar. O "HT" de HTML vem daí: HyperText, "hipertexto", o texto que leva a outros textos. Nesta aula você vai criar os primeiros links do site da Ana, para outro site e para outra página dela, escolher um bom texto para cada link e reconhecer os erros que fazem um link levar para lugar nenhum.

Você vai aprender
  • O elemento <a> e o atributo href: o que cada parte faz.
  • A diferença entre um link para outro site (https://…) e para outra página do seu (sobre.html).
  • Como escrever o texto do link para todo mundo entender, inclusive quem usa leitor de tela.
  • O que pode ir dentro de um link: texto, imagem, até um título com parágrafo.
  • Como os links funcionam no teclado.
  • Os erros reais do validador: espaço e barra invertida no href, link dentro de link, botão dentro de link e o link sem </a>.

Os resultados desta aula são desenhados pelo seu navegador, logo abaixo de cada código: clique nos links para ver aonde eles levam. As mensagens de erro são do validador W3C (vnu, a mesma ferramenta do validator.w3.org), rodado na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: a placa e o endereço

Pense numa placa de rua: "Centro →". A placa tem duas partes. O texto diz aonde ela leva, para você decidir se quer ir. O endereço é o lugar de verdade, para onde você vai se seguir a placa.

Um link é uma placa na página. O texto aparece na tela, sublinhado; o endereço fica escondido no código, e o navegador o usa quando o leitor clica.

Na placaNo link
"Centro →", o que você lêO texto do link, entre <a> e </a>
O lugar aonde ela levaO endereço, no atributo href

1. O primeiro link

<p>Aprendi a receita no <a href="https://example.com">site de exemplo</a>.</p>
<a
O elemento de link. O a vem de anchor, "âncora": o ponto da página que fica "preso" a outro lugar.
href="…"
O atributo com o endereço. O nome vem de hypertext reference, "referência de hipertexto". Sem ele, o <a> não leva a lugar nenhum.
https://example.com
Um endereço completo de outro site, com o https:// na frente. O example.com é um domínio reservado para exemplos, que existe de verdade e mostra uma página simples.
site de exemplo
O texto do link: a única parte que aparece na tela. É onde o leitor clica.
</a>
Fecha o link. Tudo entre <a …> e </a> é clicável.

Repare no resultado:

  • O texto do link aparece azul e sublinhado. Depois de visitado, muitos navegadores o pintam de roxo. São os estilos padrão do navegador; o CSS muda isso (futuro Guia CSS).
  • O link fica no meio da frase, sem quebrar a linha: o <a> é um elemento em linha (aula Bloco × Em Linha).
  • Ao passar o mouse, a seta vira uma mãozinha, e muitos navegadores mostram o endereço num cantinho de baixo da janela.
No editor do guia

Os quadros de resultado não saem desta página. Ao clicar num link para outro site, o editor escreve um aviso no console do quadro e abre o site numa aba nova do navegador. Links para os arquivos da própria caixa (as abas) abrem dentro do quadro.

Missão: transforme as palavras "Receitas do mundo" num link para https://example.com. Clique no link para testar.

<h1>Links da Ana</h1>
<p>Meu site favorito: Receitas do mundo.</p>

<h1>Links da Ana</h1>
<p>Meu site favorito: <a href="https://example.com">Receitas do mundo</a>.</p>

2. Link para outra página do seu site

Para ir de uma página sua para outra, que está na mesma pasta, basta o nome do arquivo no href, sem https://. O site da Ana tem dois arquivos lado a lado, index.html e sobre.html:

$ ls
index.html  sobre.html
<h1>Receitas da Ana</h1>
<p><a href="sobre.html">Quem é a Ana</a></p>

<h1>Sobre a Ana</h1>
<p>Cozinheira de fim de semana, de Belo Horizonte.</p>
<p><a href="index.html">Voltar ao início</a></p>
href="sobre.html"
Um endereço relativo: "o arquivo sobre.html, na mesma pasta desta página". O navegador completa o resto sozinho, seja no seu computador, seja no site publicado.
href="index.html"
O caminho de volta. Toda página do site deve ter um jeito de voltar ao início; o leitor nem sempre chega pela porta da frente.

Endereços relativos e absolutos, e arquivos em outras pastas (receitas/bolo.html, ../index.html), são o assunto da próxima aula, Caminhos Relativos e Absolutos. O nome no href tem de ser idêntico ao do arquivo: Sobre.html, com maiúscula, é outro arquivo num servidor de verdade.

Missão: esta caixa tem duas abas, como dois arquivos na mesma pasta. Na aba index.html, transforme "Receitas" num link para receitas.html. Na aba receitas.html, transforme "Voltar ao início" num link para index.html. Clique nos dois links no resultado e veja o quadro trocar de página.

<h1>Receitas da Ana</h1>
<p>Receitas</p>

<h1>Todas as receitas</h1>
<p>Bolo de fubá, pão de queijo, brigadeiro.</p>
<p>Voltar ao início</p>

<h1>Receitas da Ana</h1>
<p><a href="receitas.html">Receitas</a></p>

<h1>Todas as receitas</h1>
<p>Bolo de fubá, pão de queijo, brigadeiro.</p>
<p><a href="index.html">Voltar ao início</a></p>

Se você digitar um nome que não existe, como receita.html sem o s, o editor mostra uma página "404: página não encontrada", como um servidor de verdade faria.

3. O texto do link

O texto do link é a placa. Ele precisa dizer aonde o link leva, mesmo lido fora da frase. Compare:

<p>A receita do bolo de fubá está pronta. <a href="bolo.html">Clique aqui</a>.</p>

<p>Está pronta a <a href="bolo.html">receita do bolo de fubá</a>.</p>

Os dois links levam ao mesmo lugar, mas o segundo é muito melhor. Por quê:

  • Quem usa leitor de tela (o programa que lê a página em voz alta para quem não enxerga) costuma pedir a lista de links da página, para pular direto. Uma lista com "Clique aqui, clique aqui, clique aqui" não diz nada. "Receita do bolo de fubá" diz tudo.
  • Quem passa os olhos pela página lê primeiro o que está destacado: os links.
  • Buscadores usam o texto do link para entender do que trata a página de destino (aula HTML e SEO).
  • "Clique" nem combina com celular, onde ninguém clica: toca.
EvitePrefira
Clique aqui, Saiba mais, Leia mais sozinhosO nome do destino: Receita do bolo de fubá
O endereço como texto: https://example.com/receitas/bolo-de-fuba.htmlUm texto curto; o endereço completo só quando o leitor precisa copiá-lo
A frase inteira como linkSó as palavras que dizem o destino
Dois links com o mesmo texto para destinos diferentesTextos diferentes para destinos diferentes

O atributo title

O atributo title mostra uma dica quando o mouse para em cima do link:

<p><a href="bolo.html" title="Rende 12 fatias">Receita do bolo de fubá</a></p>

Passe o mouse e espere um pouco. A dica é só um extra: no celular e no teclado ela não aparece, e muitos leitores de tela não a leem. Nada importante pode ficar só no title; o texto do link precisa se bastar.

4. O que pode ir dentro de um link

Uma imagem

Uma imagem dentro do <a> vira clicável (imagens têm aula própria, Imagens). Como a imagem é o único conteúdo, o texto alternativo, o alt, passa a ser o texto do link: ele deve dizer aonde o link leva, e não só o que a foto mostra (aula Texto Alternativo).

<a href="bolo.html">
  <img src="assets/midia/bolo-400.jpg" alt="Receita do bolo de cenoura" width="200" height="150">
</a>

Um bloco inteiro: o "cartão"

Desde o HTML5, o link pode envolver blocos, como um título e um parágrafo. Isso cria um "cartão" todo clicável, comum em listas de receitas e notícias:

<h1>Receitas da Ana</h1>
<a href="bolo.html">
  <h2>Bolo de fubá</h2>
  <p>Fofinho, com erva-doce. 50 minutos.</p>
</a>

O título e o parágrafo ficaram sublinhados e clicáveis. O leitor de tela lê o cartão inteiro como o texto do link, então mantenha-o curto.

O que não pode

Um link não pode ter dentro dele outra coisa clicável: outro <a>, um botão (<button>), um campo de formulário. Se pudesse, um clique ali seria ambíguo: vale o link de fora ou o de dentro? O validador avisa (veja Quando dá errado).

5. Links e o teclado

Nem todo mundo usa mouse. Muita gente navega só com o teclado, por escolha ou por necessidade. Os links já vêm prontos para isso:

  • A tecla Tab pula de link em link, na ordem do código; Shift+Tab volta.
  • O link escolhido ganha um contorno (o "foco") para você ver onde está.
  • Enter abre o link.

Isso só funciona com <a href="…"> de verdade. Um <a> sem href é válido (ele serve de "lugar reservado" para um link que ainda não existe), mas não é clicável e o Tab o pula. Mais sobre o teclado em Teclado e Foco.

Experimente: clique dentro do resultado e aperte Tab algumas vezes. Quais itens recebem o contorno? O "Pão de queijo" não tem href: ponha um (href="pao.html") e teste de novo.

<p><a href="bolo.html">Bolo de fubá</a></p>
<p><a>Pão de queijo</a></p>
<p><a href="brigadeiro.html">Brigadeiro</a></p>
Link ou botão?

Use <a href> quando o clique leva a outro lugar (outra página, outro site, outro ponto da página). Use <button> quando o clique faz alguma coisa ali mesmo (enviar um formulário, abrir um menu). Um link com href="#" fingindo de botão confunde o teclado e o leitor de tela (aula Botões).

Quando dá errado

Esqueceu o https://: o link vai para dentro do seu site 
<p><a href="www.example.com">Site de exemplo</a></p>

O que o navegador faz: sem o https://, o endereço é lido como o nome de um arquivo na pasta atual, um arquivo chamado www.example.com. Num site publicado, o link vai para algo como https://site-da-ana.example/www.example.com e dá erro 404. Clique no resultado: o quadro mostra uma página de erro 404. Não é a página do editor: como o nome termina em .com, e não em .html, o editor deixa o pedido seguir até o servidor que hospeda o guia, e quem responde "não encontrado" é ele, como aconteceria no site da Ana. O botão ↻ da barra do quadro volta ao exemplo.

O que o validador diz: nada. Para ele, www.example.com é um nome de arquivo tão válido quanto sobre.html. Só testando o link você descobre.

Como consertar: endereço de outro site sempre começa com https:// (ou http://, nos sites antigos).

Espaço no endereço: Illegal character in path segment 
$ vnu espaco.html
"file:/home/ana/site/espaco.html":8.4-8.32: error: Bad value “minha receita.html” for attribute “href” on element “a”: Illegal character in path segment. Space is not allowed.

O que significa: "valor inválido minha receita.html para o atributo href do elemento a: caractere ilegal num pedaço do caminho. Espaço não é permitido." O navegador até tenta (troca o espaço por %20), mas o endereço fica frágil.

Como consertar: renomeie o arquivo sem espaços: minha-receita.html. A regra do guia para nomes de arquivo: letras minúsculas, sem acento, palavras separadas por hífen (aula Organizar os Arquivos).

Barra invertida: Backslash ("\") used as path segment delimiter

Quem usa Windows vê caminhos como receitas\bolo.html e copia para o href:

$ vnu barra.html
"file:/home/ana/site/barra.html":8.4-8.32: error: Bad value “receitas\bolo.html” for attribute “href” on element “a”: Backslash ("\") used as path segment delimiter.

O que significa: "barra invertida usada para separar pedaços do caminho". Na web, a separação é sempre a barra normal, /.

Como consertar: receitas/bolo.html.

Esqueceu o </a>: o resto da página vira link 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Links</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<p>Veja o <a href="bolo.html">bolo de fubá.</p>
<p>Novidades toda semana.</p>
</body>
</html>

O que o navegador faz: fecha o link junto com o parágrafo, mas como ele não foi fechado de verdade, abre outro link igual em volta de tudo o que vem depois. O "Novidades toda semana." também fica sublinhado e clicável, levando para o bolo. O que o navegador monta:

<h1>Receitas da Ana</h1>
<p>Veja o <a href="bolo.html">bolo de fubá.</a></p><a href="bolo.html">
<p>Novidades toda semana.</p>
</a>

$ vnu aberto.html
"file:/home/ana/site/aberto.html":9.44-9.47: error: End tag “p” seen, but there were open elements.
"file:/home/ana/site/aberto.html":9.11-9.30: error: Unclosed element “a”.
"file:/home/ana/site/aberto.html":11.1-11.7: error: End tag for  “body” seen, but there were unclosed elements.

O que significa: "tag de fechamento p vista, mas havia elementos abertos" (o a), "elemento a não fechado" (apontando a linha 9, coluna 11, onde ele começa) e, no fim, "a página terminou com elementos abertos".

Como consertar: <a href="bolo.html">bolo de fubá</a>. Feche o link logo depois do texto.

Missão: passe o mouse sobre "Novidades toda semana.": ele virou link sem querer. Feche o link no lugar certo, logo depois de "bolo de fubá", para que só essas palavras sejam clicáveis.

<h1>Receitas da Ana</h1>
<p>Veja o <a href="bolo.html">bolo de fubá.</p>
<p>Novidades toda semana.</p>

<h1>Receitas da Ana</h1>

Link dentro de link: Start tag “a” seen but an element of the same type was already open 
<p><a href="bolo.html">Bolo de fubá, <a href="cobertura.html">com cobertura</a></a></p>

O que o navegador faz: ao ver o segundo <a>, ele fecha o primeiro. Ficam dois links, um ao lado do outro, e o último </a> sobra. Na linha 8 de uma página completa, o validador diz:

$ vnu dentro.html
"file:/home/ana/site/dentro.html":8.38-8.62: error: Start tag “a” seen but an element of the same type was already open.
"file:/home/ana/site/dentro.html":8.80-8.83: error: Stray end tag “a”.

"Tag de abertura a vista, mas um elemento do mesmo tipo já estava aberto" e "tag de fechamento a perdida" (stray, "extraviada": não há link aberto para ela fechar).

Como consertar: dois links separados, cada um com o seu texto: <a href="bolo.html">Bolo de fubá</a>, <a href="cobertura.html">com cobertura</a>.

Botão dentro de link: must not appear as a descendant of the “a” element 
$ grep button botao.html
<p><a href="bolo.html"><button>Ver receita</button></a></p>
$ vnu botao.html
"file:/home/ana/site/botao.html":8.24-8.31: error: The element “button” must not appear as a descendant of the “a” element.

O que significa: "o elemento button não pode aparecer dentro do elemento a". O navegador desenha o botão, mas o que um clique faz não é garantido (o botão e o link disputam o mesmo clique), e o leitor de tela anuncia duas coisas clicáveis, uma dentro da outra.

Como consertar: se leva a outra página, é um link: <a href="bolo.html">Ver receita</a>. A aparência de botão vem do CSS.

Link sem texto: o validador não reclama

O que acontece: com <a href="bolo.html"></a>, ou com uma imagem sem alt dentro do link, não há nada para clicar na tela, e o leitor de tela anuncia só "link", ou lê o endereço letra por letra. O vnu não mostra nenhum erro para o link vazio.

Como consertar: todo link precisa de um texto, ou de uma imagem com alt que diga o destino.

Resumo

  • Um link é <a href="endereço">texto</a>: o a (anchor) é o link, o href (hypertext reference) é o endereço, e o texto é o que aparece e recebe o clique.
  • Outro site: endereço completo, com https://. Outra página sua, na mesma pasta: só o nome do arquivo (sobre.html). Sem o https://, www.example.com vira nome de arquivo, e o validador não avisa.
  • O texto do link diz aonde ele leva, mesmo fora da frase. Nada de "clique aqui". O title é só um extra.
  • Dentro de um link podem ir texto, uma imagem (o alt vira o texto do link) e até blocos. Não podem ir outro link, botões nem campos.
  • Links funcionam com o teclado (Tab e Enter) se tiverem href. Link leva a um lugar; botão faz uma ação.
  • Validador: espaço (Illegal character in path segment) e \ no href; a dentro de a; button dentro de a; Unclosed element “a” quando falta o </a>, e o navegador estica o link pelo resto da página.
