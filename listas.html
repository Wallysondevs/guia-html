HTML Listas com Marcadores

Lista de compras, ingredientes de uma receita, produtos da lojinha, o menu de um site: a internet está cheia de listas. Em HTML, a lista mais comum é a de marcadores, aquela com uma bolinha na frente de cada item. Ela usa só duas tags: <ul> para a lista inteira e <li> para cada item. Nesta aula a Ana monta a lista de ingredientes do bolo de cenoura e descobre o que o navegador faz quando a lista está montada do jeito errado.

Você vai aprender
  • O que são ul e li e como montar uma lista de marcadores.
  • O que o navegador desenha sozinho: a bolinha e o recuo.
  • O que pode ir dentro de um item.
  • Por que o </li> é opcional e por que o guia sempre o escreve.
  • Por que não digitar "•" à mão, e como trocar a bolinha.
  • Os erros reais do validador: li fora da lista, texto ou parágrafo solto dentro do ul e o </ul> esquecido.

Cada exemplo com o quadro Resultado é desenhado pelo seu próprio navegador, na hora. As mensagens do validador são reais: saíram do vnu 26.10.12 (o mesmo do validator.w3.org) na máquina fictícia da Ana, na pasta ~/site. Como usar o validador está em Validar o HTML.

A ideia: a lista presa na geladeira

Pense na lista de compras presa na porta da geladeira. Ela tem duas partes: o papel, que junta tudo, e as linhas, uma para cada coisa que falta comprar. Tanto faz comprar os ovos antes da farinha: a ordem não importa.

Uma lista HTML é igual. O papel é o ul; cada linha é um li.

TagVem do inglêsNa geladeira
<ul>unordered list, "lista não ordenada"o papel, que junta os itens
<li>list item, "item da lista"cada linha do papel

"Não ordenada" quer dizer que a ordem dos itens não muda o sentido. Quando a ordem importa, como nos passos de uma receita, a lista é outra, o ol (aula Listas Numeradas).

1. A primeira lista

Escreva a abertura <ul>, um <li>…</li> para cada item e o fechamento </ul>:

<h2>Ingredientes</h2>
<ul>
  <li>3 cenouras médias</li>
  <li>4 ovos</li>
  <li>1 xícara de óleo</li>
</ul>
<ul>
Abre a lista. Tudo até o </ul> faz parte dela.
<li>3 cenouras médias</li>
Um item. O texto do item fica entre a abertura e o fechamento do li.
os espaços antes de cada <li>
São só para você ler melhor o código (o recuo, ou indentação). O navegador ignora esses espaços (aula Espaços e Quebras de Linha).
</ul>
Fecha a lista. Depois dele, o texto volta a ser texto comum.

No resultado, o navegador fez três coisas que não estão no código:

  1. Desenhou uma bolinha na frente de cada item. Ela se chama marcador (em inglês, bullet, "bala").
  2. Empurrou a lista para a direita, deixando um recuo à esquerda, onde ficam as bolinhas.
  3. Pôs cada item numa linha própria e deixou um espaço acima e abaixo da lista, como faz com um parágrafo.

A bolinha não é uma letra do texto: é um enfeite que o navegador desenha. Se você abrir as Ferramentas do Desenvolvedor (F12, aula Ferramentas do Desenvolvedor) e clicar num item, verá o li com o texto, e nenhuma bolinha digitada.

Experimente: a Ana esqueceu o fermento. Acrescente um quarto item no fim da lista: 1 colher de fermento. Veja a bolinha nova aparecer sozinha.

<h2>Ingredientes</h2>
<ul>
  <li>3 cenouras médias</li>
  <li>4 ovos</li>
  <li>1 xícara de óleo</li>
</ul>

<h2>Ingredientes</h2>
<ul>
  <li>3 cenouras médias</li>
  <li>4 ovos</li>
  <li>1 xícara de óleo</li>
  <li>1 colher de fermento</li>
</ul>

2. A lista numa página completa

Numa página de verdade, a lista fica dentro do <body>, junto dos títulos e parágrafos. Este é o arquivo inteiro da Ana:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Lista de compras</title>
</head>
<body>
<h1>Bolo de cenoura</h1>
<h2>Ingredientes</h2>
<ul>
  <li>3 cenouras médias</li>
  <li>4 ovos</li>
  <li>1 xícara de óleo</li>
  <li>2 xícaras de açúcar</li>
  <li>2 xícaras de farinha de trigo</li>
</ul>
</body>
</html>

$ vnu --verbose compras.html
compras.html                « só o nome do arquivo: nenhum erro

O validador não reclamou de nada. Com --verbose ("detalhado"), ele escreve o nome do arquivo para mostrar que conferiu; sem essa opção, uma página certa não gera nenhuma linha.

Uma regra de família

O ul e o li formam uma dupla com uma regra fixa, chamada modelo de conteúdo (as regras de quem pode ficar dentro de quem):

  • Os filhos diretos de um ul só podem ser li. Nada de texto solto, parágrafo ou título entre um item e outro.
  • Um li só pode morar dentro de uma lista: ul, ol ou menu.

"Filho direto" é o elemento que está logo dentro do outro, sem nenhum no meio (aula Aninhamento). Quando essa regra é quebrada, o navegador desenha alguma coisa mesmo assim, e o validador acusa. Você vai ver os dois em Quando dá errado.

3. O que cabe dentro de um item

Por fora, o li é exigente: só aceita morar numa lista. Por dentro, ele é generoso: aceita texto, destaques, links, imagens e até parágrafos inteiros.

<h2>Na lojinha da Ana</h2>
<ul>
  <li><strong>Caderno</strong>: 96 folhas, capa dura</li>
  <li>Caneta azul <em>(a mais vendida)</em></li>
  <li>
    <p>Estojo grande</p>
    <p>Cabe 30 lápis. Tem duas cores: verde e roxo.</p>
  </li>
</ul>
<strong> e <em> dentro do li
Destaques no meio do texto do item, como em qualquer parágrafo (aula Negrito e Itálico).
<li> com dois <p>
Um item pode ter vários parágrafos. A bolinha aparece uma vez só, na frente do primeiro. Repare que os parágrafos trazem o espaço deles acima e abaixo.

É por isso que os menus de quase todos os sites são listas: cada item tem um link dentro. Fica assim (o nav, "navegação", tem aula própria em nav):

<nav>
  <ul>
    <li><a href="index.html">Início</a></li>
    <li><a href="receitas.html">Receitas</a></li>
    <li><a href="contato.html">Contato</a></li>
  </ul>
</nav>

O link é filho do li, e o li é filho do ul. O contrário, um <a> em volta do <li>, quebra a regra de família.

4. O </li> é opcional

Este código não tem nenhum </li>, e mesmo assim é HTML válido:

<ul>
  <li>3 cenouras médias
  <li>4 ovos
</ul>

$ vnu sem-li.html
$ echo $?
0                           « 0 = nenhum erro (o arquivo completo tem o esqueleto de sempre)

A especificação do HTML diz que o </li> pode ser omitido quando o próximo item começa ou quando a lista termina. O navegador fecha o item sozinho nesses pontos, e a página desenhada fica idêntica à versão com </li>.

Regra do guia: feche sempre o li

Omitir é permitido, mas fechar deixa claro onde cada item termina, principalmente quando o item tem uma lista dentro (aula Listas Dentro de Listas). Todos os exemplos do guia fecham o li. O </ul>, ao contrário, nunca é opcional.

5. Lista de verdade × lista "desenhada"

Dá para fazer algo parecido com uma lista sem usar ul, digitando a bolinha no teclado:

<p>• 3 cenouras médias<br>
• 4 ovos<br>
• 1 xícara de óleo</p>

<ul>
  <li>3 cenouras médias</li>
  <li>4 ovos</li>
  <li>1 xícara de óleo</li>
</ul>

As duas parecem listas, e as duas são válidas. A diferença está no que o computador entende:

Bolinhas digitadas (p + br)ul + li
O que é, para o navegadorum parágrafo com três linhasuma lista com três itens
Leitor de tela (programa que lê a página em voz alta para quem não enxerga)lê tudo como um texto corrido (alguns leem até a palavra "bolinha")avisa que é uma lista com 3 itens e deixa pular de item em item
Texto que não cabe na linhaa continuação volta para baixo da bolinhaa continuação fica alinhada com o texto, depois da bolinha
Trocar o visual de todas as listaseditar item por itemuma regra de CSS para o site inteiro

Qual usar: se o conteúdo é uma lista, use ul (ou ol, se a ordem importa). Escolher a tag pelo significado, e não pela aparência, é a ideia do HTML Semântico, e é o que faz o site funcionar bem para todo mundo (aula Acessibilidade).

6. Trocar a bolinha

Antigamente se trocava a bolinha por um quadradinho com o atributo type no ul. O navegador ainda obedece, mas o atributo é obsoleto (saiu da especificação):

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Lista de compras</title>
</head>
<body>
<ul type="square">
  <li>3 cenouras médias</li>
  <li>4 ovos</li>
</ul>
</body>
</html>

$ vnu quadrado.html
"file:/home/ana/site/quadrado.html":8.1-8.18: info warning: The “type” attribute on the “ul” element is obsolete. Use CSS instead.
8.1-8.18
Linha 8, da coluna 1 à 18: a tag <ul type="square"> inteira.
info warning
"Aviso informativo": não é erro, e o código de saída continua 0. Mas é um recado para mudar.
The “type” attribute on the “ul” element is obsolete. Use CSS instead.
"O atributo type no elemento ul é obsoleto. Use CSS no lugar."

O jeito atual é a propriedade de CSS list-style-type ("tipo de estilo da lista"). Aqui ela vai no atributo style (aula O Atributo style); num site de verdade, ela fica num arquivo CSS (quer aprender mais? futuro Guia CSS):

<ul style="list-style-type: square">
  <li>quadrado: square</li>
</ul>
<ul style="list-style-type: circle">
  <li>círculo vazio: circle</li>
</ul>
<ul style="list-style-type: none">
  <li>sem marcador: none</li>
</ul>

O padrão, quando você não escreve nada, é disc ("disco"), a bolinha cheia. Uma lista com none continua sendo uma lista para o leitor de tela; só a bolinha some. É assim que os menus horizontais dos sites são feitos.

Quando dá errado

Nos erros abaixo o navegador não mostra mensagem nenhuma: ele desenha a página do jeito que consegue. Só o validador conta o que está errado. Todos os arquivos têm as mesmas 7 primeiras linhas do compras.html (do <!DOCTYPE html> ao <body>); o código abaixo começa na linha 8.

error: Element “li” not allowed as child of element “body” in this context.

A Ana esqueceu o <ul> e escreveu os itens direto no body:

<p>Ingredientes:</p>
<li>3 cenouras médias</li>
<li>4 ovos</li>

$ vnu solto.html
"file:/home/ana/site/solto.html":9.1-9.4: error: Element “li” not allowed as child of element “body” in this context. (Suppressing further errors from this subtree.)
"file:/home/ana/site/solto.html":10.1-10.4: error: Element “li” not allowed as child of element “body” in this context. (Suppressing further errors from this subtree.)

O que significa: "o elemento li não é permitido como filho do elemento body neste contexto". Um erro para cada li solto. O final, Suppressing further errors from this subtree, quer dizer "deixando de mostrar outros erros dentro deste pedaço": o validador não olha o que está dentro desse li.

O que o navegador faz: ele não cria nenhum ul. Os dois li ficam soltos no body, e mesmo assim a bolinha aparece, porque todo li é desenhado como item de lista. Compare com a primeira lista da aula: no Chrome, o item solto fica sem o recuo, com a bolinha colada na margem; outros navegadores podem pôr a bolinha para fora da margem, meio escondida. Quem decide o recuo é o ul, e aqui ele não existe. Para o leitor de tela, também não existe lista.

Como consertar: ponha os itens dentro de um <ul>…</ul>.

error: Text not allowed in element “ul” in this context.

A Ana quis dar um título para a lista e escreveu o texto dentro do ul:

<ul>Ingredientes:
  <li>3 cenouras médias</li>
  <li>4 ovos</li>
</ul>

$ vnu texto-ul.html
"file:/home/ana/site/texto-ul.html":8.5-9.2: error: Text not allowed in element “ul” in this context.

O que significa: "texto não é permitido no elemento ul neste contexto". O trecho 8.5-9.2 vai da coluna 5 da linha 8 (logo depois do <ul>) até o começo da linha 9: é o texto solto.

O que o navegador faz: mostra "Ingredientes:" dentro do recuo da lista, alinhado com os itens, mas sem bolinha. Parece um item quebrado.

Como consertar: o título vai antes da lista, num título de verdade (<h2>Ingredientes</h2>) ou num parágrafo.

error: Element “p” not allowed as child of element “ul” in this context.

A mesma ideia, agora com o título num parágrafo, mas ainda dentro do ul:

<ul>
  <p>Ingredientes:</p>
  <li>3 cenouras médias</li>
  <li>4 ovos</li>
</ul>

$ vnu p-no-ul.html
"file:/home/ana/site/p-no-ul.html":9.3-9.5: error: Element “p” not allowed as child of element “ul” in this context. (Suppressing further errors from this subtree.)

O que significa: o p está como filho direto do ul, e ali só cabe li. Um parágrafo dentro de um li pode (seção 3); entre os itens, não.

Como consertar: tire o <p> de dentro do ul e ponha-o antes do <ul>.

error: Unclosed element “ul”.

A Ana esqueceu o </ul>. O parágrafo seguinte foi parar dentro da lista:

<ul>
  <li>3 cenouras médias</li>
  <li>4 ovos</li>
<p>Bata tudo no liquidificador.</p>

$ vnu sem-fechar.html
"file:/home/ana/site/sem-fechar.html":11.1-11.3: error: Element “p” not allowed as child of element “ul” in this context. (Suppressing further errors from this subtree.)
"file:/home/ana/site/sem-fechar.html":12.1-12.7: error: End tag for  “body” seen, but there were unclosed elements.
"file:/home/ana/site/sem-fechar.html":8.1-8.4: error: Unclosed element “ul”.

O que significa: três mensagens para um esquecimento só, lidas de baixo para cima:

  • Unclosed element “ul”, na linha 8: "elemento ul não fechado". É a causa, e a posição aponta onde a lista abriu.
  • End tag for “body” seen, but there were unclosed elements: "vi o </body>, mas ainda havia elementos abertos". (O espaço duplo depois de for está assim mesmo na mensagem.)
  • Element “p” not allowed as child of element “ul”: como a lista nunca fechou, o parágrafo virou filho dela.

O que o navegador faz: o parágrafo aparece com o recuo da lista, alinhado com os itens. O navegador só fecha o ul no fim da página.

Como consertar: escreva o </ul> logo depois do último </li>. Uma lista que não precisa de </ul> não existe.

Uma lista vazia: <ul></ul>

O que acontece: nada. Hoje o HTML aceita um ul sem nenhum item, e o validador não reclama. Isso é comum em páginas que preenchem a lista depois, com JavaScript. Num HTML escrito à mão, porém, uma lista vazia quase sempre é um item esquecido.

Referência rápida

<li>…</li>Um item. Só vive dentro de ul, ol ou menu. O </li> é opcional, mas o guia sempre fecha.
Filhos do ulSó li (e script/template). Sem texto solto, p ou títulos entre os itens.
Dentro do liTexto, strong, a, img, p, outras listas…

list-style-type (CSS)disc (padrão), circle, square, none

Resumo

  • ul (unordered list) é a lista de marcadores, para quando a ordem não importa. Cada item é um li (list item).
  • O navegador desenha sozinho a bolinha (o marcador) e o recuo. Nada disso está no texto.
  • Filhos diretos do ul: só li. Dentro do li: quase tudo (texto, links, parágrafos).
  • O </li> é opcional, mas o guia sempre fecha. O </ul> é obrigatório; esquecê-lo puxa o resto da página para dentro da lista.
  • Use ul em vez de "•" digitado: o leitor de tela anuncia a lista e os itens.
  • type="square" é obsoleto; o visual da bolinha é do CSS (list-style-type).
  • Erros do validador: Element “li” not allowed as child of element “body”, Text not allowed in element “ul”, Element “p” not allowed as child of element “ul” e Unclosed element “ul”.
