Tutorial HTML

Aprenda HTML do zero, como numa escola: cada pedacinho de código é explicado, você vê o resultado de verdade logo embaixo e pratica num editor aqui mesmo na página. Os resultados não são imagens: quem desenha cada exemplo é o seu próprio navegador, na hora. O guia ensina o HTML Living Standard, o "HTML5" de hoje, e todo o código foi conferido com o validador oficial do W3C. Você só precisa de um navegador e de um editor de texto, em qualquer sistema: Windows, macOS, Linux ou até um Chromebook.

Experimente agora

A caixa abaixo é o editor Experimente do guia. Em cima fica o código; embaixo, o resultado, desenhado pelo seu navegador a partir desse código. Mude o código e veja o resultado mudar junto. Nada do que você fizer aqui mexe no seu computador, e você não precisa instalar nada.

Missão: troque o texto Meu primeiro site por Receitas da Ana. Mexa só no texto entre <h1> e </h1>; os sinais < e > ficam como estão.

<h1>Meu primeiro site</h1>
<p>Bolo de cenoura com cobertura de chocolate.</p>

<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com cobertura de chocolate.</p>

O que aconteceu: o navegador leu o seu texto e encontrou duas marcações. O <h1> diz "aqui começa um título principal" e o </h1>, com a barra, diz "aqui ele termina". O <p> e o </p> fazem o mesmo para um parágrafo. As marcações não aparecem no resultado: elas só dizem ao navegador o que cada pedaço de texto é, e ele decide como mostrar (o título sai grande e em negrito). Essas marcações se chamam tags, e é exatamente isso que o HTML é: texto com tags. A aula O que é HTML conta essa história com calma.

Se você apagou um < sem querer, viu a tag aparecer escrita no resultado, como texto comum. O navegador nunca mostra uma mensagem de erro: ele faz o melhor que pode com o que recebeu. Isso é bom (a página sempre abre) e é ruim (o erro passa despercebido). Por isso o guia ensina, desde o começo, a usar o validador, que aponta cada erro com a linha e a coluna (aula Validar o HTML).

Uma lista de compras

Listas aparecem em quase todo site: menus, ingredientes, produtos. Em HTML, a lista com marcadores é o <ul> (de unordered list, "lista não ordenada"), e cada item fica dentro de um <li> (list item, "item da lista"). Você vai aprender listas na aula Listas com Marcadores; por enquanto, basta copiar o padrão.

Missão: a Ana esqueceu o açúcar. Acrescente um terceiro item, Açúcar, depois de Ovos. Copie a linha do <li> dos ovos e troque só o texto.

<h1>Lista de compras</h1>
<ul>
  <li>Farinha</li>
  <li>Ovos</li>
</ul>

<h1>Lista de compras</h1>
<ul>
  <li>Farinha</li>
  <li>Ovos</li>
  <li>Açúcar</li>
</ul>

Repare que você não desenhou nenhuma bolinha: escreveu só "isto é uma lista, e estes são os itens". O navegador pôs os marcadores e o recuo sozinho. Essa é a ideia central do HTML: você diz o que cada coisa é, e não como ela deve parecer. A aparência (cores, fontes, tamanhos) é trabalho de outra linguagem, o CSS (quer aprender mais? futuro Guia CSS).

O que é este guia

O HTML (HyperText Markup Language, "linguagem de marcação de hipertexto") é a linguagem em que as páginas da Web são escritas. Toda página que você já abriu, de um blog pequeno a uma loja enorme, chega ao seu navegador como um arquivo de texto com tags HTML. Ele foi criado por volta de 1990, por Tim Berners-Lee, junto com a própria Web, e hoje é mantido por um grupo das empresas que fazem os navegadores (a história está em Versões do HTML).

Quem aprende HTML consegue:

  • criar páginas com títulos, parágrafos, listas, imagens, tabelas e links para outras páginas;
  • montar formulários de contato, de cadastro e de pesquisa;
  • colocar áudio, vídeo e mapas numa página;
  • fazer páginas que funcionam bem no celular, que pessoas cegas conseguem usar com um leitor de tela e que o Google entende;
  • publicar um site de verdade, de graça, no GitHub Pages;
  • dar o primeiro passo para o CSS (a aparência) e o JavaScript (o comportamento), porque os dois trabalham em cima do HTML.

O guia é para quem nunca fez um site. Ele começa do zero absoluto (o que é uma tag? como o navegador lê um arquivo?) e vai até acessibilidade, SEO, formulários completos, Web Components e a publicação do site. O HTML tem fama de fácil, e é mesmo o melhor lugar para começar. Mas ele tem uma armadilha: o navegador aceita quase tudo e conserta os erros em silêncio, às vezes de um jeito estranho. Por isso as aulas mostram, em todo assunto, o que o navegador fez com o código errado e o que o validador diz sobre ele.

Como as aulas funcionam

Nenhum código aparece "seco". Toda aula segue o mesmo caminho:

  1. A ideia primeiro. Antes do código, você entende o problema que ele resolve, com uma comparação do dia a dia.
  2. Anatomia. Cada parte de uma tag nova é separada e explicada: o nome, os sinais, os atributos e o que vai dentro.
  3. O resultado real. Logo abaixo de cada exemplo aparece um quadro "Resultado", desenhado pelo seu navegador a partir daquele código. Não é uma foto: se o seu navegador desenhar diferente, você vê a diferença.
  4. Experimente. Pelo menos duas caixas por aula para você mudar o código e ver o resultado na hora, muitas com uma missão que confere sozinha se você acertou.
  5. Várias formas de fazer. Quase sempre há mais de um caminho, e uma tabela "qual usar" mostra quando escolher cada um.
  6. Quando dá errado. O código com erro, o que o navegador realmente mostra e a mensagem real do validador W3C, traduzida e explicada.
  7. Exercícios e resumo. Perguntas com correção na hora e uma lista curta do que levar da aula.

Exemplo: a anatomia de uma linha

Veja como as aulas desmontam uma linha de HTML. Primeiro o código, com o resultado embaixo:

<p>Bolo de cenoura com <strong>cobertura de chocolate</strong>.</p>

Agora cada parte:

<p>
A tag de abertura do parágrafo (p de paragraph). Os sinais < e > dizem ao navegador "isto é uma marcação, não é texto para mostrar".
Bolo de cenoura com
O conteúdo: o texto que aparece na página.
<strong>
Abre outra tag, dentro do parágrafo: strong ("forte") marca um trecho importante. O navegador mostra em negrito (aula Negrito e Itálico).
cobertura de chocolate
O conteúdo do strong.
</strong>
A tag de fechamento: a mesma palavra, com uma barra / antes. Aqui termina o trecho importante.
.</p>
O ponto final ainda faz parte do parágrafo; depois dele, o </p> fecha o parágrafo. Repare na ordem: quem abriu por último (strong) fecha primeiro (aula Aninhamento).

O conjunto "tag de abertura + conteúdo + tag de fechamento" se chama elemento. A linha acima tem dois elementos, um dentro do outro: um p com um strong dentro. Elementos e tags têm aula própria: Elementos e Tags.

Exemplo: o terminal e o validador

Além do editor, as aulas mostram o terminal da máquina fictícia do guia: um computador chamado notebook, da usuária ana, com Linux em português. Lá, a Ana guarda as páginas na pasta ~/site e confere cada uma com o validador do W3C (o comando vnu, de Nu Html Checker, o mesmo programa que roda no site validator.w3.org):

$ cat index.html                    « mostra o conteúdo do arquivo
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com cobertura de chocolate.</p>
</body>
</html>
$ vnu --verbose index.html           « confere o arquivo e diz o nome dele se estiver tudo certo
index.html
$ echo $?
0                                    « código de saída 0: nenhum erro

Esse arquivo é uma página completa. As linhas de cima (<!DOCTYPE html>, <html>, <head>…) são a moldura que toda página precisa ter; a aula Estrutura de uma Página explica cada uma. Agora veja o que acontece quando a Ana fecha o título com a tag errada, </h2> em vez de </h1>:

$ vnu index.html
"file:/home/ana/site/index.html":8.20-8.24: error: End tag “h2” seen, but there were open elements.
$ echo $?
1                                    « 1: o validador achou erro

A mensagem sai em inglês: "vi a tag de fechamento h2, mas havia elementos abertos". O 8.20-8.24 é a posição do problema: linha 8, das colunas 20 a 24, exatamente onde está o </h2>. O guia traduz e explica cada mensagem assim. E o navegador? Veja o resultado do código errado:

<h1>Receitas da Ana</h2>
<p>Bolo de cenoura com cobertura de chocolate.</p>

Parece tudo certo. O navegador percebeu o engano e fechou o título sozinho. Dessa vez deu sorte; na aula Como o Navegador Lê HTML você vai ver erros que o navegador "conserta" de um jeito que ninguém queria. É por isso que "no meu navegador está aparecendo certo" não quer dizer que o código está certo.

Como estudar

Fazer sites se aprende fazendo, como andar de bicicleta. Para cada aula, siga estes quatro passos:

  1. Leia com calma. Leia a ideia, a anatomia e o resultado. Não pule a parte "Quando dá errado": quem sabe por que o navegador fez uma coisa estranha conserta o problema em minutos.
  2. Mexa nos exemplos. Em toda caixa Experimente, mude um texto, apague uma tag de propósito e veja o que o navegador faz. Não tem como estragar nada.
  3. Faça as missões. As caixas com Missão conferem sozinhas se você acertou. Tente de verdade antes de abrir a solução; se abrir, digite a solução você mesmo em vez de só olhar.
  4. Repita no seu computador. Crie a pasta do seu site, escreva os arquivos no seu editor e abra no navegador. É assim que se faz um site "de verdade", e algumas aulas (o F12, o servidor local, a publicação) só funcionam ali.
A regra de ouro

Ler não basta: digite cada exemplo. Copiar e colar ensina pouco; digitar faz você reparar em cada <, cada barra e cada aspa. Para escolher onde escrever, veja Editores; para criar o primeiro arquivo e abri-lo no navegador, Criar e Abrir um Arquivo .html. Se ainda não quiser instalar nada, tudo bem: quase todo o Nível 1 pode ser feito só nas caixas Experimente.

O editor do guia

As caixas Experimente não imitam um navegador: o resultado é desenhado pelo seu navegador, num quadro separado do resto da página, a partir do código que está na caixa naquele momento. Algumas caixas têm várias abas, uma para cada arquivo (index.html, estilo.css, sobre.html…), e os links entre elas funcionam dentro do quadro. Quando um exemplo usa um pouco de JavaScript, o que ele escreve aparece num console embaixo do resultado. A aula O Editor do Guia mostra tudo isso com calma.

Versão de referência: HTML Living Standard

O guia segue o HTML Living Standard, a especificação mantida pelo WHATWG e usada por todos os navegadores atuais. Ele não tem número de versão: é atualizado continuamente, e é o que as pessoas chamam de "HTML5". As mensagens de erro foram conferidas com o validador oficial do W3C, o vnu versão 26.10.12, o mesmo do site validator.w3.org, num Linux (Ubuntu 26.04) em português do Brasil. O que o navegador faz com código errado foi conferido num navegador de verdade (Chromium); como todos os navegadores atuais leem HTML com as mesmas regras, o resultado é o mesmo no Chrome, no Firefox, no Edge e no Safari.
