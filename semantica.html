HTML Semântico

Na aula div e span, você viu que o div é uma caixa sem significado. Dá para montar uma página inteira só com ela, e muita gente monta. Mas o HTML tem elementos que dizem o que cada parte da página é: o topo, o menu, o conteúdo principal, uma receita, o rodapé. Usar o elemento que diz o que a coisa é se chama escrever HTML semântico. Nesta aula você vai ver a mesma página da Ana feita dos dois jeitos, descobrir que na tela elas são idênticas e entender quem enxerga a diferença.

Você vai aprender
  • O que quer dizer "semântico" e o que é uma "sopa de div".
  • A mesma página feita com div e com header, nav, main, article, aside e footer.
  • Quem lê a diferença: leitores de tela (com as regiões da página), buscadores, o modo de leitura do navegador e outras pessoas.
  • Que a semântica também vale para o texto: strong, em, time, títulos.
  • Os avisos reais do validador: role desnecessário, título que pula nível e section sem título.

Os arquivos desta aula foram validados com o validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/receitas. Cada elemento novo desta aula tem a sua própria aula logo depois desta, no grupo Semântica do menu.

A ideia: caixas com etiqueta

Volte à mudança de casa. Você pode encher vinte caixas de papelão e não escrever nada nelas. Tudo chega ao destino, mas quem for desempacotar precisa abrir caixa por caixa para descobrir onde estão as panelas. Agora imagine as mesmas vinte caixas com etiquetas: "COZINHA", "QUARTO", "BANHEIRO". O conteúdo é o mesmo, mas qualquer pessoa sabe para onde levar cada uma, até sem abrir.

O div é a caixa sem etiqueta. Os elementos semânticos são as caixas com etiqueta, e a etiqueta é o próprio nome do elemento. A palavra vem do grego sēmantikós, "que tem significado": a semântica é o estudo do significado.

Na mudançaEm HTML
Caixa sem nada escrito<div>
Caixa com um bilhete colado dentro, que só quem abre vê<div class="rodape">: o nome da classe ajuda você e o CSS, mas o navegador não sabe o que "rodape" quer dizer
Caixa com a etiqueta "COZINHA" do lado de fora<footer>: o próprio elemento diz "isto é o rodapé", e todo programa que lê HTML entende

1. A página em "sopa de div"

Esta é a página inicial do site de receitas, feita só com div. Cada parte tem um id ou uma class com um nome que explica o que ela é (aula class e id):

<div id="topo">
  <h1>Receitas da Ana</h1>
  <div class="menu">
    <a href="index.html">Início</a>
    <a href="doces.html">Doces</a>
    <a href="salgados.html">Salgados</a>
  </div>
</div>
<div id="conteudo">
  <div class="receita">
    <h2>Bolo de cenoura</h2>
    <p>Fofinho e fácil, com cobertura de chocolate.</p>
  </div>
</div>
<div class="lateral">
  <h2>Mais vistas</h2>
  <p>Pão de queijo e brigadeiro.</p>
</div>
<div id="rodape">
  <p>© 2026 Ana. Receitas testadas na minha cozinha.</p>
</div>

Para uma pessoa que lê o código com calma, está tudo claro: topo, menu, conteudo, rodape. O problema é que esses nomes estão em português, foram escolhidos pela Ana e poderiam ser qualquer coisa: cabecalho, top, barra1, xyz. Para o navegador, são sete caixas sem significado. Uma página assim, com div dentro de div dentro de div, ganhou o apelido de sopa de div (em inglês, div soup).

2. A mesma página, semântica

Agora a mesma página, trocando cada div pelo elemento que diz o que aquela parte é:

<header>
  <h1>Receitas da Ana</h1>
  <nav>
    <a href="index.html">Início</a>
    <a href="doces.html">Doces</a>
    <a href="salgados.html">Salgados</a>
  </nav>
</header>
<main>
  <article>
    <h2>Bolo de cenoura</h2>
    <p>Fofinho e fácil, com cobertura de chocolate.</p>
  </article>
</main>
<aside>
  <h2>Mais vistas</h2>
  <p>Pão de queijo e brigadeiro.</p>
</aside>
<footer>
  <p>© 2026 Ana. Receitas testadas na minha cozinha.</p>
</footer>

Compare os dois quadros "Resultado": eles são idênticos. Nenhum elemento semântico desta página muda a aparência. Todos são blocos (aula Bloco × Em Linha), sem borda, sem cor e sem margem, exatamente como o div. A diferença não está na tela; está no significado.

header
"Cabeçalho": o topo da página, com o nome do site e, muitas vezes, o menu. Aula header e footer.
nav
De navigation, "navegação": o grupo dos links principais do site. Aula nav.
main
"Principal": o conteúdo principal desta página, aquele que muda de uma página para outra. Só um por página. Aula main.
article
"Artigo": um conteúdo completo, que faz sentido sozinho, como uma receita ou um post. Aula section e article.
aside
"À parte": um conteúdo relacionado, mas que não é o principal, como a caixa "Mais vistas". Aula aside.
footer
"Rodapé": o fim da página, com direitos autorais, contato, links finais. Aula header e footer.

3. Quem enxerga a diferença

Se a tela é a mesma, por que trocar? Porque a página não é lida só por olhos.

Leitores de tela e as regiões da página

Um leitor de tela é o programa que lê a página em voz alta para pessoas cegas ou com baixa visão (aula Leitores de Tela). Ninguém quer ouvir a página inteira do começo, todas as vezes, para chegar à receita. Por isso os leitores de tela oferecem atalhos para pular de região em região: "ir para o menu", "ir para o conteúdo principal", "ir para o rodapé".

Essas regiões se chamam marcos ou pontos de referência (em inglês, landmarks). E quem diz onde elas estão são justamente os elementos semânticos. Cada um tem um papel (em inglês, role) que o navegador repassa ao leitor de tela:

ElementoPapel (role)O leitor de tela entende…
header (o da página)banner"o topo do site"
navnavigation"um grupo de links de navegação"
mainmain"o conteúdo principal começa aqui"
aside (o da página)complementary"um conteúdo complementar"
footer (o da página)contentinfo"informações sobre a página: autoria, direitos"
articlearticle"um conteúdo completo, independente"
divnenhum (genérico)nada: o leitor de tela passa direto

Na sopa de div, essa lista fica vazia: não há região nenhuma para pular. Na versão semântica, a pessoa ouve algo como "navegação" ao chegar no menu e pode ir direto ao "principal". As palavras exatas mudam de um leitor de tela para outro, mas a ideia é a mesma. Os papéis entre aspas (banner, contentinfo) vêm do ARIA, um padrão de acessibilidade com aula própria (ARIA). No F12 (aula Ferramentas do Desenvolvedor), os navegadores têm uma parte de acessibilidade que mostra o papel do elemento selecionado.

Buscadores, modo de leitura e outras pessoas

  • Buscadores (Google, Bing…) usam a estrutura para entender qual parte é o conteúdo de verdade e qual é menu ou rodapé repetido em todas as páginas (aula HTML e SEO).
  • O modo de leitura dos navegadores, aquele botão que mostra só o texto de uma notícia, sem menus nem anúncios, procura o conteúdo principal da página. Elementos como main e article ajudam a achar.
  • Outras pessoas (e você, daqui a seis meses) leem </nav> e sabem na hora o que está terminando. Já um </div> no fim de uma linha não diz qual das sete caixas fechou.

4. Semântica também é para o texto

Os elementos de página são a parte mais visível da semântica, mas a ideia vale para tudo. Cada vez que você escolhe um elemento, a pergunta é a mesma: "o que isto é?", e não "como quero que isto pareça?".

O que éSem significadoCom significadoAula
Um título de seção<p style="font-size: 24px;"><h2>Títulos
Um trecho importante<b> ou <span class="negrito"><strong>Negrito e Itálico
Uma ênfase na fala<i><em>Negrito e Itálico
Uma lista de ingredienteslinhas com <br> e um "-" na frente<ul> e <li>Listas
Uma data17/10/2026 solto<time datetime="2026-10-17">time e data
Uma foto com legenda<div> com img e p<figure> e <figcaption>figure e figcaption

O b e o i não estão proibidos: eles têm usos próprios, explicados na aula de negrito e itálico. O problema é escolher um elemento pela aparência, como você vai ver no Quando dá errado.

E o div, nunca mais?

Não é isso. O div continua sendo o elemento certo quando você precisa de uma caixa só para o CSS e nenhum elemento semântico serve: por exemplo, uma caixa em volta do main e do aside, para colocá-los lado a lado. A regra é: primeiro procure um elemento com significado; se não houver, use o div.

Quando dá errado

A sopa de div passa no validador

Uma surpresa: o validador não reclama da sopa de div. Os dois arquivos desta aula, completos, passam sem nenhuma mensagem:

$ vnu --verbose sopa.html semantico.html
sopa.html                         « só os nomes: nenhum erro, nenhum aviso
semantico.html

O validador confere as regras do HTML: o que pode ficar dentro de quê, quais atributos existem, se as tags fecham. Ele não sabe que o seu <div id="rodape"> é um rodapé. A semântica é responsabilidade de quem escreve.

Como consertar: para cada div, pergunte "o que é isto?". Se a resposta for "o topo", "o menu", "o conteúdo principal", "uma receita", "um quadro à parte" ou "o rodapé", existe um elemento para isso.

info warning: The “navigation” role is unnecessary for element “nav”.

Antes dos elementos semânticos existirem, a acessibilidade da sopa de div era feita com o atributo role: <div role="navigation">. Muita gente ainda escreve o role por costume, junto com o elemento novo:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<header role="banner">
  <h1>Receitas da Ana</h1>
  <nav role="navigation">
    <a href="index.html">Início</a>
  </nav>
</header>
<main role="main">
  <p>Bolo de cenoura.</p>
</main>
<footer role="contentinfo">
  <p>© 2026 Ana.</p>
</footer>
</body>
</html>

"file:/home/ana/receitas/com-role.html":10.3-10.25: info warning: The “navigation” role is unnecessary for element “nav”.

"Aviso informativo". Não é um erro: o vnu termina com código de saída 0, como se estivesse tudo certo. Mas vale a pena ler.

"O papel navigation é desnecessário para o elemento nav": o nav já tem esse papel sozinho. Escrever de novo não ajuda e só polui o código.

Como consertar: apague o role dos elementos semânticos. Ele só faz sentido em casos especiais, vistos na aula ARIA.

Escolher pela aparência: error: The heading “h4” (with computed level 4) follows the heading “h1”…

A Ana queria uma frase de efeito embaixo do nome do site, em letra pequena e em negrito. O h4 tem essa cara, então ela usou um h4 na linha 9:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<h4>As receitas mais gostosas da família</h4>
<p>Bolo de cenoura, pão de queijo e brigadeiro.</p>
</body>
</html>

$ vnu titulo-pequeno.html
"file:/home/ana/receitas/titulo-pequeno.html":9.1-9.4: error: The heading “h4” (with computed level 4) follows the heading “h1” (with computed level 1), skipping 2 heading levels.

"O título h4 (de nível calculado 4) vem depois do título h1 (de nível 1), pulando 2 níveis." Para o validador, a página ficou com um capítulo (h1) e, dentro dele, um "sub-sub-subtítulo", sem os níveis 2 e 3. O leitor de tela também anuncia "título nível 4", e quem usa a lista de títulos para navegar acha que perdeu alguma parte.

Como consertar: a frase não é um título; é um texto. Use <p> (e, se quiser a letra menor, CSS). Escolha o nível do título pela posição na página, nunca pelo tamanho da letra (aula Títulos).

Trocar todo div por section: info warning: Section lacks heading.

Quem descobre a semântica às vezes troca todos os div por section, achando que é "mais semântico". Na linha 10, a caixa da foto virou uma section:

$ vnu tudo-section.html
"file:/home/ana/receitas/tudo-section.html":10.3-10.24: info warning: Section lacks heading. Consider using “h2”-“h6” elements to add identifying headings to all sections, or else use a “div” element instead for any cases where no heading is needed.

"A seção não tem título. Considere usar elementos h2-h6 para dar títulos que identifiquem todas as seções, ou então use um div nos casos em que nenhum título é necessário." O próprio validador manda voltar para o div: uma section é uma parte com título, e não uma caixa qualquer. A aula section e article conta a história toda.

Como consertar: se a caixa existe só para o CSS, ela é um div. Semântico não é "sem div"; é "cada elemento no seu papel".

Resumo

  • HTML semântico é escolher o elemento que diz o que cada parte é, e não como ela parece.
  • Uma página só de div é uma "sopa de div": funciona, mas nenhum programa sabe o que é topo, menu ou rodapé.
  • A troca: topo → header, menu → nav, conteúdo principal → main, receita → article, barra lateral → aside, rodapé → footer.
  • Na tela, nada muda. Quem enxerga a diferença são os leitores de tela (que pulam entre as regiões), os buscadores, o modo de leitura e as pessoas que leem o código.
  • O validador não acusa sopa de div. Ele avisa quando sobra role repetido (info warning), quando um título pula nível (error) e quando uma section não tem título.
  • O div continua valendo para caixas só de CSS: primeiro o elemento com significado; se não houver, o div.
