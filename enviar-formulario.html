HTML Enviar (action, method, GET e POST)

Nas últimas aulas, a ficha de encomenda da Ana ganhou campos, listas, botões e regras. Falta o principal: o que acontece quando a cliente clica em Enviar pedido? O navegador junta as respostas numa mensagem e manda essa mensagem para um endereço, de um de dois jeitos. O endereço é o action; o jeito é o method, GET ou POST. Nesta aula você vai ver uma mensagem dessas chegando de verdade a um servidor, na máquina da Ana, e entender cada pedaço dela.

Você vai aprender
  • O que o navegador faz, passo a passo, quando um formulário é enviado.
  • O papel do name: só os campos com nome vão na mensagem.
  • Para onde a mensagem vai: o atributo action.
  • Como ela vai: method="get" (no endereço) e method="post" (no corpo).
  • O formato dos dados, application/x-www-form-urlencoded: os pares nome=valor, o &, o + e o %C3%A3.
  • Um envio de verdade a um servidor local, com o python3 -m http.server e o curl, e o erro 501 do POST.
  • Quando usar GET e quando usar POST.

Você vai precisar de Formulários e das aulas anteriores deste grupo. O terminal da aula é a máquina fictícia da Ana (usuária ana, computador notebook), com Python e curl; o servidor local é explicado em Servidor Local. O jeito como o navegador monta os dados foi conferido num envio de verdade no Chromium 155, e os erros de escrita, no validador W3C (vnu).

A ideia: cartão-postal ou carta no envelope

Para mandar uma mensagem pelo correio, você precisa de duas coisas: o endereço e o jeito de mandar.

  • Um cartão-postal tem a mensagem escrita do lado de fora, junto do endereço. É rápido, mas o carteiro, o porteiro e quem mais pegar o cartão consegue ler, e cabe pouca coisa. Esse é o GET: os dados vão no endereço.
  • Uma carta vai dentro de um envelope: do lado de fora, só o endereço; a mensagem vai dentro, e pode ser longa. Esse é o POST: os dados vão no corpo da mensagem, separados do endereço.

E a mensagem em si é uma lista de etiquetas com respostas: "nome: Ana Maria", "sabor: cenoura". As etiquetas são os name dos campos.

No correioNo formulário

Cartão-postal ou cartamethod="get" ou method="post"
"nome: Ana Maria"o par nome=Ana+Maria (o name do campo e o valor)

action="obrigado.html"
O endereço para onde a mensagem vai (action = "ação": a página que vai cuidar dos dados). Aqui, é uma página do mesmo site.
method="get"
O jeito (method = "método"): get põe os dados no endereço. Se o method não for escrito, ele é get.
name="nome", name="sabor"
As etiquetas. Cada campo com name vira um par name=valor.

Quando a cliente clica em Enviar pedido, o navegador:

  1. confere as regras de validação (required, pattern…); se alguma falhar, para aqui (aula Validação);
  2. junta os campos que têm name e não estão desligados, na ordem em que aparecem: nome com "Ana Maria", sabor com "cenoura";
  3. codifica cada par para ele poder viajar: nome=Ana+Maria, sabor=cenoura (o espaço virou +; seção 5);
  4. une os pares com &: nome=Ana+Maria&sabor=cenoura;
  5. envia para o action, do jeito do method. Com GET, ele abre o endereço obrigado.html?nome=Ana+Maria&sabor=cenoura: o ? separa o endereço da página dos dados.

O editor do guia não tem servidor, mas ele imita o envio: clique em Enviar pedido no resultado e veja a página "Formulário enviado", com o endereço que o navegador abriria e a tabela dos pares.

3. Para onde: action

O action é um endereço como o href de um link, e segue as mesmas regras de caminhos (aula Caminhos Relativos e Absolutos):

EscritaPara onde vai
action="obrigado.html"uma página na mesma pasta
action="pedidos/novo"um caminho do mesmo site
action="https://padaria.example/pedidos"um endereço completo, que pode ser de outro site
sem actiona própria página em que o formulário está

Quem está do outro lado do action é um programa no servidor (feito em PHP, Python, JavaScript, Java…), que lê os pares, grava a encomenda e responde com uma página. Escrever esse programa não é HTML e fica fora deste guia. Um site estático, como um do GitHub Pages (aula Publicar no GitHub Pages), não tem programa nenhum: ele só entrega arquivos prontos. Para receber formulários num site assim, existem serviços de formulário, que dão um action para você usar.

5. O formato: application/x-www-form-urlencoded

Um endereço não pode ter espaço, e caracteres como & e = já têm função nele. Por isso, antes de enviar, o navegador codifica cada nome e cada valor. Esse formato tem um nome comprido: application/x-www-form-urlencoded, "dados de formulário codificados como numa URL" (URL é o endereço de uma página).

Testamos num envio de verdade no Chromium 155, com o nome "Ana Maria", o sabor "pão de mel" e a observação "sem açúcar & sem leite". O endereço aberto foi:

obrigado.html?nome=Ana+Maria&sabor=p%C3%A3o+de+mel&obs=sem+a%C3%A7%C3%BAcar+%26+sem+leite
No campoNo envioPor quê
espaço+endereço não tem espaço
ã%C3%A3letras fora do inglês viram os bytes do UTF-8, cada um como % e dois algarismos hexadecimais (aula Acentos, UTF-8 e Emoji)
ç, ú%C3%A7, %C3%BAo mesmo
& dentro de um valor%26o & solto separa os pares; dentro de um valor, ele é codificado
letras sem acento, números, -, ., _iguaisjá podem viajar

Quem recebe decodifica tudo de volta: p%C3%A3o+de+mel volta a ser "pão de mel". A Ana pede esse mesmo endereço ao servidor, ainda na mesma sessão do terminal (com -o /dev/null, que joga fora a página devolvida, para mostrar só o registro):

$ curl -s -o /dev/null 'http://localhost:8000/obrigado.html?nome=Ana+Maria&sabor=p%C3%A3o+de+mel&obs=sem+a%C3%A7%C3%BAcar+%26+sem+leite'
127.0.0.1 - - [17/Oct/2026 16:11:18] "GET /obrigado.html?nome=Ana+Maria&sabor=p%C3%A3o+de+mel&obs=sem+a%C3%A7%C3%BAcar+%26+sem+leite HTTP/1.1" 200 -

O nome desse formato importa porque ele é o mesmo no GET e no POST: no GET, os pares vão depois do ?; no POST, vão no corpo, como você vai ver agora.

7. GET ou POST?

Aparecem na barra do navegador, no histórico e nos registros do servidorsimnão
Dá para salvar nos favoritos e mandar o linksim, com as respostasnão
Tamanhopequeno (endereços muito longos são cortados)grande

A pergunta que decide: o envio muda alguma coisa no servidor? Uma busca só lê, então é GET, e ainda ganha um link que dá para compartilhar ("veja estas receitas de bolo": busca.html?q=bolo). Uma encomenda cria um pedido: é POST. Imagine um pedido feito com GET: a cliente recarrega a página, ou o navegador abre o endereço de novo pelo histórico, e a Ana recebe o mesmo pedido duas vezes.

POST não é segredo

O POST tira os dados do endereço, mas não os esconde: qualquer um no caminho entre o navegador e o servidor consegue ler o corpo, como você leu com o curl -v. Quem protege os dados no caminho é o HTTPS (o cadeado do navegador), que embaralha a mensagem toda, endereço e corpo. Formulário com senha ou dados pessoais: POST e HTTPS. (Aula Segurança.)

E para enviar arquivos?

Um campo <input type="file"> (aula Tipos de input) não cabe no formato da seção 5. Para ele, o formulário precisa de method="post" e de outro formato, escolhido com o atributo enctype ("tipo de codificação"): <form action="…" method="post" enctype="multipart/form-data">. Nesse formato, cada campo vai numa "parte" separada da mensagem, e o arquivo vai inteiro.

Quando dá errado

Os arquivos desta seção são páginas completas com o mesmo começo de 7 linhas (<!DOCTYPE html> até <body>, como em Estrutura de uma Página). O código mostrado começa na linha 8.

Um método que não existe 
<form action="obrigado.html" method="put">
  <button type="submit">Enviar</button>
</form>

$ vnu metodo.html
"file:/home/ana/site/metodo.html":8.1-8.42: error: Bad value “put” for attribute “method” on element “form”.

O que significa: "valor ruim, put, para o atributo method". O HTTP tem outros métodos (como o PUT), mas um formulário HTML só conhece get, post e dialog (este último fecha um <dialog>, aula dialog). Maiúsculas não importam: POST e post são iguais.

O que o navegador faz: trata um método que ele não conhece como get. Os dados vão parar no endereço, sem aviso.

Como consertar: method="post" ou method="get".

action vazio 
<form action="" method="post">
  <button type="submit">Enviar</button>
</form>

$ vnu vazio.html
"file:/home/ana/site/vazio.html":8.1-8.30: error: Bad value “” for attribute “action” on element “form”: Must be non-empty.
"file:/home/ana/site/vazio.html":8.1-8.30: info: To set the document’s location as the action for a form, omit the “action” attribute.

O que significa: o erro diz "valor vazio para o action: não pode ser vazio". A segunda linha é uma informação (info), não um erro, e já dá a solução: "para enviar à própria página, omita o atributo action".

Como consertar: apague o action="", ou escreva o endereço de verdade.

Um formulário dentro de outro 
<form action="pedido.html">
  <label for="n">Nome:</label> <input type="text" id="n" name="nome">
  <form action="busca.html">
    <label for="q">Busca:</label> <input type="search" id="q" name="q">
  </form>
  <button type="submit">Enviar</button>
</form>

$ vnu dentro.html
"file:/home/ana/site/dentro.html":10.3-10.28: error: Saw a “form” start tag, but there was already an active “form” element. Nested forms are not allowed. Ignoring the tag.
"file:/home/ana/site/dentro.html":14.1-14.7: error: Stray end tag “form”.

O que significa: o primeiro erro diz "encontrei uma tag form, mas já havia um form ativo. Formulários dentro de formulários não são permitidos. Ignorando a tag". O segundo, "tag de fechamento form perdida": o </form> da linha 12 fechou o formulário de fora, e o da linha 14 sobrou.

O que o navegador faz: o mesmo que o validador descreve: ignora o <form action="busca.html">. O campo de busca vira parte do formulário de pedido, e o botão "Enviar", depois do primeiro </form>, fica fora de qualquer formulário e não envia nada.

Como consertar: formulários lado a lado, nunca um dentro do outro. Se um botão ou campo precisa ficar longe do seu formulário, use o atributo form="id-do-form" (aula Botões).

O servidor responde 501

Você enviou com method="post" para um servidor que só entrega arquivos, como o python3 -m http.server ou um site estático: a resposta é um erro (501 Unsupported method ('POST') no Python, seção 6; outros servidores dão outros códigos, como o 405, "método não permitido"). O HTML está certo; falta um programa que receba os dados.

Como consertar: aponte o action para um endereço que aceite POST (o programa do seu site ou um serviço de formulários). Para testar o HTML sem servidor, use o editor do guia.

A senha no endereço

Um formulário de login sem method é GET. O que a pessoa digitar vai para o endereço, entrar.html?usuario=ana&senha=…, e fica gravado no histórico do navegador e em registros de servidor como os que você viu na seção 4. O validador não acusa nada: o HTML é válido.

Como consertar: method="post" em todo formulário com senha ou dados pessoais, e o site em HTTPS.

O campo some do envio

Um campo sem name (seção 2), desligado com disabled, ou fora do <form> não vai na mensagem. Nenhum desses casos dá erro no validador. Para descobrir, envie e olhe o que chegou: a barra de endereço (num GET), a página "Formulário enviado" do editor do guia, ou a aba Rede do F12 (aula Ferramentas do Desenvolvedor).

Missão final: a busca e a encomenda

Missão: a página tem dois formulários, mas eles estão incompletos:

  • a busca vai para busca.html, por GET (pode deixar sem method), e o campo dela se chama q;
  • a encomenda vai para enviar.php por POST, com os campos nome e sabor.

Teste os dois botões: a busca abre busca.html?q=…; a encomenda mostra a página "Formulário enviado" do editor, com o corpo da mensagem.

<form>
  <label for="q">Buscar receita:</label>
  <input type="search" id="q">
  <button type="submit">Buscar</button>
</form>

<form>
  <p><label for="nome">Nome:</label> <input type="text" id="nome"></p>
  <p><label for="sabor">Sabor:</label>
    <select id="sabor">
      <option value="cenoura">Cenoura</option>
      <option value="chocolate">Chocolate</option>
    </select></p>
  <button type="submit">Enviar pedido</button>
</form>

<h1>Resultado da busca</h1>
<p>Olhe o endereço desta página na barra do quadro.</p>

<form action="busca.html">
  <label for="q">Buscar receita:</label>
  <input type="search" id="q" name="q">
  <button type="submit">Buscar</button>
</form>

<form action="enviar.php" method="post">
  <p><label for="nome">Nome:</label> <input type="text" id="nome" name="nome"></p>
  <p><label for="sabor">Sabor:</label>
    <select id="sabor" name="sabor">
      <option value="cenoura">Cenoura</option>
      <option value="chocolate">Chocolate</option>
    </select></p>
  <button type="submit">Enviar pedido</button>
</form>

Resumo

  • No envio, o navegador valida, junta os campos com name (e não desligados), codifica os pares nome=valor, une com & e manda para o action.
  • action é o endereço; sem ele, a própria página (nunca action=""). method é o jeito: get (padrão) ou post.
  • GET põe os dados no endereço, depois do ?: aparecem no histórico e no registro do servidor (você viu "GET /obrigado.html?nome=Ana+Maria&sabor=cenoura"). Use para buscas e filtros.
  • POST põe os dados no corpo, com Content-Type: application/x-www-form-urlencoded e Content-Length. Use para pedidos, cadastros e senhas, sempre com HTTPS. Um servidor só de arquivos responde 501.
  • No formato x-www-form-urlencoded, espaço vira +, acentos viram %C3%A3 e um & dentro de um valor vira %26.
  • Formulário dentro de formulário e método inventado são erros do validador; campo sem name e senha por GET passam calados.
