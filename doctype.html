HTML O DOCTYPE

Toda página HTML de verdade começa com a mesma linha: <!DOCTYPE html>. Ela é curta, parece um enfeite e muita gente copia sem saber para que serve. Mas ela decide de que jeito o navegador vai desenhar a sua página. Sem ela, o navegador entra num modo antigo, chamado modo quirks, feito para imitar os navegadores dos anos 1990. Nesta aula você vai entender essa linha parte por parte, ver com os próprios olhos a diferença entre os dois modos e conhecer as mensagens do validador quando ela falta ou está errada.

Você vai aprender
  • O que é o DOCTYPE e por que ele não é uma tag como as outras.
  • Onde ele fica (na primeira linha) e como escrevê-lo: <!DOCTYPE html>.
  • A diferença entre o modo padrão e o modo quirks, e como descobrir o modo com document.compatMode.
  • O que muda de verdade no desenho da página quando o DOCTYPE falta.
  • Os DOCTYPEs compridos do HTML 4 e do XHTML, que você ainda vai encontrar em sites antigos.
  • As mensagens reais do validador W3C para cada erro de DOCTYPE.

Os arquivos desta aula foram validados com o validador W3C (vnu, versão 26.10.12) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site/doctype, e abertos no Chromium. O validador tem uma aula própria, Validar o HTML; aqui basta saber que ele lê o arquivo e lista o que está fora das regras do HTML.

A ideia: o aviso na capa do livro de regras

Imagine um juiz de futebol que conhece dois livros de regras: o de hoje e um muito antigo, de quando cada time jogava de um jeito. Antes do jogo, alguém precisa dizer a ele: "hoje vale o livro novo". Se ninguém disser nada, ele fica com o livro antigo, por garantia, para não prejudicar os times que só conhecem as regras velhas.

O navegador é esse juiz. Nos anos 1990, cada navegador desenhava as páginas do seu jeito, com vários defeitos. Milhões de sites foram feitos contando com esses defeitos. Quando os navegadores passaram a seguir as regras oficiais, esses sites antigos iam quebrar. A solução foi esta:

  • página com o aviso <!DOCTYPE html> → o navegador usa as regras de hoje: o modo padrão (em inglês, standards mode ou no-quirks mode);
  • página sem o aviso → o navegador imita os defeitos antigos: o modo quirks. Quirk quer dizer "mania", "esquisitice".

O nome DOCTYPE vem de document type, "tipo de documento". Antigamente ele dizia qual versão do HTML a página usava (veja a seção 4). Hoje ele serve quase só para uma coisa: ligar o modo padrão.

1. Escrever o DOCTYPE

O DOCTYPE vem antes de tudo, na primeira linha do arquivo, antes até do <html>. Esta é a página mínima completa que o guia usa (cada parte dela é explicada em Estrutura de uma Página):

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com cobertura de chocolate.</p>
</body>
</html>

Repare que o DOCTYPE não aparece no resultado. Ele não é conteúdo: é um recado para o navegador. Vamos olhar a linha por partes:

<!
Começo de uma declaração. O ponto de exclamação logo depois do < avisa que isso não é uma tag comum. (Os comentários também começam assim, com <!--; veja Comentários.)
DOCTYPE
A palavra-chave: "tipo de documento". Pode ser escrita em maiúsculas ou minúsculas: DOCTYPE, doctype e até DocType funcionam igual.
html
O nome do tipo: "este documento é HTML". Também tanto faz maiúscula ou minúscula. Depois do DOCTYPE vem um espaço e então o html.
>
Fim da declaração. Não existe </!DOCTYPE>: o DOCTYPE não tem fechamento.

Maiúsculas ou minúsculas?

As duas formas são válidas, e o validador aceita as duas sem reclamar:

$ head -1 certo.html minusculo.html
==> certo.html <==
<!DOCTYPE html>

==> minusculo.html <==
<!doctype html>
$ vnu certo.html minusculo.html; echo "código de saída: $?"
código de saída: 0          « nenhuma mensagem: os dois estão certos

O vnu fica calado quando está tudo certo, e o código de saída 0 quer dizer "sem erros". Este guia escreve <!DOCTYPE html>, em maiúsculas, nos exemplos, que é a forma mais vista em livros e tutoriais. Muitos sites (e as próprias páginas deste guia) usam <!doctype html>. Escolha uma e use sempre a mesma.

Antes do DOCTYPE, só espaço ou comentário

O HTML permite linhas em branco e comentários (<!-- assim -->) antes do DOCTYPE: o validador aceita e o navegador continua no modo padrão. Qualquer outra coisa antes dele, mesmo uma palavra só, estraga tudo (veja Quando dá errado). O mais simples é a regra: o DOCTYPE é a primeira linha.

2. Os dois modos e o document.compatMode

Dá para perguntar ao navegador em que modo ele está. A resposta fica em document.compatMode (compatibility mode, "modo de compatibilidade"), uma informação que o JavaScript consegue ler. O JavaScript tem aula própria (O Elemento script); aqui ele só escreve o modo na tela:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Qual é o modo?</title>
</head>
<body>
<p id="modo"></p>
<script>
  document.getElementById("modo").textContent = "Modo desta página: " + document.compatMode;
</script>
</body>
</html>
<p id="modo"></p>
Um parágrafo vazio, com o nome modo, onde o script vai escrever.

3. O que muda no modo quirks

Quase sempre a página parece igual nos dois modos, e é por isso que o erro passa despercebido. As diferenças aparecem nos detalhes, principalmente no CSS, a linguagem que cuida da aparência (quer aprender mais? futuro Guia CSS; a ligação entre HTML e CSS está em Ligar CSS). Esta página tem dois erros de CSS que um navegador moderno deveria ignorar: a cor sem o # e a largura sem a unidade px:

<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
<style>
  body { font-size: 24px; }
  h1 { color: ff0000; }
  .aviso { width: 200; border: 2px solid; }
</style>
</head>
<body>
<h1>Receitas da Ana</h1>
<p class="aviso">Receita nova toda sexta.</p>
<table><tr><td>Bolo de cenoura</td></tr></table>
</body>
</html>

A Ana abriu esse arquivo no Chromium duas vezes: como está e com <!DOCTYPE html> na primeira linha. O que o navegador calculou (com as ferramentas do desenvolvedor, aula Ferramentas do Desenvolvedor):

O que olharSem DOCTYPE (quirks)Com DOCTYPE (padrão)
Cor do título (color: ff0000)vermelho: o navegador aceitou a cor sem #preto: a regra errada foi ignorada
Largura do aviso (width: 200)200 pixels: aceitou o número sem unidadea largura toda da janela: a regra foi ignorada
Tamanho da letra dentro da tabela16 pixels: a tabela não herdou os 24px da página24 pixels, como o resto da página

Leia a primeira linha com atenção: no modo quirks, o código errado "funciona". Isso parece bom, mas é uma armadilha. A Ana testa no navegador, vê o título vermelho e acha que acertou. Um dia ela acrescenta o DOCTYPE (ou copia o CSS para outra página) e o vermelho some sem explicação. No modo padrão, o erro aparece logo, e você conserta (color: #ff0000; e width: 200px;).

O validador também confere o CSS que está dentro do <style>, e pega os dois erros, com ou sem DOCTYPE. O padrao.html é o mesmo arquivo com o DOCTYPE na linha 1 (por isso os números de linha andam uma casa):

Existem dezenas de outras manias do modo quirks, quase todas ligadas a altura de caixas, tabelas e espaço entre linhas. Você não precisa decorar nenhuma: basta nunca cair nele.

O terceiro modo: "quase padrão"

Existe ainda um modo do meio, o modo quase padrão (almost standards mode, ou limited-quirks mode), ligado por alguns DOCTYPEs antigos (seção 4). Ele segue as regras de hoje, com uma única exceção: o espaço em volta de imagens dentro de células de tabela. O document.compatMode não distingue esse modo: ele responde CSS1Compat.

4. Os DOCTYPEs antigos

Antes do HTML5, o DOCTYPE era comprido e dizia qual versão do HTML a página seguia, com o endereço de um arquivo de regras (um DTD, Document Type Definition). A história das versões está em Versões do HTML. Você ainda vai encontrar estes em sites antigos e em tutoriais velhos:

<!-- HTML 4.01 Strict -->
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN" "http://www.w3.org/TR/html4/strict.dtd">

<!-- HTML 4.01 Transitional -->
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" "http://www.w3.org/TR/html4/loose.dtd">

<!-- XHTML 1.0 Transitional -->
<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN" "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">
HTML
O nome do tipo, como hoje.
PUBLIC
"Público": o que vem a seguir é o nome oficial de um padrão conhecido.
"-//W3C//DTD HTML 4.01//EN"
O nome do padrão: um DTD do W3C para o HTML 4.01, escrito em inglês (EN).
"http://www.w3.org/TR/html4/strict.dtd"
O endereço do arquivo de regras. O navegador nunca baixa esse arquivo: ele só olha o texto do DOCTYPE para escolher o modo.

Existe um DOCTYPE "comprido" ainda válido

Ferramentas que geram HTML por programa às vezes escrevem <!DOCTYPE html SYSTEM "about:legacy-compat">. Ele é aceito pelo validador e liga o modo padrão. Você nunca precisa escrevê-lo; só não estranhe se o vir.

Qual usar

Só um: <!DOCTYPE html> (ou <!doctype html>), na primeira linha, em toda página. Ele é curto, fácil de decorar, liga o modo padrão em todos os navegadores (inclusive em navegadores bem antigos) e vale para todas as versões futuras do HTML: o HTML de hoje é um Living Standard, um "padrão vivo" sem número de versão, então o DOCTYPE não muda mais.

Ao pegar um site antigo para consertar, troque o DOCTYPE comprido por <!DOCTYPE html> e confira a página com calma: se ela dependia do modo quirks, algumas coisas vão mudar de lugar, e o CSS precisa de ajuste.

Quando dá errado

O navegador nunca mostra uma mensagem de erro por causa do DOCTYPE. Ele simplesmente escolhe o modo quirks e segue em frente. Quem avisa é o validador.

Sem DOCTYPE: Start tag seen without seeing a doctype first. 
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<p>Bolo de cenoura.</p>
</body>
</html>

$ vnu sem-doctype.html; echo "código de saída: $?"
"file:/home/ana/site/doctype/sem-doctype.html":1.1-1.19: error: Start tag seen without seeing a doctype first. Expected “<!DOCTYPE html>”.
código de saída: 1

O que significa: "Tag de abertura encontrada sem ver um DOCTYPE antes. Esperava <!DOCTYPE html>". As colunas 1 a 19 da linha 1 são o <html lang="pt-BR">: a primeira coisa do arquivo foi uma tag, e não o DOCTYPE. O código de saída 1 quer dizer "achei erro". No navegador: a página aparece normal, mas em modo quirks (BackCompat).

Como consertar: escreva <!DOCTYPE html> na linha 1.

O que significa: um erro só virou seis mensagens. Leia na ordem:

  • Non-space characters found without seeing a doctype first: "caracteres que não são espaço encontrados antes de um DOCTYPE".
  • Element “head” is missing a required instance of child element “title”: ao ver texto, o navegador já montou sozinho um <html>, um <head> vazio (sem <title>) e um <body> com a palavra dentro (aula Como o Navegador Lê HTML).
  • Stray doctype: "DOCTYPE perdido", fora do lugar. Na linha 2 ele não vale mais nada.
  • Stray start tag “html”: o <html lang="pt-BR"> da linha 3 chegou tarde, porque a página já tinha um html. Por isso o lang dele não conta, e a última mensagem pede um lang.
  • error fatal: Cannot recover after last error: "não consigo me recuperar depois do último erro": o validador parou de procurar.

No navegador: a palavra "Receitas" aparece no alto da página, e o modo é quirks. Como consertar: apague o que vem antes do DOCTYPE. Quase sempre o primeiro erro é o único de verdade; os outros são consequência dele.

O que significa: "caractere ruim (um espaço) depois de <". Com o espaço, o navegador não reconhece nem uma declaração nem uma tag: ele entende o < como um sinal de "menor que" no meio do texto. A dica do validador ("escape como &lt;") serve para quem queria mesmo escrever o sinal na tela (aula Entidades). No navegador: o texto < !DOCTYPE html> aparece escrito no alto da página, e o modo é quirks. Como consertar: nada de espaço entre < e !.

DOCTYPE repetido ou no meio: Stray doctype. 
$ vnu dois.html meio.html
"file:/home/ana/site/doctype/dois.html":1.16-2.15: error: Stray doctype.
"file:/home/ana/site/doctype/meio.html":8.1-8.15: error: Stray doctype.

O que significa: "DOCTYPE perdido". No dois.html, a linha 2 repete o DOCTYPE; no meio.html, alguém colou um DOCTYPE dentro do <body>, na linha 8 (isso acontece quando se junta o código de duas páginas). O navegador ignora o DOCTYPE extra; como o primeiro estava certo, a página fica no modo padrão. Como consertar: deixe só um, na linha 1.

Missão final: a página antiga da Ana

Missão: a Ana achou a primeira versão do site dela, de anos atrás. Ela não tem DOCTYPE, e a cor do título está escrita sem o #, um erro que só "funcionava" no modo quirks. Faça duas coisas: (1) coloque <!DOCTYPE html> na primeira linha e (2) escreva a cor do jeito certo, #c0392b (um vermelho-tijolo), para o título ficar vermelho também no modo padrão.

<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
<style>
  h1 { color: c0392b; }
</style>
</head>
<body>
<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com cobertura de chocolate.</p>
</body>
</html>

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
<style>
  h1 { color: #c0392b; }
</style>
</head>
<body>
<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com cobertura de chocolate.</p>
</body>
</html>

A missão confere três coisas: que o DOCTYPE é mesmo a primeira coisa do código, que não há nada antes dele e que a cor calculada do título é o vermelho-tijolo. Ela não aceita a cor sem #, mesmo que algum navegador a mostre vermelha, porque esse "acerto" depende do modo quirks.

Resumo

  • O DOCTYPE é a primeira linha de toda página: <!DOCTYPE html>. Não é uma tag, não tem fechamento e não aparece na tela.
  • Maiúsculas ou minúsculas tanto faz. Antes dele, só linhas em branco ou comentários.
  • Com ele, o navegador usa o modo padrão (document.compatMode = CSS1Compat). Sem ele, ou com ele errado, usa o modo quirks (BackCompat), que imita os defeitos dos navegadores antigos.
  • No modo quirks, CSS errado pode "funcionar" (cor sem #, largura sem unidade) e tabelas mudam de letra. O erro fica escondido até o dia em que a página muda de modo.
  • Os DOCTYPEs compridos do HTML 4 e do XHTML são obsoletos: troque-os por <!DOCTYPE html>.
  • O navegador nunca avisa: quem avisa é o validador, com Start tag seen without seeing a doctype first, Quirky doctype, Obsolete doctype ou Stray doctype.
