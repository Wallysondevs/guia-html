Projeto Blog Semântico

A Ana quer um blog para contar as histórias da cozinha dela. Um blog tem sempre as mesmas partes: o cabeçalho com o nome, o menu, os posts, uma coluna "sobre a autora" e o rodapé. Neste projeto, cada parte ganha o elemento com o nome certo: header, nav, main, article, aside, footer. Na tela, quase nada muda. Para o leitor de tela, o buscador e o modo de leitura do navegador, muda tudo: eles passam a saber o que é o quê.

Você vai praticar
  • Trocar uma "sopa de div" pelos elementos semânticos (HTML Semântico, div e span).
  • Montar o esqueleto de um site com header, nav, main e footer (header e footer, nav, main).
  • Marcar cada post com article e a data com time (section e article, time).
  • Separar o conteúdo complementar com aside (aside).
  • Montar a página de um post, com header e footer do próprio artigo, section e comentários.

E, na versão 4, a página de um post (post.html), com comentários.

  1. Da sopa de div ao esqueleto semântico (header, nav, main, footer).

  3. A coluna "Sobre a Ana" (aside e figure).
  4. A página do post (header e footer do artigo, section e comentários).

Antes de começar

Você precisa ter visto HTML Semântico e as aulas do grupo Semântica, de header e footer a aside. A pasta do projeto, com a pasta de imagens:

$ cd sites/blog

Compare os dois resultados: são iguais. A diferença é para quem não olha a tela.

ElementoEraO que éPara o leitor de tela
headerdiv id="cabecalho"O cabeçalho do site: nome, frase, menu.Uma região "banner" (faixa do topo).
navdiv id="menu"Um grupo de links de navegação.Uma região "navegação": dá para pular direto para o menu.
maindiv id="posts"O conteúdo principal, o que só esta página tem. Um por página.A região "principal": a pessoa pula direto para cá, sem ouvir o menu toda vez.
footerdiv id="contato"O rodapé: contato, direitos.Uma região "informações".

Essas regiões (os landmarks, "pontos de referência") são como os capítulos de um livro em áudio: o leitor de tela lista as regiões, e a pessoa escolhe para onde ir. Os id continuam lá: eles servem para os links do menu (href="#posts"), e não para dizer o que a parte é.

Dois main na mesma página

A Ana achou que cada post merecia o seu main e fechou o primeiro antes do segundo post:

$ vnu --verbose index.html
index.html
"file:/home/ana/sites/blog/index.html":24.3-24.8: error: A document must not include more than one visible “main” element.

"Um documento não pode ter mais de um main visível." Na tela, nada muda; para o leitor de tela, há duas regiões "principais", e o atalho que pula para o conteúdo principal vai só para a primeira. Como consertar: um main com todo o conteúdo principal; para separar os posts, a versão 2 usa article.

Missão (versão 1): troque as quatro div pelos elementos semânticos: o cabeçalho vira header, o menu vira nav, os posts viram main e o contato vira footer. Mantenha os id posts e contato (os links do menu usam), e não se esqueça das tags de fechamento.

Versão 2 · Cada post num article

Um post de blog faz sentido sozinho: dá para copiá-lo para outro site, mandar por e-mail ou ler no celular sem o resto da página. Conteúdos assim são article, "artigo": um post, uma notícia, um comentário, um produto. E cada post tem uma data, marcada com time.

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Blog da Ana — receitas e histórias da minha cozinha</title>
</head>
<body>
  <header>
    <h1>Blog da Ana</h1>
    <p>Receitas e histórias da minha cozinha.</p>

        <li><a href="#posts">Posts</a></li>

      </ul>
    </nav>

  <main id="posts">
    <article>

      <p><time datetime="2026-10-12">12 de outubro de 2026</time></p>
      <p>Fiz o bolo de cenoura da minha avó pela primeira vez sozinha. Saiu fofinho, do jeito que eu lembrava.</p>

<article>
Um conteúdo completo e independente: o post inteiro, do título ao texto.
<h2>
Todo article tem um título. Aqui, h2, porque o h1 da página é o nome do blog.
<time datetime="2026-10-12">
A data no formato de máquina, ano-mês-dia. Os buscadores e os leitores de feed usam para mostrar a data do post e ordenar.
12 de outubro de 2026</time>
A data como as pessoas leem.
"Tiro o article da página: ainda faz sentido?"

É o teste para escolher entre article e section. O post, sozinho, faz sentido: é article. Uma parte de um texto ("Por que dá certo"), sozinha, fica sem pé nem cabeça: é section, como você vai ver na versão 4. E se a caixa só existe para o CSS, sem significado nenhum, é div.

A data no formato brasileiro dentro do datetime

A Ana escreveu <time datetime="05/10/2026">. Para nós é 5 de outubro; para um programa americano, seria 10 de maio. O formato do datetime é um só, no mundo inteiro, e o validador o conhece:

$ vnu --verbose index.html
index.html
"file:/home/ana/sites/blog/index.html":28.10-28.37: error: Bad value “05/10/2026” for attribute “datetime” on element “time”: The literal did not satisfy the time-datetime format.

"Valor ruim para o datetime: não segue o formato." Como consertar: no datetime, sempre 2026-10-05 (ano com 4 dígitos, mês e dia com 2). O texto entre as tags pode ser escrito do jeito que você quiser.

Missão (versão 2): o primeiro post já é um article; o segundo ainda está solto. Coloque o título, a data e o texto do segundo post dentro de um <article>, e marque a data com <time datetime="2026-10-05">.

<aside id="sobre">
Conteúdo complementar: relacionado ao site, mas fora do assunto principal. Fica fora do main, como uma coluna lateral (o CSS é que a colocaria do lado; sem CSS, ela vem embaixo). Para o leitor de tela, é uma região "complementar".

O avatar. O alt descreve o desenho, porque o texto ao lado não diz como a Ana é.
<figure> dentro do <article>
A foto faz parte do post: fica dentro do article, com a legenda.
Uma section sem título

Para "organizar", a Ana pôs o parágrafo do aside dentro de uma section. O validador estranhou:

$ vnu --verbose index.html
index.html
"file:/home/ana/sites/blog/index.html":41.5-41.13: info warning: Section lacks heading. Consider using “h2”-“h6” elements to add identifying headings to all sections, or else use a “div” element instead for any cases where no heading is needed.

"A section não tem título. Considere usar h2–h6 para identificar todas as seções, ou então use uma div nos casos em que não precisa de título." É só um conselho (info warning), mas um bom conselho: uma seção é uma parte com assunto, e todo assunto tem nome. Se a caixa não tem assunto, ela não é section. Aqui, ela nem precisava existir.

Missão (versão 3): a caixa "Sobre a Ana" ainda é uma div. Troque-a por um <aside> (mantendo o id="sobre", que o link do menu usa). Ela fica onde está: depois do main, antes do footer.

Um main dentro do artigo

A Ana achou que o texto principal do post merecia um main e o colocou em volta do primeiro parágrafo, dentro do article. Uma tag, três erros:

"file:/home/ana/sites/blog/post.html":30.7-30.12: error: The “main” element must not appear as a descendant of the “main” element.

"O main não pode estar dentro de um article", "nem dentro de outro main", e "um documento não pode ter mais de um main visível". O main é o conteúdo principal da página inteira, e só existe um. Como consertar: tire o main de dentro do artigo; o artigo já está dentro do main da página.

Desafios extras

  1. Pular para o conteúdo. Como primeiro item do body, um link <a href="#posts">Pular para os posts</a>: quem navega pelo teclado não precisa passar pelo menu toda vez (veja Teclado e Foco).
  2. Página atual no menu. No post.html, nenhum link do menu é a página atual; no index.html, ponha aria-current="page" no link "Posts" (veja ARIA).
  3. Hora do comentário. Troque a data dos comentários por data e hora: <time datetime="2026-10-13T19:30">13/10, 19h30</time> (veja time).
  4. Mais respostas. Faça a Ana responder ao Bruno com um article dentro do article do comentário dele.
  5. Uma terceira página. Crie sobre.html com o perfil completo da Ana e mude o link "Sobre" do menu para ela (o próximo projeto, o Portfólio, é todo sobre sites de várias páginas).

Exercícios

1. Trocar as div por header, nav, main e footer muda o quê na tela, sem CSS?

2. Quantos main visíveis uma página pode ter?

3. Um comentário de leitor, embaixo do post, é marcado com…

4. Qual destes é um datetime válido para 5 de outubro de 2026?

5. Complete o elemento da coluna "Sobre a Ana", que fica fora do conteúdo principal:

< id="sobre"> <h2>Sobre a Ana</h2> … </aside>

6. Complete o elemento do menu principal:

<> <ul> <li><a href="#posts">Posts</a></li> </ul> </nav>

Resumo

  • Os elementos semânticos dizem o que cada parte é; a tela quase não muda, mas o leitor de tela ganha regiões para pular.
  • header, nav, main (um só), aside e footer montam o esqueleto do site.
  • article para o que faz sentido sozinho (post, comentário); section para partes com título; div para caixas sem significado.
  • header e footer também existem dentro de um artigo.
  • time datetime="2026-10-12": a data para os programas, no formato ano-mês-dia.
  • Em cada página, o h1 é o assunto daquela página.
