HTML Introdução

A Ana cozinha muito bem e quer colocar as receitas dela na internet. Para isso, ela precisa escrever as páginas numa língua que o navegador entende: o HTML. Nesta aula você vai descobrir o que é uma página da Web "por dentro", o que quer dizer cada letra da sigla HTML, o que são as tags e por que o HTML não é uma linguagem de programação, e sim de marcação.

Você vai aprender
  • Que uma página da Web é só um arquivo de texto, com a extensão .html.
  • O que quer dizer HyperText Markup Language, palavra por palavra.
  • O que é uma tag (<h1>, </h1>) e o que é um elemento.
  • Por que o navegador junta tudo numa linha só quando o texto não tem marcação.
  • A diferença entre marcar e programar, e o trio HTML, CSS e JavaScript.
  • O que acontece com uma tag escrita errada ou inventada, com a mensagem real do validador.

Os arquivos desta aula estão na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site, e foram conferidos com o validador oficial do W3C (vnu). Os quadros Resultado são desenhados pelo seu navegador, na hora, a partir do código que está logo acima deles.

A ideia: as anotações na receita

Imagine que a Ana escreveu uma receita à mão e entregou para uma gráfica imprimir num livro. O texto é só texto: o gráfico não sabe o que é o nome da receita, o que é a lista de ingredientes e o que é o modo de fazer. Então a Ana faz anotações na margem, com caneta vermelha: "isto é o título", "isto é uma lista", "isto aqui é importante". O gráfico lê as anotações e decide como imprimir: o título grande, a lista com marcadores, o importante em negrito.

O HTML é exatamente isso. Você escreve o texto e coloca marcações em volta de cada pedaço, dizendo o que ele é. Quem lê as marcações é o navegador (o Chrome, o Firefox, o Edge, o Safari), e ele decide como desenhar cada coisa na tela.

1. Uma página é um arquivo de texto

Pode parecer estranho, mas toda página da Web, por mais bonita que seja, começa como um arquivo de texto, igual a um bilhete do Bloco de Notas. Esta é a página de receitas da Ana, vista no terminal com o comando cat (que mostra o conteúdo de um arquivo):

$ cat receita.html
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com cobertura de chocolate.</p>
</body>
</html>
$ file receita.html                  « o comando file diz que tipo de arquivo é
receita.html: HTML document, ASCII text

O file respondeu "documento HTML, texto ASCII" (ASCII é o jeito mais simples de guardar letras sem acento). Não tem nada de especial ali dentro: só letras, números e alguns sinais como <, > e /. Qualquer editor de texto abre e muda esse arquivo, e qualquer navegador sabe desenhá-lo. Veja o que o navegador faz com ele:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com cobertura de chocolate.</p>
</body>
</html>

Das onze linhas do arquivo, só duas aparecem na tela: o título e o parágrafo. O resto é a moldura da página (o tipo de documento, o idioma, o título da aba), que a aula Estrutura de uma Página explica linha por linha. Por enquanto, olhe só para as duas linhas do meio.

A extensão .html

O nome do arquivo termina em .html. Essa extensão avisa ao sistema e ao navegador: "este texto é uma página da Web". Você também vai ver .htm, com três letras, um costume antigo do tempo em que o Windows só aceitava extensões de três letras. As duas funcionam igual; o guia usa sempre .html. Criar e abrir o arquivo no seu computador é a aula Criar e Abrir um Arquivo .html.

2. Texto sem marcação: tudo numa linha

Para entender por que as marcações existem, veja o que acontece quando a Ana escreve a receita sem nenhuma, uma coisa em cada linha, como num caderno:

Bolo de cenoura
Ingredientes
2 xícaras de farinha
3 ovos
1 xícara de açúcar

Tudo grudou numa linha só (ou em poucas, se a tela for estreita), sem título, sem lista, sem nada. Não é um defeito do navegador: ele recebeu só texto, e quebra de linha no código não é quebra de linha na página. Para o navegador, apertar Enter no meio do texto é o mesmo que dar um espaço. Ele não tem como adivinhar que "Bolo de cenoura" é um título e que as três últimas linhas são uma lista. Alguém precisa dizer. (Os espaços e as quebras têm aula própria: Espaços e Quebras de Linha.)

O validador, aliás, não reclama de nada nesse texto: texto solto é permitido numa página. Ele está certo; só não está organizado.

Agora a mesma receita, com marcações:

<h1>Bolo de cenoura</h1>
<h2>Ingredientes</h2>
<ul>
  <li>2 xícaras de farinha</li>
  <li>3 ovos</li>
  <li>1 xícara de açúcar</li>
</ul>

O texto é o mesmo. A diferença são as marcações, e o navegador obedeceu a cada uma:

MarcaçãoO que ela dizComo o navegador mostrou
<h1> … </h1>"Isto é o título principal" (heading 1, "título de nível 1")Letras grandes, em negrito, numa linha própria
<h2> … </h2>"Isto é um subtítulo" (título de nível 2)Um pouco menor que o h1
<ul> … </ul>"Aqui começa e termina uma lista" (unordered list, "lista não ordenada")Recuo à esquerda
<li> … </li>"Isto é um item da lista" (list item)Uma linha com uma bolinha na frente

Repare que nenhuma marcação diz "use letra grande" ou "ponha uma bolinha". Elas dizem o que o texto é. A aparência é decisão do navegador, e pode ser mudada depois com CSS. Essa ideia tem nome, semântica (o significado das coisas), e é tão importante que tem uma seção inteira no Nível 2 (HTML Semântico).

Experimente: o nome da receita está solto, sem marcação. Coloque <h1> antes de Bolo de cenoura e </h1> depois, na mesma linha, e veja o título crescer no resultado. Depois, se quiser, faça o mesmo com Modo de fazer, usando <h2> e </h2>.

Bolo de cenoura
<p>Rende 8 fatias.</p>
Modo de fazer
<p>Bata tudo no liquidificador e asse por 40 minutos.</p>

<h1>Bolo de cenoura</h1>
<p>Rende 8 fatias.</p>
<h2>Modo de fazer</h2>

3. HTML, palavra por palavra

A sigla vem do inglês: HyperText Markup Language, "linguagem de marcação de hipertexto". Cada palavra conta um pedaço da história:

HyperText
Hipertexto: um texto com links, que levam a outros textos. Num livro, você lê de uma página para a seguinte. Num hipertexto, você clica numa palavra e pula para outro documento, que pode estar em outro computador, do outro lado do mundo. Essa foi a grande ideia da Web.
Markup
Marcação: as anotações em volta do texto, como a caneta vermelha da Ana. Em HTML, as marcações são as tags.
Language
Linguagem: um conjunto de regras combinadas. Existe uma lista fixa de tags, cada uma com um significado, e regras de onde cada uma pode aparecer. Todos os navegadores seguem as mesmas regras, por isso a mesma página funciona em qualquer um.

O "hiper" do hipertexto é o link. Ele é feito com a tag <a> (de anchor, "âncora") e tem aula própria, Links. Só para você ver um:

<p>A receita da cobertura está na <a href="https://pt.wikipedia.org/wiki/Ganache">Wikipédia</a>.</p>

A palavra "Wikipédia" virou um link (normalmente azul e sublinhado). O endereço para onde ele leva fica escondido dentro da tag, no href (hypertext reference, "referência de hipertexto"). Isso é um atributo, uma informação extra dentro da tag de abertura (aula Atributos).

4. Tags e elementos

Duas palavras aparecem o tempo todo em livros, sites e mensagens do validador. Vale a pena separá-las desde já:

<h1>Receitas da Ana</h1>
<h1>
A tag de abertura: o nome da tag (h1) entre os sinais de menor < e maior >. Ela diz "aqui começa".
Receitas da Ana
O conteúdo: o que aparece na tela.
</h1>
A tag de fechamento: o mesmo nome, com uma barra / logo depois do <. Ela diz "aqui termina".
PalavraO que éExemplo
tagA marcação em si, com os sinais < ><h1> e </h1> são duas tags
elementoA coisa inteira: tag de abertura, conteúdo e tag de fechamento<h1>Receitas da Ana</h1> é um elemento h1

No dia a dia, muita gente diz "a tag h1" querendo dizer "o elemento h1", e todo mundo entende. O validador, porém, usa as duas palavras com cuidado: end tag (tag de fechamento) e element (elemento) aparecem em mensagens diferentes. A aula Elementos e Tags mostra os detalhes, inclusive os elementos que não têm tag de fechamento, como o <br>.

5. Marcar não é programar

O HTML é uma linguagem de marcação, e não de programação. A diferença é importante:

  • Uma linguagem de programação (como C, Python ou JavaScript) dá ordens ao computador: faça esta conta, repita isto dez vezes, se o usuário clicar aqui, faça aquilo.
  • Uma linguagem de marcação só descreve um documento: isto é um título, isto é uma lista, isto é um link. Ela não faz conta, não toma decisão, não repete nada.

Veja o que o HTML faz com uma conta:

<p>2 + 2</p>

Apareceu 2 + 2, e não 4. Para o HTML, "2 + 2" é só um texto, como "Bolo de cenoura". Quem faz contas numa página é o JavaScript.

Isso quer dizer que o HTML é "menos" que uma linguagem de programação? Não: é outra ferramenta, para outro trabalho. E é a base de tudo na Web. Escrever HTML bem feito (organizado, com o significado certo em cada tag, acessível para todo mundo) é uma habilidade profissional de verdade.

O trio: HTML, CSS e JavaScript

Quase todo site usa três linguagens juntas, cada uma com um trabalho. Pense numa casa:

LinguagemNa casaNa páginaArquivo
HTMLAs paredes, as portas, os cômodos: a estruturaO conteúdo e o que cada parte é: título, parágrafo, lista, imagem, formulárioindex.html
CSSA pintura, os móveis, a decoração: a aparênciaCores, fontes, tamanhos, espaçamentos, a posição de cada coisaestilo.css
JavaScriptA eletricidade: o que funciona quando você aperta um botãoO comportamento: contas, respostas a cliques, conteúdo que muda sem recarregarscript.js

Dá para morar numa casa sem pintura e sem luz, mas não numa casa sem paredes. Do mesmo jeito, uma página só com HTML funciona (fica simples, mas funciona), enquanto CSS e JavaScript sozinhos não mostram nada: eles sempre trabalham em cima de um HTML. Por isso o HTML é a primeira coisa a aprender.

A caixa abaixo tem os três, cada um na sua aba. Clique nas abas para ver cada arquivo. O CSS pinta o título de vermelho-tijolo; o JavaScript faz a conta que o HTML não sabe fazer e escreve o resultado no console, embaixo do quadro. Você não precisa entender o CSS nem o JavaScript agora (eles têm guias próprios); repare só em quem faz o quê.

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
<link rel="stylesheet" href="estilo.css">
</head>
<body>
<h1>Bolo de cenoura</h1>
<p>Rende 2 + 2 + 4 fatias.</p>
<script src="script.js"></script>
</body>
</html>

h1 {
  color: #b5462f;
}

console.log("2 + 2 + 4 =", 2 + 2 + 4);

O parágrafo continua mostrando 2 + 2 + 4: o HTML não faz a conta, o JavaScript faz (o console mostra o 8). Experimente trocar a cor no estilo.css (blue, green) ou apagar a linha do <link> no index.html: sem ela, o CSS não é carregado e o título volta à cor normal. As tags que ligam o CSS e o JavaScript ao HTML têm aulas próprias no Nível 2: Ligar CSS e O Elemento script.

6. Onde o HTML está

Em todo lugar onde existe uma página da Web, e em alguns lugares que você nem imagina:

  • Todo site, do mais simples ao mais complicado. Mesmo os sites feitos com ferramentas prontas (WordPress, Wix, lojas virtuais) entregam HTML ao navegador no fim. Você pode ver o HTML de qualquer página com o atalho Ctrl + U na maioria dos navegadores de computador (aula Ferramentas do Desenvolvedor).
  • E-mails com cores, imagens e botões são escritos em HTML.
  • Livros digitais no formato EPUB guardam cada capítulo como um arquivo do tipo HTML.
  • Programas de computador: vários aplicativos de desktop são, por dentro, páginas HTML num navegador embutido. O editor VS Code, que você vai conhecer em Editores, é um deles.

Um pouco de história

O HTML nasceu junto com a Web, no CERN (um laboratório de física na Suíça), criado por Tim Berners-Lee entre 1989 e 1991. Ele queria que os cientistas compartilhassem documentos com links entre eles. A primeira lista de tags tinha pouco mais de uma dúzia de marcações; hoje são mais de cem elementos, para vídeo, formulários, gráficos e muito mais. A linguagem mudou muito, mas uma página escrita nos anos 1990 ainda abre num navegador de hoje. As versões, do HTML 2.0 ao Living Standard, estão em Versões do HTML.

Quando dá errado

O navegador quase nunca mostra uma mensagem de erro. Ele sempre desenha alguma coisa, e é por isso que o validador é tão útil: ele diz o que está errado mesmo quando a página "parece" funcionar.

A tag aparece escrita na página 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
h1>Bolo de cenoura</h1>
<p>Rende 8 fatias.</p>
</body>
</html>

O que aconteceu: faltou o < no começo da tag. Sem ele, h1> é texto comum, e o navegador mostra o texto. O título não cresceu, e o </h1>, que fecha uma coisa que nunca foi aberta, foi simplesmente ignorado. O validador aponta justamente esse fechamento sem par:

$ vnu receita.html
"file:/home/ana/site/receita.html":8.19-8.23: error: Stray end tag “h1”.

Stray end tag = "tag de fechamento perdida", sem uma abertura correspondente. A posição 8.19-8.23 (linha 8 do arquivo, colunas 19 a 23) aponta o </h1>; a causa está um pouco antes, no começo da mesma linha.

Como consertar: toda tag começa com < e termina com >: <h1>Bolo de cenoura</h1>.

Uma tag inventada (ou em português) 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<titulo>Bolo de cenoura</titulo>
<p>Rende 8 fatias.</p>
</body>
</html>

O que aconteceu: não existe a tag <titulo>. As tags do HTML têm nomes fixos, em inglês (ou abreviações do inglês). O navegador não reconhece a tag e mostra o texto de dentro como texto comum, sem estilo de título. O validador é mais direto:

$ vnu receita.html
"file:/home/ana/site/receita.html":8.1-8.8: error: Element “titulo” not allowed as child of element “body” in this context. (Suppressing further errors from this subtree.)
"file:/home/ana/site/receita.html":8.1-8.8: error: The “titulo” element is a completely-unknown element that is not allowed anywhere in any HTML content.

A primeira linha diz "o elemento titulo não é permitido como filho do elemento body neste contexto" (e avisa que vai ignorar os erros de dentro dele). A segunda é a importante: "o elemento titulo é completamente desconhecido e não é permitido em nenhum lugar do HTML".

Como consertar: use a tag certa, <h1>. Na dúvida, procure o nome na lista de todos os elementos.

O navegador mostra o código em vez da página

O que aconteceu: o arquivo foi salvo com a extensão errada, quase sempre .txt (por exemplo, receita.txt ou receita.html.txt). O conteúdo é HTML, e o file até percebe isso pelo que está escrito dentro:

$ file receita.txt
receita.txt: HTML document, Unicode text, UTF-8 text

Mas o navegador não olha o conteúdo para decidir: ele olha o nome. Com .txt, ele entende "isto é um texto simples" e mostra tudo como está, com os < e > à vista, numa fonte de máquina de escrever.

Como consertar: renomeie o arquivo para terminar em .html. No Windows, a extensão costuma ficar escondida, e o arquivo pode estar com um .txt que você não vê; a aula Criar e Abrir um Arquivo .html mostra como ligar a exibição das extensões.

A página escrita no Word não funciona

O que aconteceu: processadores de texto como o Word e o LibreOffice Writer não salvam texto puro. O arquivo .docx é um pacote com o texto, as fontes, as margens e muito mais, num formato que o navegador não entende. E, mesmo quando você escolhe salvar "como página da Web", eles costumam trocar as aspas retas " por aspas curvas “ ” e escrevem um HTML enorme e cheio de coisas próprias.

Como consertar: escreva HTML num editor de texto puro ou num editor de código (aula Editores).

Missão: a receita de pudim da Ana está toda solta. Marque o nome Pudim de leite como título principal (h1), Ingredientes como subtítulo (h2) e os três ingredientes como uma lista (ul, com um li para cada item). Não mude os textos.

Resumo

  • Uma página da Web é um arquivo de texto com a extensão .html. O navegador lê esse texto e desenha a página.
  • HTML = HyperText Markup Language, "linguagem de marcação de hipertexto": texto com links, organizado por marcações.
  • As marcações são as tags: <h1> abre, </h1> fecha. Abertura + conteúdo + fechamento = elemento.
  • Sem tags, o navegador junta tudo: quebra de linha no código vira espaço na página.
  • As tags dizem o que cada coisa é, não como ela parece. HTML é a estrutura; CSS, a aparência; JavaScript, o comportamento.
  • HTML é marcação, não programação: 2 + 2 aparece como texto.
  • O navegador não mostra erros: tag sem < vira texto, tag inventada é ignorada. Quem aponta o erro é o validador.
  • Próximo passo: Como o Navegador Lê HTML, o caminho do arquivo até a tela.
