HTML nav

Todo site precisa de um caminho para as outras páginas: o menu. Em HTML, o grupo dos links principais fica num elemento próprio, o nav. Nesta aula você vai montar o menu do site de receitas da Ana do jeito que os sites profissionais montam, com uma lista de links, marcar em qual página a pessoa está, criar uma "trilha" (Início › Doces › Bolo) e descobrir quando um grupo de links não precisa de nav.

Você vai aprender
  • O que é o nav e o que vai dentro dele.
  • Por que o menu costuma ser uma lista: nav › ul › li › a.
  • Como marcar a página atual com aria-current="page".
  • Como dar um nome a cada nav com aria-label, quando há mais de um.
  • A trilha de navegação (breadcrumb) com ol.
  • Quando não usar nav, e os erros reais: a dentro de ul, li dentro de nav e um valor errado em aria-current.

Os arquivos desta aula foram validados com o validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/receitas. Antes desta aula, vale ter visto Links e Listas com Marcadores.

A ideia: as placas de um shopping

Num shopping, perto da entrada, existe um painel com as placas principais: "Praça de alimentação", "Cinema", "Estacionamento". Não são todas as lojas, só os caminhos mais importantes. E ao lado do painel tem um adesivo: "Você está aqui".

O nav é esse painel. O nome vem de navigation, "navegação": ele guarda os links principais para andar pelo site. Cada link é uma placa, e o aria-current (seção 3) é o adesivo "Você está aqui".

1. O primeiro nav

No começo, o menu da Ana era só um grupo de links. Colocá-los num nav já diz ao navegador: "isto é navegação".

<h1>Receitas da Ana</h1>
<nav>
  <a href="index.html">Início</a>
  <a href="doces.html">Doces</a>
  <a href="salgados.html">Salgados</a>
  <a href="sobre.html">Sobre</a>
</nav>
<nav>
Começa o grupo de navegação. É um bloco invisível: sozinho, não muda nada na tela.
<a href="doces.html">Doces</a>
Cada link leva a uma página do site. O texto do link diz para onde ele vai.
</nav>
Termina o grupo.

No resultado, os quatro links ficaram lado a lado, separados só por um espaço, porque o a é um elemento em linha (aula Bloco × Em Linha). Para o leitor de tela, porém, o nav já fez diferença: ele vira a região navegação (papel navigation), e quem usa leitor de tela pode pular direto para ela, ou pular por cima dela para chegar ao conteúdo (aula HTML Semântico).

2. O menu como lista

Quase todos os sites montam o menu como uma lista de links: um ul, um li para cada item e o a dentro do li.

<h1>Receitas da Ana</h1>
<nav>
  <ul>
    <li><a href="index.html">Início</a></li>
    <li><a href="doces.html">Doces</a></li>
    <li><a href="salgados.html">Salgados</a></li>
    <li><a href="sobre.html">Sobre</a></li>
  </ul>
</nav>
nav
A região: "isto é navegação".
ul
A lista sem ordem (unordered list): os itens do menu não têm uma sequência obrigatória.
li
Um item da lista (list item). O ul só aceita li como filho.
a
O link, dentro do li.

Por que o trabalho a mais? Porque a lista diz quantos itens o menu tem. Ao entrar nele, o leitor de tela costuma anunciar algo como "navegação, lista, 4 itens", e a pessoa já sabe o tamanho do menu antes de ouvir tudo. Sem a lista, ela só descobre quantos links há ouvindo um por um.

E as bolinhas e o recuo que apareceram no resultado? Isso é aparência, e se resolve com CSS (por exemplo, com o display: inline que você viu na aula Bloco × Em Linha, ou com regras que o futuro Guia CSS mostra). O HTML continua dizendo o que o menu é: uma lista de links.

Missão: a Ana colocou os links direto no ul, sem li. Isso é um erro (você vai ver a mensagem do validador no fim da aula). Ponha cada link dentro do seu próprio <li>.

<h1>Receitas da Ana</h1>
<nav>
  <ul>
    <a href="index.html">Início</a>
    <a href="doces.html">Doces</a>
    <a href="salgados.html">Salgados</a>
  </ul>
</nav>

<h1>Receitas da Ana</h1>
<nav>
  <ul>
    <li><a href="index.html">Início</a></li>
    <li><a href="doces.html">Doces</a></li>
    <li><a href="salgados.html">Salgados</a></li>
  </ul>
</nav>

Onde o nav fica

O menu principal costuma ficar dentro do header, junto com o nome do site (aula header e footer). Também pode ficar logo depois dele, ou numa barra lateral. Os três jeitos estão certos: o nav é uma região própria em qualquer lugar.

<header>
  <h1>Receitas da Ana</h1>
  <nav>
    <ul>
      <li><a href="index.html">Início</a></li>
      <li><a href="doces.html">Doces</a></li>
      <li><a href="salgados.html">Salgados</a></li>
    </ul>
  </nav>
</header>
<p>Bem-vindo! Escolha uma categoria no menu.</p>

3. "Você está aqui": aria-current="page"

Quando a pessoa está na página de doces, o link "Doces" do menu leva para a própria página em que ela já está. Os sites costumam destacar esse link, para mostrar onde a pessoa está. O jeito certo de marcar isso no HTML é o atributo aria-current:

<h1>Doces</h1>
<nav>
  <ul>
    <li><a href="index.html">Início</a></li>
    <li><a href="doces.html" aria-current="page">Doces</a></li>
    <li><a href="salgados.html">Salgados</a></li>
  </ul>
</nav>
aria-current
"Atual". Os atributos que começam com aria- são do ARIA, o padrão de acessibilidade (aula ARIA). Este diz que o link aponta para o item atual.
="page"
"Página": o item atual é a página em que a pessoa está. Outros valores aceitos são step (passo atual de um processo), location, date, time, true e false.

Na tela, nada mudou: o aria-current não tem aparência. O leitor de tela, porém, anuncia o link como "página atual". Para os olhos, o destaque se faz com CSS, usando o próprio atributo como alvo (algo como "todo a com aria-current fica em negrito"). Assim, o mesmo atributo serve aos dois públicos.

Missão: esta é a página de salgados. Marque, no menu, o link da página atual com aria-current="page". Só esse link pode ter o atributo.

<h1>Salgados</h1>
<nav>
  <ul>
    <li><a href="index.html">Início</a></li>
    <li><a href="doces.html">Doces</a></li>
    <li><a href="salgados.html">Salgados</a></li>
  </ul>
</nav>
<p>Pão de queijo, coxinha e esfiha.</p>

    <li><a href="doces.html">Doces</a></li>

4. Mais de um nav: dê um nome a cada um

Uma página pode ter vários nav: o menu principal, um menu da categoria na lateral, uma trilha. O validador aceita sem nenhuma mensagem. Mas pense no leitor de tela: na lista de regiões, ele mostra "navegação", "navegação", "navegação". Qual é qual?

A solução é dar um nome a cada um com aria-label ("rótulo"):

<header>
  <h1>Receitas da Ana</h1>
  <nav aria-label="Menu principal">
    <ul>
      <li><a href="index.html">Início</a></li>
      <li><a href="doces.html" aria-current="page">Doces</a></li>
      <li><a href="salgados.html">Salgados</a></li>
    </ul>
  </nav>
</header>
<nav aria-label="Trilha">
  <ol>
    <li><a href="index.html">Início</a></li>
    <li><a href="doces.html">Doces</a></li>
    <li><a href="bolo.html" aria-current="page">Bolo de cenoura</a></li>
  </ol>
</nav>
aria-label="Menu principal"
O nome do primeiro nav. O leitor de tela passa a dizer algo como "Menu principal, navegação". O texto não aparece na tela.
aria-label="Trilha"
O nome do segundo. Não escreva a palavra "navegação" no nome: o leitor de tela já a diz, e ficaria "navegação navegação".
<ol>
A trilha usa uma lista numerada (aula Listas Numeradas), porque aqui a ordem importa: Início, depois Doces, depois o Bolo.
aria-current="page"
Aparece duas vezes, uma em cada nav, e está certo: no menu, a seção atual é "Doces"; na trilha, a página atual é o bolo.

A trilha (breadcrumb)

A trilha de navegação mostra o caminho do começo do site até a página atual: Início › Doces › Bolo de cenoura. Em inglês ela se chama breadcrumb, "migalha de pão", por causa da história de João e Maria, que deixavam migalhas pelo caminho para achar a volta. No resultado acima ela apareceu como lista numerada; o CSS é que a deixa numa linha, com os "›" entre os itens.

Um nome que aparece na tela: aria-labelledby

Se o nav já tem um título visível, como <h2 id="titulo-categorias">Categorias</h2>, você pode usar esse título como nome: <nav aria-labelledby="titulo-categorias"> ("rotulado por"). O valor é o id do título (aula class e id). Assim o nome que o leitor de tela diz é o mesmo que os olhos leem.

5. Nem todo grupo de links é um nav

O padrão do HTML diz que o nav é para os blocos de navegação principais. Se cada grupo de links virar um nav, a lista de regiões do leitor de tela fica cheia de entradas sem importância, e o atalho deixa de ser atalho.

Grupo de linksUsar nav?
O menu principal do siteSim
A trilha (Início › Doces › Bolo)Sim
O índice de uma página longa ("Nesta página: Ingredientes, Modo de preparo")Sim
A paginação de uma lista ("Anterior", "1", "2", "Próxima")Sim
Os links do rodapé ("Privacidade", "Contato")Em geral, não: o footer já basta
Um link no meio de um parágrafoNão
Os links para as redes sociais da AnaEm geral, não: uma lista simples resolve

Uma boa pergunta para decidir: "uma pessoa que usa leitor de tela ia querer pular direto para estes links?". Para o menu principal, sim. Para três links do rodapé, provavelmente não.

Quando dá errado

error: Element “a” not allowed as child of element “ul” in this context.

É o erro da primeira missão: links direto na lista, sem li.

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<nav>
  <ul>
    <a href="index.html">Início</a>
    <a href="doces.html">Doces</a>
  </ul>
</nav>
</body>
</html>

$ vnu link-na-ul.html
"file:/home/ana/receitas/link-na-ul.html":11.5-11.25: error: Element “a” not allowed as child of element “ul” in this context. (Suppressing further errors from this subtree.)
"file:/home/ana/receitas/link-na-ul.html":12.5-12.25: error: Element “a” not allowed as child of element “ul” in this context. (Suppressing further errors from this subtree.)

Uma mensagem para cada link: "o elemento a não é permitido como filho do elemento ul". O ul só aceita li. O Chromium monta a página exatamente como está escrita, sem consertar nada, e os links aparecem lado a lado, sem bolinhas. Por isso parece funcionar. Mas, para o navegador, essa lista tem zero itens: os links estão nela sem ser itens dela, e o anúncio "lista, 3 itens" deixa de fazer sentido.

Como consertar: cada a dentro de um <li>…</li>.

error: Element “li” not allowed as child of element “nav” in this context.

O erro "do meio": os li estão lá, mas falta o ul em volta deles (linhas 10 e 11).

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<nav>
  <li><a href="index.html">Início</a></li>
  <li><a href="doces.html">Doces</a></li>
</nav>
</body>
</html>

$ vnu li-na-nav.html
"file:/home/ana/receitas/li-na-nav.html":10.3-10.6: error: Element “li” not allowed as child of element “nav” in this context. (Suppressing further errors from this subtree.)
"file:/home/ana/receitas/li-na-nav.html":11.3-11.6: error: Element “li” not allowed as child of element “nav” in this context. (Suppressing further errors from this subtree.)

Um li só existe dentro de uma lista (ul, ol ou menu). O nav não é uma lista; ele é a região que guarda a lista. De novo, o navegador não conserta nada.

Como consertar: ponha um <ul> entre o nav e os li.

error: Bad value “sim” for attribute “aria-current” on element “a”.

A Ana traduziu o valor do atributo: <a href="index.html" aria-current="sim">, na linha 11.

$ vnu current-sim.html
"file:/home/ana/receitas/current-sim.html":11.9-11.48: error: Bad value “sim” for attribute “aria-current” on element “a”.

"Valor inválido “sim” para o atributo aria-current no elemento a". Nomes e valores de atributos são palavras fixas, em inglês, definidas pelo padrão; não dá para traduzir. Já o texto do aria-label é livre, e deve ser em português, a língua da página.

Como consertar: use um dos valores da lista: para a página atual, aria-current="page".

Nenhum erro, mas um problema: role="navigation" e nav sem nome

Escrever <nav role="navigation"> dá o aviso informativo The “navigation” role is unnecessary for element “nav”. (veja a aula HTML Semântico): o nav já tem esse papel. E dois nav sem aria-label passam no validador sem nenhuma mensagem, mas deixam o leitor de tela com duas regiões iguais.

Como consertar: tire o role; dê um aria-label diferente a cada nav, quando houver mais de um.

Resumo

  • O nav guarda os blocos de links de navegação principais e vira a região "navegação" para o leitor de tela.
  • O padrão dos sites: nav › ul › li › a. A lista diz quantos itens o menu tem; as bolinhas se tiram com CSS.
  • aria-current="page" marca o link da página atual ("Você está aqui"). Os valores são fixos, em inglês.
  • Com mais de um nav, dê um nome a cada um com aria-label (ou aria-labelledby). A trilha (breadcrumb) usa ol.
  • Nem todo grupo de links é nav: links do rodapé e links no meio do texto em geral não são.
  • Erros reais: Element “a” not allowed as child of element “ul”, Element “li” not allowed as child of element “nav” e Bad value “sim” for attribute “aria-current”. O navegador não conserta nenhum deles.
