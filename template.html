HTML template e slot

Imagine o site de receitas da Ana com 200 receitas, cada uma num cartão igual: título, foto, tempo de forno. Escrever 200 cartões à mão é trabalho de sobra, e uma mudança no cartão vira 200 mudanças. O <template> resolve isso: ele guarda um molde de HTML que não aparece na página, para o JavaScript copiar quantas vezes precisar. E o <slot> marca, dentro de um molde, os espaços onde cada cópia encaixa o seu conteúdo. Nesta aula você vai usar os dois, com um JavaScript pequeno e explicado.

Você vai aprender
  • O que o <template> faz com o que está dentro dele (e por que nada aparece).
  • Como copiar o molde com JavaScript: content.cloneNode(true), preencher e pôr na página.
  • Por que o <template> pode ficar até dentro de uma tabela.
  • O que é o shadow DOM, criado sem JavaScript com shadowrootmode.
  • Como o <slot> e o atributo slot encaixam conteúdo no molde, e o conteúdo padrão.
  • Os erros reais: <template />, esquecer o .content, shadowrootmode="aberto" e um caso que o validador aceita, mas o navegador recusa.

As mensagens do validador desta aula saíram do validador W3C (vnu, o mesmo do validator.w3.org) na máquina da Ana (usuária ana, computador notebook), na pasta ~/site. As do console foram conferidas no Chromium. Os resultados são desenhados pelo seu próprio navegador.

A ideia: a forma de biscoito

Na cozinha da Ana tem uma gaveta com formas de biscoito: uma estrela, um coração. A forma em si não se come e não vai para a mesa. Ela fica guardada, e cada vez que a Ana aperta a forma na massa, sai um biscoito igual, que ela decora do jeito que quiser.

Decorar cada biscoitotrocar o texto da cópia

1. O template: um molde que não aparece

<h1>Receitas da Ana</h1>
<template id="molde-receita">
  <article>
    <h2>Nome da receita</h2>
    <p>Este texto está guardado no molde.</p>
  </article>
</template>
<p>Só o título e este parágrafo aparecem.</p>
<template>
"Molde", "modelo". Tudo o que está dentro é lido pelo navegador, mas não é desenhado.
id="molde-receita"
O nome do molde, para o JavaScript achá-lo.
<article>…</article>
O conteúdo do molde: qualquer HTML. Aqui, um cartão de receita (aula section e article).
</template>
A tag de fechamento é obrigatória.

O conteúdo de um <template> fica numa espécie de gaveta separada da página, chamada content ("conteúdo"). Enquanto está na gaveta:

  • não aparece na tela e não é lido por leitores de tela;
  • um <script> lá dentro não roda, e uma <img> não é baixada;
  • a busca do JavaScript na página (document.querySelector("article")) não acha o que está lá dentro.

Mas o navegador lê e organiza o conteúdo, como faz com o resto da página: um <p>Oi<p>Tchau dentro do molde vira dois parágrafos fechados. Assim, cada cópia já sai pronta.

Desde quando?

O <template> entrou no HTML junto com os Web Components e funciona em todos os navegadores atuais há muitos anos. É seguro usar.

2. Copiar o molde com JavaScript

Um molde guardado não serve para nada sozinho. O JavaScript faz as cópias. Aqui, uma lista de três nomes vira três cartões:

<h1>Receitas da Ana</h1>
<div id="receitas"></div>

<template id="molde-receita">
  <article>
    <h2>Nome da receita</h2>
    <p>Receita testada pela Ana.</p>
  </article>
</template>

<script src="script.js"></script>

const nomes = ["Bolo de cenoura", "Brigadeiro", "Pudim"];
const molde = document.getElementById("molde-receita");
const lugar = document.getElementById("receitas");

for (const nome of nomes) {
  const copia = molde.content.cloneNode(true);
  copia.querySelector("h2").textContent = nome;
  lugar.append(copia);
}

console.log("Cartões na página: " + lugar.querySelectorAll("article").length);
const nomes = ["…", "…", "…"]
Uma lista (array) de textos, entre colchetes e separados por vírgula. Num site de verdade, essa lista poderia vir de um arquivo ou de um servidor.
document.getElementById("molde-receita")
Acha o <template> pela id. (O <template> em si está na página; só o conteúdo dele fica na gaveta.)
for (const nome of nomes) { … }
"Para cada nome da lista nomes, faça o que está entre as chaves." O bloco roda três vezes, uma por nome.
molde.content
A gaveta: o conteúdo do molde.
.cloneNode(true)
"Clonar": faz uma cópia. O true quer dizer "copie também tudo o que está dentro" (o <h2>, o <p>…); com false, sairia uma cópia vazia.
copia.querySelector("h2").textContent = nome
Acha o <h2> dentro da cópia e troca o texto dele pelo nome da vez. É a "decoração do biscoito".
lugar.append(copia)
Append = "acrescentar no fim": põe a cópia dentro do <div id="receitas">. Só agora o cartão aparece.

O console mostra Cartões na página: 3. Acrescente "Torta de limão" na lista e rode de novo: aparece um quarto cartão, sem nenhuma linha nova de HTML. E se a Ana quiser mudar o texto do parágrafo de todos os cartões, muda uma vez só, no molde.

3. Um molde dentro de uma tabela

Algumas tags só aceitam filhos certos: dentro de um <tbody> só cabem linhas (<tr>), e dentro de um <ul> só itens (<li>). Um <div> ali seria erro. O <template> é uma exceção: ele pode ficar em qualquer lugar, até no meio de uma tabela, bem perto de onde as cópias vão entrar:

<table>
  <thead>
    <tr><th>Doce</th><th>Preço</th></tr>
  </thead>
  <tbody id="linhas">
    <template id="molde-linha">
      <tr><td></td><td></td></tr>
    </template>
  </tbody>
</table>

Esse código passa no validador sem nenhum erro. A missão final desta aula usa exatamente essa ideia. (Tabelas têm aulas próprias, a partir de Tabelas.)

4. O slot: espaços para encaixar conteúdo

Até aqui, o JavaScript copiava o molde e trocava os textos um por um. Existe outro jeito, em que o próprio navegador encaixa o conteúdo nos lugares certos: o slot ("encaixe", "fenda"). Para entendê-lo, falta uma peça: o shadow DOM.

O shadow DOM: uma página dentro do elemento

O DOM é a árvore de elementos que o navegador monta a partir do seu HTML (aula Como o Navegador Lê HTML). O shadow DOM ("DOM de sombra") é uma árvore escondida dentro de um elemento, com o seu próprio HTML e o seu próprio CSS. É como um aquário dentro da sala: o que está dentro do vidro tem a sua própria água, e o que acontece na sala não molha o aquário.

Você cria um shadow DOM sem JavaScript, pondo um <template shadowrootmode="open"> como primeiro filho de um elemento. Esse template é diferente: em vez de ir para a gaveta, o conteúdo dele vira o shadow DOM do elemento pai, na hora. Dentro dele, cada <slot name="…"> é um espaço; cada filho comum do elemento com slot="…" vai para o espaço de mesmo nome:

<h1>Cartões de receita</h1>

<div class="cartao">
  <template shadowrootmode="open">
    <style>
      div { border: 2px solid darkred; padding: 8px; margin-bottom: 8px; }
      h2 { color: darkred; margin: 0; }
    </style>
    <div>
      <h2><slot name="titulo">Receita sem nome</slot></h2>
      <slot name="descricao">Ainda sem descrição.</slot>
    </div>
  </template>
  <span slot="titulo">Bolo de cenoura</span>
  <p slot="descricao">Fofinho, com cobertura de chocolate.</p>
</div>

<div class="cartao">
  <template shadowrootmode="open">
    <style>
      div { border: 2px solid darkred; padding: 8px; margin-bottom: 8px; }
      h2 { color: darkred; margin: 0; }
    </style>
    <div>
      <h2><slot name="titulo">Receita sem nome</slot></h2>
      <slot name="descricao">Ainda sem descrição.</slot>
    </div>
  </template>
  <span slot="titulo">Brigadeiro</span>
</div>

<h2>Este h2 é da página</h2>
<div class="cartao">
O hospedeiro (host): o elemento que vai ganhar o shadow DOM.
<template shadowrootmode="open">
Shadow root mode = "modo da raiz de sombra". Transforma o conteúdo deste template no shadow DOM do <div>. O valor open ("aberto") deixa o JavaScript da página olhar lá dentro; closed ("fechado") não deixa.
<style>…</style>
Um CSS que vale só dentro do shadow DOM. Repare no resultado: o "Este h2 é da página" continua preto, e as bordas não vazaram para o resto. É o vidro do aquário.
<slot name="titulo">Receita sem nome</slot>
Um espaço chamado titulo. O texto de dentro é o conteúdo padrão: aparece só se ninguém encaixar nada ali.
<span slot="titulo">Bolo de cenoura</span>
Um filho comum do <div>, com o atributo global slot="titulo": "encaixe-me no espaço titulo". Ele aparece dentro do <h2> vermelho do molde e até herda a cor dele.
<p slot="descricao">
Vai para o espaço descricao. O segundo cartão não tem esse filho, e por isso mostra o conteúdo padrão: "Ainda sem descrição."

Repare no que não aconteceu: nenhuma linha de JavaScript. O navegador montou os cartões sozinho, já na leitura da página. Esse jeito de escrever, com shadowrootmode, se chama shadow DOM declarativo e funciona em todos os navegadores atuais desde 2024 (o Chrome e o Safari aceitaram em 2023, e o Firefox no começo de 2024). O validador W3C atual aceita o shadowrootmode.

O slot sem nome e os espaços em branco

Existe também o <slot> sem name: ele recebe todos os filhos que não têm slot="…". Mas isso inclui os espaços e quebras de linha entre as tags do seu código. Na prática, o conteúdo padrão de um slot sem nome quase nunca aparece, porque sempre "tem alguma coisa" (um espaço) encaixada. Por isso esta aula usa slots com nome.

O preço desse jeito sem JavaScript está à vista no código: o molde foi repetido nos dois cartões, porque cada hospedeiro precisa do seu <template shadowrootmode>. Para escrever o molde uma vez só e usar uma tag sua, como <cartao-receita>, entram os Web Components, a próxima aula.

Quando dá errado

Fechar com <template />: o resto da página vai para a gaveta

O que o navegador faz: a barra do /> é ignorada (o <template> não é um elemento vazio), a tag fica aberta, e tudo o que vem depois vira conteúdo do molde, invisível. Veja o parágrafo sumir:

<h1>Receitas da Ana</h1>
<template id="molde" />
<p>Este parágrafo deveria aparecer.</p>

O validador, com esse código numa página completa (o <template> na linha 9):

$ vnu index.html
"file:/home/ana/site/index.html":9.1-9.23: error: Self-closing syntax (“/>”) used on a non-void HTML element. Ignoring the slash and treating as a start tag.
"file:/home/ana/site/index.html":11.1-11.7: error: End tag for  “body” seen, but there were unclosed elements.
"file:/home/ana/site/index.html":9.1-9.23: error: Unclosed element “template”.

"Sintaxe de autofechamento num elemento que não é vazio: ignorando a barra"; "fim do body com elementos abertos"; "elemento template não fechado". Como consertar: <template id="molde">…</template>.

Esqueceu o .content: nada aparece, e nenhum erro

O que acontece: com molde.cloneNode(true), sem o .content, o JavaScript copia o próprio <template>, com gaveta e tudo. A cópia vai para a página, mas é outro molde invisível. O console fica quieto, e a página, vazia. Se o código procurar algo dentro da cópia, aí sim aparece um erro:

<ul id="doces"></ul>
<template id="molde-doce"><li><strong></strong></li></template>
<script src="script.js"></script>

const molde = document.getElementById("molde-doce");
const copia = molde.cloneNode(true);
copia.querySelector("strong").textContent = "Brigadeiro";
document.getElementById("doces").append(copia);

O console mostra Cannot set properties of null (setting 'textContent'): o <strong> está na gaveta da cópia, e o querySelector não procura em gavetas. Como consertar: molde.content.cloneNode(true). O validador não pega esse erro: o HTML está certo.

Bad value “aberto” for attribute “shadowrootmode”

O que o navegador faz: não cria o shadow DOM; o template vira um molde comum, invisível. Os filhos com slot="…" aparecem soltos, sem o cartão. O Chrome escreve no console do F12: Invalid declarative shadowrootmode attribute value. Valid values are "open" and "closed". ("valor inválido; os válidos são open e closed").

$ vnu index.html
"file:/home/ana/site/index.html":8.6-8.39: error: Bad value “aberto” for attribute “shadowrootmode” on element “template”.

(Com <div><template shadowrootmode="aberto"> na linha 8.) Como consertar: os valores são em inglês: open ou closed.

O validador aceita, o navegador recusa: shadow DOM num <a>

O que acontece: só alguns elementos podem hospedar um shadow DOM: <div>, <span>, <p>, <article>, <section>, <header>, <footer>, <main>, <nav>, <aside>, <blockquote>, <body>, os títulos <h1> a <h6> e as tags personalizadas. Um <a><template shadowrootmode="open">… passa no validador W3C sem nenhum erro, mas o navegador não cria o shadow DOM: o template fica como um molde comum, e o Chrome avisa no console do F12: This element does not support attachShadow ("este elemento não aceita um shadow DOM").

Como consertar: ponha o template num <div> ou num <span> dentro do link, ou num elemento personalizado. Lição: "passou no validador" quer dizer que a sintaxe está certa, não que tudo funciona. Sempre olhe o resultado.

Resumo

  • <template> guarda um molde que não aparece: lá dentro, scripts não rodam, imagens não são baixadas e o querySelector da página não procura. Ele pode ficar em qualquer lugar, até numa tabela.
  • Para usar: molde.content.cloneNode(true) faz a cópia, você troca os textos com querySelector e põe na página com append. Sem o .content, você copia o molde inteiro, e nada aparece.
  • O shadow DOM é uma árvore escondida dentro de um elemento, com CSS próprio que não vaza. Sem JavaScript: <template shadowrootmode="open"> como primeiro filho.
  • <slot name="x">padrão</slot> marca um espaço no shadow DOM; um filho com slot="x" encaixa nele. Sem ninguém encaixado, aparece o conteúdo padrão. O molde decide a posição.
  • Os valores de shadowrootmode são open e closed. Nem todo elemento aceita shadow DOM (o <a> não aceita), e o validador não avisa.
