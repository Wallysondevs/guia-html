HTML Editores

Um arquivo HTML é texto puro, então qualquer programa que edita texto serve para escrevê-lo, até o Bloco de Notas. Mas um editor de código facilita muito a vida: ele pinta as tags de outra cor, fecha as tags sozinho, completa o que você começou a digitar e escreve a moldura da página com duas teclas. Nesta aula você conhece o VS Code, o editor mais usado hoje, outras boas opções e os cuidados que todo editor exige para o arquivo sair certo.

Você vai aprender
  • O que um editor de código faz por você, e por que o Word não serve.
  • Instalar o VS Code e abrir a pasta do site.
  • Os ajudantes do VS Code para HTML: cores, fechamento automático de tags, formatação e o Emmet (!, ul>li*3).
  • Ver a página no navegador enquanto edita (extensão Live Server).
  • Outras opções: Notepad++, Sublime Text, Kate, Editor de Texto, nano, Vim, editores on-line.
  • Os cuidados com o arquivo: texto puro, extensão .html, codificação UTF-8 e salvar antes de recarregar.

As telas dos editores não puderam ser reproduzidas na máquina do guia, então esta aula as descreve, sem prometer o texto exato de cada menu (ele muda com a versão e o idioma). Os arquivos, as mensagens do validador e os resultados, sim, são reais: vieram da máquina fictícia da Ana, na pasta ~/site.

A ideia: lápis, caneta ou estojo completo

Dá para escrever uma redação a lápis, numa folha qualquer. Mas um estojo com borracha, régua, marca-texto e corretivo ajuda a escrever mais rápido e com menos erros. Com HTML é igual:

1. O que um editor de código faz por você

Todos os editores de código fazem mais ou menos as mesmas coisas, com nomes diferentes:

  • Cores no código (syntax highlighting, "destaque de sintaxe"): as tags aparecem numa cor, os atributos em outra, o texto em outra. Um < esquecido muda a cor de tudo o que vem depois, e você enxerga o erro na hora.
  • Fechamento automático: quando você termina de digitar <p>, o editor escreve o </p> logo depois do cursor. É o fim do </strong> esquecido que vazava o negrito em Como o Navegador Lê HTML.
  • Autocompletar: comece a digitar <bl e ele sugere blockquote; dentro de uma tag, ele sugere os atributos que ela aceita.
  • Formatar: arruma o recuo (os espaços no começo das linhas) de um arquivo bagunçado com um atalho.
  • Atalhos de digitação: no VS Code, o Emmet escreve a moldura inteira da página a partir de um !.
  • Ver a pasta inteira: uma barra lateral com todos os arquivos do site, para pular de um para outro.

Nada disso muda o arquivo final: ele continua sendo o mesmo texto puro que você escreveria no Bloco de Notas. O editor só ajuda a escrevê-lo.

2. VS Code

O Visual Studio Code (ou só VS Code) é um editor gratuito da Microsoft, para Windows, macOS e Linux. É o mais usado no mundo para desenvolvimento web, e é o que o guia recomenda para quem está começando: ele já vem com tudo o que o HTML precisa, sem instalar nada a mais.

Instalando

  1. Entre no site oficial, code.visualstudio.com, e baixe a versão do seu sistema. Cuidado com sites que oferecem o "VS Code" para baixar em outros endereços.
  2. Windows: rode o instalador. Uma das opções do instalador adiciona o comando code ao terminal; vale deixá-la marcada.
  3. macOS: abra o arquivo baixado e arraste o aplicativo para a pasta Aplicativos.
  4. Linux (Ubuntu): baixe o pacote .deb e abra-o com a central de programas, ou instale pelo terminal com sudo snap install code --classic.
  5. Para o VS Code em português, instale a extensão de idioma Portuguese (Brazil) Language Pack (o próprio editor costuma oferecer isso na primeira vez que abre).
VSCodium

Existe uma versão do VS Code montada pela comunidade, o VSCodium, sem a coleta de dados de uso da Microsoft. Ela funciona igual para tudo o que este guia ensina.

Abrir a pasta do site

No VS Code, você abre a pasta do site inteira, e não um arquivo de cada vez. Use a opção de abrir pasta do menu Arquivo (File → Open Folder, no VS Code em inglês) e escolha a pasta do site. Os arquivos aparecem numa barra lateral, à esquerda; clique num para abri-lo. Pelo terminal, dá no mesmo entrar na pasta e digitar code . (o ponto quer dizer "esta pasta").

Na primeira vez, o VS Code pode perguntar se você confia nos autores dos arquivos da pasta. Como é a sua própria pasta, pode confirmar.

Criar a moldura com o Emmet: !

O VS Code traz embutido o Emmet, um atalho de digitação para HTML. Num arquivo novo terminado em .html, digite só um ponto de exclamação, !. O editor mostra uma sugestão do Emmet; aceite com Tab ou Enter, e o ! vira a moldura completa de uma página:

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>

</body>
</html>

O resultado está em branco porque o body, a parte que aparece na tela, está vazio: o cursor fica justamente ali, esperando o conteúdo. Cada linha é explicada em Estrutura de uma Página; aqui, repare em duas que você sempre precisa mudar:

lang="en"
Diz que a página está em inglês (English). Para uma página em português do Brasil, troque por lang="pt-BR". O navegador usa isso para escolher a pronúncia do leitor de tela, as regras de hifenização e a oferta de tradução.
<title>Document</title>
O título que aparece na aba do navegador e nos resultados do Google. "Document" não diz nada; troque pelo nome da página.

As outras linhas estão boas como estão. O UTF-8 em maiúsculas é o mesmo que o utf-8 que o guia usa (tanto faz). O meta name="viewport" faz a página funcionar bem no celular (aula Celular (meta viewport)), e os quatro espaços de recuo são o costume do VS Code. Dependendo da versão do Emmet, pode aparecer uma linha a mais, com X-UA-Compatible; ela era para o Internet Explorer e pode ser apagada.

Experimente: esta é a moldura do Emmet com um título no body. Faça as duas trocas de sempre: o idioma para pt-BR e o título da aba para Receitas da Ana. O resultado na tela não muda (nenhuma das duas coisas aparece no corpo da página), mas a missão confere as duas no DOM.

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>
    <h1>Receitas da Ana</h1>
</body>
</html>

<!DOCTYPE html>
<html lang="pt-BR">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Receitas da Ana</title>
</head>
<body>
    <h1>Receitas da Ana</h1>
</body>
</html>
Para o Emmet já escrever pt-BR

Nas configurações do VS Code (o arquivo settings.json do usuário), a opção "emmet.variables": { "lang": "pt-BR" } faz o ! sair com lang="pt-BR" daqui para a frente. O título continua sendo "Document", porque cada página tem o seu.

Outras abreviações do Emmet

O ! é só a mais famosa. O Emmet entende uma "taquigrafia" de HTML: você escreve a abreviação, aceita a sugestão e ele escreve as tags. Estas são as mais úteis no começo:

Você digitaO Emmet escreveLeia como
!A moldura completa da página"página nova"
p<p></p>o nome de uma tag vira a tag aberta e fechada
h1{Receitas da Ana}<h1>Receitas da Ana</h1>{ } = o texto de dentro
ul>li*3Um ul com três li vazios, cada um na sua linha> = "dentro de"; *3 = "três vezes"
a<a href=""></a>já com o atributo do endereço (aula Links)
img<img src="" alt="">já com o alt (aula Texto Alternativo)

O ul>li*3, por exemplo, sai assim, com o recuo de quatro espaços do VS Code:

<ul>
    <li></li>
    <li></li>
    <li></li>
</ul>

O resultado mostra três marcadores sem texto: a estrutura está pronta, falta o conteúdo. O Emmet é ótimo, mas não deixe ele pensar por você. No começo, digitar as tags inteiras ajuda a decorá-las; use o Emmet quando já souber o que ele vai escrever.

Ver a página enquanto edita: Live Server

Para ver o resultado, você salva no editor e recarrega o navegador (F5). Uma extensão muito usada faz o navegador recarregar sozinho a cada vez que você salva: a Live Server. Depois de instalá-la (pela área de extensões do VS Code), aparece um botão na barra de baixo do editor; ele liga um pequeno servidor e abre a página num endereço como http://127.0.0.1:5500/index.html. É o mesmo tipo de servidor local que você viu em Como o Navegador Lê HTML, só que com o recarregamento automático. A própria Microsoft tem uma extensão parecida, a Live Preview, que mostra a página dentro do editor.

4. Os cuidados com o arquivo

Qualquer que seja o editor, três coisas precisam estar certas no arquivo salvo.

Texto puro, com a extensão .html

O arquivo tem de ser texto puro (nada de Word) e terminar em .html. Os editores de código já fazem isso; nos editores simples, confira na hora de salvar o tipo do arquivo e o nome completo. Os detalhes de cada sistema estão na próxima aula, Criar e Abrir um Arquivo .html.

Codificação: UTF-8

Um arquivo de texto guarda cada letra como um ou mais números (bytes). A tabela que diz qual número é qual letra se chama codificação (encoding). Para o a sem acento, todas as tabelas concordam; para o ã, o é e o ç, não. A tabela de hoje, que tem as letras de todos os idiomas e até os emojis, é a UTF-8, e é a que a página declara com <meta charset="utf-8">. Se o editor salvar com outra tabela, a declaração mente e os acentos quebram.

Veja dois arquivos com o mesmo texto: um salvo em UTF-8 e outro numa tabela antiga, a ISO-8859-1 (também chamada de Latin-1, comum em editores e sistemas antigos). O comando file percebe a diferença:

$ file receita.html
receita.html: HTML document, ISO-8859 text          « salvo na tabela antiga
$ file receita-utf8.html
receita-utf8.html: HTML document, Unicode text, UTF-8 text

O receita.html diz <meta charset="utf-8">, mas foi salvo em ISO-8859. O validador encontra os bytes que não fazem sentido em UTF-8:

$ vnu receita.html
"file:/home/ana/site/receita.html":9.5-9.5: error: Malformed byte sequence: “e3”.
"file:/home/ana/site/receita.html":9.23-9.23: error: Malformed byte sequence: “e9”.
"file:/home/ana/site/receita.html":9.30-9.30: error: Malformed byte sequence: “e7”.
"file:/home/ana/site/receita.html":9.31-9.31: error: Malformed byte sequence: “fa”.

Malformed byte sequence = "sequência de bytes malformada". Os números e3, e9, e7 e fa são, na tabela antiga, o ã, o é, o ç e o ú da frase "Pão de queijo e café com açúcar.": quatro letras acentuadas, quatro erros. E o navegador, lendo como UTF-8, troca cada uma pelo símbolo de "caractere inválido", um losango com uma interrogação. Este é o parágrafo que um navegador de verdade (Chromium) montou com esse arquivo:

<p>P�o de queijo e caf� com a��car.</p>

O conserto é salvar o arquivo de novo em UTF-8. No VS Code, a codificação do arquivo aparece na barra de baixo (por exemplo, UTF-8 ou ISO 8859-1); clicando nela, há a opção de salvar com outra codificação. No terminal, o comando iconv converte de uma tabela para outra:

$ iconv -f latin1 -t utf-8 receita.html > receita-utf8.html     « -f: de (from); -t: para (to)
$ vnu --verbose receita-utf8.html
receita-utf8.html                                             « sem erros
$ sed -n 9p receita-utf8.html                                 « mostra a linha 9
<p>Pão de queijo e café com açúcar.</p>

Os editores modernos já salvam em UTF-8 por padrão. O problema aparece com arquivos vindos de sistemas antigos ou de editores configurados de outro jeito. Acentos e emojis têm aula própria: Acentos, UTF-8 e Emoji.

Salve antes de recarregar

O navegador mostra o arquivo que está no disco, e não o que está na tela do editor. Se você mudou o código e não salvou, recarregar a página mostra a versão antiga. A rotina é sempre: salvar (Ctrl + S) e depois recarregar (F5), ou deixar o Live Server recarregar por você.

Quando dá errado

Mudei o código e a página não mudou

O que significa: quase sempre, o arquivo não foi salvo (a bolinha na aba do VS Code denuncia). Outras causas: você está editando um arquivo e abriu outro no navegador (confira o nome na barra de endereço), ou o navegador guardou a versão antiga.

Como consertar: salve, recarregue com F5 e compare o caminho na barra de endereço com o arquivo aberto no editor. Se mesmo assim não mudar, recarregue ignorando a cópia guardada: Ctrl + Shift + R (Cmd + Shift + R no macOS).

Os acentos viraram � ou Ã£

O que significa: a codificação do arquivo não bate com a que o navegador usou. O losango � aparece quando o arquivo foi salvo numa tabela antiga e lido como UTF-8 (o caso acima, com Malformed byte sequence). Já pares estranhos como Ã£ no lugar de ã aparecem no caminho contrário: o arquivo está em UTF-8, mas o navegador foi levado a ler com uma tabela antiga, em geral porque falta o <meta charset="utf-8"> (aula Estrutura de uma Página).

Como consertar: salve o arquivo em UTF-8 e confira se o <meta charset="utf-8"> está no head.

O que significa: a página foi começada com o ! do Emmet e ficou com lang="en". Quando a página tem bastante texto, o validador percebe a língua e avisa: "este documento parece estar escrito em português, mas a tag html tem lang="en". Considere usar lang="pt" (ou uma variante)". <body>

    <p>Este site é o jeito que ela encontrou de dividir esse caderno com os amigos, os vizinhos e quem mais tiver vontade de cozinhar em casa, sem complicação e sem ingredientes difíceis de achar no mercado do bairro.</p>

$ vnu sobre.html; echo $?
"file:/home/ana/site/sobre.html":1.16-2.16: info warning: This document appears to be written in Portuguese but the “html” start tag has “lang="en"”. Consider using “lang="pt"” (or variant) instead.
0                                    « é um aviso: o código de saída continua 0

Numa página curta, com um título e uma frase, o validador não tem texto suficiente para adivinhar a língua e fica quieto. O erro continua lá: o leitor de tela vai ler o português com pronúncia de inglês.

Como consertar: lang="pt-BR" (a "variante" do português do Brasil). E configure o Emmet, como na dica acima, para não precisar lembrar.

O arquivo abre como texto, ou com o ícone errado

O que significa: o editor salvou com a extensão errada (index.txt, index.html.txt) ou num formato que não é texto puro (.docx, .rtf).

Como consertar: salve de novo como texto puro, com o nome terminando em .html. A próxima aula mostra como ver a extensão verdadeira no Windows e no macOS.

Missão final: o recuo que ajuda a ler

Missão: a lista está toda numa linha só. O navegador não liga (repare que o resultado já está certo), mas quem lê o código sofre. Deixe como o Emmet e o "formatar" do VS Code deixariam: o <ul> numa linha, cada <li> na sua linha, com alguns espaços de recuo na frente, e o </ul> na última linha.

<ul><li>Farinha</li><li>Ovos</li><li>Açúcar</li></ul>

<ul>
    <li>Farinha</li>
    <li>Ovos</li>
    <li>Açúcar</li>
</ul>

O recuo não muda nada na tela: espaços no começo da linha são ignorados pelo navegador (aula Espaços e Quebras de Linha). Ele existe para as pessoas: com ele, você vê de relance quem está dentro de quem.

Resumo

  • HTML é texto puro: qualquer editor de texto serve, mas um editor de código dá cores, fechamento automático de tags, autocompletar, formatação e atalhos. Processadores de texto (Word) não servem.
  • O guia recomenda o VS Code (gratuito, Windows, macOS e Linux). Baixe só do site oficial e abra a pasta do site, não um arquivo solto.
  • O Emmet transforma ! na moldura da página e ul>li*3 numa lista. Troque sempre o lang="en" por lang="pt-BR" e o <title>Document</title> pelo título certo.
  • A extensão Live Server recarrega o navegador sozinha a cada vez que você salva.
  • Boas alternativas: Notepad++, Sublime Text, Kate, Editor de Texto, nano, Vim, editores on-line. O arquivo final é o mesmo em todos.
  • Cuidados: texto puro, extensão .html, codificação UTF-8 (senão: Malformed byte sequence e �) e salvar antes de recarregar.
