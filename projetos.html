HTML Sobre os Projetos

Nas aulas, cada página ensina um assunto: um dia os títulos, outro dia as listas, outro as tabelas. Nos projetos, você junta tudo isso para fazer uma página de verdade, do arquivo vazio até a versão final, validada pelo W3C. É aqui que as peças se encaixam: o h1 da aula de títulos fica em cima de uma ul, que fica dentro de uma section, que tem um link para outra página do seu site. Esta página explica como os sete projetos estão organizados e como fazê-los.

Você vai aprender
  • Como os sete projetos estão montados (em versões pequenas, cada uma com um Experimente).
  • Que aulas cada projeto pratica e em que ordem fazê-los.
  • Como fazer cada versão: no editor do guia ou no seu computador.
  • Como conferir o seu trabalho com o validador do W3C.
  • O que fazer quando a sua página não fica igual à do projeto.

A ideia: montar a página como quem arruma uma casa nova

Quando alguém se muda, não arruma a casa inteira de uma vez. Primeiro põe a cama no quarto, para já poder dormir. Depois a mesa da cozinha. Depois as prateleiras, os quadros, as cortinas. Em cada etapa, a casa já dá para usar, só que com menos coisas.

Os projetos funcionam assim. Cada um é dividido em versões, e cada versão acrescenta uma coisa à anterior. No fim de toda versão, a página abre no navegador e está certa: você nunca fica com um monte de código pela metade.

Toda página de projeto segue o mesmo roteiro:

  1. O que vamos construir. A página pronta, desenhada pelo seu navegador, para você ver aonde vai chegar.
  2. Antes de começar. As aulas que você precisa ter visto (com links) e a pasta do projeto.
  3. As versões 1, 2, 3 e 4. Cada uma mostra o código, explica cada parte nova, mostra o resultado e termina com um Experimente em que você faz a versão.
  4. Quando dá errado. Os erros que aparecem de verdade naquele projeto: o que o navegador faz com eles e a mensagem do validador.
  5. A página completa e os desafios. A versão final, inteira, validada, e ideias para continuar sozinho.

Onde fazer: duas formas

1. No editor do guia (mais fácil)

Toda versão tem um Experimente que já começa com o código da versão anterior. Você edita, e o seu navegador desenha o resultado na hora, logo abaixo. Nas missões, o guia confere a página desenhada e diz se você chegou lá; se travar, dá para ver a solução. Veja como o editor funciona em O Editor do Guia.

No projeto do Portfólio, o site tem vários arquivos (index.html, sobre.html, contato.html e estilo.css). No editor, cada arquivo vira uma aba, e os links entre as páginas funcionam dentro do quadro.

Experimente agora. Esta é a primeira página de quase todo projeto: o esqueleto que você aprendeu em Estrutura de uma Página. Mude o nome e a frase, e veja o resultado mudar:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Currículo da Ana</title>
</head>
<body>
  <h1>Ana Costa</h1>
  <p>Confeiteira e dona de uma lojinha on-line. Estou aprendendo HTML.</p>
</body>
</html>
<!DOCTYPE html>
Avisa que é HTML de hoje (veja O DOCTYPE).
<html lang="pt-BR">
A página inteira, em português do Brasil. O leitor de tela usa o lang para pronunciar certo.
<meta charset="utf-8">
A tabela de letras do arquivo. Sem ela, os acentos podem virar símbolos estranhos (veja Acentos e UTF-8).
<meta name="viewport"…>
Deixa a página do tamanho certo no celular (veja meta viewport).
<title>
O nome da aba do navegador e do resultado no buscador.
<body>
O que aparece na tela.

2. No seu computador (o jeito "de verdade")

Para guardar o seu trabalho, crie uma pasta para cada projeto dentro de uma pasta sites, escreva os arquivos num editor de código (Editores mostra as opções) e abra o index.html no navegador (veja Criar e Abrir um Arquivo .html). Este é o terminal da Ana começando o currículo:

$ mkdir -p sites/curriculo           « cria a pasta do projeto (e a sites, se não existir)
$ cd sites/curriculo
$ ls                                  « vazia, por enquanto
$ ls                                  « a Ana escreveu o arquivo no editor e salvou
index.html

Depois de salvar, ela abre o arquivo no navegador (dois cliques no index.html, ou arrastando o arquivo para a janela). A barra de endereço mostra file:///home/ana/sites/curriculo/index.html: o navegador está lendo o arquivo direto do disco. Toda vez que mudar o código, salve e recarregue a aba (F5): o navegador não fica olhando o arquivo sozinho.

Conferir com o validador

O navegador quase nunca reclama de erro: ele conserta sozinho e desenha alguma coisa. Por isso, no fim de toda versão, a Ana confere a página com o validador do W3C (veja Validar o HTML). No terminal, é o comando vnu; na internet, é o site validator.w3.org/nu, com as mesmas mensagens.

$ vnu --verbose index.html
index.html                           « só o nome do arquivo: nenhum erro
$ echo $?
0                                    « 0 = deu tudo certo
vnu
O validador do W3C (o "Nu Html Checker"), o mesmo do validator.w3.org.
--verbose
"Falante": mostra o nome de cada arquivo que conferiu. Sem ele, uma página certa não mostra nada, e fica difícil saber se o comando rodou.
index.html
O arquivo a conferir. Dá para passar vários (vnu --verbose *.html).

Agora a Ana errou duas coisas de propósito: apagou o <title> e fechou o <h1> com </h2>. O navegador mostrou a página quase igual. O validador não deixou passar:

$ vnu --verbose index.html
index.html
"file:/home/ana/sites/curriculo/index.html":6.1-6.7: error: Element “head” is missing a required instance of child element “title”.
"file:/home/ana/sites/curriculo/index.html":8.16-8.20: error: End tag “h2” seen, but there were open elements.
$ echo $?
1                                    « 1 = encontrou erro
Parte da mensagemO que quer dizer
"file:/home/ana/sites/curriculo/index.html"O arquivo com o problema.
6.1-6.7Linha 6, da coluna 1 à coluna 7. É onde está o </head>: foi ali que o validador percebeu que o head acabou sem título.
errorUm erro de verdade. Um info warning é só um conselho.
Element “head” is missing a required instance of child element “title”."O elemento head está sem um filho obrigatório: o title."
End tag “h2” seen, but there were open elements."Vi um </h2>, mas havia elementos abertos": o h1 ainda estava aberto. O navegador fechou o h1 ali mesmo (para ele, qualquer </h1> a </h6> fecha o título aberto), e por isso a tela ficou igual. Outro navegador, ou outro erro parecido, poderia não ter essa sorte.

As mensagens do validador são em inglês. Em cada projeto, você vai ver as mensagens reais dos erros daquele projeto, explicadas em português. A lista completa está em Mensagens do Validador.

Como estudar um projeto

  1. Leia a versão inteira antes de digitar. Entenda o que muda e por quê.
  2. Digite o código, não copie e cole. Parece mais lento, mas é digitando que você esquece um </li>, vê o que acontece e aprende a consertar. Os erros mais comuns estão em Erros Comuns.
  3. Olhe o resultado e valide. Compare com o resultado mostrado na versão. Se a tela estiver igual, passe no validador mesmo assim: o navegador esconde erros.
  4. Mude alguma coisa. Troque um texto, um título, a ordem de uma lista. Preveja o que vai acontecer e confira: é o melhor exercício que existe.
  5. Só então vá para a próxima versão. No fim, tente os desafios sem olhar a solução.
"Mudei o código e a página não mudou"

Quase sempre é um destes:

  • O arquivo não foi salvo. Muitos editores mostram um ponto ou um asterisco no nome da aba quando há mudanças não salvas.
  • A aba não foi recarregada. Aperte F5 depois de salvar.
  • Você está editando um arquivo e abrindo outro. Confira na barra de endereço o caminho do arquivo aberto e compare com o que está no editor.
"Abri o arquivo e apareceu o código, não a página"

O arquivo não termina em .html. Alguns editores de texto simples salvam como index.html.txt, e alguns sistemas escondem o final do nome. O ls mostra o nome inteiro:

$ ls
index.html.txt                        « o navegador acha que é texto puro
$ mv index.html.txt index.html        « renomeia para .html
$ ls
index.html

No editor do guia isso não acontece: as abas já têm o nome certo.

"A minha página está igual à do projeto, mas o validador reclama"

É o caso mais comum, e é exatamente para isso que o validador existe. Leia a primeira mensagem com error, vá até a linha indicada e conserte; depois rode o vnu de novo. Muitas vezes um erro só gera vários avisos, e consertar o primeiro faz os outros sumirem. Veja como ler as mensagens em Validar o HTML.

Missão: o esqueleto de toda página

Todos os sete projetos começam do mesmo esqueleto. Monte-o agora, e você vai reconhecê-lo no topo de cada um.

Missão: a Ana escreveu só o conteúdo. Coloque em volta o esqueleto completo: o <!DOCTYPE html>, o <html lang="pt-BR">, um <head> com <meta charset="utf-8"> e o título Currículo da Ana, e o <body> com o conteúdo. Se precisar, revise Estrutura de uma Página.

<h1>Ana Costa</h1>
<p>Confeiteira e dona de uma lojinha on-line.</p>

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Currículo da Ana</title>
</head>
<body>
  <h1>Ana Costa</h1>
  <p>Confeiteira e dona de uma lojinha on-line.</p>
</body>
</html>

Repare que, mesmo sem o esqueleto, o código inicial já mostrava o título e o parágrafo: o navegador cria o html, o head e o body que faltam. Mas ele não tem como adivinhar o idioma, a tabela de letras e o nome da aba. Esse é o trabalho do esqueleto, e o validador cobra cada parte dele:

$ cat sem-esqueleto.html
<h1>Ana Costa</h1>
<p>Confeiteira e dona de uma lojinha on-line.</p>
$ vnu --verbose sem-esqueleto.html
sem-esqueleto.html
"file:/home/ana/sites/curriculo/sem-esqueleto.html":1.1-1.4: error: Start tag seen without seeing a doctype first. Expected “<!DOCTYPE html>”.
"file:/home/ana/sites/curriculo/sem-esqueleto.html":1.1-1.4: error: Element “head” is missing a required instance of child element “title”.
"file:/home/ana/sites/curriculo/sem-esqueleto.html":1.1-1.4: info warning: Consider adding a “lang” attribute to the “html” start tag to declare the language of this document.

Três avisos para três peças: o DOCTYPE ("vi uma tag sem ter visto um doctype antes"), o title e o lang ("considere acrescentar um atributo lang"). A meta charset não aparece porque o vnu lê o arquivo do disco em UTF-8; num servidor que diga outra coisa, os acentos quebram (veja Acentos e UTF-8).

Resumo

  • Cada projeto é construído em versões; no fim de cada versão, a página abre no navegador e passa no validador.
  • Sete projetos, em ordem de dificuldade: Currículo, Receita, Cardápio, Cadastro, Blog, Portfólio e Produto.
  • No editor do guia, o resultado aparece na hora; no seu computador, salve e recarregue a aba a cada mudança.
  • O navegador conserta os erros sem avisar; o validador (vnu --verbose ou validator.w3.org/nu) mostra a linha, a coluna e o motivo.
  • Leia a versão, digite, olhe o resultado, valide, mude algo, e só então siga.
