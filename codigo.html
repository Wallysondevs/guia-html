HTML Código

A Ana resolveu escrever no blog um tutorial: "como fiz o meu site". Agora ela precisa mostrar código na página, comandos que o leitor vai digitar e a resposta que o computador dá. O HTML tem cinco tags para isso: <code>, <pre>, <kbd>, <samp> e <var>. E tem uma pegadinha que todo mundo que escreve sobre HTML encontra: para mostrar uma tag na tela, você não pode escrevê-la como tag, senão o navegador a obedece. Esta é a aula que ensina a "escapar" o código.

Você vai aprender
  • <code>: um trecho de código no meio do texto.
  • <pre>: texto pré-formatado, que guarda os espaços e as quebras de linha.
  • <pre><code>: o bloco de código, e a pegadinha da indentação.
  • <kbd>: o que o leitor digita ou a tecla que ele aperta (Ctrl+C).
  • <samp>: a resposta de um programa. <var>: uma variável.
  • O escape: escrever &lt; no lugar de < e &amp; no lugar de &.
  • O que o navegador faz quando o escape falta: a tag "mostrada" vira tag de verdade.

Os exemplos são desenhados pelo seu navegador, no quadro "Resultado". As mensagens do validador saíram do vnu (o validador do W3C) na máquina fictícia da Ana, na pasta ~/site.

A ideia: a placa "não é para obedecer"

Imagine um professor de trânsito dando aula. Ele levanta uma placa de "PARE" para mostrar à turma como ela é. Ninguém na sala para de respirar: todo mundo entende que aquela placa está sendo mostrada, não dada como ordem.

O navegador não entende sozinho essa diferença. Se o texto da sua página tiver <h1>, ele obedece e cria um título. Para mostrar a "placa" sem que ela seja obedecida, você precisa avisar, trocando o < por um código especial (seção 6). E para deixar claro, para o leitor, que aquilo é código, você usa as tags desta aula, que normalmente aparecem numa letra de largura fixa (monospace), aquela em que o "i" ocupa o mesmo espaço que o "m", como numa máquina de escrever.

1. <code>: código no meio do texto

<p>Abra o arquivo <code>index.html</code> e procure o <code>&lt;h1&gt;</code>.</p>
<p>O comando <code>python3 -m http.server</code> liga um servidor local.</p>
<code>index.html</code>
Um nome de arquivo, marcado como código. O navegador troca a letra pela de largura fixa.
<code>&lt;h1&gt;</code>
Uma tag mostrada. No código está &lt;h1&gt;, e na tela aparece <h1>. O &lt; quer dizer "um sinal de menor, para mostrar" (less than, "menor que"), e o &gt;, "um sinal de maior" (greater than). A seção 6 explica.
<code>python3 -m http.server</code>
Um comando. (O comando em si é da aula Servidor Local.)

O <code> é um elemento em linha: fica dentro do parágrafo. Ele não guarda os espaços: como num parágrafo comum, vários espaços viram um e as quebras de linha somem. Para isso existe o <pre>.

2. <pre>: o texto exatamente como foi digitado

Lembra da aula Parágrafos, em que o navegador juntava os espaços e ignorava as quebras de linha? O <pre> é a exceção: dentro dele, cada espaço e cada quebra de linha aparecem na tela.

<pre>
Ingrediente      Quantidade
Cenoura          3
Ovos             3
Farinha          2 xícaras
</pre>
<pre>
Abre o texto pré-formatado. É um elemento de bloco, com a letra de largura fixa. Por causa dela, as colunas ficam alinhadas: cada letra ocupa o mesmo espaço.
a quebra de linha logo depois de <pre>
Uma regra especial: a primeira quebra de linha, logo depois do <pre>, é ignorada. Por isso você pode começar o texto na linha de baixo, como no exemplo, sem ganhar uma linha em branco no começo.
os espaços
Todos aparecem: os seis depois de "Ingrediente", os dez depois de "Cenoura".
</pre>
Fecha o bloco.
<pre> não quebra linha sozinho

Como o <pre> respeita as suas quebras de linha, ele também não cria outras: uma linha comprida continua para a direita, além da borda da tela, e no celular aparece uma barra de rolagem. Mantenha as linhas de um <pre> curtas. E não use <pre> para texto comum só para "guardar os espaços": isso é tarefa do CSS.

3. <pre><code>: o bloco de código

Para um bloco de código, junte os dois: o <pre> guarda as linhas e a indentação; o <code> diz que aquilo é código. É assim que quase todos os sites de programação mostram código.

<p>O começo do meu site:</p>
<pre><code>&lt;h1&gt;Receitas da Ana&lt;/h1&gt;
&lt;ul&gt;
  &lt;li&gt;Bolos&lt;/li&gt;
  &lt;li&gt;Tortas&lt;/li&gt;
&lt;/ul&gt;</code></pre>
<pre><code>
Abre os dois juntos, na mesma linha, com o código começando logo depois.
&lt;h1&gt;…
O código mostrado, com todo < trocado por &lt; e todo > por &gt;. Sem isso, o navegador criaria um título e uma lista de verdade (veja em Quando dá errado).
os dois espaços antes de &lt;li&gt;
A indentação do código, que o <pre> guarda.
</code></pre>
Fecha os dois, na ordem inversa, colados no fim do código.

A pegadinha da indentação

Dentro de um <pre>, todo espaço conta, inclusive os que você põe para deixar o seu próprio HTML arrumado. Se o <pre> estiver dentro de algo indentado, e você indentar as linhas do código junto, os espaços extras aparecem na tela:

<div>
  <pre><code>&lt;ul&gt;
      &lt;li&gt;Bolos&lt;/li&gt;
    &lt;/ul&gt;</code></pre>
</div>

A Ana quis manter o código "alinhado" com o <pre>, e o resultado saiu torto: o <li> com seis espaços, o </ul> com quatro. A regra: as linhas de dentro de um <pre> começam na margem esquerda do arquivo, mesmo que o resto do HTML esteja indentado.

4. <kbd>: o que você digita

O <kbd> marca o que a pessoa vai digitar ou a tecla que ela vai apertar:

<p>Para salvar, aperte <kbd>Ctrl</kbd>+<kbd>S</kbd>.</p>
<p>Para abrir as ferramentas do desenvolvedor, aperte <kbd>F12</kbd>.</p>
<p>No terminal, digite <kbd>ls</kbd> e aperte <kbd>Enter</kbd>.</p>
<kbd>Ctrl</kbd>+<kbd>S</kbd>
Uma combinação de teclas: cada tecla no seu <kbd>, e o + fora, como texto. O padrão do HTML também aceita embrulhar a combinação inteira em mais um <kbd>: <kbd><kbd>Ctrl</kbd>+<kbd>S</kbd></kbd>.
<kbd>ls</kbd>
Um comando que a pessoa digita.

Por padrão, o <kbd> aparece só com a letra de largura fixa, igual ao <code>. Muitos sites dão a ele, com CSS, a cara de uma tecla de verdade, com borda e sombra.

Experimente: a Ana marcou o atalho com <code>, mas são teclas. Troque por <kbd>, uma tecla em cada: Ctrl num <kbd>, C em outro, e o + no meio, fora deles.

<p>Para copiar, aperte <code>Ctrl+C</code>.</p>

<p>Para copiar, aperte <kbd>Ctrl</kbd>+<kbd>C</kbd>.</p>

5. <samp> e <var>: a resposta e a variável

O <samp> marca o que um programa responde: uma mensagem de erro, a saída de um comando. Para uma saída de várias linhas, coloque-o dentro de um <pre>, como no bloco de código:

<p>Digitei <kbd>lss</kbd> por engano, e o terminal respondeu <samp>bash: lss: comando não encontrado</samp>.</p>
<p>Com <kbd>ls</kbd>, apareceu:</p>
<pre><samp>index.html  receitas.html  sobre.html</samp></pre>

O <var> marca uma variável: um nome que representa um valor, numa fórmula ou num programa. O navegador o mostra em itálico.

<p>A área da mesa é <var>l</var> × <var>c</var>, a largura vezes o comprimento.</p>
<p>Troque <var>nome-do-arquivo</var> pelo nome do seu arquivo: <kbd>vnu <var>nome-do-arquivo</var></kbd>.</p>

No segundo parágrafo, o <var> está dentro do <kbd>: a pessoa digita vnu e, no lugar da parte em itálico, o nome do arquivo dela. É assim que muitos manuais mostram "a parte que você troca".

6. O escape: &lt; e &amp;

Agora a parte mais importante da aula. Para o navegador, o sinal < quer dizer "aqui começa uma tag", e o & quer dizer "aqui começa um código especial" (uma entidade). Para mostrar esses sinais, você escreve o código especial de cada um:

Para mostrarEscrevaNome
<&lt;less than, "menor que"
>&gt;greater than, "maior que"
&&amp;ampersand, o "e comercial"

Trocar um sinal pelo seu código se chama escapar (escape): o sinal "escapa" de ser lido como parte do HTML. Os três vêm com ponto e vírgula no fim. A lista completa de entidades está na aula Entidades.

Só três, e o mais importante é o <

Na prática, o > sozinho raramente confunde o navegador, mas escapá-lo junto deixa o código mais fácil de ler. Os que você sempre precisa escapar são o < e o &. Uma regra fácil: ao colar código dentro de <code> ou <pre>, troque primeiro todo & por &amp; e depois todo < por &lt; (nessa ordem, senão você estraga os &lt; que acabou de criar).

Para mostrar uma entidade (por exemplo, ensinar alguém a escrever &lt;), escape o & dela: no código vai &amp;lt;, e na tela aparece &lt;. Este guia inteiro é escrito assim.

Missão: a Ana quer mostrar a tag do título, mas o navegador criou um título de verdade no meio da página. Escape a tag que está dentro do <code> para ela aparecer como texto: <h1>Receitas</h1>.

<p>Para criar um título, escreva <code><h1>Receitas</h1></code> no seu arquivo.</p>

<p>Para criar um título, escreva <code>&lt;h1&gt;Receitas&lt;/h1&gt;</code> no seu arquivo.</p>

Quando dá errado

O navegador nunca mostra mensagem de erro. Em cada caso, veja no quadro "Resultado" o que ele fez de verdade.

A tag dentro de <code> sem escape 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<p>Para criar um parágrafo, escreva <code><p>Olá</p></code>.</p>
</body>
</html>

O que o navegador faz: ele não vê um exemplo; vê um parágrafo novo começando dentro do primeiro. Fecha o primeiro parágrafo (com um <code> vazio), abre outro com "Olá", deixa o ponto final solto e cria um parágrafo vazio no fim. Na tela, a frase quebra em duas, e as tags que a Ana queria mostrar sumiram. A página montada ficou assim:

<p>Para criar um parágrafo, escreva <code></code></p><p><code>Olá</code></p>.<p></p>

$ vnu semescape.html
"file:/home/ana/site/semescape.html":8.43-8.45: error: End tag “p” implied, but there were open elements.
"file:/home/ana/site/semescape.html":8.37-8.42: error: Unclosed element “code”.
"file:/home/ana/site/semescape.html":8.49-8.52: error: End tag “p” seen, but there were open elements.
"file:/home/ana/site/semescape.html":8.53-8.59: error: No “code” element in scope but a “code” end tag seen.
"file:/home/ana/site/semescape.html":8.61-8.64: error: No “p” element in scope but a “p” end tag seen.

Cinco erros numa linha só. O primeiro, "o fechamento do p ficou subentendido, mas havia elementos abertos", aponta as colunas 43 a 45: o <p> que a Ana queria mostrar. Quando o validador acusa uma tag dentro de um <code>, quase sempre é escape que faltou.

Como consertar: <code>&lt;p&gt;Olá&lt;/p&gt;</code>.

Código sem escape dentro de <pre> 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<pre><code><h1>Receitas da Ana</h1>
<p>Bolo de cenoura.</p></code></pre>
</body>
</html>

O que o navegador faz: o <pre> guarda os espaços, mas não desliga as tags. O <h1> e o <p> viram um título e um parágrafo de verdade, desenhados dentro do bloco. É um erro comum de quem acha que o <pre> "mostra tudo como está".

$ vnu presemescape.html
"file:/home/ana/site/presemescape.html":8.12-8.15: error: Element “h1” not allowed as child of element “code” in this context. (Suppressing further errors from this subtree.)
"file:/home/ana/site/presemescape.html":9.1-9.3: error: Element “p” not allowed as child of element “code” in this context. (Suppressing further errors from this subtree.)

Como consertar: escape cada < do código mostrado: &lt;h1&gt;Receitas da Ana&lt;/h1&gt;.

Um & sem escape que vira outra coisa 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<p>Em C: <code>if (a && b)</code> e <code>&copy</code> e <code>R&D</code></p>
</body>
</html>

O que o navegador faz: o && e o R&D saem certos, porque depois do & não vem um nome de entidade. Mas o &copy é o começo da entidade do símbolo de direitos autorais, e o navegador mostra © no lugar do que a Ana escreveu, mesmo sem o ponto e vírgula.

$ vnu ecomercial.html
"file:/home/ana/site/ecomercial.html":8.43-8.48: error: Named character reference was not terminated by a semicolon. (Or “&” should have been escaped as “&amp;”.)

"A referência de caractere com nome não terminou com ponto e vírgula. (Ou o & devia ter sido escapado como &amp;.)" O validador entendeu &copy como uma entidade mal escrita, e ele mesmo sugere o conserto. Os outros dois & passaram sem erro, mas não conte com a sorte: escape todos.

Como consertar: &amp;copy, e também &amp;&amp; e R&amp;D.

<pre> dentro de um parágrafo

O <pre> é um bloco, então o navegador fecha o parágrafo antes dele, e o </p> que sobra vira um parágrafo vazio, como você já viu com listas e citações. Com <p>O código:, um <pre>ls -l</pre> e o </p> na linha 10:

$ vnu prep.html
"file:/home/ana/site/prep.html":10.1-10.4: error: No “p” element in scope but a “p” end tag seen.

Como consertar: feche o parágrafo antes do <pre>: <p>O código:</p> e, depois, o <pre>.

<xmp> e <listing>: os antigos

Páginas muito antigas usam <xmp> (de example, "exemplo"), que mostrava as tags sem precisar de escape. O navegador ainda obedece, mas o validador recusa:

$ vnu xmp.html
"file:/home/ana/site/xmp.html":8.1-8.5: error: The “xmp” element is obsolete. Use “pre” or “code” element instead.
$ vnu listing.html
"file:/home/ana/site/listing.html":8.1-8.9: error: The “listing” element is obsolete. Use “pre” or “code” element instead.

"O elemento é obsoleto. Use o elemento pre ou code no lugar." O mesmo vale para o <tt> (aula Formatação).

Como consertar: <pre><code>, com o escape.

Resumo

  • <code> = código no meio da frase. <pre> = bloco que guarda espaços e quebras (e não quebra linhas compridas). Juntos, <pre><code>, fazem o bloco de código.
  • Dentro de <pre>, todo espaço conta: as linhas começam na margem do arquivo. A primeira quebra logo depois do <pre> é ignorada.
  • <kbd> = o que a pessoa digita ou a tecla (uma por kbd). <samp> = a resposta do programa. <var> = variável.
  • Nenhuma dessas tags desliga o HTML: para mostrar uma tag, escape. < vira &lt;, > vira &gt;, & vira &amp; (troque o & primeiro).
  • Sem escape, a tag mostrada vira tag de verdade (Element “h1” not allowed as child of element “code”), e um &copy vira ©.
  • <xmp>, <listing> e <tt> são obsoletos.
