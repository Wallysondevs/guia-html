HTML Botões (button)

Todo formulário termina num botão: "Enviar pedido", "Cadastrar", "Buscar". Mas nem todo botão envia. Alguns devolvem o formulário ao começo, outros só fazem alguma coisa na própria página, como somar mais um bolo ao pedido. Em HTML, todos eles são o mesmo elemento, o <button>, e quem decide o que cada um faz é o atributo type. Nesta aula você vai conhecer os três tipos, descobrir por que um botão esquecido sem type envia o formulário sem querer e ver o que o validador diz dos botões mal montados.

Você vai aprender
  • Como criar um botão com <button> e escrever o texto dele.
  • Os três tipos: submit (enviar), reset (voltar ao começo) e button (não fazer nada sozinho).
  • Por que o tipo padrão é submit, e a armadilha que isso cria.
  • Como dois botões de enviar dizem qual foi clicado, com name e value.
  • A diferença entre <button> e <input type="submit">, e entre um botão e um link.
  • Os erros mais comuns e as mensagens reais do validador W3C.

Você vai precisar de Formulários e O Elemento input. Os exemplos com o resultado embaixo são desenhados pelo seu navegador. Os comportamentos descritos ("o navegador envia…") foram conferidos no Chromium 155, e as validações com o validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: três botões no balcão

Imagine o balcão de encomendas da padaria, com uma fichinha de papel para a cliente preencher e três coisas ao lado:

  • a caixinha de entregar: a cliente põe a ficha ali e ela vai para a cozinha. É o submit ("enviar", "submeter");
  • uma ficha nova: joga fora o que foi escrito e começa de novo, do jeito que a ficha vinha impressa. É o reset ("redefinir", "voltar ao início");
  • uma campainha: não faz nada com a ficha; ela só toca, e alguém decide o que acontece quando ela toca. É o button comum, que só faz algo quando um script (JavaScript) manda.

1. O primeiro botão

O texto do botão vai entre <button> e </button>:

<form>
  <label for="nome">Seu nome:</label>
  <input type="text" id="nome" name="nome">
  <button type="submit">Enviar pedido</button>
</form>
<button
Começa o botão (button = "botão").
type="submit"
O tipo: este botão envia o formulário em que está.
Enviar pedido
O texto que aparece no botão. Escreva o que vai acontecer ("Enviar pedido"), e não só "OK" ou "Clique aqui": quem usa leitor de tela costuma pular de botão em botão e ouve só esse texto.
</button>
Fecha o botão. Ao contrário do <input>, o <button> tem tag de fechamento, porque tem conteúdo.

O navegador desenha o botão com a cara de botão do sistema: um retângulo com borda, que muda de cor quando o mouse passa e quando é apertado. Você pode clicar, ou chegar nele com Tab e apertar Enter ou Espaço. Tudo isso vem de graça: é a maior vantagem de usar um <button> de verdade.

2. submit: enviar o formulário

Um clique num botão submit faz o navegador juntar os campos do formulário (cada name com o seu valor) e mandar para o endereço do action. Antes de mandar, ele confere as regras de validação, como o required (aula Validação). Para onde e como vai é a aula Enviar (action, method, GET e POST).

Há um segundo jeito de enviar, que muita gente usa sem perceber: apertar Enter dentro de um campo de texto. O navegador procura o primeiro botão submit do formulário e age como se ele tivesse sido clicado. É por isso que, numa busca, você digita e aperta Enter.

O tipo padrão é submit

Aqui está o detalhe mais importante da aula. Se você não escrever o type, o botão é submit. Testamos no Chromium 155: um <button>Sem tipo</button> dentro de um formulário tinha o tipo submit e, clicado, enviou o formulário.

<form>
  <button>Enviar</button>           <!-- é submit -->
  <button type="submit">Enviar</button>   <!-- o mesmo, dito com todas as letras -->
</form>

Os dois são iguais. Mesmo assim, o guia sempre escreve o type: quem lê o código não precisa lembrar da regra, e você nunca cai na armadilha da seção 4.

3. reset: voltar ao começo

O botão reset devolve cada campo ao valor que ele tinha quando a página abriu. Experimente no resultado: mude a quantidade e o sabor e clique em Recomeçar.

<form>
  <label for="qtd">Quantidade:</label>
  <input type="number" id="qtd" name="qtd" value="1">
  <label for="sabor">Sabor:</label>
  <select id="sabor" name="sabor">
    <option>Cenoura</option>
    <option selected>Chocolate</option>
  </select>
  <button type="reset">Recomeçar</button>
</form>

A quantidade volta para 1, e não para vazio, e o sabor volta para Chocolate, a opção com selected (aula select e option). O reset não "limpa": ele restaura o value e o selected escritos no HTML. No Chromium 155, um campo com value="Ana", mudado para "Bia", voltou a "Ana" com o reset.

Pense duas vezes antes de pôr um reset

Quase ninguém precisa recomeçar um formulário do zero, mas muita gente clica em "Recomeçar" sem querer, achando que é o "Enviar", e perde tudo o que digitou. Não há como desfazer. Se usar, deixe o reset bem diferente do botão de enviar e longe dele. A maioria dos formulários de hoje não tem reset nenhum.

Missão: o botão de enviar só diz "OK". Troque o texto dele para Enviar pedido. Depois acrescente, no fim do formulário, um botão do tipo reset com o texto Recomeçar. Escreva um nome no campo e teste o reset.

<form>
  <label for="nome">Seu nome:</label>
  <input type="text" id="nome" name="nome">
  <button type="submit">OK</button>
</form>

<form>
  <label for="nome">Seu nome:</label>
  <input type="text" id="nome" name="nome">
  <button type="submit">Enviar pedido</button>
  <button type="reset">Recomeçar</button>
</form>

4. button: um botão que só faz o que um script manda

O type="button" é a campainha: sozinho, ele não envia nem recomeça nada. Ele existe para o JavaScript, a linguagem que dá comportamento à página (aula O Elemento script). Aqui, um script soma 1 cada vez que o botão é clicado:

<form>
  <p>Bolos no pedido: <span id="qtd">1</span></p>
  <button type="button" id="mais">Mais um</button>
</form>

<script>
  const qtd = document.querySelector("#qtd");
  document.querySelector("#mais").addEventListener("click", function () {
    qtd.textContent = Number(qtd.textContent) + 1;
  });
</script>

Clique algumas vezes em Mais um: o número sobe e nada mais acontece. Você não precisa entender o script agora; ele só diz "quando clicarem em #mais, some 1 ao número de #qtd".

A armadilha: o botão sem type dentro do formulário

Agora apague o type="button" e deixe só <button id="mais">. Como o tipo padrão é submit (seção 2), o clique faz duas coisas: soma 1 e envia o formulário. Num site de verdade, enviar recarrega a página, e o número volta para 1 logo depois de subir. Parece que o botão "não funciona", e o validador não acusa nada, porque o HTML é válido. É um dos erros mais comuns em formulários.

Missão: no cadastro da Ana, o botão Mostrar dicas é para um script (ele não deve enviar nada), e o Cadastrar envia o formulário. Nenhum dos dois tem type. Escreva o tipo certo em cada um.

<form>
  <label for="email">E-mail:</label>
  <input type="email" id="email" name="email">
  <button id="mostrar">Mostrar dicas</button>
  <button id="enviar">Cadastrar</button>
</form>

<form>
  <label for="email">E-mail:</label>
  <input type="email" id="email" name="email">
  <button type="button" id="mostrar">Mostrar dicas</button>
  <button type="submit" id="enviar">Cadastrar</button>
</form>

5. Dois botões de enviar: name e value

A ficha da Ana tem dois botões de enviar: um manda o pedido para a cozinha; o outro só guarda a ficha para a cliente terminar depois. Os dois enviam o mesmo formulário. Como quem recebe sabe qual foi clicado? Dê ao botão um name e um value, como um campo:

<form>
  <label for="nome">Seu nome:</label>
  <input type="text" id="nome" name="nome" value="Ana">
  <button type="submit" name="acao" value="enviar">Enviar pedido</button>
  <button type="submit" name="acao" value="rascunho">Salvar rascunho</button>
</form>

Só o botão clicado entra no envio. Testamos no Chromium 155: clicando em "Salvar rascunho", os dados enviados foram nome=Ana&acao=rascunho; clicando em "Enviar pedido", seriam nome=Ana&acao=enviar. Um botão sem name não manda nada de si mesmo, só dispara o envio.

E se a pessoa apertar Enter?

O Enter num campo age como um clique no primeiro botão submit do formulário. Por isso, ponha primeiro o botão principal ("Enviar pedido"), e não o secundário.

6. <button> ou <input type="submit">?

Antes do <button> existir, os botões eram feitos com o <input>, e você vai encontrá-los em muitos sites. Os três tipos existem lá também:

<form>
  <input type="submit" value="Enviar pedido">
  <input type="reset" value="Recomeçar">
  <input type="button" value="Mais um">
</form>

Com o <input>, o texto do botão é o atributo value, e não há tag de fechamento. Sem o value, um submit ou reset mostra um texto padrão escolhido pelo navegador, na língua dele (e um type="button" sem value fica vazio).

A grande diferença: o <button> pode ter outros elementos dentro, como um negrito ou uma imagem com alt. O <input> só tem o texto do value.

<button type="submit">Enviar <strong>agora</strong></button>
<button type="button"><span aria-hidden="true">🎂</span> Mais um bolo</button>
<strong>agora</strong>
Dentro do botão pode ir conteúdo "em linha" (o que caberia no meio de uma frase): strong, em, span, img. Não podem ir blocos como div e p, nem outro elemento clicável (outro botão, um link, um campo).
aria-hidden="true"
"Esconda do leitor de tela". O emoji é só enfeite, e sem isso o leitor de tela leria o nome dele ("bolo de aniversário") antes do texto (aula ARIA).

7. Botão desligado e botão fora do formulário

Com o atributo booleano disabled ("desabilitado"), o botão aparece apagado e não reage a cliques nem ao Tab:

<button type="submit" disabled>Enviar pedido</button>

Use com cuidado: um botão apagado não explica por que está apagado. Muitas vezes é melhor deixar clicar e mostrar o que falta (aula Validação).

Um botão submit só envia o formulário em que está dentro. Fora de qualquer <form>, ele não envia nada: no Chromium 155, um <button> solto tinha o tipo submit, mas nenhum formulário (form nulo). Se o desenho da página obriga o botão a ficar longe, o atributo form liga o botão ao formulário pelo id:

<form id="pedido">
  <label for="nome">Seu nome:</label>
  <input type="text" id="nome" name="nome">
</form>

<p>Confira tudo antes de enviar.</p>
<button type="submit" form="pedido">Enviar pedido</button>

Formas diferentes: qual usar?

Você quer…Use
enviar um formulário<button type="submit">
um botão para um script (somar, abrir, mostrar)<button type="button">
recomeçar o formulário (raramente)<button type="reset">
mexer num site antigo, que já usa <input type="submit">pode manter; funciona igual
ir para outra páginaum link, <a href="…"> (aula Links), e não um botão

A regra de ouro: link leva a um lugar, botão faz uma ação. "Ver o cardápio" é um link; "Enviar pedido" é um botão. Leitores de tela anunciam os dois de jeitos diferentes ("link", "botão"), e o teclado também os trata de forma diferente: um link é seguido com Enter, um botão é apertado com Enter ou Espaço. Se precisa parecer um botão, o link ganha cara de botão pelo CSS (quer aprender mais? futuro Guia CSS).

Quando dá errado

Os arquivos desta seção são páginas completas com o mesmo começo de 7 linhas (<!DOCTYPE html> até <body>, como em Estrutura de uma Página). O código mostrado começa na linha 8.

Tipo escrito errado: type="sumbit" 
<form>
  <button type="sumbit">Enviar</button>
</form>

$ vnu tipo.html
"file:/home/ana/site/tipo.html":9.3-9.24: error: Bad value “sumbit” for attribute “type” on element “button”.

O que significa: "valor ruim, sumbit, para o atributo type do elemento button". Só existem submit, reset e button.

O que o navegador faz: trata um tipo que ele não conhece como o padrão, submit. Neste caso deu certo por acaso. Mas um type="buton" (com um t só) também vira submit, e o botão do script passa a enviar o formulário.

Como consertar: corrija a palavra. O validador pega todo erro de digitação nos valores de type.

Botão dentro de botão 
<form>
  <button type="submit">Pedir <button type="button">ajuda</button></button>
</form>

$ vnu dentro.html
"file:/home/ana/site/dentro.html":9.31-9.52: error: Start tag “button” seen but an element of the same type was already open.
"file:/home/ana/site/dentro.html":9.67-9.75: error: Stray end tag “button”.

O que significa: o primeiro erro é "tag de abertura button encontrada, mas um elemento do mesmo tipo já estava aberto". O segundo, "tag de fechamento button perdida": sobrou um </button> que não fecha nada.

O que o navegador faz: ao ver o segundo <button>, ele fecha o primeiro e começa outro ao lado. No Chromium 155, o resultado foram dois botões irmãos, "Pedir " e "ajuda", e o último </button> foi jogado fora. É o navegador consertando sozinho, do jeito dele (aula Como o Navegador Lê HTML).

Como consertar: dois botões lado a lado, nunca um dentro do outro.

Botão dentro de um link 
<a href="carrinho.html"><button type="button">Ver carrinho</button></a>

$ vnu link.html
"file:/home/ana/site/link.html":8.25-8.46: error: The element “button” must not appear as a descendant of the “a” element.

O que significa: "o elemento button não pode aparecer dentro do elemento a". São duas coisas clicáveis, uma dentro da outra: o leitor de tela anuncia as duas, o Tab para duas vezes no mesmo lugar e não fica claro qual delas o clique aciona.

Como consertar: "Ver carrinho" leva a outra página, então é só um link: <a href="carrinho.html">Ver carrinho</a>.

Um bloco dentro do botão 
<button type="button"><div>Comprar</div></button>

$ vnu bloco.html
"file:/home/ana/site/bloco.html":8.23-8.27: error: Element “div” not allowed as child of element “button” in this context. (Suppressing further errors from this subtree.)

O que significa: "o elemento div não é permitido como filho de button neste contexto". Dentro do botão só vai conteúdo em linha.

Como consertar: troque o div por span, ou tire-o: <button type="button">Comprar</button> (aula div e span).

Um botão só com imagem, sem texto 
<button type="button"><img src="lixeira.png"></button>

$ vnu icone.html
"file:/home/ana/site/icone.html":8.23-8.45: error: An “img” element must have an “alt” attribute, except under certain conditions. For details, consult guidance on providing text alternatives for images.

O que significa: "um elemento img precisa ter o atributo alt". Aqui é mais grave do que numa imagem comum: a imagem é o único conteúdo do botão. Sem o alt, o botão não tem nome, e o leitor de tela anuncia só "botão". Botão de quê?

Como consertar: o alt diz a ação, e não o desenho: <img src="lixeira.png" alt="Apagar pedido"> (aula Texto Alternativo).

Um botão vazio, <button type="button"></button>, passa no validador sem nenhuma mensagem, e tem o mesmo problema. O validador não pega tudo: leia o seu botão como se você não o enxergasse.

O botão do script envia o formulário

Um <button> sem type dentro de um <form>, usado por um script. O HTML é válido, o validador fica quieto, mas cada clique também envia o formulário e a página recarrega (seção 4).

Como consertar: type="button". Melhor ainda: escreva o type em todo botão, sempre.

Resumo

  • <button> cria um botão; o texto vai entre as tags e deve dizer a ação ("Enviar pedido").
  • type="submit" envia o formulário, type="reset" restaura os valores do HTML (não "limpa"), type="button" não faz nada sem um script.
  • Sem type, o botão é submit: um botão de script sem type="button" envia o formulário sem querer. Escreva sempre o type.
  • name e value no botão dizem qual botão de enviar foi clicado; o Enter aciona o primeiro submit.
  • <button> aceita conteúdo em linha (strong, img com alt); <input type="submit"> só o texto do value.
  • Link leva a um lugar, botão faz uma ação. Nunca um botão dentro de um link, de outro botão ou com um div dentro.
