HTML canvas

O <canvas> é um quadro em branco dentro da página. Sozinho, ele não mostra nada: o HTML só pendura o quadro na parede e diz o tamanho dele. Quem desenha é o JavaScript, ponto por ponto, como uma mão com giz. Com ele se fazem gráficos, jogos, editores de foto e assinaturas digitais. Nesta aula você vai criar o quadro, fazer seus primeiros desenhos com um JavaScript bem pequeno (explicado linha a linha) e ver o que acontece quando algo dá errado.

Você vai aprender
  • O que é o canvas e quando ele é a ferramenta certa.
  • Os atributos width e height e o tamanho padrão (300 × 150).
  • O conteúdo alternativo, escrito entre <canvas> e </canvas>.
  • O mínimo de JavaScript para desenhar: getContext("2d"), retângulos, linhas, círculos e texto.
  • Como as coordenadas funcionam (o ponto 0,0 fica no canto de cima).
  • Como deixar o desenho acessível com role="img" e aria-label.
  • Os erros reais: width="300px", <canvas />, alt no canvas e o null no console.

Os arquivos desta aula foram conferidos com o validador W3C (vnu, o mesmo do validator.w3.org) na máquina da Ana (usuária ana, computador notebook), na pasta ~/site. Os desenhos você vê ao vivo: o seu próprio navegador roda cada exemplo.

A ideia: a lousa e o giz

Pense numa sala de aula. Antes da aula, alguém pendura a lousa na parede: escolhe onde ela fica e o tamanho dela. Depois, a professora pega o giz e desenha: um quadrado aqui, uma linha ali, uma palavra no canto.

Na sala de aulaNa páginaQuem faz
Pendurar a lousa e escolher o tamanho<canvas width="300" height="150">HTML
Pegar o gizgetContext("2d")JavaScript
DesenharfillRect(…), fillText(…)…JavaScript

Uma diferença importante: a lousa não lembra o que foi desenhado, só guarda os pontinhos de cor (os pixels). Depois de pintado, um quadrado não é mais "um quadrado" que você pode clicar ou mover: é só tinta. Isso deixa o canvas muito rápido para jogos e gráficos que mudam o tempo todo, mas tem um preço na acessibilidade, que você vai ver na seção 5.

1. O elemento canvas

O quadro mais simples tem uma id (para o JavaScript achá-lo depois), uma largura e uma altura:

<canvas id="quadro" width="300" height="150" style="border: 1px solid gray">
  Aqui haveria um desenho, mas o seu navegador não mostra canvas.
</canvas>
<canvas>
"Tela de pintura", em inglês: o quadro em branco. Tem tag de abertura e de fechamento; nunca escreva <canvas /> (veja em Quando dá errado).
id="quadro"
Um nome único na página. O JavaScript vai procurar o quadro por esse nome (aula class e id).
width="300"
Width = "largura", em pixels. Só o número, sem px. Sem o atributo, a largura é 300.
height="150"
Height = "altura", em pixels. Sem o atributo, a altura é 150.
style="border: 1px solid gray"
Só para você ver onde o quadro está. O canvas nasce transparente: sem a borda, o resultado acima seria um espaço vazio (aula O Atributo style).
Aqui haveria um desenho…
O conteúdo alternativo (fallback). Aparece só quando o navegador não pode desenhar: um navegador muito antigo ou com o JavaScript desligado. No seu navegador, ele fica escondido.

Repare no resultado: um retângulo vazio, e o texto de dentro não aparece. Isso está certo. Um navegador que entende canvas mostra o quadro e esconde o que está dentro dele; o conteúdo alternativo é para quem não pode ver o desenho.

Todos os navegadores entendem canvas

O canvas nasceu no Safari, da Apple, por volta de 2004, e entrou no HTML5. Hoje funciona em todos os navegadores atuais, de computador e de celular, há mais de dez anos. O conteúdo alternativo continua útil para quem desliga o JavaScript e para os leitores de tela.

2. O primeiro desenho: um retângulo

Agora entra o JavaScript. Ele fica num arquivo separado, o script.js, ligado pela tag <script src="script.js"> no fim do HTML, depois do canvas (o porquê está em Quando dá errado; a tag em si tem aula própria, O Elemento script).

Clique nas abas para ver os dois arquivos. O retângulo laranja do resultado foi desenhado agora pelo seu navegador:

<canvas id="quadro" width="300" height="150" style="border: 1px solid gray">
  Um retângulo laranja.
</canvas>
<script src="script.js"></script>

const quadro = document.getElementById("quadro");
const giz = quadro.getContext("2d");

giz.fillStyle = "orange";
giz.fillRect(20, 20, 120, 80);

São só quatro linhas de JavaScript. Uma por vez:

const quadro =
const cria uma "caixa com nome" (uma constante) chamada quadro. O que vem depois do = é guardado nela.
document.getElementById("quadro")
"Documento, pegue o elemento pela id quadro." Devolve o seu <canvas>. A id tem de ser igual à do HTML, com as mesmas maiúsculas e minúsculas.
quadro.getContext("2d")
"Quadro, me dê o seu giz de duas dimensões." O resultado se chama contexto: o objeto que sabe desenhar. Aqui ele foi guardado em giz; em outros sites você vai ver o nome ctx (de context).
giz.fillStyle = "orange"
Fill style = "estilo do preenchimento": a cor da tinta. Aceita nomes de cor em inglês ("red", "green", "blue") e códigos como "#ff8800".
giz.fillRect(20, 20, 120, 80)
Fill rectangle = "preencher retângulo". Os quatro números, na ordem: x (distância da esquerda), y (distância do topo), largura e altura, todos em pixels.
;
O ponto e vírgula termina cada instrução, como o ponto final de uma frase.

As coordenadas: o 0,0 fica em cima

Na escola, o gráfico tem o 0,0 embaixo, e o y cresce para cima. No canvas é diferente: o ponto 0,0 é o canto de cima à esquerda, o x cresce para a direita e o y cresce para baixo, como as linhas de um caderno.

PontoOnde fica num quadro de 300 × 150
(0, 0)canto de cima, à esquerda
(300, 0)canto de cima, à direita
(0, 150)canto de baixo, à esquerda
(150, 75)o centro

Então fillRect(20, 20, 120, 80) começa 20 pixels à direita da borda esquerda e 20 abaixo do topo, e se estende por 120 de largura e 80 de altura. O que passar da borda do quadro é simplesmente cortado.

Missão: pinte o retângulo de verde ("green") e mova-o para que ele comece no ponto x = 150, y = 50, sem mudar o tamanho. Veja no resultado se ele foi para o lugar que você imaginou.

<canvas id="quadro" width="300" height="150" style="border: 1px solid gray">
  Um retângulo colorido.
</canvas>
<script src="script.js"></script>

const quadro = document.getElementById("quadro");
const giz = quadro.getContext("2d");

giz.fillStyle = "orange";
giz.fillRect(20, 20, 120, 80);

O retângulo agora vai de x = 150 até x = 270 e de y = 50 até y = 130: cabe inteiro no quadro. Experimente também fillRect(250, 100, 120, 80) e veja o pedaço que sobra ser cortado.

3. Mais formas: contorno, linha, círculo e texto

O mesmo giz sabe fazer outras coisas. Cada exemplo abaixo usa só uma ou duas instruções novas.

Contorno de retângulo

O fill… pinta por dentro; o stroke… (stroke = "traço") desenha só a borda:

giz.strokeStyle = "blue";
giz.lineWidth = 4;
giz.strokeRect(20, 20, 120, 80);
strokeStyle
A cor do traço (a do preenchimento é a fillStyle).
lineWidth
"Largura da linha": a grossura do traço, em pixels.
strokeRect(x, y, largura, altura)
Desenha só a borda de um retângulo. Os números funcionam como no fillRect.

Uma linha reta

Linhas e outras formas livres se desenham como quem faz um desenho sem tirar o lápis do papel: você começa um caminho (path), leva o lápis a um ponto, risca até outro e, no fim, passa a tinta:

giz.beginPath();
giz.moveTo(20, 130);
giz.lineTo(280, 20);
giz.stroke();
beginPath()
"Começar caminho": avisa que um desenho novo vai começar.
moveTo(20, 130)
"Mover para": leva o lápis até o ponto (20, 130) sem riscar.
lineTo(280, 20)
"Linha até": risca do ponto atual até (280, 20). Por enquanto, o risco ainda está "a lápis", invisível.
stroke()
Passa a tinta por cima do caminho, com a strokeStyle e a lineWidth atuais. Sem ele, a linha não aparece.

Um círculo

Círculos são arcos que dão a volta completa. O arc recebe o centro, o raio e de onde até onde desenhar:

giz.fillStyle = "gold";
giz.beginPath();
giz.arc(150, 75, 40, 0, Math.PI * 2);
giz.fill();
arc(150, 75, 40, …)
Arc = "arco". O centro fica em (150, 75) e o raio é de 40 pixels.
0, Math.PI * 2
O começo e o fim do arco, medidos em radianos, a unidade de ângulo do JavaScript. 0 até Math.PI * 2 (2 × 3,14…) é a volta inteira; Math.PI sozinho seria meia volta.
fill()
Pinta o caminho por dentro com a fillStyle. Com stroke() no lugar, sairia só o contorno do círculo.

Texto

giz.fillStyle = "black";
giz.font = "20px sans-serif";
giz.fillText("Receitas da Ana", 20, 40);
font
O tamanho e a família da letra, escritos como no CSS: "20px sans-serif" = 20 pixels, uma letra sem serifa.
fillText("Receitas da Ana", 20, 40)
Escreve o texto. Atenção: o (20, 40) é o ponto da linha de base do texto, a linha onde as letras "pousam", e não o canto de cima. Com y = 0, o texto ficaria quase todo para fora do quadro.

Tudo junto: o sol da Ana

Aqui estão as quatro formas num desenho só. Mexa nos números, nas cores e no texto, e veja o resultado mudar:

<canvas id="quadro" width="300" height="150" style="border: 1px solid gray">
  Um sol amarelo sobre um chão verde, com a frase "Bom dia!".
</canvas>
<script src="script.js"></script>

const quadro = document.getElementById("quadro");
const giz = quadro.getContext("2d");

// o chão: um retângulo verde
giz.fillStyle = "green";
giz.fillRect(0, 120, 300, 30);

// o sol: um círculo amarelo
giz.fillStyle = "gold";
giz.beginPath();
giz.arc(230, 50, 30, 0, Math.PI * 2);
giz.fill();

// um raio de sol: uma linha
giz.strokeStyle = "orange";
giz.lineWidth = 3;
giz.beginPath();
giz.moveTo(195, 85);
giz.lineTo(170, 110);
giz.stroke();

// o texto
giz.fillStyle = "black";
giz.font = "24px sans-serif";
giz.fillText("Bom dia!", 20, 50);

console.log("Desenho pronto!");

Duas coisas novas no script.js:

  • As linhas que começam com // são comentários: o JavaScript ignora tudo dali até o fim da linha. Servem para você lembrar o que cada pedaço faz.
  • console.log("Desenho pronto!") escreve uma mensagem no console, que aparece embaixo do resultado. No navegador de verdade, o console fica nas Ferramentas do Desenvolvedor (F12). É lá que aparecem os erros de JavaScript.

A ordem importa: o que é desenhado depois fica por cima, como tinta sobre tinta. Mova o bloco do chão para o fim do arquivo e faça o sol descer até y = 120: o chão vai cobrir a metade de baixo do sol.

4. O tamanho: atributo × CSS

O width e o height do canvas definem quantos pixels o quadro tem por dentro, a "resolução" do desenho. Já o CSS (por exemplo, style="width: 600px") só muda o tamanho em que o quadro aparece na tela. Se os dois não combinam, o navegador estica o desenho, como uma foto pequena ampliada:

<p>Atributos: 150 × 75, mostrado com 150 de largura.</p>
<canvas class="placa" width="150" height="75" style="border: 1px solid gray">Texto "Ana"</canvas>

<p>Atributos: 150 × 75, mas o CSS manda mostrar com 300 de largura.</p>
<canvas class="placa" width="150" height="75" style="border: 1px solid gray; width: 300px">Texto "Ana"</canvas>

<script src="script.js"></script>

// desenha a mesma coisa nos dois quadros
for (const quadro of document.querySelectorAll(".placa")) {
  const giz = quadro.getContext("2d");
  giz.font = "40px sans-serif";
  giz.fillText("Ana", 20, 55);
}

O segundo "Ana" saiu maior e mais borrado: são os mesmos 150 × 75 pixels, esticados para o dobro. (O for … of repete o desenho para cada quadro com a classe placa; laços são assunto do JavaScript, não deste guia.)

Regra prática

Escolha o tamanho do canvas pelos atributos width e height. Se precisar mudar o tamanho com CSS, mantenha a mesma proporção e saiba que o desenho vai ser ampliado ou reduzido.

5. Acessibilidade: o desenho precisa de palavras

Para um leitor de tela (o programa que lê a página em voz alta para quem não enxerga), um canvas é uma caixa vazia: ele não sabe que ali tem um sol e um "Bom dia!". Lembre que o canvas guarda só pixels. Você tem três jeitos de ajudar, do mais simples ao mais completo:

  1. Um rótulo. role="img" diz "trate este quadro como uma imagem", e aria-label dá a descrição, como o alt de uma imagem (aulas Texto Alternativo e ARIA).
  2. O conteúdo alternativo. O texto (ou uma tabela, ou uma imagem) entre <canvas> e </canvas>. É o que aparece com o JavaScript desligado.
  3. O texto na própria página. Para um gráfico com números, escreva os números também num parágrafo ou numa tabela ao lado. Isso serve para todo mundo.
<canvas id="vendas" width="300" height="150" role="img"
        aria-label="Gráfico de barras: 12 bolos vendidos em maio e 20 em junho.">
  <p>Bolos vendidos: 12 em maio e 20 em junho.</p>
</canvas>

O resultado aparece vazio porque não há script.js desenhando as barras, mas o rótulo já está lá para o leitor de tela. Note que alt não existe no canvas: o validador recusa (veja abaixo).

Missão: o gráfico de vendas está "mudo". Coloque role="img" e um aria-label com a descrição no <canvas>, e escreva dentro dele um parágrafo com os números: <p>Bolos vendidos: 12 em maio e 20 em junho.</p>.

<canvas id="vendas" width="300" height="150" style="border: 1px solid gray"></canvas>
<script src="script.js"></script>

const quadro = document.getElementById("vendas");
const giz = quadro.getContext("2d");

giz.fillStyle = "steelblue";
giz.fillRect(60, 90, 60, 60);   // maio: 12
giz.fillRect(180, 50, 60, 100); // junho: 20

giz.fillStyle = "black";
giz.font = "16px sans-serif";
giz.fillText("maio", 70, 80);
giz.fillText("junho", 185, 40);

<canvas id="vendas" width="300" height="150" style="border: 1px solid gray" role="img"
        aria-label="Gráfico de barras: 12 bolos vendidos em maio e 20 em junho.">
  <p>Bolos vendidos: 12 em maio e 20 em junho.</p>
</canvas>
<script src="script.js"></script>

O desenho continua igual na tela: a mudança é invisível para quem enxerga e enorme para quem usa leitor de tela.

A página completa, conferida no validador

Nas caixas "Experimente", o código é só um pedaço da página. Num arquivo de verdade, o canvas fica dentro de uma página inteira, com <!DOCTYPE html>, lang, charset e title, e o script no fim do <body>:

<!DOCTYPE html>

</head>

$ vnu --verbose index.html

O --verbose ("falante") faz o vnu mostrar o nome de cada arquivo que ele conferiu; sem nenhuma linha de error depois, a página está válida. O validador confere só o HTML: ele não roda o script.js.

6. canvas, SVG ou img: qual usar?

Existem três jeitos de pôr um desenho na página. Cada um tem o seu lugar:

<img><svg><canvas>
O que éum arquivo de imagem pronto (foto, logo)um desenho descrito em tags (<circle>, <rect>)um quadro de pixels pintado pelo JavaScript
Precisa de JavaScript?nãonãosim
Ampliado, fica…borrado (JPG, PNG)nítidoborrado
Cada forma é um elemento?nãosim: dá para clicar e mudar cada umanão: depois de pintada, é só tinta
Acessibilidadealt<title> e texto de verdaderole="img", aria-label e conteúdo alternativo

Para um logo ou um ícone, prefira <img> ou SVG. Use o canvas quando o desenho é feito na hora pelo programa e muda muito, como um jogo.

Quando dá errado

Escrever width="300px"

O que o navegador faz: lê os algarismos do começo (300), para no p e segue em frente, sem avisar ninguém. O quadro fica com 300 de largura. Funciona por sorte: com width="50%", o navegador lê só o 50, e o quadro fica com 50 pixels, e não com metade da página.

O validador, com este index.html:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Desenho da Ana</title>
</head>
<body>
<canvas id="quadro" width="300px" height="150"></canvas>
</body>
</html>

$ vnu index.html
"file:/home/ana/site/index.html":8.1-8.47: error: Bad value “300px” for attribute “width” on element “canvas”: Expected a digit but saw “p” instead.

"Valor ruim “300px” para o atributo width no elemento canvas: esperava um algarismo, mas encontrou um “p”." Como consertar: só o número, width="300". Para tamanhos em porcentagem, use CSS e lembre da seção 4.

Fechar com <canvas />: o resto da página some

O que o navegador faz: no HTML, a barra do /> só vale para elementos vazios (como <img> e <br>). No canvas, ela é ignorada: a tag fica aberta, e tudo o que vem depois vira conteúdo alternativo do canvas. E o conteúdo alternativo fica escondido. Veja: o parágrafo sumiu do resultado.

<h1>Desenho da Ana</h1>
<canvas id="quadro" width="300" height="150" style="border: 1px solid gray" />
<p>Este parágrafo deveria aparecer embaixo do quadro.</p>

(Experimente trocar /> por ></canvas> e veja o parágrafo voltar.) O validador, com o mesmo código numa página completa, mostra três erros, todos vindos do mesmo engano:

</head>

<h1>Desenho da Ana</h1>
<canvas id="quadro" width="300" height="150" />

"file:/home/ana/site/index.html":11.1-11.7: error: End tag for  “body” seen, but there were unclosed elements.

Como consertar: sempre <canvas …></canvas>, com a tag de fechamento.

Usar alt no canvas

O que o navegador faz: nada. O alt é da <img>; no canvas ele é ignorado, e o leitor de tela continua sem descrição.

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Desenho da Ana</title>
</head>
<body>
<canvas id="quadro" width="300" height="150" alt="Um sol amarelo"></canvas>
</body>
</html>

$ vnu index.html
"file:/home/ana/site/index.html":8.1-8.66: error: Attribute “alt” not allowed on element “canvas” at this point.

"O atributo alt não é permitido no elemento canvas neste ponto." Como consertar: troque por role="img" aria-label="…" e escreva o conteúdo alternativo (seção 5).

No console: Cannot read properties of null (reading 'getContext')

O que significa: o getElementById não achou o canvas e devolveu null ("nada"). E "nada" não tem getContext. As duas causas mais comuns:

  • O <script> veio antes do <canvas>. O navegador lê a página de cima para baixo e roda o script assim que o encontra, quando o canvas ainda não existe.
  • A id está escrita diferente: id="Quadro" no HTML e "quadro" no JavaScript.

Aqui o script está antes do canvas. Veja o erro no console, embaixo do resultado:

<script src="script.js"></script>
<canvas id="quadro" width="300" height="150" style="border: 1px solid gray"></canvas>

const quadro = document.getElementById("quadro");
const giz = quadro.getContext("2d");
giz.fillStyle = "orange";
giz.fillRect(20, 20, 120, 80);

No Chrome, o erro completo é TypeError: Cannot read properties of null (reading 'getContext'): "erro de tipo: não dá para ler as propriedades de null (lendo getContext)". O Firefox diz a mesma coisa com outras palavras. O validador W3C não pega esse erro: o HTML está certo; o problema é a ordem.

Como consertar: ponha o <script src="script.js"> no fim, depois do canvas (ou use defer, assunto da aula Desempenho), e confira se a id é idêntica.

No console: Cannot set properties of null (setting 'fillStyle')

O que significa: desta vez o canvas foi achado, mas o getContext devolveu null. Quase sempre é o nome do contexto: tem de ser "2d", com d minúsculo. Com getContext("2D"), o navegador não reconhece o pedido e não entrega giz nenhum; o erro só aparece na linha seguinte, a do fillStyle.

Como consertar: escreva exatamente getContext("2d").

O desenho saiu borrado ou esticado

O que significa: o CSS mostra o canvas num tamanho diferente do width/height (seção 4). O validador não reclama, porque o HTML está certo.

Como consertar: ajuste os atributos width e height ao tamanho em que o quadro aparece, ou mantenha a proporção.

Missão final: a placa da lojinha

Missão: a Ana quer uma placa desenhada para o site.

  1. No index.html, crie um <canvas> com id="placa", 300 de largura e 100 de altura, role="img" e um aria-label com o texto da placa. Não esqueça a tag de fechamento.
  2. No script.js, pegue o contexto 2D, pinte um retângulo de fundo com fillRect e escreva "Lojinha da Ana" com fillText, numa cor diferente do fundo.
<h1>Lojinha da Ana</h1>
<!-- crie o canvas aqui -->

<script src="script.js"></script>

// 1. ache o canvas pela id

// 2. pegue o contexto 2D

// 3. pinte o fundo

// 4. escreva o texto

<h1>Lojinha da Ana</h1>
<canvas id="placa" width="300" height="100" role="img" aria-label="Placa: Lojinha da Ana">
  Lojinha da Ana
</canvas>

<script src="script.js"></script>

// 1. ache o canvas pela id
const placa = document.getElementById("placa");

// 2. pegue o contexto 2D
const giz = placa.getContext("2d");

// 3. pinte o fundo
giz.fillStyle = "darkred";
giz.fillRect(0, 0, 300, 100);

// 4. escreva o texto
giz.fillStyle = "white";
giz.font = "30px sans-serif";
giz.fillText("Lojinha da Ana", 30, 62);

Se o fundo cobriu o texto, lembre da ordem: primeiro o fundo, depois o texto. Se o texto não apareceu, confira se o y do fillText não é 0 (a linha de base ficaria no topo, e as letras, para fora).

Resumo

  • <canvas width="…" height="…"></canvas> cria um quadro transparente de pixels. Sem os atributos, ele tem 300 × 150. Os números vão sem px, e a tag de fechamento é obrigatória.
  • O HTML só cria o quadro; quem desenha é o JavaScript: getElementById acha o canvas, getContext("2d") dá o "giz", e fillRect, strokeRect, lineTo, arc e fillText desenham.
  • O ponto 0,0 fica no canto de cima à esquerda; o y cresce para baixo. O que é desenhado depois fica por cima.
  • O width/height são a resolução; o CSS só muda o tamanho na tela e pode esticar o desenho.
  • O canvas é mudo para leitores de tela: use role="img", aria-label e conteúdo alternativo (nunca alt).
  • Script antes do canvas ou id diferente dá Cannot read properties of null no console; o validador não vê esse erro.
  • Para logos e ícones, prefira img ou SVG; o canvas é para desenhos feitos na hora, como jogos e gráficos.
