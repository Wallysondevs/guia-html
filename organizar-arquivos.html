HTML Organizar os Arquivos

Um site de verdade não é um arquivo só: são várias páginas, uma folha de estilo, um script, um monte de fotos. Enquanto são três arquivos, tanto faz onde eles ficam. Com trinta, a pasta vira uma gaveta de bagunça, e os links começam a quebrar. Nesta aula a Ana arruma a pasta do site de receitas: escolhe nomes que funcionam em qualquer servidor, separa os arquivos em pastas, entende por que a primeira página se chama index.html e aprende a escrever os caminhos entre uma pasta e outra.

Você vai aprender
  • As regras para dar nome a arquivos de site (e o que acontece quando você as quebra).
  • Uma estrutura de pastas simples: css/, js/, img/ e uma pasta para as páginas.
  • Por que a página inicial se chama index.html.
  • Como escrever os caminhos entre pastas, com ../.
  • A ver a árvore de pastas com o comando tree e a validar o site inteiro com o vnu.

Os comandos desta aula rodaram na máquina fictícia da Ana (usuária ana, computador notebook, Ubuntu), na pasta ~/sites, com o tree 2.3.1, o validador W3C (vnu 26.10.12) e o servidor de teste do Python, que tem aula própria em Servidor Local. O que é terminal e como ele funciona está no Guia Bash; aqui basta ler os comandos e as saídas.

A ideia: a cozinha arrumada

Numa cozinha arrumada, os talheres ficam numa gaveta, as panelas noutro armário e os temperos numa prateleira, cada pote com etiqueta. Você acha qualquer coisa de olhos fechados, e qualquer pessoa que entra na cozinha também acha. Um site é igual: o navegador e o servidor precisam achar cada arquivo pelo nome exato e pelo caminho até ele.

A gaveta de talheres, o armário de panelasas subpastas: css/, js/, img/

Tudo misturado, e quase todo nome tem um problema: espaços, maiúsculas, acentos, parênteses, uma foto com o nome que a câmera deu, uma folha de estilo "antiga" que ninguém sabe se ainda é usada. No computador da Ana, tudo isso funciona. Num servidor de verdade, metade quebra. A próxima seção mostra por quê.

2. Nomes de arquivo que funcionam em qualquer lugar

O nome de um arquivo do site vira um pedaço do endereço dele na internet (a URL). E as URLs têm regras mais duras que as pastas do seu computador. Siga estas cinco regras e você nunca vai ter problema:

RegraRuimBomPor quê
1. Só minúsculasFoto.JPGfoto.jpgOs servidores (quase todos Linux) diferenciam A de a
2. Hífen no lugar de espaçosobre mim.htmlsobre-mim.htmlEspaço não é permitido em URL: vira %20
3. Sem acentos nem çPágina Inicial.htmlindex.htmlViram códigos como %C3%A1 e confundem programas
4. Só letras, números, - e .bolo FINAL (2).htmlbolo-de-cenoura.html( ) & # ? % têm significado especial em URLs
5. Nomes que descrevemIMG_20260315_142233.jpgbolo-de-cenoura.jpgVocê (e os buscadores) entendem o que é sem abrir

A maiúscula que vira 404

No Windows e no macOS, Pudim.jpg e pudim.jpg são o mesmo arquivo. No Linux, onde roda a maioria dos servidores, são dois nomes diferentes. Na pasta arrumada da Ana existe img/pudim.jpg, com p minúsculo:

$ ls img
bolo-de-cenoura.jpg
logo.svg
pudim.jpg
$ ls img/Pudim.jpg
ls: não foi possível acessar 'img/Pudim.jpg': Arquivo ou diretório inexistente

E o servidor responde do mesmo jeito. Com o servidor de teste ligado nessa pasta, o curl -I pede só o cabeçalho da resposta, a primeira linha diz se deu certo:

$ curl -sI http://localhost:8000/img/pudim.jpg | head -1
HTTP/1.0 200 OK
$ curl -sI http://localhost:8000/img/Pudim.jpg | head -1
HTTP/1.0 404 File not found
$ curl -sI http://localhost:8000/img/pudim.JPG | head -1
HTTP/1.0 404 File not found

200 OK quer dizer "achei, aqui está". 404 File not found quer dizer "arquivo não encontrado": no lugar da foto, o visitante veria o ícone de imagem quebrada. É o erro clássico de quem testou tudo no Windows e publicou: "no meu computador funcionava!". Com tudo minúsculo, esse problema nunca acontece.

O espaço que vira %20

Uma URL não pode ter espaço. A Ana copiou a foto antiga, com o nome da pasta bagunçada, para dentro de img/. Para pedir o arquivo Foto do Bolo.JPG, o endereço precisa trocar cada espaço por %20, e foi assim que ele apareceu no registro do servidor (o grep mostra só as linhas com "Foto"):

$ cp ~/sites/bagunca/"Foto do Bolo.JPG" img/      « só para o teste
$ curl -sI "http://localhost:8000/img/Foto%20do%20Bolo.JPG" | head -1
HTTP/1.0 200 OK
$ grep Foto ~/servidor.log
127.0.0.1 - - [17/Oct/2026 15:59:30] "HEAD /img/Foto%20do%20Bolo.JPG HTTP/1.1" 200 -

Funciona, mas é feio, fácil de errar e o validador reclama quando o espaço aparece direto no href (veja Quando dá errado). Use hífen.

Depois da arrumação, a pasta ficou assim. O comando tree ("árvore") desenha as pastas e o que há dentro de cada uma:

│   └── script.js

5 directories, 9 files
.
O ponto é "a pasta onde estou": a raiz do site, ~/sites/receitas. Tudo que o site precisa mora aqui dentro.
index.html
A página inicial, sempre na raiz (seção 5).
sobre.html
Uma página avulsa, também na raiz.
css/
As folhas de estilo (aula Ligar CSS).
js/
Os scripts (aula O Elemento script).
img/
As imagens. Muitos sites chamam de images/ ou juntam tudo em assets/ ("recursos"); o nome não importa, desde que você use sempre o mesmo.
receitas/
Uma pasta para um grupo de páginas: cada receita é uma página.
5 directories, 9 files
"5 pastas, 9 arquivos". O tree conta também a própria raiz (o .), por isso são 5, e não 4.

Outras formas de ver a árvore

Num site grande, a árvore inteira fica enorme. Três opções do tree ajudam:

$ tree -L 1

├── img
├── index.html
├── js
├── receitas
└── sobre.html

5 directories, 2 files
$ tree -d
.
├── css
├── img
├── js
└── receitas

5 directories
$ tree --dirsfirst
.
├── css
│   └── estilo.css
├── img
│   ├── bolo-de-cenoura.jpg
│   ├── logo.svg
│   └── pudim.jpg
├── js
│   └── script.js
├── receitas
│   ├── bolo-de-cenoura.html
│   └── pudim.html
├── index.html
└── sobre.html

5 directories, 9 files
  • -L 1 ("level", nível 1): só o primeiro andar, sem entrar nas pastas.
  • -d ("directories"): só as pastas.
  • --dirsfirst: as pastas primeiro, os arquivos depois.
Sem o tree

No Ubuntu, se o comando não existir, instale com sudo apt install tree. No Windows, o Prompt de Comando tem um tree /f parecido. E o painel de arquivos do VS Code (aula Editores) mostra a mesma árvore, com setinhas para abrir e fechar as pastas.

4. Caminhos entre pastas

Com as pastas, cada link precisa dizer onde está o arquivo, a partir da página que tem o link. Este é o assunto da aula Caminhos Relativos e Absolutos; aqui vão os dois casos que todo site organizado usa.

De uma página na raiz

O index.html está na raiz. Para ele, a folha de estilo está "na pasta css, arquivo estilo.css":

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
<link rel="stylesheet" href="css/estilo.css">
</head>
<body>
<h1>Receitas da Ana</h1>
<img src="img/logo.svg" alt="Logo das Receitas da Ana" width="100" height="100">
<ul>
  <li><a href="receitas/bolo-de-cenoura.html">Bolo de cenoura</a></li>
  <li><a href="receitas/pudim.html">Pudim</a></li>
</ul>
<p><a href="sobre.html">Sobre a Ana</a></p>
<script src="js/script.js"></script>
</body>
</html>

De uma página dentro de uma pasta

O pudim.html mora em receitas/. Para ele, css/estilo.css significaria "a pasta css dentro de receitas", que não existe. Ele precisa primeiro subir uma pasta, com ../ ("a pasta de cima"):

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Pudim | Receitas da Ana</title>
<link rel="stylesheet" href="../css/estilo.css">
</head>
<body>
<h1>Pudim</h1>
<img src="../img/pudim.jpg" alt="Pudim de leite com calda de caramelo" width="400" height="300">
<p><a href="../index.html">Voltar ao início</a></p>
<script src="../js/script.js"></script>
</body>
</html>
Na página…para chegar em…escreva
index.htmlcss/estilo.csscss/estilo.css

receitas/pudim.htmlcss/estilo.css../css/estilo.css

receitas/pudim.htmlreceitas/bolo-de-cenoura.htmlbolo-de-cenoura.html (mesma pasta)

Se o pudim.html usasse href="css/estilo.css", o navegador pediria /receitas/css/estilo.css. Foi o que a Ana testou no servidor:

$ curl -sI http://localhost:8000/receitas/css/estilo.css | head -1
HTTP/1.0 404 File not found
$ curl -sI http://localhost:8000/css/estilo.css | head -1
HTTP/1.0 200 OK

Nenhuma mensagem aparece na página: o pudim só fica sem estilo. Quem conta o 404 é o F12, na aba de rede (aula Ferramentas do Desenvolvedor).

No editor do guia, as abas podem ter pastas no nome (css/estilo.css, receitas/pudim.html) e funcionam como um site de verdade: um caminho errado não acha o arquivo, e um link errado mostra uma página "404: página não encontrada".

5. A porta de entrada: index.html

Quando alguém digita só o endereço do site, sem nome de arquivo (http://localhost:8000/, ou https://ana.example/), o servidor procura na pasta um arquivo chamado index.html ("índice") e entrega esse. É uma convenção de quase todos os servidores, inclusive o GitHub Pages (aula Publicar):

$ curl -s http://localhost:8000/ | head -5
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>

O endereço terminou em / e veio o index.html. E numa pasta sem index.html? O servidor de teste do Python mostra a lista de arquivos da pasta:

$ curl -s http://localhost:8000/img/
<!DOCTYPE HTML>
<html lang="en">
<head>
<meta charset="utf-8">
<style type="text/css">
:root {
color-scheme: light dark;
}
</style>
<title>Directory listing for /img/</title>
</head>
<body>
<h1>Directory listing for /img/</h1>
<hr>
<ul>
<li><a href="bolo-de-cenoura.jpg">bolo-de-cenoura.jpg</a></li>
<li><a href="logo.svg">logo.svg</a></li>
<li><a href="pudim.jpg">pudim.jpg</a></li>
</ul>
<hr>
</body>
</html>

"Directory listing" é "lista do diretório": uma página que o próprio servidor montou, com um link para cada arquivo. Outros servidores fazem diferente: o GitHub Pages, por exemplo, responde 404. Por isso:

  • a página inicial do site se chama index.html, em minúsculas, na raiz;
  • Index.html, index.htm, home.html ou Página Inicial.html não servem de porta de entrada.
Endereços bonitos com index.html

Alguns sites dão a cada página uma pasta com um index.html dentro: receitas/pudim/index.html. Assim, o endereço fica /receitas/pudim/, sem o .html no fim. Funciona porque o servidor procura o index.html em toda pasta, não só na raiz.

6. Validar o site inteiro

O vnu aceita vários arquivos de uma vez. O asterisco (*.html) quer dizer "todos os arquivos terminados em .html" desta pasta, e receitas/*.html, os da pasta receitas:

$ vnu --verbose *.html receitas/*.html
index.html
sobre.html
receitas/bolo-de-cenoura.html
receitas/pudim.html

Com --verbose, ele mostra o nome de cada arquivo conferido; sem nenhuma outra linha, nenhum erro. Dá também para passar a pasta (.), mas aí ele tenta ler todo arquivo como HTML, inclusive o CSS e as fotos:

$ vnu . 2>&1 | head -3
"file:/home/ana/sites/receitas/./css/estilo.css":1.1-3.1: error: Non-space characters found without seeing a doctype first. Expected “<!DOCTYPE html>”.
"file:/home/ana/sites/receitas/./css/estilo.css":1.1-3.1: error: Element “head” is missing a required instance of child element “title”.
"file:/home/ana/sites/receitas/./css/estilo.css":1.1-3.1: info warning: Consider adding a “lang” attribute to the “html” start tag to declare the language of this document.

Erros falsos: um arquivo CSS não tem <!DOCTYPE html>, e nem deveria. A opção --skip-non-html ("pule o que não é HTML") resolve; o validador só avisa, como info warning, cada arquivo que pulou:

$ vnu --skip-non-html --verbose .
"file:/home/ana/sites/receitas/./css/estilo.css": info warning: File was not checked. Files must have .html, .xhtml, .htm, or .xht extensions.
"file:/home/ana/sites/receitas/./img/logo.svg": info warning: File was not checked. Files must have .html, .xhtml, .htm, or .xht extensions.
"file:/home/ana/sites/receitas/./img/bolo-de-cenoura.jpg": info warning: File was not checked. Files must have .html, .xhtml, .htm, or .xht extensions.
./receitas/bolo-de-cenoura.html
./receitas/pudim.html
"file:/home/ana/sites/receitas/./img/pudim.jpg": info warning: File was not checked. Files must have .html, .xhtml, .htm, or .xht extensions.
./sobre.html
./index.html
"file:/home/ana/sites/receitas/./js/script.js": info warning: File was not checked. Files must have .html, .xhtml, .htm, or .xht extensions.

"Arquivo não conferido. Os arquivos precisam ter as extensões .html, .xhtml, .htm ou .xht." As quatro páginas passaram. (A ordem embaralhada é normal: o validador confere vários arquivos ao mesmo tempo.)

Quando dá errado

A Ana juntou num arquivo os caminhos que vinham do jeito Windows de pensar:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Erros de caminho</title>
<link rel="stylesheet" href="css\estilo.css">
</head>
<body>
<img src="C:\Users\Ana\Desktop\site\img\bolo.jpg" alt="Bolo">
<img src="file:///C:/Users/Ana/Desktop/site/img/bolo.jpg" alt="Bolo">
<a href="sobre mim.html">Sobre</a>
<a href="Página Inicial.html">Início</a>
</body>
</html>

$ vnu barra.html
"file:/home/ana/sites/bagunca/barra.html":6.1-6.45: error: Bad value “css\estilo.css” for attribute “href” on element “link”: Backslash ("\") used as path segment delimiter.
"file:/home/ana/sites/bagunca/barra.html":9.1-9.61: error: Bad value “C:\Users\Ana\Desktop\site\img\bolo.jpg” for attribute “src” on element “img”: Illegal character after “c:”. “\” is not allowed.
"file:/home/ana/sites/bagunca/barra.html":11.1-11.25: error: Bad value “sobre mim.html” for attribute “href” on element “a”: Illegal character in path segment. Space is not allowed.
"file:/home/ana/sites/bagunca/barra.html":12.1-12.30: error: Bad value “Página Inicial.html” for attribute “href” on element “a”: Illegal character in path segment. Space is not allowed.
Backslash ("\") used as path segment delimiter.

O que significa: "Barra invertida usada para separar as pastas do caminho". O Windows separa pastas com \; a web, sempre com /. O navegador até costuma trocar uma pela outra, mas o validador acusa, e outros programas não perdoam.

Como consertar: href="css/estilo.css", com a barra normal.

Illegal character after “c:”. “\” is not allowed. (e o file:///C:/ que passou)

O que significa: o caminho aponta para uma pasta do computador da Ana (C:\Users\Ana\Desktop). O validador recusou a versão com \. A versão file:///C:/… é uma URL bem escrita e passou, mas é ainda mais traiçoeira: no computador da Ana, a imagem aparece; no site publicado, o navegador do visitante procura um C: no computador dele, e não acha nada. Isso acontece quando você arrasta uma imagem para dentro do editor e ele escreve o caminho completo.

Como consertar: use sempre caminhos relativos à página (img/bolo.jpg), com a imagem dentro da pasta do site.

Illegal character in path segment. Space is not allowed.

O que significa: "Caractere ilegal num pedaço do caminho. Espaço não é permitido." O navegador consegue abrir o link (ele troca o espaço por %20 sozinho), mas o endereço não é válido. O acento de Página não foi o problema aqui (o validador aceita letras acentuadas), e sim o espaço.

Como consertar: renomeie o arquivo (sobre-mim.html, index.html) e o link junto.

"No meu computador funciona, no servidor a imagem não aparece"

O que significa: quase sempre, uma diferença de maiúscula: o arquivo é Foto.JPG e o código diz foto.jpg, ou o contrário. O Windows e o macOS não ligam; o servidor Linux responde 404 File not found, como na seção 2. O validador não pega esse erro, porque ele não confere se o arquivo existe.

Como consertar: renomeie todos os arquivos para minúsculas e confira os nomes no código. Testar num servidor local (aula Servidor Local) no Linux ajuda a pegar o erro antes de publicar.

Resumo

  • Nomes de arquivo: minúsculas, hífen no lugar de espaço, sem acentos, só a-z, 0-9, - e ., e nomes que descrevem o conteúdo.
  • O servidor Linux diferencia maiúsculas: Pudim.jpg ≠ pudim.jpg dá 404 File not found, e o validador não pega.
  • Uma estrutura simples: páginas na raiz (ou numa pasta de páginas) e css/, js/, img/. O tree mostra a árvore.
  • A página inicial é o index.html da raiz: o servidor a entrega quando o endereço termina em /.
  • De uma página numa subpasta, suba com ../: ../css/estilo.css. Barras sempre /, nunca \, e nunca caminhos do seu computador (C:\…, file:///).
  • Valide o site inteiro com vnu *.html pasta/*.html ou vnu --skip-non-html ..
