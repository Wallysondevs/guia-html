Projeto Portfólio

Até aqui, cada projeto era uma página só. Um site de verdade tem várias: a Ana quer um portfólio com a página inicial (os bolos que já fez), uma página sobre ela e uma de contato. As três se ligam por um menu e usam o mesmo arquivo de CSS. Neste projeto você aprende a pensar em arquivos e pastas: como uma página encontra a outra, por que um nome com letra maiúscula funciona no seu computador e quebra quando o site é publicado, e como testar tudo num servidor local antes de publicar.

Você vai praticar
  • Ligar páginas com caminhos relativos (href="sobre.html") e repetir o menu em todas (Links, nav).
  • Organizar os arquivos de um site numa pasta (Organizar os Arquivos).
  • Ligar um arquivo de CSS a todas as páginas com <link> (Ligar CSS).
  • Marcar a página atual no menu com aria-current="page" (ARIA).
  • Testar o site num servidor local e validar todas as páginas e o CSS de uma vez (Servidor Local, Validar).

"Sobre.html" com S maiúsculo: funciona no computador, quebra no servidor

A Ana salvou o arquivo como sobre.html, mas no menu escreveu href="Sobre.html". Ela testou no notebook dela (com Windows) e funcionou. Depois de publicar, o link deu erro. O que aconteceu? Muitos computadores com Windows ou macOS não diferenciam maiúsculas de minúsculas nos nomes de arquivo; os servidores (quase sempre Linux, como o do GitHub Pages) diferenciam: para eles, Sobre.html e sobre.html são dois arquivos diferentes. Um servidor local, na máquina da Ana com Linux, mostra o problema antes de publicar:

$ python3 -m http.server &
[1] 4
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
$ curl -sI http://localhost:8000/sobre.html | head -n 1
127.0.0.1 - - [17/Oct/2026 16:11:13] "HEAD /sobre.html HTTP/1.1" 200 -
HTTP/1.0 200 OK                                « o arquivo existe
$ curl -sI http://localhost:8000/Sobre.html | head -n 1
127.0.0.1 - - [17/Oct/2026 16:11:13] code 404, message File not found
127.0.0.1 - - [17/Oct/2026 16:11:13] "HEAD /Sobre.html HTTP/1.1" 404 -
HTTP/1.0 404 File not found                    « com S maiúsculo, não
$ kill %1                                      « desliga o servidor
python3 -m http.server &
Liga um servidor de arquivos na pasta atual, na porta 8000 (veja Servidor Local). O & o deixa rodando "nos bastidores", para o terminal continuar livre.
curl -sI http://localhost:8000/sobre.html
Pede o arquivo ao servidor e mostra só o cabeçalho da resposta (-I), sem a barra de progresso (-s). No navegador, seria abrir o mesmo endereço.
| head -n 1
Mostra só a primeira linha da resposta: o código. 200 OK = achou; 404 File not found = não achou.
127.0.0.1 - - […] "HEAD /Sobre.html HTTP/1.1" 404 -
O registro do próprio servidor: quem pediu, o quê e o que ele respondeu.

O validador também não ajuda aqui: Sobre.html é um endereço válido. Como consertar: nomes de arquivo sempre em minúsculas, sem acento e sem espaço (sobre.html, contato.html), e os href copiados exatamente iguais.

Copiar o menu em cada página?

Sim: o HTML não tem um jeito de "incluir" um pedaço de outro arquivo. Num site de três páginas, copiar é o mais simples. Sites grandes usam programas que montam as páginas a partir de um modelo (os "geradores de sites estáticos"), mas o resultado final é o mesmo: cada página com o seu menu completo.

Nada de href="/sobre.html"

Com a barra no começo, o caminho passa a ser contado a partir da raiz do servidor, e não da pasta da página. No GitHub Pages, um projeto fica em https://seu-usuario.github.io/portfolio/, e /sobre.html vai procurar em https://seu-usuario.github.io/sobre.html, fora do seu site. No seu computador, aberto com dois cliques, procura na raiz do disco. Use caminhos relativos (veja Caminhos).

Versão 3 · Um CSS para todas as páginas

A Ana quer o título em laranja, o texto numa coluna confortável e o menu em linha. Se escrevesse o CSS num <style> em cada página, teria de mudar três arquivos a cada ajuste. Em vez disso, o CSS vai num arquivo próprio, estilo.css, e cada página o "chama" com um <link> no head. É como o uniforme de uma loja: muda o uniforme, mudam todos os funcionários.

body {
  font-family: sans-serif;
  max-width: 40em;
  margin: 0 auto;
  padding: 0 1em;
}

h1 {
  color: #b5541c;
}

nav ul {
  list-style: none;
  padding: 0;
  display: flex;
  gap: 1em;
}

nav a[aria-current="page"] {
  font-weight: bold;
  text-decoration: none;
}
<link rel="stylesheet" href="estilo.css">
No head de cada página. rel="stylesheet" ("folha de estilo") diz o que o arquivo é; href, onde ele está: mais um caminho relativo.
body { max-width: 40em; margin: 0 auto; }
O texto numa coluna de cerca de 40 letras de largura, no meio da tela.
nav ul { list-style: none; display: flex; }
Tira as bolinhas da lista do menu e põe os itens lado a lado. A lista continua sendo lista para o leitor de tela; só o visual mudou.

O CSS é assunto de outro guia (quer aprender mais? futuro Guia CSS). Aqui, o que importa é o <link>: uma linha de HTML que liga um arquivo ao outro.

O CSS numa pasta que não existe

A Ana viu em outro site o costume de guardar o CSS numa pasta css e escreveu <link rel="stylesheet" href="css/estilo.css">, mas deixou o arquivo na pasta principal. A página aparece sem estilo nenhum, com o visual padrão do navegador, e o validador não reclama (o endereço é válido). No editor do guia, o console embaixo do quadro avisa que não conseguiu carregar o arquivo. No terminal:

$ ls css/estilo.css
ls: não foi possível acessar 'css/estilo.css': Arquivo ou diretório inexistente

Como consertar: o href tem de seguir o caminho real do arquivo. Ou o <link> aponta para estilo.css, ou o arquivo vai para dentro de uma pasta css (e então todas as páginas usam css/estilo.css). No F12, a aba de rede mostra os arquivos que deram erro (veja Ferramentas do Desenvolvedor).

Missão (versão 3): a aba sobre.html já tem o <link>; a index.html, ainda não. No head de index.html, depois do title, acrescente <link rel="stylesheet" href="estilo.css">. O título deve ficar laranja. Depois, mude a cor no estilo.css e veja as duas páginas mudarem.

Validando no laboratório

Num site de várias páginas, valide todas de uma vez. Com --also-check-css, o vnu confere também o CSS:

$ vnu --verbose --also-check-css *.html estilo.css
contato.html
index.html
sobre.html
estilo.css
$ echo $?
0
--also-check-css
"Confira também o CSS": sem essa opção, o vnu pula os arquivos .css.
*.html
Todos os arquivos terminados em .html da pasta (o terminal troca o * pelos nomes).
estilo.css
O CSS, que o *.html não pega.

Depois, o teste de verdade: ligue o servidor local, abra http://localhost:8000 no navegador e clique em todos os links, de todas as páginas. Se tudo funcionar ali, vai funcionar no GitHub Pages (veja Publicar no GitHub Pages).

Desafios extras

  1. Uma página de galeria. Crie bolos.html com três figure, ponha o link no menu das quatro páginas e confira com o servidor local.
  2. Organizar em pastas. Mova o estilo.css para uma pasta css e conserte o <link> das três páginas. Teste com o servidor (veja Organizar os Arquivos).
  3. Ícone da aba. Ponha o ícone assets/midia/favicon.svg nas três páginas (veja Ícone da Aba).
  4. Uma página 404. O GitHub Pages mostra o seu 404.html, se ele existir, quando alguém erra o endereço. Crie um, com o menu e um link para o início.
  5. Publicar. Siga Publicar no GitHub Pages e mande o link para alguém abrir no celular.

Exercícios

1. A página index.html e a sobre.html estão na mesma pasta. Qual link vai de uma para a outra?

2. O link href="Sobre.html" funcionou no Windows da Ana, mas deu 404 no site publicado. Por quê?

3. Por que o CSS vai num arquivo estilo.css separado?

4. Em sobre.html, qual link do menu leva aria-current="page"?

5. Complete a linha que liga o arquivo de CSS à página:

<link rel="" href="estilo.css">

6. Complete o comando que liga o servidor local na pasta atual:

python3 -m

Resumo

  • Um site é uma pasta: index.html é a página inicial, e cada página é um arquivo com o esqueleto completo e o seu próprio title.
  • As páginas se ligam com caminhos relativos (href="sobre.html"); nunca com / no começo nem com o caminho do seu disco.
  • Nomes de arquivo em minúsculas, sem acento e sem espaço: o servidor diferencia Sobre.html de sobre.html.
  • Um estilo.css, ligado a todas as páginas com <link rel="stylesheet" href="estilo.css">.
  • aria-current="page" marca, no menu, a página em que a pessoa está.
  • Teste com python3 -m http.server e valide tudo com vnu --verbose --also-check-css *.html estilo.css.
