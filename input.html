HTML input

Na aula Formulários, o <input> apareceu como "o campo onde a pessoa digita". Ele é o elemento mais usado dos formulários, e também o mais versátil: com uma única palavra trocada, a mesma tag vira um campo de texto, de senha, de data, de cor, uma caixa de marcar ou um seletor de arquivo. Nesta aula você conhece o <input> por dentro: como se escreve, quais atributos ele sempre tem e os erros que todo mundo comete no começo.

Você vai aprender
  • Por que o <input> não tem tag de fechamento (é um elemento vazio).
  • O atributo type, que decide que tipo de campo ele é, e o que acontece com um type que não existe.
  • A diferença entre id e name, e por que quase sempre os dois aparecem.
  • Como dar um valor inicial com value (e por que as aspas importam).
  • Que o <input> é um elemento em linha, e que ele pode até ficar fora do <form>.
  • Os erros reais do validador W3C: Stray end tag “input”, Bad value “txt”, Duplicate attribute e o atributo fantasma das aspas esquecidas.

Os exemplos foram validados com o validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook). O que o navegador faz com o código errado foi conferido no Chromium. Os quadros "Resultado" são desenhados pelo seu próprio navegador: você pode digitar neles.

A ideia: a tomada com vários adaptadores

Pense num carregador com pontas trocáveis: a base é sempre a mesma, e você encaixa a ponta do celular, do fone ou do relógio. O <input> é a base; o atributo type ("tipo") é a ponta. Muda o type, muda o campo inteiro: a aparência, o teclado que o celular abre e o que o navegador confere antes de enviar.

Por isso existem duas aulas: esta, sobre a base (o que vale para todo <input>), e Tipos de input, sobre cada ponta.

1. O <input> mais simples

<label for="nome">Seu nome:</label>
<input id="nome" name="nome">
<input
"Entrada", em inglês: um lugar por onde a informação entra na página. Sem type, ele é uma caixa de texto de uma linha.
id="nome"
A identidade do campo dentro da página. É ela que o <label for="nome"> procura, e é por ela que o CSS e o JavaScript o acham. Tem de ser única na página.
name="nome"
O nome do dado no envio: o navegador manda nome=o que foi digitado. Sem name, o campo não é enviado (aula Formulários).
>
E acabou. Não existe </input>.

Um elemento vazio

Um parágrafo tem conteúdo: o texto entre <p> e </p>. Um campo não tem: o que aparece dentro dele é o que a pessoa digita, e não um texto do código. Elementos assim se chamam vazios (void elements), como o <img> e o <br> (aula Elementos e Tags). Eles têm só a tag de abertura.

<input id="nome" name="nome"></input>NãoNão existe tag de fechamento (veja Quando dá errado).

2. O atributo type

O mesmo elemento, quatro tipos:

<p><label for="nome">Nome:</label> <input type="text" id="nome" name="nome"></p>
<p><label for="email">E-mail:</label> <input type="email" id="email" name="email"></p>
<p><label for="senha">Senha:</label> <input type="password" id="senha" name="senha"></p>
<p><input type="checkbox" id="novidades" name="novidades"> <label for="novidades">Quero receber novidades</label></p>
type="text"
Texto de uma linha. É o padrão: <input> sem type é igual a type="text".
type="email"
Parece igual ao texto, mas o navegador confere se tem cara de e-mail antes de enviar, e o celular mostra um teclado com @.
type="password"
Senha: o que você digita aparece como bolinhas ou asteriscos. Digite no resultado para ver.
type="checkbox"
Uma caixinha de marcar. Repare que aqui o <label> vem depois do campo, que é o costume para caixas de marcar (aula checkbox e radio).

Existem mais de vinte tipos. Todos estão, com o resultado de cada um, na próxima aula: Tipos de input. O desenho de cada campo muda de um navegador para outro e de um sistema para outro (no celular, um campo de data abre um calendário diferente do computador, por exemplo). Por isso o guia descreve o que o campo faz, e não o desenho exato.

Escreva o type="text" mesmo sendo o padrão?

Tanto faz para o navegador. Muita gente escreve, para deixar claro para quem lê o código. Neste guia, ele aparece quando o assunto é o tipo e some nos exemplos curtos.

4. Um valor inicial: value

O atributo value ("valor") faz o campo já começar preenchido. A pessoa pode apagar e escrever outra coisa:

<form action="pedido.html">
  <p>
    <label for="produto">Produto:</label>
    <input id="produto" name="produto" value="Bolo de cenoura">
  </p>
  <p>
    <label for="cliente">Seu nome:</label>
    <input id="cliente" name="cliente" value="Ana Maria">
  </p>
  <button>Pedir</button>
</form>
value="Bolo de cenoura"
O texto que aparece no campo quando a página abre. Se a pessoa enviar sem mexer, vai produto=Bolo+de+cenoura.
As aspas
Com espaço no valor, as aspas são obrigatórias. Sem elas, value=Ana Maria vira duas coisas: o valor Ana e um atributo chamado maria (veja Quando dá errado). Por isso o guia põe aspas em todo valor.

O value é um valor de verdade, que vai no envio. Não confunda com o texto cinza de exemplo que some quando você começa a digitar: esse é o placeholder, explicado em placeholder, value, autocomplete…, junto com outros atributos do <input>.

Missão: a maioria dos clientes pede 2 pacotes de pão de queijo. Faça o campo quantidade começar com 2 e o campo produto com Pão de queijo. Envie para ver os valores na tabela do editor.

<form action="pedido.html">

    <label for="produto">Produto:</label>
    <input id="produto" name="produto">
  </p>
  <p>
    <label for="quantidade">Pacotes:</label>
    <input id="quantidade" name="quantidade">
  </p>
  <button>Pedir</button>
</form>

<form action="pedido.html">

  </p>

5. Um elemento em linha

O <input> é um elemento em linha (aula Bloco × Em Linha): ele fica no meio do texto, como uma palavra, e não pula de linha sozinho.

<p>Quero <input id="qtd" name="qtd" value="1" size="3" aria-label="Quantidade"> bolo(s) para o dia 20.</p>
<label for="a">Rua:</label> <input id="a" name="rua">
<label for="b">Bairro:</label> <input id="b" name="bairro">
  • Na primeira linha, o campo ficou no meio da frase. O size="3" pede uma caixa estreita, de uns 3 caracteres. Como não há um <label> ali, o aria-label dá ao campo um nome para os leitores de tela (aula ARIA).
  • Os dois pares de baixo ficaram lado a lado, e, se a tela for estreita, quebram onde der. Para um campo por linha, embrulhe cada par num bloco, como os <p> das missões acima (ou use CSS).

Fora do <form>

Um <input> fora de um <form> é válido. Ele aparece e aceita digitação, só não é enviado. Isso é útil quando um script usa o campo (um filtro que esconde receitas enquanto você digita, por exemplo). E, se o campo precisa ficar longe do formulário no código, o atributo form o liga ao formulário pelo id:

<form id="busca" action="busca.html">
  <button>Buscar</button>
</form>
<p>
  <label for="q">Termo:</label>
  <input id="q" name="q" form="busca">
</p>

O campo está fora do <form>, mas o form="busca" faz o navegador enviá-lo junto com o formulário de id="busca". Digite e clique em Buscar: o q vai no envio. Use isso só quando o layout exigir; na maioria das vezes, deixar o campo dentro do <form> é mais simples.

Quando dá errado

As páginas abaixo têm o esqueleto de sempre nas linhas 1 a 7 e um <label> na linha 8. O <input> errado está na linha 9.

</input>: fechar um elemento vazio 
<label for="nome">Nome:</label>
<input id="nome" name="nome"></input>

$ vnu fecha.html
"file:/home/ana/campos/fecha.html":9.30-9.37: error: Stray end tag “input”.

O validador diz: "Tag de fechamento input perdida" (stray = "extraviada"). As colunas 30 a 37 são exatamente o </input>.

O que o navegador faz: joga o </input> fora, sem dizer nada. A página fica certa, por isso o erro passa despercebido.

Como consertar: apague o </input>.

Texto "dentro" do <input> 
<label for="nome">Nome:</label>
<input id="nome" name="nome">Digite seu nome</input>

$ vnu dentro.html
"file:/home/ana/campos/dentro.html":9.45-9.52: error: Stray end tag “input”.

O que o navegador faz: o campo termina no primeiro >. "Digite seu nome" vira um texto comum do lado de fora do campo, como mostra o resultado, e o </input> é jogado fora.

Como consertar: para um valor inicial, use value="…"; para um texto de exemplo que some ao digitar, placeholder="…" (aula placeholder, value, autocomplete…).

Um type que não existe: type="txt" 
$ vnu txt.html
"file:/home/ana/campos/txt.html":9.1-9.40: error: Bad value “txt” for attribute “type” on element “input”.

O validador diz: "Valor ruim txt para o atributo type".

O que o navegador faz: não reconhece o tipo e usa o padrão, text. Por isso, com type="txt", tudo parece funcionar. O perigo aparece com type="emial" ou type="pasword": o campo vira texto comum, sem conferência de e-mail e, pior, com a senha visível na tela.

Como consertar: confira a grafia na tabela de Tipos de input.

Dois type na mesma tag 
$ sed -n 9p dois.html
<input type="text" id="email" name="email" type="email">
$ vnu dois.html
"file:/home/ana/campos/dois.html":9.1-9.48: error: Duplicate attribute “type”.

O validador diz: "Atributo type repetido".

O que o navegador faz: fica com o primeiro e ignora o segundo. Este campo é text, e não email. Acontece muito quando se copia e cola um campo e se acrescenta o atributo novo no fim, sem apagar o antigo.

Como consertar: um atributo de cada, uma vez só.

Aspas esquecidas: value=Ana Maria 
<label for="nome">Nome:</label>
<input id="nome" name="nome" value=Ana Maria>

$ vnu aspas.html
"file:/home/ana/campos/aspas.html":9.1-9.45: error: Attribute “maria” not allowed on element “input” at this point.

O validador diz: "Atributo maria não permitido no elemento input". Que atributo maria?

O que o navegador faz: sem aspas, o valor termina no primeiro espaço. O navegador lê value="Ana" e depois um atributo novo, sem valor, chamado maria (em minúsculas, porque nomes de atributo não diferenciam maiúsculas). O campo mostra só "Ana", como no resultado.

Como consertar: value="Ana Maria". Aspas sempre, mesmo quando o valor não tem espaço.

A barra no fim e o valor sem aspas

A barra de <input … /> é aceita, mas o validador dá uma dica (info, que não é erro):

$ sed -n 9,10p barra.html
<input id="nome" name="nome" />
<input id="x" name="x" value=a/>
$ vnu barra.html
"file:/home/ana/campos/barra.html":9.1-9.31: info: Trailing slash on void elements has no effect and interacts badly with unquoted attribute values.

O que significa: "A barra no fim de elementos vazios não tem efeito e se dá mal com valores sem aspas". A linha 10 mostra o porquê, e repare que ela passou sem aviso: com value=a/>, a barra entra no valor, e o campo começa com a/, e não com a.

Como consertar: aspas em todo valor resolvem; a barra pode ficar ou sair.

Resumo

  • <input> é um elemento vazio: só a tag de abertura. </input> é erro (Stray end tag “input”); a barra em <input /> é aceita e ignorada.
  • type decide o tipo de campo. Sem ele, ou com um valor que não existe (txt, pasword), o campo vira text, e o validador acusa Bad value.
  • id acha o campo na página (o <label for> usa); name dá nome ao dado no envio. Quase sempre os dois aparecem, muitas vezes com o mesmo valor.
  • value="…" é o valor inicial. Sem aspas, o valor termina no primeiro espaço, e o resto vira um atributo fantasma.
  • O <input> é em linha. Fora do <form> ele não é enviado, a não ser com form="id". A aparência muda de um navegador e de um sistema para outro.
