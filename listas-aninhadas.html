HTML Listas Dentro de Listas

A lista de compras da Ana cresceu. Agora ela separa o que comprar na feira e o que comprar no mercado, e embaixo de cada lugar vêm os produtos. Isso é uma lista dentro de outra lista, ou lista aninhada: como os ninhos de passarinho, uma coisa dentro da outra. Sumários de livros, menus com submenus e receitas com várias partes são todos assim. Nesta aula você aprende o único lugar certo para pôr a lista de dentro e vê o que acontece quando ela vai parar no lugar errado.

Você vai aprender
  • Onde a lista de dentro fica: dentro do li, antes do </li>.
  • Como o navegador troca o marcador a cada nível (bolinha cheia, bolinha vazia, quadradinho).
  • Como fica um ol dentro de outro ol, e por que ele não vira "1.1".
  • Como misturar ol e ul.
  • Como o recuo no código ajuda a não se perder.
  • Os erros reais do validador: ul direto dentro de ul e a lista de dentro sem </ul>.

Antes, veja as aulas Listas com Marcadores, Listas Numeradas e Aninhamento. Os quadros Resultado são desenhados pelo seu navegador; as mensagens do validador saíram do vnu 26.10.12 na máquina fictícia da Ana, na pasta ~/site.

A ideia: o sumário do livro

Abra o sumário de um livro de receitas. Os capítulos são uma lista: Bolos, Pães, Doces. Dentro de cada capítulo há outra lista, a das receitas. A lista das receitas de bolo pertence ao capítulo Bolos: ela faz parte desse item.

Essa frase é a regra inteira da aula: a lista de dentro faz parte de um item da lista de fora. Em HTML, "faz parte do item" quer dizer "fica dentro do li".

1. A primeira lista aninhada

<ul>
  <li>Feira
    <ul>
      <li>Cenoura</li>
      <li>Laranja</li>
    </ul>
  </li>
  <li>Mercado</li>
</ul>
<li>Feira
Abre o item da lista de fora e escreve o texto dele. O li ainda não fecha.
<ul> … </ul> (a de dentro)
A lista da feira, inteira, com abertura, itens e fechamento. Ela está dentro do li "Feira".
</li> (o da Feira)
Só agora o item "Feira" fecha, depois da lista de dentro.
<li>Mercado</li>
O segundo item da lista de fora, no mesmo nível de "Feira".

Para montar sem errar, siga sempre a mesma ordem:

  1. Escreva o <li> e o texto do item de fora.
  2. Antes de fechar esse item, abra a lista de dentro (<ul>), escreva os itens dela e feche-a (</ul>).
  3. Feche o item de fora (</li>).

No resultado, a lista de dentro ganhou um recuo a mais e um marcador diferente: uma bolinha vazia. Quem decide isso é o navegador, olhando quantas listas há em volta.

A página completa, com as duas sublistas, passa no validador:

<!DOCTYPE html>

<meta charset="utf-8">

</head>

    </ul>

2. Um marcador para cada nível

Cada lista nova dentro de outra é um nível a mais. O navegador troca o marcador do ul conforme o nível, para o olho perceber onde está:

<ul>
  <li>Nível 1
    <ul>
      <li>Nível 2
        <ul>
          <li>Nível 3
            <ul>
              <li>Nível 4</li>
            </ul>
          </li>
        </ul>
      </li>
    </ul>
  </li>
</ul>
NívelMarcador padrão nos navegadoresNome no CSS
1bolinha cheiadisc
2bolinha vaziacircle
3 em diantequadradinhosquare

Do terceiro nível em diante, o marcador fica sempre o quadradinho. O recuo, ao contrário, continua crescendo: cada lista empurra a de dentro mais um pouco para a direita. Com quatro ou cinco níveis, o texto vai ficando espremido do lado direito, principalmente no celular. Se o seu conteúdo precisa de tantos níveis, vale pensar em dividir em títulos e seções.

3. ol dentro de ol

Um ol aninhado recomeça do 1. Cada lista conta os seus próprios itens:

<ol>
  <li>Prepare a massa
    <ol>
      <li>Bata as cenouras com os ovos.</li>
      <li>Misture a farinha.</li>
    </ol>
  </li>
  <li>Prepare a cobertura
    <ol>
      <li>Derreta o chocolate.</li>
      <li>Espalhe sobre o bolo.</li>
    </ol>
  </li>
</ol>

Muita gente espera ver "1.1, 1.2, 2.1, 2.2", como num documento de escritório. O HTML não faz isso sozinho: cada ol mostra só o número dele. O formato "1.1" é possível com CSS, usando contadores (quer aprender mais? futuro Guia CSS). Uma ideia simples que já ajuda: type diferente no nível de dentro, como <ol type="a">, que dá 1, a, b, 2, a, b.

4. Misturando ol e ul

A lista de dentro não precisa ser do mesmo tipo da de fora. Escolha cada uma pelo sentido: os passos da receita têm ordem (ol); os ingredientes de um passo, não (ul).

<ol>
  <li>Bata no liquidificador:
    <ul>
      <li>3 cenouras</li>
      <li>4 ovos</li>
      <li>1 xícara de óleo</li>
    </ul>
  </li>
  <li>Despeje numa tigela com:
    <ul>
      <li>2 xícaras de açúcar</li>
      <li>2 xícaras de farinha</li>
    </ul>
  </li>
  <li>Asse por 40 minutos.</li>
</ol>

Os passos ficaram numerados (1, 2, 3) e os ingredientes com bolinha. A sublista não atrapalha a contagem: o passo "Asse" continua sendo o 3. Um ul dentro de um ol conta como segundo nível, por isso a bolinha costuma sair vazia.

5. O recuo no código

O navegador não liga para os espaços no começo das linhas. Este código desenha exatamente a mesma lista da seção 1:

<ul><li>Feira<ul><li>Cenoura</li>
<li>Laranja</li></ul></li><li>Mercado</li></ul>

Mas tente descobrir, só olhando, qual </li> fecha qual item. Com o recuo (dois espaços a mais por nível), cada fechamento fica na mesma coluna da sua abertura, e um esquecimento salta aos olhos. Os editores de código, como o VS Code, fazem esse recuo sozinhos (aula Editores).

Dica: feche antes de encher

Ao criar uma sublista, escreva primeiro <ul> e </ul>, um embaixo do outro, e só depois os itens no meio. Assim o fechamento nunca é esquecido.

Quando dá errado

Os arquivos completos têm as mesmas 7 primeiras linhas do compras.html; o código mostrado começa na linha 8.

error: Element “ul” not allowed as child of element “ul” in this context.

O erro mais comum desta aula. A Ana fechou o item "Feira" e depois abriu a sublista:

<ul>
  <li>Feira</li>
  <ul>
    <li>Cenoura</li>
    <li>Laranja</li>
  </ul>
  <li>Mercado</li>
</ul>

$ vnu ul-no-ul.html
"file:/home/ana/site/ul-no-ul.html":10.3-10.6: error: Element “ul” not allowed as child of element “ul” in this context. (Suppressing further errors from this subtree.)

O que significa: "o elemento ul não é permitido como filho do elemento ul". Lembre a regra de família: os filhos diretos de um ul só podem ser li. A lista de dentro ficou entre dois itens, e não dentro de um.

O que o navegador faz: compare com o primeiro exemplo da aula. O desenho é praticamente igual: o mesmo recuo, a mesma bolinha vazia. Por isso esse erro passa despercebido. A diferença está na estrutura: a lista da feira não pertence ao item "Feira". Para um leitor de tela, ela é uma lista solta no meio de outra, sem dono.

Como consertar: apague o </li> depois de "Feira" e escreva-o depois do </ul> da sublista.

error: No “li” element in scope but a “li” end tag seen.

Agora a sublista está no lugar certo, mas a Ana esqueceu o </ul> dela:

<ul>
  <li>Feira
    <ul>
      <li>Cenoura</li>
      <li>Laranja</li>
  </li>
  <li>Mercado</li>
</ul>

$ vnu esqueceu.html
"file:/home/ana/site/esqueceu.html":13.3-13.7: error: No “li” element in scope but a “li” end tag seen.
"file:/home/ana/site/esqueceu.html":16.1-16.7: error: End tag for  “body” seen, but there were unclosed elements.
"file:/home/ana/site/esqueceu.html":8.1-8.4: error: Unclosed element “ul”.
No “li” element in scope but a “li” end tag seen
"Não há elemento li ao alcance, mas vi um </li>". Na linha 13, o </li> queria fechar o item "Feira", mas a sublista ainda estava aberta, e um </li> não consegue fechar nada através de uma lista aberta. O navegador simplesmente ignora essa tag.
End tag for “body” seen, but there were unclosed elements
Quando a página acabou, ainda havia elementos abertos.
Unclosed element “ul”
E o que ficou aberto foi a lista da linha 8, a de fora. O único </ul> que existe fechou a de dentro.

O que o navegador faz: como o </li> foi ignorado, "Mercado" entra na lista de dentro, com bolinha vazia, como se fosse um produto da feira. Tudo o que vier depois na página também fica dentro da lista de fora.

Como consertar: escreva o </ul> da sublista antes do </li> da Feira. Repare que o validador não aponta a linha do esquecimento (a 12): ele aponta onde percebeu o problema. Nesses casos, o recuo do código é o que ajuda a achar o lugar.

Texto do item depois da sublista (sem erro)

<li><ul>…</ul>Feira</li> é válido, mas desenha a sublista antes do nome do item, e, no Chrome, a bolinha de fora fica sozinha numa linha, com "Feira" lá embaixo. O texto do item vem primeiro; a sublista, logo antes do </li>.

Missão final: o sumário do livro

Missão: o sumário da Ana ficou com tudo no mesmo nível. Só os capítulos (Bolos e Pães) devem ser numerados. As receitas de cada capítulo vão numa sublista com marcadores (ul) dentro do capítulo, na mesma ordem.

<h2>Sumário</h2>
<ol>
  <li>Bolos</li>
  <li>Bolo de cenoura</li>
  <li>Bolo de fubá</li>
  <li>Pães</li>
  <li>Pão de queijo</li>
  <li>Pão caseiro</li>
  <li>Pão de mel</li>
</ol>

<h2>Sumário</h2>
<ol>
  <li>Bolos
    <ul>
      <li>Bolo de cenoura</li>
      <li>Bolo de fubá</li>
    </ul>
  </li>
  <li>Pães
    <ul>
      <li>Pão de queijo</li>
      <li>Pão caseiro</li>
      <li>Pão de mel</li>
    </ul>
  </li>
</ol>

Com a estrutura certa, o "Pães" voltou a ser o capítulo 2, e não o 4: a numeração conta só os itens da lista de fora.

Resumo

  • Uma lista aninhada é uma lista que faz parte de um item de outra. Por isso ela fica dentro do li: texto do item, sublista, </li>.
  • O navegador muda o marcador do ul a cada nível (disc, circle, square) e aumenta o recuo.
  • Um ol dentro de outro recomeça do 1. "1.1" só com CSS.
  • ol e ul podem se misturar; escolha cada uma pelo sentido.
  • Recue o código (dois espaços por nível) e escreva o fechamento logo depois da abertura.
  • Erros: Element “ul” not allowed as child of element “ul” (sublista entre dois itens, quase invisível na tela) e No “li” element in scope but a “li” end tag seen (sublista sem </ul>, que engole os itens seguintes).
