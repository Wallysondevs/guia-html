HTML O Editor do Guia

Em quase toda aula deste guia aparecem caixas Experimente: você escreve HTML de um lado e vê a página pronta logo embaixo, desenhada pelo seu próprio navegador. Não precisa instalar nada, criar arquivo nem abrir outra janela. Nesta página você conhece cada parte do editor, aprende a usar as abas, o console e as imagens de exemplo, e descobre o que muda entre o editor e um site publicado de verdade.

Você vai aprender
  • As partes de uma caixa Experimente: abas, código, Resultado, console e missão.
  • Como trabalhar com várias abas: index.html, sobre.html, estilo.css e script.js.
  • Quais imagens, sons e vídeos de exemplo você pode usar (assets/midia/…).
  • O que acontece quando você envia um formulário no editor.
  • Como mandar o seu código para o validador do W3C com um clique.
  • O que o editor não faz e o que muda num site publicado.

A ideia: um caderno de rascunho que desenha a página

Pense num caderno de desenho com papel vegetal: você risca por cima e vê o resultado na hora. O editor do guia é isso para o HTML. Você digita, e meio segundo depois o navegador desenha a página de novo no quadro Resultado.

O resultado é de verdade: é o mesmo navegador que você usa para ver qualquer site. Se você esquecer de fechar uma tag, o quadro mostra exatamente o que o navegador faz com o erro (ele quase sempre conserta sozinho, às vezes de um jeito estranho).

As partes da caixa

Esta é uma caixa livre, sem missão. Mude o texto do título e veja o quadro acompanhar:

<h1>Receitas da Ana</h1>
<p>Bolo de cenoura com cobertura de chocolate.</p>

Repare no que não aparece no código acima: não há <!DOCTYPE html>, <html>, <head> nem <body>. É só um pedaço de página. O editor desenha esse pedaço como se ele estivesse dentro de uma página completa (com <!DOCTYPE html>). Quando o código tem a página inteira, o editor desenha exatamente o que você escreveu, inclusive o que acontece se faltar o DOCTYPE (aula O DOCTYPE).

O quadro "Resultado" embaixo do código

Nas aulas, muitos exemplos são só para ler, e não para editar. Mesmo assim, o navegador desenha cada um logo embaixo, num quadro Resultado do tamanho do conteúdo:

<h2>Ingredientes</h2>
<ul>
  <li>3 cenouras</li>
  <li>3 ovos</li>
  <li>2 xícaras de farinha</li>
</ul>

Esse quadro também é o navegador de verdade. Se o exemplo tiver um link, você pode clicar nele: o quadro segue o link, e a barra do quadro mostra o endereço. O botão ↻ da barra desenha o exemplo de novo, do começo. Quando o exemplo escreve alguma coisa no console (ou uma imagem não carrega), aparece um console embaixo dele. Quer mexer no exemplo? Clique em copiar e cole numa caixa Experimente.

Várias abas: um site de verdade

Um site é feito de vários arquivos: as páginas .html, o estilo .css e os scripts .js. No editor, cada arquivo é uma aba, e as abas funcionam como os arquivos de uma pasta:

  • <link rel="stylesheet" href="estilo.css"> carrega a aba estilo.css;
  • <script src="script.js"></script> roda a aba script.js;
  • <a href="sobre.html"> abre a aba sobre.html dentro do quadro, e a barra de endereço mostra sobre.html.

Clique numa aba .html e o quadro passa a mostrar essa página. Mudou o CSS ou o JS? O quadro desenha de novo a página que está aberta.

Missão: o estilo.css já deixa o título verde, mas o index.html ainda não o carrega. No <head> do index.html, acrescente <link rel="stylesheet" href="estilo.css">. Depois clique no link "Ana" e volte com ↻.

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Receitas da Ana</title>
</head>
<body>
  <h1>Receitas da Ana</h1>
  <p>Conheça a <a href="sobre.html">Ana</a>.</p>
</body>
</html>

O console

Quando a página tem JavaScript, aparece embaixo do quadro uma janelinha escura: o console. Ele mostra o que o script escreve com console.log e os erros, com o arquivo e a linha. É uma versão simples do console que existe nas Ferramentas do Desenvolvedor do navegador (a tecla F12, aula Ferramentas do Desenvolvedor).

O console do editor também avisa quando um arquivo não carregou, como uma imagem com o nome errado. Clique no botão do quadro e veja as mensagens:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Console</title>
  <script src="script.js" defer></script>
</head>
<body>
  <img src="assets/midia/bolo-4OO.jpg" alt="Bolo">
  <button id="pedir">Pedir um bolo</button>
</body>
</html>

console.log("A página carregou.");

document.getElementById("pedir").addEventListener("click", function () {
  console.log("Pedido feito!");
  mandarPedido();
});

O que você vê no console (a ordem das duas primeiras pode variar):

  • a imagem bolo-4OO.jpg (com a letra O no lugar do zero) não carregou;
  • A página carregou., escrito pelo script;
  • depois do clique, Pedido feito! e um erro em vermelho: a função mandarPedido não existe. O texto do erro é o do seu navegador (em inglês) e muda um pouco de navegador para navegador. No Chrome, é Uncaught ReferenceError: mandarPedido is not defined, seguido de (script.js, linha 5).

O botão Limpar apaga as mensagens. Cada vez que o quadro desenha a página de novo, o console também recomeça.

Formulários no editor

Num site publicado, ao clicar em "Enviar", o navegador manda os dados para um servidor, um programa que fica num computador da internet (aula Enviar). O editor não tem servidor. Então, no envio, ele faz assim:

  1. O navegador confere os campos primeiro: required, type="email", pattern e companhia funcionam de verdade, com os balões de aviso do seu navegador.
  2. O console mostra o que seria enviado, por exemplo [editor] Formulário enviado: GET obrigado.html?nome=Ana. Os dados vão escritos como o navegador os mandaria: o espaço vira +, e cada quebra de linha de um <textarea> vira %0D%0A.
  3. Se o action é uma aba e o método é GET, o quadro abre essa aba com os dados no endereço, depois do ?.
  4. Nos outros casos (um method="post", ou um action que não é aba, como enviar.php), o quadro mostra a página "📨 Formulário enviado", com o método, o endereço e a tabela de cada name e value.
<form action="enviar.php" method="post">
  <p>
    <label for="nome">Seu nome:</label>
    <input id="nome" name="nome" required>
  </p>
  <p>
    <label for="sabor">Sabor:</label>
    <select id="sabor" name="sabor">
      <option>Cenoura</option>
      <option>Chocolate</option>
    </select>
  </p>
  <button>Fazer o pedido</button>
</form>

Tente enviar com o nome vazio: o navegador não deixa. Preencha e envie: a tabela mostra nome e sabor. Um campo sem o atributo name não aparece na tabela, porque o navegador não o envia.

Validar no W3C

O navegador conserta os erros sozinho e não reclama. Quem aponta os erros é o validador do W3C (aula Validar o HTML). O botão Validar no W3C manda o código da aba .html aberta para o validador on-line (validator.w3.org) e mostra a resposta embaixo do código.

  • O editor pergunta antes de mandar, porque o código sai do seu computador e vai para a internet.
  • As mensagens vêm em inglês, com a linha e a coluna do erro.
  • Quando o código é só um pedaço de página, o editor o põe dentro de um esqueleto mínimo antes de mandar (com <!DOCTYPE html>, <html lang="pt-BR"> e um <title>), e as linhas continuam as do seu código.

É o mesmo validador que a Ana usa no terminal, com o programa vnu. Na pasta ~/site, com uma imagem sem alt:

$ vnu index.html
"file:/home/ana/site/index.html":9.3-9.64: error: An “img” element must have an “alt” attribute, except under certain conditions. For details, consult guidance on providing text alternatives for images.
$ echo $?
1

A mensagem diz: "um elemento img precisa ter o atributo alt". O 9.3-9.64 é a linha 9, da coluna 3 à coluna 64. Depois de acrescentar o alt, o --verbose só mostra o nome do arquivo, e o código de saída vira 0:

$ vnu --verbose index.html
index.html
$ echo $?
0

Missões, Restaurar e Ver solução

Algumas caixas têm uma missão. Embaixo da caixa aparece o andamento:

  • Missão em andamento… e, logo abaixo, o que ainda falta, por exemplo Ainda falta: h1 com o texto “Receitas da Ana” (hoje o texto é “Meu site”).
  • ✔ Missão cumprida! quando tudo confere.

A missão olha a página desenhada, e não o texto do código. Por isso, o que conta é o que o navegador montou: se você escreveu <h1>Oi</h2>, o navegador consertou e existe um h1. Ela confere de novo a cada mudança: no código, no console e na página (um clique num botão, um texto num campo).

Ver soluçãoPergunta antes ("Trocar o seu código pela solução?") e troca as abas que a solução muda. Tente sozinho primeiro!
Validar no W3CPergunta antes e manda a aba .html aberta para o validador do W3C.
↻Desenha de novo a partir da primeira página .html.
↗Abre o resultado numa aba nova do navegador.

O editor × um site publicado

O que funciona igual

  • Tudo o que o navegador faz sozinho: HTML, CSS, JavaScript, imagens, áudio, vídeo e legendas, <dialog>, <details>, alert(), a validação dos formulários.
  • Os caminhos relativos entre as abas (sobre.html, estilo.css, css/estilo.css, ../index.html) e as âncoras (#receita).
  • O link com download baixa o arquivo de verdade.

O que é diferente

Modo completo e modo simples

Para que as abas funcionem como arquivos de uma pasta, o editor liga no seu navegador um pequeno "servidor de mentirinha", o service worker. É o modo completo, o que você vê no guia publicado na internet (endereço com https://).

Às vezes o navegador não deixa ligar esse servidor: com o guia aberto direto do disco (file://), num endereço http:// que não seja o do próprio computador, numa janela anônima do Firefox ou com o recurso bloqueado. Aí o editor usa o modo simples, e quase tudo continua igual: os links entre as abas, as âncoras (#receita), os formulários, o console e as missões. As diferenças:

  • o CSS e o JS das abas entram embutidos na página, então o <link href="estilo.css"> do DOM muda, e uma missão que confere esse href não é cumprida;
  • um link para uma página que não existe só dá um aviso no console, em vez da página 404;
  • um envio GET para outra aba não leva os dados no endereço;
  • uma página sem <!DOCTYPE html> não entra em modo quirks (aula O DOCTYPE);
  • links com target para as abas abrem dentro do próprio quadro, e não numa aba nova.

O que não dá para fazer no editor

  • Programas de servidor (PHP, por exemplo): o editor só tem o navegador.
  • Guardar os arquivos: ao sair da página, o código volta ao original. Para guardar, copie para um arquivo no seu computador (aula Criar e Abrir um Arquivo .html).
  • Ver o resultado num celular de verdade. Para isso, publique o site (aula Publicar no GitHub Pages).

Quando dá errado

A imagem não aparece

No lugar dela fica um ícone de imagem quebrada (ou só o texto do alt), e o console diz Não foi possível carregar "assets/midia/bolo.jpg" (<img>). Confira o nome e o caminho do arquivo. O arquivo bolo.jpg não existe: os nomes têm o tamanho, como bolo-800.jpg. Confira na tabela da mídia. Maiúsculas, acentos e a extensão contam.

O CSS não pega

O título continua preto. O console diz Não foi possível carregar "estilos.css" (<link>): o href pede estilos.css, mas a aba se chama estilo.css. Outra causa comum é esquecer o rel="stylesheet": aí nada carrega e o console não avisa nada.

Cliquei num link e apareceu "404: página não encontrada"

O link aponta para um arquivo que não é nenhuma das abas. A página do editor mostra a lista dos arquivos que existem. Clique em ↻ para voltar ao início.

A missão diz "volte a ela com o botão ↻"

Você navegou para outra página dentro do quadro (sobre.html, ou a página "Formulário enviado"). A missão confere a primeira página: clique em ↻.

O quadro ficou em branco

Quase sempre é um comentário aberto e não fechado: tudo depois de <!-- sem o --> vira comentário, e o navegador não desenha nada. Também pode ser um <title> ou um <textarea> sem a tag de fechamento, que engolem o resto da página. Procure a tag aberta ou use Restaurar.

Resumo

  • As caixas Experimente desenham o seu código com o seu navegador, ao vivo, num quadro separado da página do guia.
  • Um pedaço de código (sem <html>) é desenhado como parte de uma página completa; uma página inteira é desenhada exatamente como está.
  • Cada arquivo é uma aba; href="estilo.css", src="script.js" e href="sobre.html" funcionam como numa pasta.
  • A mídia de exemplo fica em assets/midia/: bolo-800.jpg, logo-lojinha-400.png, video-bolo.mp4 e outros.
  • O console mostra console.log, os erros de JavaScript e os arquivos que não carregaram.
  • Formulários: a validação é de verdade; o envio mostra os dados que seriam enviados, porque o editor não tem servidor.
  • Validar no W3C manda o código para o validador on-line, depois de perguntar.
  • Restaurar volta ao original; Ver solução mostra uma solução; a missão confere a página desenhada.
  • Próximo passo: as ferramentas que todo navegador traz, em Ferramentas do Desenvolvedor (F12).
