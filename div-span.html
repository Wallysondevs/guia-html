HTML div e span

Até aqui, cada elemento que você aprendeu tinha um significado: h1 é título, p é parágrafo, ul é lista. Mas às vezes você só quer juntar algumas coisas num grupo, ou marcar um pedacinho de uma frase, para dar um estilo ou um nome a ele. Para isso existem dois elementos sem significado nenhum: o div, a caixa para juntar blocos, e o span, a marcação para um trecho do texto. Nesta aula você vai usar os dois no site de receitas da Ana e descobrir por que eles são a última opção, e não a primeira.

Você vai aprender
  • O que é o div e como agrupar um título, um parágrafo e uma lista numa caixa só.
  • O que é o span e como marcar uma palavra ou um trecho dentro de uma frase.
  • Como dar um nome ao grupo com class, para o CSS achá-lo depois.
  • Por que div e span não mudam nada na tela sozinhos.
  • Por que eles são "genéricos" e quando um elemento com significado é melhor.
  • Os erros reais: div dentro de p, div dentro de span e um div sem fechar.

Os arquivos desta aula foram validados com o validador W3C (vnu, o mesmo do validator.w3.org) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/receitas. Como validar está em Validar o HTML. Os quadros "Resultado" são desenhados pelo seu navegador, agora.

A ideia: uma caixa e um marca-texto

Pense numa mudança de casa. Você junta as panelas, a frigideira e as colheres numa caixa de papelão. A caixa em si não é nada: ela só mantém as coisas juntas, para você carregar tudo de uma vez. Se escrever "COZINHA" do lado de fora, fica ainda mais fácil achar depois.

Agora pense num livro de receitas impresso. Você passa um marca-texto amarelo sobre "40 minutos" no meio de uma frase, para não esquecer o tempo de forno. O marca-texto não muda as palavras; só marca aquele trecho.

Os nomes vêm do inglês. div é a abreviação de division, "divisão": uma parte da página. span quer dizer "trecho", "extensão": um pedaço do texto, do começo ao fim da marcação.

1. O div: juntar blocos numa caixa

A página da Ana tem uma receita com título, um parágrafo e uma lista de ingredientes. São três elementos soltos. Com um div em volta, eles viram um grupo:

<h1>Receitas da Ana</h1>
<div class="receita">
  <h2>Bolo de cenoura</h2>
  <p>Fofinho, fácil e com cobertura de chocolate.</p>
  <ul>
    <li>3 cenouras</li>
    <li>3 ovos</li>
    <li>2 xícaras de farinha</li>
  </ul>
</div>
<div>
A tag de abertura: "a caixa começa aqui". Tudo o que vem depois, até o </div>, fica dentro dela.
class="receita"
A etiqueta da caixa. O atributo class ("classe", no sentido de "tipo", "categoria") dá um nome ao grupo. O nome é você quem escolhe. Ele não aparece na tela; serve para o CSS (e o JavaScript) acharem esta caixa depois. A aula class e id mostra os detalhes.
h2, p, ul
O conteúdo da caixa. Dentro de um div cabe quase tudo: títulos, parágrafos, listas, imagens, tabelas e até outros div.
</div>
A tag de fechamento: "a caixa termina aqui". Esquecer essa tag é um erro comum (veja em Quando dá errado).

Olhe o resultado com atenção: ele é exatamente igual ao que seria sem o div. Não apareceu borda, nem cor, nem espaço a mais. O div é uma caixa invisível. Ele agrupa, mas não enfeita.

Ver a caixa com um pouco de CSS

Para enxergar o div, é preciso pedir uma aparência a ele com CSS. Aqui o atributo style (aula O Atributo style) desenha uma borda tracejada e um espaço por dentro:

<h1>Receitas da Ana</h1>
<div class="receita" style="border: 2px dashed gray; padding: 8px;">
  <h2>Bolo de cenoura</h2>
  <p>Fofinho, fácil e com cobertura de chocolate.</p>
</div>
<p>Este parágrafo está fora da caixa.</p>
border: 2px dashed gray;
"Borda" de 2 pixels, tracejada (dashed), cinza (gray).
padding: 8px;
"Enchimento": um espaço de 8 pixels entre a borda e o conteúdo.

Agora dá para ver: o título e o parágrafo do bolo estão dentro da caixa, e o último parágrafo está fora. Repare também que a caixa ocupa toda a largura disponível, mesmo com textos curtos. Esse é o jeito "de bloco", que a próxima aula, Bloco × Em Linha, explica com calma.

Para que serve uma caixa invisível?

Principalmente para o CSS. Com todas as receitas dentro de <div class="receita">, uma única regra no arquivo de estilo (por exemplo, "toda .receita tem borda e fundo claro") muda todas de uma vez. Sem o div, não haveria um elemento só para receber esse estilo. O CSS de verdade fica para o futuro Guia CSS; aqui ele aparece só o necessário para você ver o efeito.

Missão: a página tem duas receitas soltas. Coloque cada receita (o h2 e o p dela) dentro do seu próprio <div class="receita">. Uma caixa não pode ficar dentro da outra. A borda tracejada já está pronta no style do primeiro div: copie-a para o segundo, se quiser ver as duas caixas.

2. O span: marcar um trecho da frase

O div agrupa blocos inteiros. Quando você quer marcar só algumas palavras no meio de um parágrafo, o elemento certo é o span:

<p>Tempo de forno: <span class="tempo">40 minutos</span>.</p>
<p>Rende <span class="porcoes">12 fatias</span>.</p>
<span
Começa a marcação. Fica dentro do parágrafo, no meio do texto.
class="tempo"
O nome desta marcação. "tempo" e "porcoes" são nomes escolhidos pela Ana. Em nomes de classe, evite acentos e espaços: use letras sem acento, números e hífen (tempo-forno).
>40 minutos<
O trecho marcado.
</span>
Termina a marcação. O ponto final da frase ficou fora do span, porque ele não faz parte do tempo.

De novo, o resultado é igual a um parágrafo comum: o span também é invisível. A diferença é que agora o texto "40 minutos" tem um nome e pode receber um estilo só para ele:

<p>Tempo de forno: <span class="tempo" style="background: yellow;">40 minutos</span>.</p>
<p>Rende <span class="porcoes">12 fatias</span>.</p>

O background: yellow; pinta o fundo de amarelo, como o marca-texto. Repare em duas coisas no resultado:

  • O fundo amarelo cobre só o trecho "40 minutos", e não a linha inteira.
  • O texto continua na mesma linha, antes e depois do span. Ele não "quebra" a frase. Esse é o jeito "em linha" (próxima aula).

Missão: na lista de ingredientes, a Ana quer destacar a quantidade de açúcar. Marque o trecho 200 g de açúcar com um <span class="destaque">, sem tirar o texto de dentro do p. Para ver a marcação, acrescente style="background: yellow;" ao span.

<h1>Receitas da Ana</h1>
<h2>Bolo de cenoura</h2>
<p>Bata no liquidificador 3 cenouras, 3 ovos e meia xícara de óleo.</p>
<p>Numa tigela, misture 2 xícaras de farinha e 200 g de açúcar.</p>

<h1>Receitas da Ana</h1>
<h2>Bolo de cenoura</h2>
<p>Bata no liquidificador 3 cenouras, 3 ovos e meia xícara de óleo.</p>
<p>Numa tigela, misture 2 xícaras de farinha e <span class="destaque" style="background: yellow;">200 g de açúcar</span>.</p>

3. div × span: qual é qual

Os dois são caixas sem significado. A diferença está no tamanho do que eles guardam e no que eles fazem com a linha:

divspan
Guardablocos inteiros: títulos, parágrafos, listas, outros divum trecho de texto: palavras, links, ênfases, outros span

Os dois podem andar juntos: um div com parágrafos, e span dentro dos parágrafos.

<h1>Receitas da Ana</h1>
<div class="receita">
  <h2>Bolo de cenoura</h2>
  <p>Tempo de forno: <span class="tempo">40 minutos</span>.</p>
</div>
<div class="receita">
  <h2>Pão de queijo</h2>
  <p>Tempo de forno: <span class="tempo">25 minutos</span>.</p>
</div>

Com essa organização, o CSS pode pedir "toda .receita ganha uma borda" e "todo .tempo fica em negrito", e as duas receitas mudam juntas. Uma caixa dentro de outra também é permitida: um <div class="cardapio"> com várias <div class="receita"> dentro, por exemplo. As regras de quem pode ficar dentro de quem estão em Aninhamento.

4. Genérico: o elemento que não diz nada

Para você, class="receita" diz claramente "isto é uma receita". Mas o nome da classe é só uma etiqueta para o CSS. Para o navegador, um div é só "um grupo qualquer" e um span é só "um trecho qualquer". Por isso eles se chamam elementos genéricos.

Isso importa porque o HTML não é lido só por olhos. Ele também é lido por:

  • Leitores de tela, os programas que leem a página em voz alta para quem não enxerga. Num <h2>, eles anunciam "título nível 2". Num <strong>, podem mudar o tom. Num div ou span, não anunciam nada (aula Leitores de Tela).
  • Buscadores, como o Google, que tentam entender do que a página fala (aula HTML e SEO).
  • Outras pessoas, que vão ler e mexer no seu código depois.

Compare dois jeitos de destacar "não abra o forno":

<p>Nos primeiros 30 minutos, <span class="aviso">não abra o forno</span>.</p>
<p>Nos primeiros 30 minutos, <strong>não abra o forno</strong>.</p>

No primeiro, o aviso parece um texto comum, para os olhos e para o leitor de tela. No segundo, o strong diz que o trecho é importante, e o navegador ainda o mostra em negrito sem nenhum CSS (aula Negrito e Itálico).

A regra do HTML: div e span são o último recurso

O próprio padrão do HTML (o HTML Living Standard) recomenda ver o div como um elemento "de último recurso": use-o só quando nenhum outro elemento serve. Antes de escrever um div ou um span, pergunte: "existe um elemento que diz o que isto é?".

Isso não quer dizer que div e span são ruins. Eles são o elemento certo quando o grupo existe só por causa da aparência: uma caixa colorida em volta de três elementos, uma palavra pintada de outra cor. O problema é usá-los no lugar de um elemento que já tem significado. Uma página feita só de div tem até apelido: "sopa de div". A aula HTML Semântico mostra a mesma página das duas formas.

Quando dá errado

O navegador quase nunca mostra um erro. Ele conserta o HTML do jeito dele, e às vezes o conserto muda a página de um jeito que você não esperava. O validador W3C é quem diz o que está errado.

error: No “p” element in scope but a “p” end tag seen.

A Ana quis deixar "com cobertura" numa caixa e colocou um div dentro de um parágrafo:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<p>Bolo de cenoura <div>com cobertura</div> de chocolate.</p>
</body>
</html>

"Não há nenhum elemento p aberto aqui". Mas o <p> foi aberto no começo da linha… O que aconteceu é que, ao ver o <div>, o leitor de HTML fechou o parágrafo sozinho, porque um parágrafo não pode ter um bloco dentro.
but a “p” end tag seen
"mas apareceu uma tag de fechamento </p>". Ela sobrou, e o navegador a transforma num parágrafo vazio.

Esta é a página que o navegador montou de verdade (o Chromium, sem janela, com --dump-dom):

<h1>Receitas da Ana</h1>
<p>Bolo de cenoura </p><div>com cobertura</div> de chocolate.<p></p>

Ficaram dois parágrafos (o segundo, vazio), e "de chocolate." ficou solto, fora de qualquer parágrafo. Na tela, a frase aparece quebrada em linhas. Você vai consertar isso na missão logo abaixo.

Como consertar: dentro de um parágrafo, use span (ou strong, em…), nunca div. Se o trecho precisa mesmo ser um bloco, tire-o do parágrafo.

error: Element “div” not allowed as child of element “span” in this context.

Agora o contrário: um div dentro de um span.

<!DOCTYPE html>
<html lang="pt-BR">
<head>

<title>Receitas da Ana</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<div class="receita">
  <span class="tempo">Tempo: <div>40 minutos</div></span>
</div>
</body>
</html>

$ vnu div-no-span.html
"file:/home/ana/receitas/div-no-span.html":10.30-10.34: error: Element “div” not allowed as child of element “span” in this context. (Suppressing further errors from this subtree.)

Element “div” not allowed as child of element “span” = "o elemento div não é permitido como filho do elemento span". Suppressing further errors from this subtree = "deixando de mostrar outros erros deste trecho": o validador para de olhar o que está dentro desse div.

Aqui o navegador não conserta nada: o Chromium montou a página com o div dentro do span, exatamente como está escrito. Na tela, "40 minutos" desce para a linha de baixo, e o erro passa despercebido. Só o validador avisa.

Como consertar: o que vai dentro de um span é texto e elementos de texto (strong, a, outro span). Troque o div de dentro por span, ou o span de fora por div.

"Apareceu o </body>, mas ainda havia elementos abertos". O validador só percebe o problema no fim da página. (O espaço duplo depois de for é do próprio validador.)

"Elemento div não fechado", e ele aponta a linha 9, onde a caixa sem fechamento começa. Comece o conserto por esta mensagem.

Na tela, a página parece normal. Mas o único </div> da linha 16 fechou a caixa do pão de queijo, e a caixa do bolo ficou aberta até o fim: o pão de queijo foi parar dentro da caixa do bolo. Com CSS, isso aparece na hora: a borda do bolo passa a envolver as duas receitas.

Como consertar: feche cada div antes de abrir o próximo grupo. Indentar o conteúdo (os dois espaços antes do <h2>) ajuda a ver onde cada caixa começa e termina. No editor de código, clicar numa tag de abertura costuma destacar a de fechamento correspondente.

Nenhum erro, mas um problema: div no lugar de um elemento com significado

Um <div class="titulo">Receitas da Ana</div> no lugar de <h1> passa no validador sem nenhuma mensagem. O mesmo vale para um <div class="botao">Enviar</div> no lugar de um botão: o validador fica calado, mas quem usa só o teclado não consegue chegar nele com a tecla Tab, e o leitor de tela não diz que é um botão.

Como consertar: o validador confere as regras, não o significado. Quem escolhe o elemento certo é você: título é h1…h6, botão é button (aula Botões), link é a.

Missão: este é o erro do primeiro cenário. Olhe o resultado: a frase saiu quebrada, porque o navegador fechou o parágrafo ao ver o div. Troque o div por um span, para a frase voltar a ser um parágrafo só, sem nenhum parágrafo vazio sobrando.

<h1>Receitas da Ana</h1>
<p>Bolo de cenoura <div>com cobertura</div> de chocolate.</p>
<p>Rende 12 fatias.</p>

<h1>Receitas da Ana</h1>
<p>Bolo de cenoura <span>com cobertura</span> de chocolate.</p>
<p>Rende 12 fatias.</p>

Repare que a missão confere a página que o navegador montou: com o div, existem três parágrafos (um deles vazio); com o span, só os dois que você escreveu.

Resumo

  • div é uma caixa genérica para blocos: junta títulos, parágrafos e listas num grupo.
  • span é uma marcação genérica para um trecho do texto, dentro de um parágrafo.
  • Sozinhos, os dois são invisíveis. Eles servem para dar um nome (class) e um lugar para o CSS e o JavaScript agirem.
  • Eles não têm significado: o leitor de tela e o buscador não sabem o que há ali. Use-os só quando nenhum outro elemento serve.
  • div dentro de p: o navegador fecha o parágrafo sozinho, e o validador diz No “p” element in scope but a “p” end tag seen.
  • div dentro de span: o navegador aceita, mas o validador diz Element “div” not allowed as child of element “span”. Um div sem fechar dá Unclosed element “div”.
