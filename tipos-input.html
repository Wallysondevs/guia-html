HTML Tipos de input

Na aula anterior, o <input> foi comparado a um carregador com pontas trocáveis, e a ponta é o atributo type. Agora é hora de conhecer as pontas: o campo de e-mail que confere o @, o de número com setinhas, o calendário, o seletor de cor, o botão de escolher arquivo. Trocar uma palavra no código dá ao seu formulário um teclado certo no celular, uma conferência antes do envio e um campo mais fácil de preencher, sem nenhuma linha de JavaScript.

Você vai aprender
  • Os tipos de texto: text, search, email, tel, url e password.
  • Os de número: number e range (com min, max e step).
  • Os de data e hora: date, time, datetime-local, month e week, e por que o value é sempre 2026-10-17, mesmo que a tela mostre 17/10/2026.
  • O color, o file e o hidden.
  • Onde estão os outros (checkbox, radio, submit…).
  • O que o navegador faz com um value no formato errado, e o que o validador W3C diz (e o que ele não pega).

Os exemplos foram validados com o validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook); o que o navegador faz com valores errados foi conferido no Chromium. Os quadros "Resultado" são desenhados pelo seu navegador, então o que você vê depende dele.

Cada navegador desenha do seu jeito

O calendário do date, a paleta do color, as setinhas do number e o botão do file são desenhados pelo navegador e pelo sistema, e mudam bastante entre o Chrome, o Firefox e o Safari, entre o Windows, o Mac e o Linux, e entre o computador e o celular. Por isso esta aula descreve o que cada campo faz, e não o desenho dele. Abra esta página em dois navegadores e compare.

A ideia: o campo certo para cada pergunta

Numa ficha de papel, a pergunta "Data de nascimento" costuma vir com quadradinhos: __/__/____. Ninguém escreve "dia de São João" ali, porque o desenho da linha já mostra o que se espera. Os tipos de <input> fazem isso, e mais: no celular, abrem o teclado de números para o telefone, e, antes de enviar, o navegador confere se o e-mail tem @.

1. Tipos de texto

<p><label for="busca">Buscar:</label> <input type="search" id="busca" name="q"></p>
<p><label for="email">E-mail:</label> <input type="email" id="email" name="email"></p>
<p><label for="tel">Celular:</label> <input type="tel" id="tel" name="tel"></p>
<p><label for="site">Seu site:</label> <input type="url" id="site" name="site"></p>
<p><label for="senha">Senha:</label> <input type="password" id="senha" name="senha"></p>
typeParaO que muda
textQualquer texto de uma linhaNada: é o padrão.
searchUma buscaMuitos navegadores mostram um "x" para limpar o campo quando há texto, e o Esc limpa. No celular, a tecla Enter pode virar "Buscar". O leitor de tela anuncia "campo de busca".
emailUm e-mailO navegador confere se tem cara de e-mail (um @ com algo antes e depois) e não envia se não tiver. No celular, o teclado ganha o @.

urlUm endereço de siteConfere se é um endereço completo, com https:// na frente. No celular, o teclado ganha / e .com.
passwordUma senhaEsconde o que é digitado. Os gerenciadores de senha do navegador reconhecem o campo.

Teste no resultado: digite "ana" no e-mail e "www.exemplo.com.br" no site. Nada acontece ainda, porque não há botão de enviar. A conferência aparece na hora do envio, como você vai ver no Experimente logo abaixo.

CPF, CEP e cartão não são number

Um CEP tem só algarismos, mas não é um número: ninguém soma CEPs, e o zero da frente importa (01310-100). Para esses códigos, use type="text" e, se quiser o teclado numérico no celular, o atributo inputmode="numeric". O type="number" é para quantidades: idade, fatias, quilos.

Missão: todos os campos estão como text. Troque o tipo do e-mail para email, o do celular para tel e o do site para url. Depois escreva "ana" no e-mail e clique em Enviar: o navegador não deixa enviar e mostra um aviso (o texto do aviso é do seu navegador). Corrija para "ana@exemplo.com.br" e envie de novo.

  <p><label for="email">E-mail:</label> <input type="text" id="email" name="email"></p>
  <p><label for="tel">Celular:</label> <input type="text" id="tel" name="tel"></p>
  <p><label for="site">Seu site:</label> <input type="text" id="site" name="site"></p>
  <button>Enviar</button>
</form>

A conferência do navegador ajuda a pessoa a não errar, mas ela pode ser desligada por quem entende um pouco de HTML. O servidor sempre precisa conferir de novo. Mais sobre isso em Validação.

2. Números: number e range

<p>
  <label for="fatias">Fatias:</label>
  <input type="number" id="fatias" name="fatias" min="1" max="24" value="8">
</p>
<p>
  <label for="peso">Peso (kg):</label>
  <input type="number" id="peso" name="peso" min="0.5" step="0.5" value="1.5">
</p>
<p>
  <label for="doce">Doçura:</label>
  <input type="range" id="doce" name="doce" min="0" max="10" value="7">
</p>
type="number"
Só aceita números. Muitos navegadores mostram setinhas para aumentar e diminuir, e as setas do teclado fazem o mesmo. No celular, abre o teclado numérico.
min="1" max="24"
O menor e o maior valor permitidos. As setinhas param nesses limites, e o navegador não envia um valor fora deles (aula Validação).
step="0.5"
O "passo": de quanto em quanto o valor anda. Sem step, o passo é 1, e um valor como 1.5 seria recusado no envio.
value="1.5"
No código, número com casa decimal usa ponto, como no inglês. O que o navegador mostra na tela pode seguir o seu idioma, mas o value e o que vai no envio usam ponto.
type="range"
Uma barrinha de arrastar, para quando o valor exato importa pouco ("mais doce, menos doce"). Ela não mostra o número escolhido. Sem min e max, vai de 0 a 100; sem value, começa no meio (50).

3. Datas e horas

<p><label for="dia">Dia da entrega:</label> <input type="date" id="dia" name="dia" value="2026-10-24"></p>
<p><label for="hora">Horário:</label> <input type="time" id="hora" name="hora" value="15:00"></p>
<p><label for="festa">Início da festa:</label> <input type="datetime-local" id="festa" name="festa" value="2026-10-24T19:30"></p>
<p><label for="mes">Mês da assinatura:</label> <input type="month" id="mes" name="mes" value="2026-11"></p>
<p><label for="semana">Semana:</label> <input type="week" id="semana" name="semana" value="2026-W43"></p>
typeEscolheFormato do value (e do envio)
dateum dia2026-10-24
timeuma hora15:00
datetime-localdia e hora, sem fuso horário2026-10-24T19:30
monthum mês2026-11
weekuma semana do ano2026-W43

Reconhece esses formatos? São os mesmos do atributo datetime da aula time e data: ano-mês-dia, com dois dígitos e do maior para o menor. Duas coisas confundem no começo:

  • A tela e o código são diferentes. O campo mostra a data no formato do idioma do navegador ou do sistema (em português, 24/10/2026; num navegador em inglês dos Estados Unidos, 10/24/2026), mas o value no código e o que vai no envio são sempre 2026-10-24. Você escreve um formato só, e cada pessoa vê o seu.
  • O seletor depende do navegador. O calendário que abre, a roda de horas do celular, até o ícone: tudo muda. O month e o week ainda não têm seletor em todos os navegadores; onde não têm, aparecem como uma caixa de texto comum. Para eles, teste no navegador do seu público ou use dois campos (select de mês e number de ano).

4. Cor, arquivo e escondido

<form action="bolo.html" method="post" enctype="multipart/form-data">
  <p>
    <label for="cor">Cor da cobertura:</label>
    <input type="color" id="cor" name="cor" value="#ff8800">
  </p>
  <p>
    <label for="foto">Foto de inspiração:</label>
    <input type="file" id="foto" name="foto" accept="image/*">
  </p>
  <input type="hidden" name="origem" value="site">
  <button>Enviar pedido</button>
</form>
type="color"
Abre o seletor de cores do navegador ou do sistema. O value é a cor em hexadecimal: # e seis algarismos de 0 a 9 e letras de a até f (#ff8800 é um laranja). Sem value, começa preto (#000000).
type="file"
Um botão para escolher um arquivo do computador ou do celular (no celular, pode oferecer a câmera). O texto do botão ("Escolher arquivo", "Procurar…") é do navegador, no idioma dele.
accept="image/*"
"Aceitar": sugere quais arquivos mostrar. image/* = qualquer imagem; também vale uma lista como .pdf,.jpg. É só uma sugestão para a janela de escolha.
method="post" enctype="multipart/form-data"
Para o arquivo ir junto no envio, o formulário precisa dessas duas coisas: post e o enctype ("tipo de codificação") que divide a mensagem em partes. Sem elas, vai só o nome do arquivo. Detalhes em Enviar.
type="hidden"
Um campo escondido: não aparece na tela, mas vai no envio (origem=site). Serve para dados que o site precisa e a pessoa não precisa ver, como de qual página o pedido veio. Escondido não é secreto: qualquer pessoa vê o valor no código da página.

Escolha uma cor e um arquivo e clique em "Enviar pedido": na tabela do editor, o arquivo aparece com o nome e o tamanho em bytes, e o origem aparece mesmo sem nunca ter estado na tela.

Experimente: um campo de cada tipo. Mexa em todos e envie para ver o que cada um manda. Depois troque um type por outro (por exemplo, o range por number) e veja o mesmo dado num campo diferente. Se tiver outro navegador, abra esta página nele e compare os desenhos.

<form action="teste.html">
  <p><label for="a">search:</label> <input type="search" id="a" name="busca"></p>
  <p><label for="b">number:</label> <input type="number" id="b" name="numero" value="3"></p>
  <p><label for="c">range:</label> <input type="range" id="c" name="faixa"></p>
  <p><label for="d">date:</label> <input type="date" id="d" name="dia"></p>
  <p><label for="e">time:</label> <input type="time" id="e" name="hora"></p>
  <p><label for="f">color:</label> <input type="color" id="f" name="cor"></p>
  <p><label for="g">password:</label> <input type="password" id="g" name="senha"></p>
  <input type="hidden" name="escondido" value="eu existo">
  <button>Enviar</button>
</form>

Quando dá errado

Nos tipos especiais, o value tem de estar no formato do tipo. Quando não está, o navegador não avisa a pessoa: ele simplesmente descarta o valor (ou o troca por outro). As páginas abaixo têm o esqueleto de sempre nas linhas 1 a 7, um <label> na linha 8 e o <input> na linha 9. Nos quadros "Resultado", veja com os próprios olhos o que o seu navegador faz.

Data no formato brasileiro: value="17/10/2026" 
<label for="entrega">Entrega:</label>
<input type="date" id="entrega" name="entrega" value="17/10/2026">

$ vnu data.html
"file:/home/ana/tipos/data.html":9.1-9.66: error: Bad value “17/10/2026” for attribute “value” on element “input”: The literal did not satisfy the date format.

O que o navegador faz: o campo aparece vazio, como se não houvesse value. No Chrome, o console das Ferramentas do Desenvolvedor (F12) mostra um aviso: The specified value "17/10/2026" does not conform to the required format, "yyyy-MM-dd". ("o valor não segue o formato exigido, ano-mês-dia").

Como consertar: value="2026-10-17". A pessoa continua vendo 17/10/2026.

Vírgula no número: value="1,5" 
<label for="peso">Peso (kg):</label>
<input type="number" id="peso" name="peso" value="1,5">

$ vnu numero.html
"file:/home/ana/tipos/numero.html":9.1-9.55: error: Bad value “1,5” for attribute “value” on element “input”: Expected a decimal point, “e”, “E” or a digit but saw “,” instead.

O validador diz: "Esperava um ponto decimal, um e ou um algarismo, mas encontrou uma vírgula". (O e é da notação científica, como 1e3 = 1000.)

O que o navegador faz: campo vazio. O Chrome avisa no console: The specified value "1,5" cannot be parsed, or is out of range.

Como consertar: value="1.5" e, como o passo padrão é 1, step="0.5" (ou step="any", "qualquer").

Cor por nome: value="red" 
$ vnu cor.html
"file:/home/ana/tipos/cor.html":9.1-9.52: error: Bad value “red” for attribute “value” on element “input”: Incorrect length for color string.

O validador diz: "Tamanho errado para uma cor": ele espera exatamente # + 6 caracteres.

O que o navegador faz: depende do navegador, e é por isso que este exemplo não tem quadro "Resultado". No Chromium usado para conferir este guia, red foi aceito e virou #ff0000, porque os navegadores recentes começaram a aceitar nomes de cor do CSS nesse campo. Navegadores mais antigos descartam o valor e mostram preto (#000000).

Como consertar: escreva sempre em hexadecimal: value="#ff0000". Funciona em todos e passa no validador.

Um tipo que não existe mais: type="datetime" 
$ vnu datetime.html
"file:/home/ana/tipos/datetime.html":9.1-9.49: error: Bad value “datetime” for attribute “type” on element “input”.

O que significa: o datetime (com fuso horário) chegou a existir num rascunho do HTML5 e foi removido. Muitos tutoriais antigos ainda o usam. O navegador o trata como tipo desconhecido, ou seja, text.

Como consertar: type="datetime-local".

Endereço sem https:// 
$ vnu url.html
"file:/home/ana/tipos/url.html":9.1-9.67: error: Bad value “www.exemplo.com.br” for attribute “value” on element “input”: The string “www.exemplo.com.br” is not an absolute URL.

O que significa: "Não é um endereço absoluto". No type="url", endereço válido é completo: https://www.exemplo.com.br (aula Caminhos).

O que o navegador faz: mostra o valor, mas o considera inválido e não deixa enviar o formulário até alguém consertar.

O que o validador não pega

Estas duas linhas passaram no validador sem nenhum erro:

$ sed -n 9p email.html
<input type="email" id="email" name="email" value="ana.exemplo.com.br">
$ vnu email.html
$ sed -n 9p faixa.html
<input type="range" id="doce" name="doce" min="0" max="10" value="15">
$ vnu faixa.html
  • O e-mail sem @: o validador não confere o value de um type="email". O navegador confere, e não deixa enviar.
  • O value="15" com max="10": o navegador põe a barrinha no máximo, e o valor vira 10, sem aviso.

Por isso, além de validar, teste o formulário de verdade: preencha, envie e confira o que chegou.

Resumo

  • Texto: text (padrão), search, email (confere o @), tel (teclado de números, sem conferência), url (endereço completo) e password (esconde).
  • Números: number (com min, max, step; decimal com ponto) e range (barrinha, 0 a 100, não mostra o número). Códigos como CEP e CPF são text.
  • Datas: date, time, datetime-local, month, week. O value é sempre ano-mês-dia (2026-10-24); a tela mostra no formato do idioma de quem vê.
  • color (#rrggbb), file (precisa de post + multipart/form-data) e hidden (vai no envio, mas não é secreto).
  • Um value fora do formato é descartado sem aviso para a pessoa; o validador acusa Bad value … for attribute “value”. A aparência de cada campo muda de um navegador e de um sistema para outro.
