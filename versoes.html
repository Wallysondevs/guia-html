HTML Versões

Procurando HTML na internet, você vai esbarrar em "HTML 4.01", "XHTML", "HTML5"… e talvez fique em dúvida sobre qual aprender. A resposta curta: o HTML de hoje não tem número. Ele se chama HTML Living Standard ("padrão vivo"), é atualizado o tempo todo e é o que este guia ensina. Nesta aula você conhece a história da linguagem, entende por que ela parou de ter versões e aprende a reconhecer um código antigo pela primeira linha, para não copiar coisas que já saíram de moda.

Você vai aprender
  • A linha do tempo do HTML, com as datas oficiais: 2.0, 3.2, 4.01, XHTML, HTML5 e o Living Standard.
  • Quem cuida do HTML: o W3C e o WHATWG.
  • O que quer dizer "padrão vivo" e por que não existe HTML6.
  • Como reconhecer a época de uma página pelo <!DOCTYPE>.
  • Os elementos obsoletos (<font>, <center>, <marquee>…) e o que usar no lugar.
  • O estilo do XHTML (<br />) e o que o validador diz dele.

As datas desta aula foram conferidas nos documentos oficiais: as próprias especificações publicadas pelo W3C, a RFC 1866 da IETF e a seção de história da especificação do WHATWG. As mensagens do validador vieram do vnu na máquina fictícia da Ana, na pasta ~/site.

A ideia: o dicionário impresso e o dicionário on-line

Antigamente, quem queria saber o significado de uma palavra comprava um dicionário impresso, de uma certa edição. Palavras novas só entravam na edição seguinte, anos depois. Hoje, os dicionários on-line são atualizados o tempo todo: uma palavra nova aparece assim que vira uso comum, sem esperar a "próxima edição".

O HTML passou pela mesma mudança. Até 2014 ele tinha edições numeradas (HTML 2.0, 3.2, 4.01, 5). Hoje ele é como o dicionário on-line: um documento único, o Living Standard, corrigido e ampliado continuamente. E, como num idioma, as palavras antigas continuam sendo entendidas: uma página escrita em 1997 ainda abre num navegador de hoje.

Uma linguagem que todos os navegadores do mundo precisam entender do mesmo jeito precisa de um "dono" que escreva as regras. Ao longo da história, foram três:

O que o HTML5 mudou

O HTML5 foi a maior mudança da história da linguagem, e quase tudo do que você vai aprender no Nível 2 nasceu com ele:

  • Elementos com significado para as partes da página: header, nav, main, article, section, aside, footer (seção Semântica).
  • Áudio e vídeo sem plugin, com <audio> e <video> (aulas Áudio e Vídeo). Antes, era preciso o Flash.
  • Novos tipos de campo de formulário (e-mail, data, número…) e validação no próprio navegador (Tipos de input).
  • O canvas, para desenhar com JavaScript (canvas).
  • Um DOCTYPE curto: <!DOCTYPE html>, em vez das linhas enormes de antes.
  • As regras de leitura que dizem exatamente o que fazer com HTML errado, as mesmas em todos os navegadores (aula Como o Navegador Lê HTML).

E o Living Standard continua crescendo. O atributo popover (balões que abrem por cima da página), por exemplo, chegou aos navegadores principais entre 2023 e 2024, sem nenhum "HTML 6". A aula Novidades do HTML acompanha essas chegadas.

Por que não existe HTML6

Porque não precisa. No modelo do padrão vivo, um recurso novo entra na especificação quando os navegadores se comprometem a implementá-lo, e não quando chega "a próxima versão". Cada recurso tem a sua própria história: alguns já funcionam em todos os navegadores, outros só nos mais novos.

Então, em vez de perguntar "o meu navegador suporta HTML5?", a pergunta certa é "o meu navegador suporta o elemento <dialog>?". Dois sites respondem isso, com tabelas por navegador e por versão:

  • MDN Web Docs (developer.mozilla.org), a documentação da Mozilla, com uma tabela de compatibilidade no fim da página de cada elemento;
  • Can I use (caniuse.com), feito só para essa pergunta.
E a palavra "HTML5"?

Ela ficou famosa, e muita gente ainda diz "HTML5" querendo dizer "HTML moderno". Tudo bem: quando você vê "curso de HTML5", entenda "HTML de hoje". Mas, tecnicamente, o HTML5 do W3C de 2014 já foi substituído. O que vale é o Living Standard, e é ele que o validador confere.

Reconhecer a época pelo DOCTYPE

A primeira linha de uma página, o <!DOCTYPE>, é como a data na capa de um livro: ela conta de que época é o código. Cada versão tinha o seu:

VersãoDOCTYPE
HTML 4.01 Strict<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN" "http://www.w3.org/TR/html4/strict.dtd">
HTML 4.01 Transitional<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" "http://www.w3.org/TR/html4/loose.dtd">
XHTML 1.0 Strict<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Strict//EN" "http://www.w3.org/TR/xhtml1/DTD/xhtml1-strict.dtd">
HTML5 e Living Standard<!DOCTYPE html>

Se um tutorial começa com uma daquelas linhas compridas, ele é anterior a 2010, mais ou menos, e provavelmente ensina coisas que hoje são erro. O DOCTYPE tem aula própria (O DOCTYPE); aqui, veja o que o validador diz de uma página antiga, um HTML 4.01 Transitional típico dos anos 2000:

<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" "http://www.w3.org/TR/html4/loose.dtd">
<html lang="pt-BR">
<head>
<meta http-equiv="Content-Type" content="text/html; charset=utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<center><font color="red" size="6">Receitas da Ana</font></center>
<p>Bolo de cenoura<br>com cobertura de chocolate.</p>
</body>
</html>

O seu navegador desenhou o título vermelho e centralizado: ele ainda entende <font> e <center>, para não quebrar as páginas antigas da internet. Mas o validador confere as regras de hoje:

$ vnu index.html
"file:/home/ana/site/index.html":1.1-1.102: error: Almost standards mode doctype. Expected “<!DOCTYPE html>”.
"file:/home/ana/site/index.html":8.1-8.8: error: The “center” element is obsolete. Use CSS instead.
"file:/home/ana/site/index.html":8.9-8.35: error: The “font” element is obsolete. Use CSS instead.
Almost standards mode doctype.
"DOCTYPE do modo 'quase padrão'". Esse DOCTYPE antigo faz o navegador ligar um modo de compatibilidade com pequenas diferenças de desenho. Expected “<!DOCTYPE html>” = "esperava <!DOCTYPE html>".
The “center” element is obsolete.
"O elemento center é obsoleto": não faz mais parte do HTML. Use CSS instead = "use CSS no lugar".
The “font” element is obsolete.
O mesmo para o font. Cor e tamanho de letra são trabalho do CSS.

Repare no que o validador não reclamou: o <meta http-equiv="Content-Type" …> ainda é aceito (hoje se escreve mais curto, <meta charset="utf-8">), e o <br> continua valendo. Atualizar uma página antiga quase sempre é trocar o DOCTYPE e tirar os elementos de aparência.

O estilo do XHTML: <br />

Na época do XHTML, todo elemento tinha de ser fechado, até os que não têm conteúdo. Por isso se escrevia <br /> (com barra) em vez de <br>. Você ainda vê isso em muito código, inclusive em código novo. Veja uma página XHTML 1.0 no validador de hoje:

<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Strict//EN" "http://www.w3.org/TR/xhtml1/DTD/xhtml1-strict.dtd">
<html xmlns="http://www.w3.org/1999/xhtml" lang="pt-BR" xml:lang="pt-BR">
<head>
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<title>Receitas da Ana</title>
</head>
<body>
<p>Bolo de cenoura<br />com cobertura.</p>
</body>
</html>

$ vnu index.html
"file:/home/ana/site/index.html":1.1-1.109: error: Obsolete doctype. Expected “<!DOCTYPE html>”.
"file:/home/ana/site/index.html":4.1-4.69: info: Trailing slash on void elements has no effect and interacts badly with unquoted attribute values.
"file:/home/ana/site/index.html":8.19-8.24: info: Trailing slash on void elements has no effect and interacts badly with unquoted attribute values.

O único erro é o DOCTYPE (Obsolete doctype, "DOCTYPE obsoleto"). As barras ganharam só um info, uma informação: "a barra no fim de elementos vazios não tem efeito e se dá mal com valores de atributo sem aspas". Ou seja: <br /> não está errado, mas a barra não faz nada. O guia escreve <br>, sem barra, que é a forma do HTML. Os elementos "vazios" (void elements, como br, img e meta) são explicados em Elementos e Tags.

Elementos obsoletos

Vários elementos foram retirados do HTML ao longo das versões, quase sempre porque cuidavam da aparência (que agora é trabalho do CSS) ou porque atrapalhavam a acessibilidade. Os navegadores ainda desenham a maioria deles, para as páginas velhas não quebrarem, mas o validador acusa erro. Veja alguns no seu navegador:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<marquee>Promoção de bolo!</marquee>
<p><big>Grande</big> <tt>fixo</tt> <strike>riscado</strike> <acronym title="Hypertext Markup Language">HTML</acronym></p>
<p align="center">Centro</p>
</body>
</html>

O <marquee> faz o texto correr pela tela (um clássico dos sites dos anos 1990), e os outros mudam a letra. Tudo "funciona". Agora o validador:

$ vnu index.html
"file:/home/ana/site/index.html":8.1-8.9: error: The “marquee” element is obsolete. Use CSS instead.
"file:/home/ana/site/index.html":9.4-9.8: error: The “big” element is obsolete. Use CSS instead.
"file:/home/ana/site/index.html":9.22-9.25: error: The “tt” element is obsolete. Use CSS instead.
"file:/home/ana/site/index.html":9.36-9.43: error: The “strike” element is obsolete. Use “del” or “s” element instead.
"file:/home/ana/site/index.html":9.61-9.103: error: The “acronym” element is obsolete. Use the “abbr” element instead.
"file:/home/ana/site/index.html":10.1-10.18: info warning: The “align” attribute on the “p” element is obsolete. Use CSS instead.

Repare que o validador nem sempre manda "use CSS": para o strike, ele indica os elementos del ou s; para o acronym, o abbr. E o atributo align, também obsoleto, ganhou um aviso (info warning). A tabela resume as trocas:

Qual versão usar?

Sempre o HTML Living Standard, e você não precisa fazer nada de especial para isso. Na prática, "usar o HTML de hoje" quer dizer:

  1. Começar toda página com <!DOCTYPE html>.
  2. Usar <meta charset="utf-8">.
  3. Não usar elementos obsoletos: o validador avisa quando escapa algum.
  4. Desconfiar de tutoriais com DOCTYPE comprido, <font>, <center> ou tabelas usadas para montar o layout da página.
  5. Antes de usar um recurso muito novo, conferir na MDN ou no Can I use se os navegadores do seu público já o suportam.

Quando dá errado

error: Obsolete doctype. Expected “<!DOCTYPE html>”. / Almost standards mode doctype

O que significa: a página começa com um DOCTYPE de uma versão antiga (HTML 4, XHTML). O navegador desenha a página, às vezes num modo de compatibilidade, e o validador recusa.

Como consertar: troque a primeira linha inteira por <!DOCTYPE html>. Não precisa mexer no resto para isso.

error: Start tag seen without seeing a doctype first. 
$ vnu index.html
"file:/home/ana/site/index.html":1.1-1.19: error: Start tag seen without seeing a doctype first. Expected “<!DOCTYPE html>”.

O que significa: "vi uma tag antes de ver um DOCTYPE". A página não tem DOCTYPE nenhum. Sem ele, o navegador liga o modo quirks ("modo das manias"): ele imita os erros dos navegadores dos anos 1990, e várias coisas do CSS passam a se comportar de um jeito diferente. Você pode ver o modo em que o navegador está pelo JavaScript, com document.compatMode: BackCompat = quirks; CSS1Compat = padrão. Rode a caixa abaixo e depois acrescente <!DOCTYPE html> na primeira linha:

<html lang="pt-BR">
<head>
<meta charset="utf-8">
<title>Receitas da Ana</title>
</head>
<body>
<h1>Receitas da Ana</h1>
<script>console.log("Modo do navegador:", document.compatMode);</script>
</body>
</html>

Como consertar: <!DOCTYPE html> na primeira linha, sempre. O console deve passar a mostrar CSS1Compat.

error: The “font” element is obsolete. Use CSS instead.

O que significa: você usou um elemento que saiu do HTML (o mesmo vale para center, big, tt, marquee…). Quase sempre ele veio de um tutorial antigo ou de um código copiado.

Como consertar: veja a tabela de trocas acima. Se o elemento só mudava a aparência, tire-o e deixe a aparência para o CSS (quer aprender mais? futuro Guia CSS). Se ele tinha um significado (um título, um texto apagado), use o elemento certo para esse significado.

info: Trailing slash on void elements has no effect…

O que significa: você escreveu <br />, <img … /> ou <meta … />, no estilo do XHTML. Não é erro: é só uma informação de que a barra não faz nada.

Como consertar: não é obrigatório, mas o guia recomenda tirar a barra (<br>). Ela engana: quem lê acha que fecha alguma coisa, e não fecha.

Resumo

  • O HTML teve versões numeradas: 2.0 (1995, IETF), 3.2 e 4.0 (1997), 4.01 (1999), XHTML 1.0 (2000), HTML5 (2014), 5.1 e 5.2.
  • Desde 2019, o HTML é escrito só pelo WHATWG, como HTML Living Standard: um padrão vivo, sem número, atualizado continuamente. É o que o guia ensina e o que o validador confere.
  • Não existe HTML6: cada recurso novo entra quando os navegadores o implementam. Para saber se um recurso funciona, consulte a MDN ou o Can I use.
  • O DOCTYPE revela a época da página. O de hoje é <!DOCTYPE html>; os antigos dão erro, e sem DOCTYPE o navegador entra no modo quirks.
  • Elementos de aparência como <font> e <center> são obsoletos: o navegador ainda desenha, o validador recusa. A aparência é trabalho do CSS.
  • <br /> (estilo XHTML) não é erro, mas a barra não faz nada; o guia escreve <br>.
