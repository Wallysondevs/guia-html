HTML datalist

A Ana faz bolo de qualquer sabor, mas quase todo mundo pede cenoura, chocolate ou laranja. Um <select> obrigaria a escolher entre esses três, e a cliente que quer bolo de abacaxi ficaria sem opção. Um campo de texto livre aceita abacaxi, mas não ajuda quem só quer o de sempre. O <datalist> ("lista de dados") junta as duas coisas: o campo continua livre, e o navegador mostra sugestões enquanto a pessoa digita. Nesta aula você vai ligar uma lista de sugestões a um campo, ver o que é enviado e onde o datalist funciona (e onde não).

Você vai aprender
  • Como criar uma lista de sugestões com <datalist> e ligá-la a um campo com o atributo list.
  • Por que o campo continua aceitando qualquer texto, e o que é enviado.
  • A diferença entre o value e o texto de uma sugestão.
  • Como usar sugestões em outros tipos de campo, como number e range.
  • Quando usar <datalist> e quando usar <select>.
  • Os erros mais comuns e as mensagens reais do validador W3C.

Você vai precisar de O Elemento input, Tipos de input e select e option. Os exemplos com o resultado embaixo são desenhados pelo seu navegador. Os comportamentos foram conferidos no Chromium 155, e as validações com o validador W3C (vnu) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/site.

A ideia: "os mais pedidos são…"

Você chega na sorveteria e pergunta: "que sabor você recomenda?". O atendente responde: "os mais pedidos são morango, chocolate e flocos". Você pode escolher um deles, ou pedir pistache, que não estava na fala dele. Ele sugeriu, mas não limitou.

É isso que o <datalist> faz. Você já viu algo parecido na caixa de busca de muitos sites: enquanto você digita, aparece uma listinha de sugestões embaixo, e você pode clicar numa ou continuar digitando a sua.

1. O primeiro datalist

São duas peças: o campo (um <input> comum) e a lista (o <datalist>). Quem liga uma à outra é o atributo list do campo, que repete o id da lista:

<label for="sabor">Sabor do bolo:</label>
<input type="text" id="sabor" name="sabor" list="sabores">

<datalist id="sabores">
  <option value="Cenoura"></option>
  <option value="Chocolate"></option>
  <option value="Laranja"></option>
</datalist>

No resultado aparece só o campo: o <datalist> é invisível (no Chromium 155, o estilo dele é display: none). Clique no campo e digite c: a lista de sugestões aparece embaixo, já filtrada pelo que você digitou. Clique numa sugestão e ela vai para o campo. Agora apague e escreva Abacaxi: o campo aceita normalmente.

Em muitos navegadores, as sugestões também aparecem com um clique no campo vazio, ou com a seta ↓ do teclado, e alguns desenham uma setinha no canto do campo. Os detalhes de aparência mudam de navegador para navegador, e no celular a lista costuma aparecer em cima do teclado.

list="sabores"
No campo: "minhas sugestões estão no datalist de id sabores". É parecido com o for do <label>: um atributo que aponta para um id.
<datalist id="sabores">
A lista de sugestões. O id é o que o list procura. O <datalist> pode ficar em qualquer lugar da página, mas o costume é logo depois do campo.
<option value="Cenoura"></option>
Uma sugestão. O value é o texto que vai para o campo quando a pessoa clica nela. A tag </option> pode ser omitida (<option value="Cenoura"> sozinho é válido), e você vai ver muito código assim.

O que é enviado

O <datalist> não tem name e não é enviado. Quem é enviado é o campo, com o que estiver escrito nele, tenha vindo de uma sugestão ou não: sabor=Chocolate ou sabor=Abacaxi. Para quem recebe, não há diferença.

2. O value e o texto da sugestão

Uma <option> do datalist pode ter, além do value, um texto entre as tags. Os dois têm papéis diferentes:

<label for="tamanho">Fatias:</label>
<input type="text" id="tamanho" name="tamanho" list="tamanhos">

<datalist id="tamanhos">
  <option value="10">Pequeno</option>
  <option value="20">Médio</option>
  <option value="30">Grande</option>
</datalist>
  • O value é o que entra no campo (e depois é enviado): 20.
  • O texto ("Médio") é uma explicação mostrada na lista. Cada navegador a mostra do seu jeito: ao lado do valor, embaixo dele, ou só ela.

Abra a lista no resultado e veja como o seu navegador mostrou. Escolha "Médio": o que aparece no campo é o número 20. Sem o value, o texto vira o valor (<option>Chocolate</option> sugere "Chocolate"), como no select.

3. Sugestões em outros tipos de campo

O list funciona em vários tipos de <input> (aula Tipos de input): text, search, email, url, tel, number, range, color, date, time, datetime-local, month e week. O validador traz essa lista completa na mensagem de erro, que você vai ver adiante. O efeito muda com o tipo.

Num range: marquinhas na régua

Num controle deslizante (type="range"), as sugestões viram marcas na régua:

<label for="fatias">Fatias:</label>
<input type="range" id="fatias" name="fatias" min="10" max="30" step="5" list="marcas">

<datalist id="marcas">
  <option value="10"></option>
  <option value="20"></option>
  <option value="30"></option>
</datalist>

No Chromium 155, o controle ganhou três tracinhos embaixo da régua, no 10, no 20 e no 30. Nem todo navegador desenha as marcas; quando não desenha, o controle funciona igual, só sem os tracinhos.

Num email: os domínios mais comuns

<label for="email">E-mail:</label>
<input type="email" id="email" name="email" list="emails">

<datalist id="emails">
  <option value="ana@example.com"></option>
  <option value="ana.padaria@example.com"></option>
</datalist>

Repare que, no email, as sugestões são endereços inteiros. O datalist sugere o valor do campo todo, e não um pedaço dele.

O navegador também sugere sozinho

Os navegadores guardam o que você já digitou em campos parecidos e oferecem de novo: é o preenchimento automático, controlado pelo atributo autocomplete (aula placeholder, value, autocomplete…). Num campo com list, as sugestões do navegador e as do datalist podem aparecer juntas na mesma lista.

4. O que o datalist não faz

  • Não obriga a escolher uma sugestão. Se a resposta tem de ser uma das opções, use <select> ou rádios (aulas select e option e checkbox e radio). Para regras do tipo "tem de ser um número de 10 a 30", use a validação (aula Validação).
  • Não muda de aparência com CSS: a lista de sugestões é desenhada pelo navegador.
  • Não é igual em todo lugar: o jeito de filtrar, a forma de abrir a lista e o que é anunciado pelo leitor de tela mudam de um navegador para outro. Por isso, o campo tem de funcionar bem mesmo para quem nunca vê as sugestões: um bom <label> e, se ajudar, um exemplo no texto.

Quando dá errado

Os arquivos desta seção são páginas completas com o mesmo começo de 7 linhas (<!DOCTYPE html> até <body>, como em Estrutura de uma Página). O código mostrado começa na linha 8.

O list não bate com o id 
<label for="sabor">Sabor:</label>
<input type="text" id="sabor" name="sabor" list="sabores-lista">
<datalist id="sabores">
  <option value="Cenoura"></option>
</datalist>

$ vnu lista.html
"file:/home/ana/site/lista.html":9.1-9.64: error: The “list” attribute of the “input” element must refer to a “datalist” element.

O que significa: "o atributo list do elemento input precisa apontar para um elemento datalist". Não existe nenhum id="sabores-lista".

O que o navegador faz: nada de errado aparece. O campo funciona, só que sem sugestões. É um erro silencioso: só o validador (ou um teste com atenção) mostra.

Como consertar: o list e o id com o mesmo texto, letra por letra.

O list apontando para um select 
<label for="sabor">Sabor:</label>
<input type="text" id="sabor" name="sabor" list="sabores">
<select id="sabores"><option>Cenoura</option></select>

$ vnu lista-select.html
"file:/home/ana/site/lista-select.html":9.1-9.58: error: The “list” attribute of the “input” element must refer to a “datalist” element.

O que significa: a mesma mensagem: o id existe, mas é de um <select>. O list só aceita um <datalist>. Na tela aparecem um campo sem sugestões e uma lista suspensa, as duas coisas soltas.

Como consertar: troque <select> por <datalist> (e as opções viram <option value="…">). Ou, se a resposta tem de ser uma das opções, apague o campo e fique só com o select.

list num tipo que não aceita sugestões 
<label for="s">Senha:</label>
<input type="password" id="s" name="s" list="l">
<datalist id="l"><option value="a"></option></datalist>
<label><input type="checkbox" name="c" list="l"> c</label>

"file:/home/ana/site/tipo.html":9.1-9.48: error: Attribute “list” is only allowed when the input type is “color”, “date”, “datetime-local”, “email”, “month”, “number”, “range”, “search”, “tel”, “text”, “time”, “url”, or “week”.
"file:/home/ana/site/tipo.html":11.8-11.48: error: Attribute “list” is only allowed when the input type is “color”, “date”, “datetime-local”, “email”, “month”, “number”, “range”, “search”, “tel”, “text”, “time”, “url”, or “week”.

O que significa: "o atributo list só é permitido quando o tipo do input é …", e vem a lista dos tipos. Sugerir senhas não faria sentido (seria mostrar senhas na tela), e uma caixa de marcar não tem texto para sugerir.

Como consertar: tire o list desses campos.

list num textarea ou num select 
<label for="sabor">Sabor:</label>
<input type="text" id="sabor" name="sabor" list="sabores">
<datalist id="sabores">
  <option value="Cenoura"></option>
  <option value="Chocolate"></option>
</datalist>
<textarea name="t" list="sabores"></textarea>
<select name="s" list="sabores"><option>a</option></select>

$ vnu outros.html
"file:/home/ana/site/outros.html":14.1-14.34: error: Attribute “list” not allowed on element “textarea” at this point.
"file:/home/ana/site/outros.html":15.1-15.32: error: Attribute “list” not allowed on element “select” at this point.

O que significa: "o atributo list não é permitido no elemento textarea" (e no select). O list é um atributo só do <input>. (Esses dois campos também estão sem rótulo, mas isso o validador não acusa.)

Como consertar: para sugestões, use um <input>. Um <textarea> é para textos longos, que ninguém consegue sugerir inteiros.

Outra coisa dentro do datalist 
<label for="sabor">Sabor:</label>
<input type="text" id="sabor" name="sabor" list="sabores">
<datalist id="sabores">
  <option value="Cenoura"></option>
  <option value="Chocolate"></option>
  <p>Ou escreva outro sabor</p>
</datalist>

$ vnu dentro.html
"file:/home/ana/site/dentro.html":13.3-13.5: error: Element “p” not allowed as child of element “datalist” in this context. (Suppressing further errors from this subtree.)

O que significa: "o elemento p não é permitido como filho de datalist". Dentro dele vão só <option>. E, como o datalist é invisível, o parágrafo também não apareceria.

Como consertar: a instrução vai fora da lista, perto do campo: no <label> ou num parágrafo ao lado.

Resumo

  • <datalist id="x"> guarda sugestões; o campo <input list="x"> as mostra enquanto a pessoa digita.
  • O campo continua livre: qualquer texto é aceito e enviado. Para limitar às opções, use select ou rádios.
  • O value da option é o que entra no campo; o texto dela é uma explicação, mostrada de um jeito diferente em cada navegador.
  • O datalist é invisível e não é enviado; só o campo tem name.
  • list funciona em text, search, email, url, tel, number, range (marcas na régua), color e nos de data e hora; não em password, checkbox, textarea ou select.
  • Um list que não aponta para um datalist não dá sinal na tela: o campo só fica sem sugestões. O validador pega.
