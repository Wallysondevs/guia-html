HTML Arrastar e Soltar

Arrastar um arquivo para a lixeira, mudar um cartão de coluna num quadro de tarefas, puxar uma foto para dentro de um e-mail: tudo isso é arrastar e soltar (em inglês, drag and drop). O HTML tem um atributo para dizer "este elemento pode ser arrastado", o draggable. Mas o HTML sozinho só faz metade do trabalho: o "soltar" precisa de um pouco de JavaScript. Nesta aula a Ana monta um quadro de tarefas da cozinha, com o mínimo de JavaScript possível, e aprende o erro que faz o "soltar" nunca acontecer.

Você vai aprender
  • O que o navegador já deixa arrastar sozinho: links, imagens e texto selecionado.
  • O atributo draggable="true" e o draggable="false", e por que draggable sem valor não funciona.
  • Os três eventos do arraste: dragstart, dragover e drop.
  • O preventDefault() que, esquecido, faz o elemento nunca ser solto.
  • Por que o arraste precisa de uma alternativa para teclado e celular.

Os arquivos desta aula foram conferidos no validador W3C (vnu 26.10.12, o mesmo do validator.w3.org) na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/arrastar. Os arrastes foram feitos de verdade, com o mouse simulado, no Chromium 155. Os quadros "Resultado" e "Experimente" usam o seu navegador: pegue os itens com o mouse e arraste.

A ideia: os ímãs da geladeira

A Ana organiza a semana com ímãs na porta da geladeira: um quadro "A fazer" e outro "Feito". Mudar um ímã de lugar tem três momentos: pegar, passar por cima do quadro e largar. Na página é igual, e cada momento tem um nome:

Na geladeiraNa páginaQuem faz
O ímã pode ser pegodraggable="true"HTML
Pegar o ímãevento dragstart ("começo do arraste")JavaScript
Passar por cima do quadro, que diz "aqui pode"evento dragover ("arrastando por cima") + preventDefault()JavaScript
Largar o ímã no quadroevento drop ("soltar")JavaScript

O HTML decide o que pode ser pego. Onde ele pode ser largado e o que acontece depois é decisão do JavaScript.

1. O que já arrasta sozinho

Antes de qualquer atributo, três coisas já são arrastáveis em qualquer página: links, imagens e texto selecionado. Experimente no Resultado: arraste o link para a barra de endereços do navegador (ele abre a página) ou selecione um pedaço do parágrafo e arraste.

<p>Selecione um pedaço deste texto e arraste.</p>
<p>Este link também arrasta: <a href="https://example.com/">example.com</a></p>
<p>Mas este parágrafo inteiro não sai do lugar.</p>

O JavaScript enxerga isso pela propriedade draggable de cada elemento. No Chromium 155, um <a href> e um <img> deram true; um <p> comum deu false.

2. Deixar qualquer elemento arrastável: draggable="true"

Para que um parágrafo, um item de lista ou um cartão possa ser pego, escreva draggable="true":

<h2>A fazer</h2>
<ul>
  <li draggable="true">Comprar farinha</li>
  <li>Lavar a forma</li>
</ul>
draggable
"Arrastável". O nome vem do inglês drag, "arrastar".
="true"
"Verdadeiro": sim, pode ser arrastado. O valor é obrigatório (veja logo abaixo).
<li>Lavar a forma</li>
Sem o atributo: continua um item comum, que não sai do lugar.

No Resultado, pegue "Comprar farinha" com o mouse: o navegador desenha uma cópia meio transparente do item, que segue o cursor. Tente com "Lavar a forma": em vez de arrastar, o mouse seleciona o texto. E repare no que acontece quando você solta "Comprar farinha" em qualquer lugar: nada. A cópia some e o item continua onde estava. É a metade do trabalho que falta, e ela fica para a seção 4.

Atributos como required e disabled funcionam sozinhos, sem valor (aula Atributos). O draggable parece um deles, mas não é: ele precisa do ="true". No Chromium 155, um <li draggable> deu draggable = false, e o arraste com o mouse simplesmente não começou. Maiúsculas no valor tanto faz ("TRUE" funcionou e passou no validador), mas o costume é escrever em minúsculas.

3. Impedir o arraste: draggable="false"

Às vezes o arraste automático atrapalha. Num jogo de memória, por exemplo, um clique um pouco tremido numa imagem vira um arraste, e o clique se perde. Com draggable="false", o link ou a imagem fica parado:

<p><a href="https://example.com/">Este link arrasta</a></p>
<p><a href="https://example.com/" draggable="false">Este não</a></p>

No Chromium 155, o segundo link deu draggable = false. Ele continua sendo um link: o clique funciona normalmente. Só o arraste foi desligado.

Não é proteção

Desligar o arraste de uma imagem não impede ninguém de copiá-la: o visitante ainda pode clicar com o botão direito e salvar, ou abrir o endereço da imagem. Use o draggable="false" para melhorar o uso da página, não para "proteger" arquivos.

4. Soltar: o JavaScript mínimo

Agora a metade que falta. O quadro da Ana tem duas listas, "A fazer" e "Feito". O objetivo: arrastar um cartão da primeira e soltá-lo na segunda. O HTML só marca os cartões como arrastáveis e dá um id para cada coisa que o JavaScript precisa achar. O JavaScript cuida dos três momentos.

Experimente: arraste "Comprar farinha" para a caixa "Feito" e solte. Olhe o console embaixo: cada momento do arraste deixa uma mensagem. Depois arraste também "Lavar a forma" (ele ainda não está pronto: descubra por quê no HTML e conserte).

<link rel="stylesheet" href="estilo.css">
<h2>A fazer</h2>
<ul>
  <li id="farinha" draggable="true">Comprar farinha</li>
  <li id="forma">Lavar a forma</li>
</ul>
<h2>Feito</h2>
<ul id="feito"></ul>
<script src="script.js"></script>

const feito = document.getElementById("feito");

document.querySelectorAll("li").forEach(function (item) {
  item.addEventListener("dragstart", function (evento) {
    console.log("pegou: " + item.id);
    evento.dataTransfer.setData("text/plain", item.id);
  });
});

feito.addEventListener("dragover", function (evento) {
  evento.preventDefault();
});

feito.addEventListener("drop", function (evento) {
  evento.preventDefault();
  const id = evento.dataTransfer.getData("text/plain");
  console.log("soltou: " + id);
  feito.appendChild(document.getElementById(id));
});

#feito {
  min-height: 3em;
  border: 2px dashed gray;
}

Parte por parte:

addEventListener("dragstart", …)
"Quando o arraste deste item começar, rode isto." É o momento de pegar o ímã.
evento.dataTransfer.setData("text/plain", item.id)
O dataTransfer ("transferência de dados") é um bilhete que viaja junto com o arraste. Aqui a Ana escreve nele o id do item, como texto puro ("text/plain"), para saber depois qual item foi solto.
addEventListener("dragover", …) + evento.preventDefault()
Enquanto o item passa por cima de #feito, este código diz "aqui pode soltar". Por padrão, nenhum lugar da página aceita um elemento solto; o preventDefault() ("impedir o padrão") cancela essa recusa. Sem ele, o drop nunca acontece (seção 5).
addEventListener("drop", …)
"Quando soltarem algo aqui, rode isto." O preventDefault() desta vez impede o navegador de fazer o que faria com um texto ou link solto (como abrir o endereço).
evento.dataTransfer.getData("text/plain")
Lê o bilhete: o id escrito no dragstart.
feito.appendChild(document.getElementById(id))
"Ponha este elemento como último filho de #feito." Como o item já existia na página, ele muda de lista, não é copiado.
estilo.css
Só para a lista "Feito", ainda vazia, ter altura e uma borda tracejada onde dá para mirar. (O CSS tem guia próprio, o futuro Guia CSS.)

Com este mesmo código, um arraste de verdade de "Comprar farinha" até a lista "Feito", no Chromium 155, deixou no console:

pegou: farinha
soltou: farinha

E o HTML da página, depois do arraste, ficou assim (o arquivo continua igual; quem mudou foi a página aberta). A linha em branco em "A fazer" é o espaço que ficou onde o item estava: o appendChild leva só o elemento, não os espaços em volta dele.

<h2>A fazer</h2>
<ul>
  
  <li id="forma">Lavar a forma</li>
</ul>
<h2>Feito</h2>
<ul id="feito"><li id="farinha" draggable="true">Comprar farinha</li></ul>

Como no contenteditable, nada disso é salvo: recarregue a página e "Comprar farinha" volta para "A fazer". Guardar o quadro exige mais JavaScript, e isso fica para um guia de JavaScript.

5. O erro clássico: o drop que nunca acontece

O erro mais comum do arraste não dá mensagem nenhuma. A Ana escreveu o dragover, mas esqueceu o preventDefault():

feito.addEventListener("dragover", function (evento) {
  console.log("passando por cima");
});

O arraste de verdade no Chromium 155 deixou isto no console:

pegou: farinha
passando por cima
passando por cima

O item começou a ser arrastado, passou por cima da lista "Feito" (duas vezes, e muitas mais num arraste lento, porque o dragover repete enquanto o mouse se mexe) e... nenhum "soltou". O cursor mostra o sinal de "proibido" e, ao soltar, o item volta para o lugar. Sem o preventDefault() no dragover, o navegador entende que aquela lista não aceita o item, e o evento drop nem é disparado. Nenhum erro no console, nenhum aviso do validador (ele não lê JavaScript).

Regra de bolso

Todo lugar que aceita um elemento solto precisa de dois ouvintes: dragover (com preventDefault(), para dizer "aqui pode") e drop (para fazer alguma coisa). Se o drop "não funciona", olhe primeiro o dragover.

6. Acessibilidade: nem todo mundo arrasta

Arrastar exige um mouse, ou um dedo firme numa tela de toque. Quem navega pelo teclado (aula Teclado e Foco) ou usa um leitor de tela não tem como "pegar e largar". O draggable não cria nenhum atalho de teclado, e nos celulares o suporte ao arraste varia de navegador para navegador.

Por isso, o arraste deve ser um atalho, e não o único jeito. Ofereça também um botão que faz a mesma coisa:

<ul>
  <li draggable="true">Comprar farinha
    <button type="button">Mover para Feito</button>
  </li>
</ul>

O botão recebe o foco com Tab, é anunciado pelo leitor de tela e funciona com Enter. O JavaScript dele seria um addEventListener("click", …) que faz o mesmo appendChild do drop (aula Botões).

Formas de mover coisas na página: qual usar

FormaBom paraCuidado

Qual usar? Comece pelos botões, que funcionam para todo mundo. Acrescente o arraste como atalho quando ele deixar a página mais agradável para quem usa mouse.

Bad value “” for attribute “draggable” on element “p”.

O que significa: "Valor ruim, vazio, para o atributo draggable". Você escreveu draggable sozinho, como se fosse um atributo booleano. O mesmo erro aparece com “sim” e “auto”.

O que o navegador faz: nenhum erro na tela; ele trata o valor como desconhecido e o elemento fica com o comportamento padrão. Um parágrafo ou item de lista simplesmente não arrasta.

Como consertar: draggable="true".

The “dropzone” attribute is obsolete. Use script to handle the “dragenter” and “dragover” events instead.

O que significa: "O atributo dropzone é obsoleto. Use um script para tratar os eventos dragenter e dragover." Uma versão antiga da especificação tinha um atributo para marcar onde soltar, mas nenhum navegador chegou a usá-lo de verdade, e ele foi retirado. Não existe "zona de soltar" em HTML puro.

Como consertar: apague o atributo e use o dragover com preventDefault(), como na seção 4. (O dragenter, "entrou arrastando", dispara uma vez quando o item entra na área; é útil para destacar a área, mas o que libera o drop é o dragover.)

O item arrasta, mas ao soltar volta para o lugar

O que significa: o lugar onde você soltou não disse "aqui pode". Ou falta o ouvinte de dragover, ou ele existe sem o evento.preventDefault(), ou ele está no elemento errado (o id não confere).

Como consertar: no elemento que recebe, ponha um dragover com evento.preventDefault(). Um console.log dentro do drop mostra se ele está sendo chamado.

O drop acontece, mas o item não muda de lugar

O que significa: o bilhete veio vazio. Faltou o setData no dragstart, ou o tipo escrito é diferente do lido (setData("text/plain", …) e getData("text") com nomes trocados, por exemplo), ou o item não tem id. Em alguns navegadores, um arraste sem nada no dataTransfer nem chega a começar. Por isso, sempre chame o setData no dragstart.

Como consertar: escreva e leia com o mesmo tipo, "text/plain", e confira que todo item arrastável tem um id.

Resumo

  • Links, imagens e texto selecionado já arrastam sozinhos. Para qualquer outro elemento, use draggable="true"; para impedir, draggable="false".
  • draggable não é booleano: sem valor, dá Bad value “” no validador e o elemento não arrasta.
  • O HTML só decide o que pode ser pego. Soltar precisa de JavaScript: dragstart (com setData), dragover (com preventDefault()) e drop (com getData).
  • Sem preventDefault() no dragover, o drop nunca acontece, e não aparece erro nenhum.
  • O atributo dropzone é obsoleto. Nada é salvo: recarregar a página desfaz os arrastes.
  • O arraste é um atalho para quem usa mouse. Ofereça sempre botões que fazem o mesmo, para teclado, toque e leitores de tela.
