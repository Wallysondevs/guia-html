HTML Validar o HTML

Nas aulas anteriores você viu que o navegador quase nunca reclama: ele conserta sozinho o que está errado, às vezes do jeito que você queria, às vezes não. Para descobrir os erros, existe o validador: um programa que lê o seu HTML e lista tudo o que está fora das regras, com a linha e a coluna. Nesta aula você vai usar o validador oficial do W3C de dois jeitos: no site, sem instalar nada, e no terminal, com o vnu, instalado do zero. E vai aprender a ler as mensagens dele.

Você vai aprender
  • Por que validar, se a página "funciona" no navegador.
  • A usar o validador on-line (validator.w3.org/nu) com um endereço, um arquivo ou um código colado.
  • A instalar o vnu no seu computador: o Java, o arquivo vnu.jar e um apelido para digitar menos.
  • A ler uma mensagem: arquivo, linha, coluna, tipo (error, info warning, info) e descrição.
  • As opções mais úteis: --verbose, --errors-only, --skip-non-html, --format text, e como validar uma pasta inteira.
  • As armadilhas: o validador calado que não validou nada.

Tudo nesta aula foi feito na máquina fictícia da Ana (usuária ana, computador notebook, Ubuntu), na pasta ~/site/lojinha, com o vnu 26.10.12, a mesma versão que roda no site do W3C quando esta aula foi escrita. As mensagens do validador são em inglês: elas estão copiadas como saíram e explicadas em português.

A ideia: a revisão antes de entregar

Quando você escreve uma redação no computador, o corretor sublinha as palavras erradas. Ele não muda o texto sozinho: só aponta, e você decide. O navegador é o contrário: ele muda o texto sozinho, em silêncio, e nunca aponta nada.

O validador é o corretor do HTML. Por que usar, se a página aparece?

  • O conserto do navegador pode não ser o que você queria. Um </strong> esquecido deixou o resto da página em negrito (aula Aninhamento); uma aspa esquecida apagou a página (aula Atributos).
  • O erro pode estar escondido. Um </h2> fechando um <h1> não muda nada na tela, mas está errado (aula Elementos e Tags).
  • Acessibilidade. O validador cobra o alt das imagens, o title da página e outras coisas que o leitor de tela precisa.
  • Aprender. Cada mensagem ensina uma regra do HTML.

O W3C (World Wide Web Consortium, o "consórcio da web", que cuida de vários padrões da web) mantém o validador oficial, chamado Nu Html Checker ("verificador de HTML Nu"). O programa por trás dele se chama vnu (validator.nu), e é o mesmo no site e no seu computador.

1. O validador on-line

O jeito mais rápido: abra https://validator.w3.org/nu/ no navegador. A página tem um campo Check by ("verificar por") com três escolhas:

Check byQuer dizerQuando usar
address"endereço": você digita o endereço de uma página publicada (https://…)o site já está na internet (aula Publicar no GitHub Pages)
file upload"envio de arquivo": você escolhe um .html do seu computadora página ainda está só no seu computador
text input"texto digitado": você cola o código numa caixa de textopara testar um pedaço rápido

Depois de escolher, clique no botão Check ("verificar"). Se estiver tudo certo, aparece a frase Document checking completed. No errors or warnings to show. ("Verificação do documento concluída. Nenhum erro ou aviso para mostrar.").

Se houver problemas, cada um aparece num bloco. A Ana enviou a página de contato da lojinha (o arquivo contato.html, que você vai ver inteiro na seção 3). O primeiro bloco foi este:

Error: Element head is missing a required instance of child element title.
From line 5, column 1; to line 5, column 7
Error:
O tipo: um erro, algo fora das regras. Os avisos aparecem como Warning:, e as informações, como Info:.
Element head is missing a required instance of child element title.
A descrição: "o elemento head está sem uma ocorrência obrigatória do elemento filho title". Em outras palavras, faltou o <title>.
From line 5, column 1; to line 5, column 7
Onde: "da linha 5, coluna 1, até a linha 5, coluna 7". Embaixo, o site mostra o pedaço do código com o trecho marcado.

No site, os nomes dos elementos aparecem destacados, sem as aspas “ ” que você vai ver no terminal. No fim da lista aparece There were errors. ("Houve erros.").

No editor do guia

As caixas "Experimente" deste guia têm um botão para validar no W3C. Ele manda o código da aba aberta para o mesmo validator.w3.org/nu, mas só depois de você confirmar, porque o código vai para a internet. As mensagens aparecem embaixo, em inglês, com a linha e a coluna do seu código.

2. O vnu no terminal

O site é ótimo para uma página de vez em quando. Quando o site tem muitas páginas, ou você quer validar toda vez que salva, é mais prático ter o validador no próprio computador. Ele funciona sem internet e valida uma pasta inteira de uma vez. Ele é escrito em Java, então são três passos: o Java, o validador e um apelido.

Os comandos abaixo são para o terminal do Linux (no Guia Bash você aprende a usar o terminal). No Windows e no macOS, veja a dica no fim da seção.

Primeiro, confira se o Java já está instalado:

Passo 3: um apelido, para digitar só vnu

Digitar java -jar ~/ferramentas/vnu.jar toda vez cansa. O Bash permite criar um apelido (alias). A Ana acrescentou o apelido no fim do arquivo ~/.bashrc, que o terminal lê toda vez que abre, e recarregou o arquivo:

$ echo "alias vnu='java -jar ~/ferramentas/vnu.jar'" >> ~/.bashrc
$ source ~/.bashrc
$ type vnu

>> ~/.bashrc

source ~/.bashrc
Lê o arquivo de novo, para o apelido valer já neste terminal (os próximos terminais já abrem com ele).
type vnu

Daqui em diante, vnu arquivo.html basta. É o comando que todas as aulas deste guia usam.

No Windows e no macOS

Na mesma página de versões há os arquivos vnu.windows.zip e vnu.osx.zip, que já trazem um Java embutido: descompacte e rode o programa vnu da pasta vnu-runtime-image/bin (no Windows, o vnu.bat), sem instalar o Java. Também dá para usar o vnu.jar do mesmo jeito que no Linux, depois de instalar um Java (por exemplo, o OpenJDK). Se você usa o WSL, o Linux dentro do Windows, siga os passos do Linux.

Quando dá errado

O validador calado que não validou nada 
$ vnu naoexiste.html; echo "código de saída: $?"
código de saída: 0
$ vnu --verbose naoexiste.html; echo "código de saída: $?"
"file:/home/ana/naoexiste.html": info warning: File not found.
código de saída: 0

O que significa: a Ana errou o nome do arquivo (ou estava na pasta errada, aqui a ~). O vnu não achou o arquivo, não disse nada e terminou com 0, como se estivesse tudo certo! Só com --verbose aparece o aviso File not found. ("arquivo não encontrado"), e mesmo assim o código de saída continua 0. Como evitar: quando o validador ficar calado e você desconfiar, rode com --verbose e confira se o nome do seu arquivo aparece na lista.

Error: Unable to access jarfile vnu.jar 
$ java -jar vnu.jar contato.html
Error: Unable to access jarfile vnu.jar

O que significa: "não consigo acessar o arquivo jar vnu.jar". Sem um caminho, o Java procura o vnu.jar na pasta atual, e a Ana estava em ~/site/lojinha, não em ~/ferramentas. Como consertar: use o caminho completo (~/ferramentas/vnu.jar) ou, melhor, o apelido do passo 3.

vnu: comando não encontrado ou java: comando não encontrado

O que significa: o terminal não conhece esse nome. Para o vnu: o apelido ainda não foi criado, ou você abriu um terminal antes de criá-lo e não rodou o source ~/.bashrc. Para o java: o Java não está instalado. Como consertar: refaça o passo 3 (para o vnu) ou o passo 1 (para o java). O type vnu diz se o apelido existe.

"O validador acusa erro, mas no navegador está tudo certo"

O que significa: é o caso mais comum, e o motivo de o validador existir. O navegador consertou o erro sozinho, e o conserto deu certo neste navegador, nesta página. Como consertar: conserte do mesmo jeito. Um código válido não depende da sorte nem do navegador.
