HTML robots.txt e sitemap

Nas aulas de SEO e de Open Graph, você conversou com os robôs dentro de cada página, com metas no <head>. Esta aula é sobre dois arquivos que conversam com eles pelo site inteiro, e que não são HTML: o robots.txt, que diz aos robôs por onde eles não devem andar, e o sitemap.xml, a lista das páginas que você quer que eles encontrem. A Ana vai criar os dois para o site de receitas e conferir no servidor local, como um robô faria.

Você vai aprender
  • Onde fica o robots.txt e como os robôs o procuram.
  • As linhas User-agent, Disallow, Allow e Sitemap.
  • Por que o robots.txt não protege nada, e a diferença para o noindex.
  • O formato do sitemap.xml: <urlset>, <url>, <loc> e <lastmod>.
  • Como pedir os dois arquivos ao servidor local com curl, e como perguntar a um robô do Python se ele pode visitar uma página.
  • Os erros mais comuns, com as mensagens reais.

Tudo nesta aula foi feito na máquina fictícia da Ana, na pasta ~/site, com python3 -m http.server, curl e o Python 3.14. O endereço do site publicado, https://ana.exemplo.com/, é fictício.

A ideia: a placa no portão e o mapa na recepção

Imagine que um fiscal vem visitar a confeitaria da Ana. No portão há uma placa: "Visitantes: não entrem na despensa nem no escritório". Na recepção há um mapa com todas as salas que valem a visita. O fiscal educado lê a placa e usa o mapa. Mas a placa não tranca porta nenhuma: quem quiser entrar na despensa, entra.

1. Onde ficam os arquivos

O robô procura o robots.txt num lugar só: a raiz do endereço, logo depois do domínio. Para o site da Ana, https://ana.exemplo.com/robots.txt. Ele não procura em pastas. Esta é a pasta do site, com os dois arquivos ao lado do index.html:

Site em subpasta não tem robots.txt próprio

No GitHub Pages, um site de projeto fica numa subpasta: https://usuario.github.io/receitas/. Um robots.txt dentro dessa pasta (/receitas/robots.txt) não é lido: os robôs só pedem https://usuario.github.io/robots.txt. Para ter um robots.txt que valha, o site precisa estar na raiz do endereço (um domínio próprio ou o site de usuário). O sitemap.xml não tem esse problema: ele pode ficar em qualquer lugar, desde que você diga onde (seção 4).

2. O robots.txt

É um arquivo de texto simples, sem HTML, com o nome em letras minúsculas. Este é o da Ana:

# robots.txt do site Receitas da Ana
User-agent: *
Disallow: /rascunhos/
Disallow: /busca.html

User-agent: GPTBot
Disallow: /

Sitemap: https://ana.exemplo.com/sitemap.xml
# robots.txt do site…
Um comentário: tudo depois do # é ignorado pelos robôs.
User-agent: *
"Para quais robôs valem as regras abaixo." O * quer dizer "todos". User-agent ("agente do usuário") é o nome com que cada programa se apresenta ao servidor: o robô do Google se chama Googlebot, o do Bing, Bingbot.
Disallow: /rascunhos/
"Não visite": nenhum endereço que comece com /rascunhos/. Vale para a pasta toda: /rascunhos/torta-nova.html, /rascunhos/fotos/….
Disallow: /busca.html
Uma página só: os resultados da busca interna do site, que não valem a pena na busca do Google.
(linha em branco)
Separa os grupos de regras.
User-agent: GPTBot / Disallow: /
Um grupo só para um robô, pelo nome. O GPTBot é o robô que a OpenAI usa para recolher textos da internet. Disallow: / quer dizer "o site inteiro", porque todo endereço começa com /. Cada robô segue o grupo com o nome dele; se não houver, segue o grupo *.
Sitemap: https://…
Onde está o mapa do site, sempre com o endereço completo. Essa linha vale para todos os robôs, em qualquer lugar do arquivo.

As regras, uma por uma

LinhaO que quer dizer
Disallow: /Não visite nada
Disallow: (vazio)Não há nada proibido: pode visitar tudo
Disallow: /fotos/Não visite nada dentro da pasta fotos
Allow: /fotos/bolo.jpgExceção: este arquivo pode, mesmo com a pasta proibida
Disallow: /*.pdf$Nenhum endereço que termine em .pdf (* = qualquer coisa; $ = "termina aqui")

Os nomes das regras (User-agent, Disallow) não ligam para maiúsculas, mas os caminhos ligam: /Rascunhos/ e /rascunhos/ são pastas diferentes. Esse formato, que existe desde 1994, virou norma oficial da internet em 2022, a RFC 9309.

Missão: o robots.txt da Ana tem o erro mais perigoso que existe: Disallow: / para todos os robôs, que tira o site inteiro da busca. Troque por uma regra que proíba só a pasta /rascunhos/ e acrescente a linha Sitemap com https://ana.exemplo.com/sitemap.xml. Clique no link do Resultado para ver o arquivo como o robô o recebe.

Perguntar a um robô: urllib.robotparser

O Python já vem com um leitor de robots.txt, o mesmo tipo de peça que os robôs usam. A Ana escreveu um programinha que baixa o robots.txt do servidor local e responde, para cada endereço, se o robô pode visitar:

import sys
from urllib.robotparser import RobotFileParser

robo = RobotFileParser("http://localhost:8000/robots.txt")
robo.read()
nome = sys.argv[1]
for caminho in sys.argv[2:]:
    pode = robo.can_fetch(nome, "http://localhost:8000" + caminho)
    print(nome, caminho, "→", "pode visitar" if pode else "proibido")
print("Sitemap:", robo.site_maps())

4. O sitemap.xml

O mapa do site (sitemap) é a lista das páginas que você quer que os buscadores conheçam. Os robôs acham as páginas seguindo links, mas uma página nova, ou sem nenhum link apontando para ela, pode demorar a ser achada. O mapa resolve isso. Ele é escrito em XML (eXtensible Markup Language), uma linguagem de marcação prima do HTML, com tags que você inventa, mas regras mais rígidas:

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://ana.exemplo.com/</loc>
    <lastmod>2026-10-17</lastmod>
  </url>
  <url>
    <loc>https://ana.exemplo.com/bolo-de-cenoura.html</loc>
    <lastmod>2026-10-10</lastmod>
  </url>
  <url>
    <loc>https://ana.exemplo.com/torta-de-limao.html</loc>
    <lastmod>2026-09-28</lastmod>
  </url>
</urlset>
<?xml version="1.0" encoding="UTF-8"?>
A declaração XML: "este é um arquivo XML, versão 1.0, com acentos em UTF-8". Vem na primeira linha, sem nada antes. Faz o papel do <!DOCTYPE html>.
<urlset xmlns="…">
A raiz: "um conjunto de endereços". O xmlns (XML namespace, "espaço de nomes") diz que estas tags seguem o padrão sitemaps.org. Copie exatamente como está, com http://: é um nome, e não um endereço que alguém visita.
<url>
Uma página.
<loc>
De location, "localização": o endereço completo da página, com https://.
<lastmod>
De last modified, "última modificação": a data em que a página mudou de verdade, no formato AAAA-MM-DD. É opcional, mas ajuda o robô a saber o que visitar de novo.

Existem também as tags <changefreq> ("frequência de mudança") e <priority> ("prioridade"), que você vai ver em muitos mapas. O Google já disse que as ignora; pode deixar de fora.

Regras do XML que o HTML perdoa, e o XML nãoExemplo
Toda tag aberta tem de ser fechada<loc>…</loc>, nunca só <loc>
Maiúsculas e minúsculas contam<URL> não é <url>
O & é sempre escrito &amp;…/busca?q=bolo&amp;p=2
Um erro qualquer invalida o arquivo inteiroo robô não lê nada

Um mapa pode ter até 50.000 endereços e 50 MB. Um site como o da Ana, com algumas dezenas de páginas, cabe com muita folga. Para avisar onde está o mapa, use a linha Sitemap: do robots.txt e, se quiser, envie o endereço dele no Google Search Console e no Bing Webmaster Tools (aula HTML e SEO).

Conferir o XML no terminal

O vnu é validador de HTML; para o XML, a Ana usa o leitor de XML que vem no Python. Se o arquivo estiver bem formado, o programa diz quantas páginas achou; se não, ele mostra a linha e a coluna do erro:

import sys
import xml.etree.ElementTree as ET

arvore = ET.parse(sys.argv[1])
ns = {"s": "http://www.sitemaps.org/schemas/sitemap/0.9"}
for loc in arvore.getroot().findall("s:url/s:loc", ns):
    print(loc.text)

https://ana.exemplo.com/bolo-de-cenoura.html
https://ana.exemplo.com/torta-de-limao.html

5. robots.txt × noindex

Esta é a confusão mais comum do assunto. Os dois parecem fazer a mesma coisa, mas não fazem:

Disallow no robots.txt<meta name="robots" content="noindex">
Pede"não visite""não mostre na busca"
Onde ficaum arquivo na raiz do siteno <head> de cada página
A página pode aparecer na busca?Sim: se outros sites apontam para ela, o buscador pode listar o endereço, sem o resumo, porque não leu a páginaNão
Protege dados?NãoNão
Não use os dois juntos na mesma página

Se o robots.txt proíbe a visita, o robô nunca lê a página, e por isso nunca vê o noindex que está nela. Para tirar uma página da busca, deixe a visita liberada e use o noindex. E para esconder algo de verdade, só uma senha resolve: o robots.txt é público, qualquer pessoa pode lê-lo, e ele acaba avisando a todo mundo onde estão as pastas "secretas".

Quando dá errado

xml.etree.ElementTree.ParseError: not well-formed (invalid token)

Um endereço com & cru no mapa:

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://ana.exemplo.com/busca.html?q=bolo&pagina=2</loc>
  </url>
</urlset>

O que significa: "não está bem formado (sinal inválido)", na linha 4. O & começa uma entidade, como no HTML (aula Entidades); o Python leu &pagina e, ao chegar no = (a coluna 57, contando a partir do zero), viu que aquilo não é uma entidade. O navegador perdoaria isso num HTML; o XML, não. As últimas linhas do erro são as que importam: o Python mostra antes o caminho por dentro do programa (o traceback).

Como consertar: busca.html?q=bolo&amp;pagina=2. (E, de qualquer jeito, páginas de busca não deveriam estar no mapa.)

O site sumiu da busca: Disallow: / esquecido

Muita gente cria o site com um robots.txt que proíbe tudo enquanto ele está em construção, e esquece de trocar no lançamento. Nenhuma ferramenta reclama: é um arquivo válido, que pede exatamente o que diz. Como achar: curl https://seu-site/robots.txt depois de publicar, e o relatório de páginas do Search Console.

Outros enganos que passam calados
  • Nome com maiúscula ou fora da raiz: Robots.txt, /receitas/robots.txt. O robô pede /robots.txt, recebe 404 e entende "pode tudo".
  • Disallow: rascunhos/, sem a barra do começo: o caminho tem de começar com /.
  • <loc>bolo-de-cenoura.html</loc>: no mapa, o endereço é sempre completo.
  • Um mapa com páginas proibidas no robots.txt ou com noindex: as duas instruções brigam. O mapa deve ter só as páginas que você quer na busca.

Resumo

  • O robots.txt fica na raiz do endereço (/robots.txt) e diz aos robôs por onde não andar. Num site em subpasta, ele não vale.
  • User-agent escolhe o robô (* = todos); Disallow proíbe caminhos que começam com o texto dado; Allow abre exceções; Sitemap aponta o mapa, com endereço completo.
  • Disallow: / tira o site inteiro da busca. Confira com curl depois de publicar.
  • O robots.txt é um pedido público, não uma tranca. Para sair da busca, use noindex (com a visita liberada); para esconder, use senha.
  • O sitemap.xml lista as páginas com <url>, <loc> (endereço completo) e <lastmod> (AAAA-MM-DD). changefreq e priority são ignorados pelo Google.
  • XML não perdoa: toda tag fechada, maiúsculas contam, & vira &amp;. O Python mostra a linha e a coluna do erro.
