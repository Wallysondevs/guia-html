HTML Web Components

O HTML tem mais de cem elementos prontos, mas nenhum se chama <cartao-receita>. Com os Web Components, você mesmo cria essa tag: escreve uma vez como ela funciona e depois usa quantas vezes quiser, como se fosse um elemento do HTML. Nesta aula você vai criar um elemento personalizado simples com customElements.define, fazê-lo ler atributos e, no fim, juntar tudo o que viu na aula template e slot num cartão de receita de verdade. O JavaScript é pouco, e cada linha é explicada.

Você vai aprender
  • O que são os Web Components e as três peças deles.
  • A regra do nome: sempre com hífen (cartao-receita).
  • O que o navegador faz com uma tag personalizada antes de ela ser definida.
  • Como definir o elemento: class … extends HTMLElement, connectedCallback e customElements.define.
  • Como ler um atributo seu (nome="Bia") com getAttribute.
  • Como dar ao elemento um shadow DOM com attachShadow, um <template> e slots.
  • Os erros reais: nome sem hífen, nome repetido, super() esquecido e <cartao-receita />.

A ideia: o carimbo personalizado

A papelaria vende carimbos prontos: "PAGO", "URGENTE", "CÓPIA". Mas a Ana quis um carimbo com o logo da lojinha, e mandou fazer um sob medida. Depois de pronto, ela usa o carimbo dela do mesmo jeito que usa os outros: pega e carimba.

Os elementos do HTML são os carimbos prontos (<p>, <img>, <table>). Um elemento personalizado é o carimbo sob medida: você o "fabrica" uma vez, com JavaScript, e depois escreve <cartao-receita> no HTML como se fosse uma tag qualquer.

"Web Components" é o nome do conjunto de três peças, que funcionam juntas ou separadas:

PeçaO que fazOnde aprender
Elementos personalizados (custom elements)Criam uma tag nova, com comportamento seunesta aula
Shadow DOMDá ao elemento um HTML e um CSS próprios, isolados da páginatemplate e slot e a seção 5 desta aula
<template> e <slot>O molde do elemento e os espaços onde o conteúdo encaixatemplate e slot

Os três funcionam em todos os navegadores atuais desde 2020, quando o Edge passou a usar o mesmo motor do Chrome; o Chrome, o Firefox e o Safari já aceitavam antes.

1. O nome: sempre com hífen

O nome de um elemento personalizado tem regras:

  • tem de ter pelo menos um hífen: cartao-receita, saudacao-ana, meu-botao;
  • começa com uma letra minúscula e é escrito em minúsculas;
  • não pode ser um dos poucos nomes com hífen que já existem em outras linguagens, como font-face.

O hífen é uma promessa: nenhum elemento oficial do HTML tem hífen, e nunca vai ter. Assim, a sua <cartao-receita> nunca vai brigar com uma tag nova do HTML do futuro.

Antes de ser definida

Uma tag com hífen já é aceita pelo navegador e pelo validador, mesmo sem nenhum JavaScript. Ela só não faz nada de especial: o navegador mostra o conteúdo como texto em linha, como faria com um <span>:

<h1>Receitas da Ana</h1>
<p>Receita do dia: <cartao-receita>Bolo de cenoura</cartao-receita>, feita em casa.</p>

Esse código passa no validador sem erros. Já uma tag inventada sem hífen, como <cartao>, aparece igualzinha na tela, mas o validador recusa (veja em Quando dá errado): para ele, é um elemento "completamente desconhecido".

2. Definir o elemento: customElements.define

Para a tag ganhar vida, o JavaScript precisa dizer ao navegador como ela funciona. O exemplo mais simples possível: uma tag <ola-mundo> que escreve "Olá, mundo!" dentro de si mesma.

<h1>Meu primeiro elemento</h1>
<p><ola-mundo></ola-mundo></p>
<p><ola-mundo></ola-mundo></p>
<script src="script.js"></script>

class OlaMundo extends HTMLElement {
  connectedCallback() {
    this.textContent = "Olá, mundo!";
  }
}

customElements.define("ola-mundo", OlaMundo);

As duas tags vazias viraram "Olá, mundo!". Linha por linha:

class OlaMundo
Uma classe é a "receita" de um tipo de objeto. Esta receita se chama OlaMundo (o costume é escrever com maiúsculas, sem hífen).
extends HTMLElement
"Estende o elemento HTML": a receita começa de tudo o que um elemento comum já sabe fazer (ter atributos, filhos, texto) e acrescenta o que vem entre as chaves. É a fôrma de carimbo pronta, que você só grava.
connectedCallback() { … }
Connected callback = "aviso de conectado". O navegador chama esse bloco sozinho, cada vez que um elemento desse tipo entra na página.
this.textContent = "Olá, mundo!"
this ("este") é o próprio elemento, cada <ola-mundo> da vez. A linha troca o texto dele.
customElements.define("ola-mundo", OlaMundo)
"Elementos personalizados, definam": liga o nome da tag (com hífen, entre aspas) à classe. A partir desta linha, toda <ola-mundo> da página segue a receita OlaMundo.
O script pode vir antes ou depois

Na aula de canvas, o script tinha de vir depois do <canvas>. Aqui, tanto faz: se o navegador encontra a tag antes da definição, ele a mostra como uma tag comum e, quando o define roda, atualiza todas as que já existem. Se a definição vem antes, cada tag nova já nasce pronta.

3. Ler um atributo seu

Um elemento personalizado pode ter atributos inventados por você (o validador aceita qualquer atributo numa tag com hífen). Dentro da classe, o this.getAttribute("nome") lê o valor:

class SaudacaoAna extends HTMLElement {
  connectedCallback() {
    const nome = this.getAttribute("nome");
    this.textContent = "Olá, " + nome + "!";
  }
}

customElements.define("saudacao-ana", SaudacaoAna);
const nome = this.getAttribute("nome")
Lê o atributo nome deste elemento e guarda o valor numa constante. Com <saudacao-ana nome="Bia">, ela vale "Bia".
"Olá, " + nome + "!"
Junta três textos: "Olá, ", o nome e "!".

Missão: o elemento <saudacao-ana nome="Bia"> está mostrando só "Olá!". Mude o script.js para que ele leia o atributo nome e mostre Olá, Bia!. Depois, acrescente no HTML uma segunda saudação, com outro nome, e veja as duas funcionarem.

<h1>Clientes da lojinha</h1>
<p><saudacao-ana nome="Bia"></saudacao-ana></p>
<script src="script.js"></script>

class SaudacaoAna extends HTMLElement {
  connectedCallback() {
    this.textContent = "Olá!";
  }
}

customElements.define("saudacao-ana", SaudacaoAna);

class SaudacaoAna extends HTMLElement {
  connectedCallback() {
    const nome = this.getAttribute("nome");
    this.textContent = "Olá, " + nome + "!";
  }
}

customElements.define("saudacao-ana", SaudacaoAna);

Se uma saudação não tiver o atributo nome, o getAttribute devolve null, e a tela mostra "Olá, null!". Num elemento de verdade, você trataria esse caso (por exemplo, com um nome padrão); aqui, basta saber de onde vem o null.

4. Quando o navegador avisa o elemento

O connectedCallback é um dos "avisos" que o navegador manda para a classe. Os principais:

Bloco da classeQuando o navegador chama
constructor() { super(); … }Quando o elemento é criado (antes de entrar na página). O super() é obrigatório e vem primeiro.
connectedCallback()Cada vez que o elemento entra na página
disconnectedCallback()Cada vez que ele sai da página
attributeChangedCallback(nome, antigo, novo)Quando um atributo da lista static observedAttributes = ["nome"] muda

Para começar, o connectedCallback basta. Os outros servem para elementos que mudam enquanto a página está aberta, um assunto do JavaScript.

5. O cartão de receita: shadow DOM, template e slot

Na aula template e slot, o cartão de receita com shadow DOM tinha um problema: o molde era repetido em cada cartão. Agora o molde fica escrito uma vez, num <template> comum, e a classe do elemento faz o resto:

<h1>Receitas da Ana</h1>

<template id="molde-cartao">
  <style>
    div { border: 2px solid darkred; padding: 8px; margin-bottom: 8px; }
    h2 { color: darkred; margin: 0; }
  </style>
  <div>
    <h2><slot name="titulo">Receita sem nome</slot></h2>
    <slot name="descricao">Ainda sem descrição.</slot>
  </div>
</template>

<cartao-receita>
  <span slot="titulo">Bolo de cenoura</span>
  <p slot="descricao">Fofinho, com cobertura de chocolate.</p>
</cartao-receita>

<cartao-receita>
  <span slot="titulo">Brigadeiro</span>
</cartao-receita>

<script src="script.js"></script>

class CartaoReceita extends HTMLElement {
  constructor() {
    super();
    const molde = document.getElementById("molde-cartao");
    const sombra = this.attachShadow({ mode: "open" });
    sombra.append(molde.content.cloneNode(true));
  }
}

customElements.define("cartao-receita", CartaoReceita);
constructor() { super(); … }
O bloco que roda quando cada cartão é criado. O super() manda o HTMLElement preparar a parte "elemento comum" primeiro; sem ele, o navegador dá erro (veja abaixo).
this.attachShadow({ mode: "open" })
"Prenda uma sombra": cria o shadow DOM deste cartão, o mesmo que o shadowrootmode="open" fazia sem JavaScript. Devolve a raiz da sombra, guardada em sombra.
molde.content.cloneNode(true)
Copia o conteúdo do molde, como na aula anterior.
sombra.append(…)
Põe a cópia dentro da sombra, e não na página. Por isso o <style> do molde vale só dentro de cada cartão.
<span slot="titulo">
Os filhos de cada <cartao-receita> encaixam nos slots do molde. O segundo cartão não tem descrição, então mostra o conteúdo padrão: "Ainda sem descrição."

Agora, um terceiro cartão custa só três linhas de HTML: o molde, o estilo e o comportamento são compartilhados. É assim que bibliotecas de componentes inteiras são feitas: botões, menus e calendários prontos, que você usa escrevendo tags.

Acessibilidade continua sendo trabalho seu

Uma tag personalizada não tem significado nenhum para o leitor de tela: <cartao-receita> é tão "mudo" quanto um <span>. Use dentro dela os elementos certos (<h2>, <button>, <a>), que já trazem o significado e o teclado. Um "botão" feito de <meu-botao> sem um <button> dentro não recebe o foco do Tab nem responde ao Enter.

E o atributo is?

Existe um segundo tipo de elemento personalizado, que "turbina" um elemento comum: <button is="botao-fofo">, definido com extends HTMLButtonElement. O validador aceita, e o Chrome e o Firefox também, mas o Safari não aceita: lá, o botão fica um botão comum. Por isso, prefira as tags com hífen desta aula.

Quando dá errado

No console: "cartao" is not a valid custom element name

O que significa: o nome do define não tem hífen (ou tem maiúscula). O elemento não é definido, e as tags continuam paradas. Veja o erro no console:

<p><cartao></cartao></p>
<script src="script.js"></script>

class Cartao extends HTMLElement {
  connectedCallback() {
    this.textContent = "Sou um cartão!";
  }
}

customElements.define("cartao", Cartao);

No Chrome, a mensagem completa é SyntaxError: Failed to execute 'define' on 'CustomElementRegistry': "cartao" is not a valid custom element name: "falha ao executar o define: “cartao” não é um nome válido de elemento personalizado". Com "Cartao-Receita", com maiúsculas, o erro é o mesmo. O Firefox e o Safari dizem a mesma coisa com outras palavras.

O validador também reclama da tag <cartao> no HTML (com <cartao>Bolo</cartao> na linha 8):

$ vnu index.html
"file:/home/ana/site/index.html":8.1-8.8: error: Element “cartao” not allowed as child of element “body” in this context. (Suppressing further errors from this subtree.)
"file:/home/ana/site/index.html":8.1-8.8: error: The “cartao” element is a completely-unknown element that is not allowed anywhere in any HTML content.

"O elemento cartao não é permitido aqui" e "é um elemento completamente desconhecido, que não é permitido em lugar nenhum". O "(Suppressing further errors from this subtree.)" quer dizer que ele não vai procurar mais erros dentro dessa tag. Como consertar: ponha um hífen no nome, no HTML e no define: cartao-receita.

No console: the name "saudacao-ana" has already been used with this registry

O que significa: o mesmo nome foi definido duas vezes, por exemplo porque o script.js foi ligado duas vezes na página. ("O nome já foi usado neste registro"; o erro se chama NotSupportedError.) Cada nome só pode ser definido uma vez por página.

Como consertar: procure um <script src> repetido ou um segundo define com o mesmo nome.

No console: Must call super constructor in derived class before accessing 'this'

O que significa: a classe tem um constructor() sem o super() no começo. "É preciso chamar o construtor de cima (super) antes de usar o this." O erro (um ReferenceError) aparece quando o primeiro elemento é criado.

Como consertar: a primeira linha do constructor é sempre super();. Se você não precisa de constructor, não escreva um: o connectedCallback sozinho funciona, como na seção 2.

No console: Shadow root cannot be created on a host which already hosts a shadow tree

O que significa: o attachShadow rodou duas vezes no mesmo elemento. "Não dá para criar uma raiz de sombra num elemento que já tem uma." Acontece quando ele está no connectedCallback e o elemento sai e volta para a página.

Como consertar: crie o shadow DOM no constructor, como na seção 5, que roda uma vez só por elemento.

Fechar com <cartao-receita />

O que o navegador faz: como no <canvas /> e no <template />, a barra é ignorada e a tag fica aberta: tudo o que vem depois vira filho do cartão. Com o shadow DOM, esses filhos só aparecem se encaixarem num slot, e o resto da página pode sumir. O validador (com a tag na linha 8 e um parágrafo na linha 9):

$ vnu index.html
"file:/home/ana/site/index.html":8.1-8.18: error: Self-closing syntax (“/>”) used on a non-void HTML element. Ignoring the slash and treating as a start tag.
"file:/home/ana/site/index.html":10.1-10.7: error: End tag for  “body” seen, but there were unclosed elements.
"file:/home/ana/site/index.html":8.1-8.18: error: Unclosed element “cartao-receita”.

Como consertar: elementos personalizados sempre têm a tag de fechamento: <cartao-receita></cartao-receita>.

Element “cartao-item” not allowed as child of element “ul”

O que significa: as regras de quem pode ficar dentro de quem continuam valendo. Dentro de um <ul> só cabem <li>, e uma tag sua não é um <li>:

$ vnu index.html
"file:/home/ana/site/index.html":9.5-9.17: error: Element “cartao-item” not allowed as child of element “ul” in this context. (Suppressing further errors from this subtree.)

(Com <ul><cartao-item>x</cartao-item></ul> na linha 9.) Como consertar: ponha a tag dentro do item: <li><cartao-item>…</cartao-item></li>.

Resumo

  • Web Components = elementos personalizados + shadow DOM + <template>/<slot>. Funcionam em todos os navegadores atuais.
  • O nome de um elemento personalizado tem hífen, é minúsculo e sempre tem tag de fechamento. Sem hífen, o validador recusa a tag e o define dá is not a valid custom element name.
  • Antes de definida, a tag aparece como texto comum; o define atualiza as que já existem.
  • class X extends HTMLElement { connectedCallback() { … } } + customElements.define("meu-nome", X). O this é o elemento; this.getAttribute lê os atributos dele.
  • No constructor, super() vem primeiro; this.attachShadow({ mode: "open" }) cria o shadow DOM, que recebe a cópia de um <template> com slots.
  • Uma tag sua não traz significado para leitores de tela: use os elementos certos dentro dela.
