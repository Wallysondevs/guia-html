Nível 1 · Iniciante

Estrutura, texto, entidades, links, imagens, listas e tabelas.

1. O que é o HTML?

Explicação

HTML é "HyperText Markup Language", linguagem de marcação de hipertexto. Ele não faz contas nem toma decisões (isso é do JavaScript) e não cuida da aparência (isso é do CSS): marca o conteúdo.

Revise: O que é HTML

2. Para que serve o <!DOCTYPE html> na primeira linha?

Explicação

O DOCTYPE não é uma tag: é um aviso. Sem ele, o navegador entra no "modo quirks", imitando navegadores antigos, e o validador dá o erro Start tag seen without seeing a doctype first. Expected “<!DOCTYPE html>”.

Revise: O DOCTYPE

3. Onde fica o texto que aparece na aba do navegador?

Explicação

O <title> é obrigatório e vai no head. Ele aparece na aba, nos favoritos e como título do resultado de busca. Sem ele, o validador acusa Element “head” is missing a required instance of child element “title”.

Revise: title e meta

4. Qual destas linhas está aninhada corretamente?

Explicação

O que abre por último fecha primeiro, como caixas uma dentro da outra. Na primeira opção, as tags se cruzam, e o validador diz End tag “strong” violates nesting rules.

Revise: Aninhamento

5. Qual destes elementos é vazio (não tem tag de fechamento)?

Explicação

Os vazios são 13: area, base, br, col, embed, hr, img, input, link, meta, source, track e wbr. Escrever </br> é erro (End tag “br”.).

Revise: Elementos e Tags

6. Como o navegador mostra este parágrafo?

<p>Bolo      de
      cenoura</p>
Explicação

O HTML junta qualquer sequência de espaços e quebras de linha num espaço só. Para manter os espaços como estão, existe o <pre>; para quebrar a linha, o <br>.

Revise: Espaços e Quebras de Linha

7. Uma página tem um <h1> e, logo depois, um <h3>. O que o validador vnu 26.10 diz?

Explicação

A mensagem completa é The heading “h3” (with computed level 3) follows the heading “h1” (with computed level 1), skipping 1 heading level. Pular um nível atrapalha quem navega pelos títulos com um leitor de tela. Para um título menor, use h2 e mude o tamanho no CSS.

Revise: Títulos (h1 a h6)

8. Na frase "Cuidado: o forno está quente", que elemento marca o "Cuidado" como importante?

Explicação

O <strong> significa importância, seriedade ou urgência. O <b> também fica em negrito, mas só chama a atenção, sem dar importância. O <big> é obsoleto.

Revise: Negrito e Itálico

9. A Ana quer que apareça na página, como texto, a tag <p>. O que ela escreve no código?

Explicação

O < começa uma tag; para mostrá-lo, use a entidade &lt; (e, por costume, &gt; para o >). Aspas e barras invertidas não escapam nada no HTML.

Revise: Entidades

10. Para que serve o &nbsp; em R$&nbsp;12,90?

Explicação

&nbsp; é o "non-breaking space", o espaço que não quebra a linha. Ele tem a mesma largura de um espaço comum. Para afastar coisas na tela, use CSS, não vários &nbsp;.

Revise: Entidades e a tabela de espaços

11. No site da Ana, a página receitas/bolo.html precisa de um link para a página inicial, index.html, que está na pasta de cima. Qual href funciona?

Explicação

Um caminho relativo parte da pasta da página atual (receitas/). O ../ sobe uma pasta. index.html sozinho procuraria receitas/index.html, e um caminho do Windows não funciona depois que o site é publicado.

Revise: Caminhos Relativos e Absolutos

12. Como fazer um link que leva à seção <section id="contato"> da mesma página?

Explicação

O # no começo do href quer dizer "o elemento com este id, nesta página". O name no <a> é a forma antiga, obsoleta.

Revise: Âncoras na Mesma Página

13. O que o atributo target="_blank" faz num link?

Explicação

_blank abre numa aba (ou janela) nova. Use com moderação: muita gente prefere decidir sozinha, com o botão do meio do mouse. Quem baixa arquivos é o atributo download.

Revise: Nova Aba (target e rel)

14. O que o validador diz de <img src="bolo.jpg">?

Explicação

A mensagem é An “img” element must have an “alt” attribute, except under certain conditions. O <img> é vazio, então não tem </img> (escrever um dá Stray end tag “img”.).

Revise: Texto Alternativo (alt)

15. Uma imagem é só enfeite: um floreado entre duas seções, sem informação nenhuma. Qual é o melhor alt?

Explicação

O alt="" diz ao leitor de tela "pode pular esta imagem". Sem o atributo, o validador dá erro, e alguns leitores de tela leem o nome do arquivo. alt="imagem" não informa nada.

Revise: Texto Alternativo (alt)

16. Qual é o jeito certo de dizer que uma imagem tem 400 pixels de largura?

Explicação

Nos atributos width e height, o número é em pixels e vai sem unidade. Com px, o validador diz Bad value “400px” for attribute “width” on element “img”: Expected a digit but saw “p” instead.

Revise: Largura e Altura

17. O que pode ficar direto dentro de um <ul>?

Explicação

Dentro de ul e ol, só li (e elementos de script). Um <p> ali dá Element “p” not allowed as child of element “ul” in this context. Dentro do li, sim, cabe quase tudo, até outra lista.

Revise: Listas com Marcadores (ul)

18. Que lista combina com o modo de preparo de uma receita (primeiro isto, depois aquilo)?

Explicação

Quando a ordem importa, ol ("ordered list"). Para os ingredientes, em que a ordem tanto faz, ul. O dl é para pares termo → explicação.

Revise: Listas Numeradas (ol)

19. Numa tabela, qual elemento marca uma célula de cabeçalho (o título de uma coluna)?

Explicação

th = "table header", célula de cabeçalho; td = célula de dado. O thead agrupa as linhas de cabeçalho, e o caption é o título da tabela inteira.

Revise: Cabeçalhos (th, thead, tbody, tfoot)

20. O que faz <td colspan="2">?

Explicação

colspan junta colunas; rowspan junta linhas. O menor valor é 1: colspan="0" dá Zero is not a positive integer.

Revise: Mesclar Células (colspan e rowspan)

Nível 2 · Intermediário

O head, class e id, semântica, formulários e mídia.

21. O que faz <meta name="viewport" content="width=device-width, initial-scale=1">?

Explicação

Sem ela, o celular desenha a página como se fosse uma tela de computador, em miniatura. E não proíba o zoom (user-scalable=no): o validador avisa Consider avoiding viewport values that prevent users from resizing documents.

Revise: Celular (meta viewport)

22. Onde deve ficar o <meta charset="utf-8">?

Explicação

O navegador só procura a codificação no começo do arquivo. Muito para baixo, o validador acusa A “charset” attribute on a “meta” element found after the first 1024 bytes. O hábito do guia: a primeira linha do head.

Revise: Acentos, UTF-8 e Emoji

23. Qual é a diferença entre class e id?

Explicação

Dois elementos com o mesmo id dão Duplicate ID “…”. no validador. Uma class pode ter vários nomes separados por espaço (class="receita destaque"); um id não pode ter espaço.

Revise: class e id

24. Qual é a diferença entre <div> e <span>?

Explicação

São as "caixas genéricas" do HTML, para quando nenhum elemento com significado serve. O div começa numa linha nova e ocupa a largura toda; o span fica no meio do texto.

Revise: div e span

25. Que elemento envolve o menu principal de links do site?

Explicação

nav marca um bloco de navegação; o leitor de tela anuncia e deixa pular direto para ele. O <menu> existe, mas é para uma lista de comandos (botões), e uma div não diz nada.

Revise: nav

26. Quantos <main> visíveis uma página pode ter?

Explicação

O main é o conteúdo principal da página, e ele é um só. Dois dão A document must not include more than one visible “main” element.

Revise: main

27. Qual destas datas está no formato certo para o datetime?

Explicação

O datetime é para máquinas: ano-mês-dia. O texto dentro do time pode ser o que você quiser ("17 de outubro"). Com 17/10/2026, o validador diz The literal did not satisfy the time-datetime format.

Revise: time e data

28. O que acontece com este código no navegador?

<details>
  <summary>Dica da Ana</summary>
  <p>Bata as cenouras com os ovos.</p>
</details>
Explicação

O details começa fechado, mostrando só o summary. Para começar aberto, use o atributo booleano open. A janela por cima é o <dialog>.

Revise: details e summary

29. O que o for faz em <label for="email">E-mail</label> <input id="email" name="email">?

Explicação

O valor do for é o id do campo. Se não existir campo com esse id, o validador diz The value of the “for” attribute of the “label” element must be the ID of a non-hidden form control.

Revise: label

30. Num formulário, um campo <input type="text" id="cidade">, sem name, é preenchido com "Santos". O que é enviado?

Explicação

O que vai no envio é name=valor. O id serve para o label, o CSS e o JavaScript, mas não dá nome ao dado. Sem name, o campo é ignorado no envio, sem nenhum aviso.

Revise: Formulários

31. Num formulário com method="get", para onde vão os dados?

Explicação

No GET, os dados aparecem no endereço (bom para buscas, que você pode guardar nos favoritos). No POST, vão no corpo do pedido (bom para cadastros e senhas, sempre com HTTPS).

Revise: Enviar (action, method, GET e POST)

32. A Ana escreveu <input name="nome" required="false">. O campo é obrigatório?

Explicação

O navegador não olha o valor de um atributo booleano, só se ele existe. O validador diz Bad value “false” for attribute “required” on element “input”. Para um campo opcional, apague o required.

Revise: Validação (required, pattern, min…)

33. Três botões de rádio (Pequeno, Médio, Grande) devem permitir só uma escolha. O que eles precisam ter em comum?

Explicação

Os rádios com o mesmo name formam um grupo: marcar um desmarca os outros. Cada um tem o seu value (o que é enviado) e, se tiver id, um diferente.

Revise: checkbox e radio

34. Num <input type="date" name="festa">, o leitor escolhe 17 de outubro de 2026. Como o valor é enviado?

Explicação

Na tela, a data aparece na ordem do idioma do navegador; no envio (e no atributo value), é sempre ano-mês-dia. Por isso value="17/10/2026" é erro de validação.

Revise: Tipos de input e a referência

35. A Ana quer um vídeo de fundo que comece a tocar sozinho. O que, em geral, os navegadores exigem?

Explicação

Para não assustar ninguém com som, os navegadores costumam bloquear o vídeo que toca sozinho com som. Sem som (muted), ele toca. autoplay="true" é erro de validação: o atributo é booleano.

Revise: Vídeo

Nível 3 · Avançado

Acessibilidade, SEO, desempenho e o validador.

36. Qual é a melhor forma de fazer um botão que o teclado e o leitor de tela entendem?

Explicação

A primeira regra do ARIA: se existe um elemento HTML que faz o serviço, use o elemento. O <button> já recebe foco com Tab, funciona com Enter e espaço e é anunciado como botão. role="botao" nem existe (Bad value “botao” for attribute “role”).

Revise: ARIA e Botões

37. Sobre o tabindex, qual frase está certa?

Explicação

Links, botões e campos já recebem foco sozinhos. 0 inclui na ordem natural; -1 só permite o foco por JavaScript; valores positivos passam na frente de tudo e confundem quem navega pelo teclado.

Revise: Teclado e Foco (tabindex)

38. Na meta og:image (a imagem do cartão nas redes sociais), como deve ser o endereço?

Explicação

Quem lê a meta é o aplicativo da rede social, fora do seu site: ele precisa do endereço inteiro, com https://. Lembre também que o og:locale usa sublinhado: pt_BR.

Revise: Open Graph (Redes Sociais)

39. O validador mostrou Stray end tag “div”. O que isso quer dizer?

Explicação

Stray = perdida, solta. Quando falta fechar, a mensagem é outra: Unclosed element “div”. Nos dois casos, conserte a primeira mensagem e rode o validador de novo.

Revise: Mensagens do Validador e Validar o HTML

40. O que muda com <script src="receitas.js" defer></script> no head?

Explicação

Sem defer (e sem async), um <script src> no head trava a leitura da página enquanto baixa e roda. Com defer, a página aparece mais cedo, e o script já encontra todos os elementos prontos.

Revise: Desempenho (preload e defer) e O Elemento script
