HTML Formulários

A caixa de busca do Google, a tela de login do banco, o "deixe seu comentário" do blog, o carrinho da loja: tudo isso é formulário. Até aqui, as suas páginas só mostravam coisas. Com um formulário, a pessoa do outro lado da tela responde: digita, escolhe e envia. Esta aula é a visão geral: o elemento <form>, o que acontece quando alguém clica em "Enviar" e o que exatamente o navegador manda. Cada tipo de campo tem a sua aula logo depois desta.

Você vai aprender
  • O que é o <form> e quais peças ele junta (campos, rótulos e botão).
  • Por que todo campo precisa de um name, e o que acontece sem ele.
  • O que o navegador envia: os pares nome=valor, como q=bolo+de+cenoura.
  • Para onde e como os dados vão: os atributos action e method.
  • O que o editor do guia mostra quando você envia um formulário.
  • Os erros reais: formulário dentro de formulário, action vazio ou com espaço e method inventado.

Os exemplos foram validados com o validador W3C (vnu) e testados com um servidor local na máquina fictícia da Ana (usuária ana, computador notebook). Os quadros "Resultado" são desenhados pelo seu próprio navegador, e você pode digitar e enviar neles.

A ideia: a ficha de inscrição

Pense numa ficha de papel para se inscrever num curso de culinária:

  • a ficha inteira, de borda a borda, é o <form>;
  • cada linha em branco ("Nome: ______") é um campo, como o <input>;
  • o texto impresso antes da linha ("Nome:") é o rótulo, o <label>;
  • o nome interno de cada linha, que a secretaria usa para digitar a ficha no computador, é o atributo name;
  • entregar a ficha no balcão é enviar (o botão);
  • o endereço do balcão é o action, e o jeito de entregar (no envelope ou à mostra) é o method.

Uma linha preenchida fora da ficha (rabiscada na mesa) não é entregue. No HTML é igual: só vai o que está dentro do <form> e tem name.

1. O primeiro formulário: uma busca

O site de receitas da Ana vai ganhar uma caixa de busca:

<form action="busca.html">
  <label for="q">Buscar receita:</label>
  <input id="q" name="q">
  <button>Buscar</button>
</form>
<form>
De form, "formulário". Uma caixa invisível que junta os campos e sabe enviá-los. Sozinho, ele não desenha nada na tela.
action="busca.html"
"Ação": para onde os dados vão quando a pessoa envia. Aqui, para a página busca.html.
<label for="q">
O rótulo, o texto que diz o que digitar. O for="q" o liga ao campo de id="q": clicar no rótulo põe o cursor no campo, e o leitor de tela lê "Buscar receita" ao entrar nele. Tem aula própria: label.
<input id="q" name="q">
O campo onde a pessoa digita (aula O Elemento input). O id serve para o label achá-lo; o name é o nome do dado na hora do envio. O q vem de query, "consulta": é o nome que quase todo site usa para a busca.
<button>Buscar</button>
Um botão dentro de um formulário envia o formulário quando é clicado (aula Botões).

Digite "bolo de cenoura" no resultado e clique em Buscar (ou aperte Enter dentro do campo, que também envia). Como aqui não existe uma busca.html nem um servidor, o editor do guia mostra uma página "Formulário enviado" com o que o navegador mandaria: o método, o destino, o endereço que abriria e uma tabela com cada name e o seu valor. O botão "Voltar ao formulário" traz a página de volta.

Aparência

O desenho do campo e do botão (borda, cantos, cor, tamanho) muda de um navegador para outro e de um sistema para outro: no celular, no Windows e no Mac, o mesmo código fica um pouco diferente. Tudo isso pode ser mudado com CSS (futuro Guia CSS).

2. O que o navegador envia

Ao enviar, o navegador monta uma lista de pares name=valor, um para cada campo, e pede o endereço do action com essa lista depois de um ?:

busca.html?q=bolo+de+cenoura
busca.html
O destino, que veio do action.
?
Separa o endereço dos dados. Tudo o que vem depois é a "consulta" (query string).
q=bolo+de+cenoura
O par: o name do campo (q), um = e o que a pessoa digitou. Os espaços viram +.

Para ver isso chegando num servidor de verdade, a Ana criou uma busca.html qualquer, ligou o servidor local do Python (aula Servidor Local) e pediu o mesmo endereço que o navegador pediria. Quem faz o pedido aqui é o curl, um programa que pede páginas pelo terminal, como um navegador sem tela:

$ python3 -m http.server 8000 &      « liga o servidor em segundo plano
[1] 4
$ sleep 1                « espera um segundo o servidor ligar
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
$ curl -s -o /dev/null "http://localhost:8000/busca.html?q=bolo+de+cenoura"
127.0.0.1 - - [17/Oct/2026 15:53:31] "GET /busca.html?q=bolo+de+cenoura HTTP/1.1" 200 -

O -s -o /dev/null só pede ao curl para não mostrar a página recebida. A linha que começa com 127.0.0.1 é o registro do servidor: "alguém nesta máquina pediu (GET) a página /busca.html?q=bolo+de+cenoura e recebeu o código 200" (200 = deu certo). O servidor recebeu a busca inteira. Num site de verdade, um programa no servidor (em PHP, Python, JavaScript…) leria o q e montaria a lista de receitas. Isso já não é HTML: o trabalho do HTML termina quando os dados saem do navegador.

Vários campos, acentos e símbolos

Com vários campos, os pares são separados por &. Letras acentuadas e símbolos viram códigos com %, porque um endereço só pode ter letras simples, números e alguns sinais. Com o servidor ainda ligado, a Ana pediu mais dois endereços, do jeito que um formulário de contato e uma busca com acento mandariam:

$ curl -s -o /dev/null "http://localhost:8000/busca.html?nome=Ana&email=ana%40exemplo.com.br&msg=Adorei+o+bolo%21"
127.0.0.1 - - [17/Oct/2026 15:53:31] "GET /busca.html?nome=Ana&email=ana%40exemplo.com.br&msg=Adorei+o+bolo%21 HTTP/1.1" 200 -
$ curl -s -o /dev/null "http://localhost:8000/busca.html?q=p%C3%A3o+de+queijo"
127.0.0.1 - - [17/Oct/2026 15:53:31] "GET /busca.html?q=p%C3%A3o+de+queijo HTTP/1.1" 200 -
$ kill %1                « desliga o servidor
A pessoa digitouVai no endereço como
espaço+
@%40
!%21
ã%C3%A3 (os dois bytes do "ã" em UTF-8, aula Acentos e UTF-8)

Você não precisa decorar nada disso: o navegador codifica sozinho, e o servidor decodifica sozinho. Mas, quando vir um endereço cheio de % e +, você vai saber que é um formulário que passou por ali.

Sem name, não vai

O name é a etiqueta do dado. Um campo sem name aparece na tela, a pessoa digita nele, mas o navegador o deixa de fora do envio:

<form action="busca.html">
  <label for="q">Buscar receita:</label>
  <input id="q">
  <button>Buscar</button>
</form>

Digite algo e clique em Buscar: o editor avisa que nenhum campo com name foi enviado, e o endereço fica só busca.html?, sem dados. O validador não reclama, porque um campo sem name é permitido (às vezes ele só serve para um script). Por isso esse é um dos erros mais comuns em formulários.

Missão: o formulário de inscrição da aula de bolos chega sempre vazio à Ana. Envie uma vez e veja o que o editor mostra. Depois dê aos dois campos os nomes nome e cidade e envie de novo: agora a tabela mostra os dois pares.

<form action="inscricao.html">
  <p>
    <label for="nome">Nome:</label>
    <input id="nome">
  </p>
  <p>
    <label for="cidade">Cidade:</label>
    <input id="cidade">
  </p>
  <button>Inscrever</button>
</form>

<form action="inscricao.html">
  <p>
    <label for="nome">Nome:</label>
    <input id="nome" name="nome">
  </p>
  <p>
    <label for="cidade">Cidade:</label>
    <input id="cidade" name="cidade">
  </p>
  <button>Inscrever</button>
</form>

Repare nos <p> em volta de cada par rótulo + campo: eles só servem para pôr cada um numa linha. Sem eles, tudo ficaria lado a lado, porque campos e rótulos são elementos em linha (aula Bloco × Em Linha).

3. Para onde e como: action e method

AtributoO que dizSe você não escrever
action="busca.html"Para onde os dados vão: um endereço (de uma página, de um programa no servidor)Vão para a própria página em que o formulário está
method="get"Como: os dados vão no endereço, depois do ?, como você viu acimaget é o padrão
method="post"Como: os dados vão escondidos no "corpo" do pedido, fora do endereço—

Uma comparação rápida: o get é um cartão-postal, em que tudo fica à vista (no endereço, no histórico do navegador, nos favoritos); o post é uma carta no envelope. Use get para buscas e filtros (dá para guardar o link da busca) e post para o que muda alguma coisa ou é pessoal: cadastro, compra, senha, mensagem. A diferença completa, com o que chega no servidor em cada caso, está na aula Enviar (action, method, GET e POST).

<form action="obrigado.html" method="post">
  <p>
    <label for="email">Seu e-mail:</label>
    <input id="email" name="email">
  </p>
  <p>
    <label for="msg">Mensagem:</label>
    <input id="msg" name="msg">
  </p>
  <button>Enviar</button>
</form>

Preencha e envie: desta vez o editor mostra o corpo da mensagem (email=…&msg=…) em vez de um endereço com ?. Os pares são os mesmos; só o caminho muda.

Experimente: esta caixa tem duas abas. A busca da index.html manda para a busca.html, que existe aqui. Envie e repare no endereço em cima do resultado: busca.html?q=…. Depois troque para method="post" e envie de novo. Por fim, acrescente um segundo campo (name="tipo") e veja o & aparecer.

<h1>Receitas da Ana</h1>
<form action="busca.html" method="get">
  <label for="q">Buscar receita:</label>
  <input id="q" name="q">
  <button>Buscar</button>
</form>

<h1>Resultado da busca</h1>
<p>Num site de verdade, o servidor leria o endereço e listaria as receitas aqui.</p>
<p><a href="index.html">Nova busca</a></p>

4. As peças de um formulário

Dentro do <form> podem ir textos, títulos, parágrafos e listas, como em qualquer parte da página, e os controles: as peças em que a pessoa mexe. Cada uma tem a sua aula:

PeçaPara quêAula
<input>O campo mais comum: uma linha de texto e muitos outros tiposO Elemento input, Tipos de input
<label>O rótulo de cada campolabel
<textarea>Texto de várias linhas (comentários, mensagens)textarea
<select> e <option>Uma lista para escolherselect e option
<button>Enviar, limpar ou outra açãoBotões
<input type="checkbox"> e "radio"Marcar opçõescheckbox e radio
<fieldset> e <legend>Agrupar campos com um títulofieldset e legend

E, para conferir o que a pessoa digitou antes de enviar (campo obrigatório, e-mail válido), existe a validação do próprio HTML.

Quando dá errado

As páginas abaixo têm o esqueleto de sempre (<!DOCTYPE html>, <head> e <body>) nas linhas 1 a 7, e o <form> começa na linha 8.

Formulário dentro de formulário

A Ana quis pôr a busca dentro do formulário de cadastro:

<form action="cadastro.html">
<label for="nome">Nome:</label>
<input id="nome" name="nome">
<form action="busca.html">
<label for="q">Buscar:</label>
<input id="q" name="q">
<button>Buscar</button>
</form>
<button>Cadastrar</button>
</form>

$ vnu dentro.html
"file:/home/ana/formulario/dentro.html":11.1-11.26: error: Saw a “form” start tag, but there was already an active “form” element. Nested forms are not allowed. Ignoring the tag.
"file:/home/ana/formulario/dentro.html":17.1-17.7: error: Stray end tag “form”.

O validador diz: "Encontrei uma tag <form>, mas já havia um form aberto. Formulários aninhados não são permitidos. Ignorando a tag." E, na linha 17: "tag de fechamento form perdida" (stray = "extraviada").

O que o navegador faz: exatamente o que a mensagem diz. Ele ignora o segundo <form> (com o action="busca.html" e tudo). O primeiro </form> (linha 15) fecha o formulário de cadastro. O botão "Cadastrar" fica fora de qualquer formulário e não faz nada; o último </form> sobra. No resultado acima, "Buscar" envia nome e q para cadastro.html, e "Cadastrar" não envia nada. Teste.

Como consertar: um formulário nunca vai dentro de outro. Faça dois formulários separados, um depois do outro.

action="" vazio 
$ vnu vazio.html
"file:/home/ana/formulario/vazio.html":8.1-8.16: error: Bad value “” for attribute “action” on element “form”: Must be non-empty.
"file:/home/ana/formulario/vazio.html":8.1-8.16: info: To set the document’s location as the action for a form, omit the “action” attribute.

O que significa: "Valor ruim (vazio) para o atributo action: precisa ter algo". E a dica (info, que não é erro): "para enviar para a própria página, omita o atributo action". O navegador trata os dois do mesmo jeito (envia para a própria página), mas só a versão sem action é válida.

Como consertar: apague o action="", ou escreva o destino.

Espaço no action 
$ vnu espaco.html
"file:/home/ana/formulario/espaco.html":8.1-8.35: error: Bad value “busca receitas.html” for attribute “action” on element “form”: Illegal character in path segment. Space is not allowed.

O que significa: "Caractere proibido no caminho: espaço não é permitido". O action é um endereço, e endereços não têm espaço (aula Caminhos).

Como consertar: renomeie o arquivo sem espaços (busca-receitas.html), que é a regra para todo arquivo de site.

method="put" (ou qualquer outro inventado) 
$ vnu put.html
"file:/home/ana/formulario/put.html":8.1-8.39: error: Bad value “put” for attribute “method” on element “form”.

O que significa: o method de um formulário só aceita get, post e dialog (este último é o da aula dialog). Outros valores existem em programas que conversam com servidores, mas não em formulários HTML.

O que o navegador faz: não avisa nada e usa o padrão, get. Os dados vão no endereço, talvez sem a Ana perceber.

Como consertar: method="get" ou method="post".

O campo não chegou (e ninguém reclamou)

O que acontece: a página funciona, o validador não acusa nada, mas um dado não aparece no envio. Confira, nesta ordem:

  1. O campo tem name? Sem ele, não vai.
  2. O campo está dentro do <form>? Um campo fora dele não vai junto.
  3. Dois campos têm o mesmo name sem querer? Os dois vão (q=bolo&q=torta), e o programa do servidor pode ficar só com um.

Use o editor do guia (ou, num site publicado, a aba de rede das Ferramentas do Desenvolvedor) para ver exatamente quais pares saíram.

Resumo

  • <form> junta os campos e os envia. Ele não aparece na tela; quem aparece são os campos, os rótulos e o botão.
  • Ao enviar (botão ou Enter), o navegador monta pares name=valor. Campo sem name ou fora do <form> não vai, e o validador não avisa.
  • action = para onde (sem ele, a própria página; vazio é inválido). method = como: get (padrão, dados no endereço: ?q=bolo+de+cenoura) ou post (dados no corpo).
  • No editor do guia, enviar mostra uma página "Formulário enviado" com o método, o destino e os pares.
  • Formulário dentro de formulário não existe: o navegador ignora a tag de dentro (Nested forms are not allowed. Ignoring the tag.), e os botões passam a enviar para o lugar errado.
